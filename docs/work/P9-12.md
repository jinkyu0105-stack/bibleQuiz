## CI 모바일 스크롤 검사 보정

최초 CI38202232552의 유일한 실패는 `sky-controls-polish.spec.ts`의 긴 섹션 읽기 검사다. 모바일에서 wheel 직후 위치를 단발성으로 읽어 bottom678.71875와 고정 기준698을 비교했고 재시도2회도 같은 원인으로 실패했다. 합성 응답/동일1280×700에서 PC·Pixel7을 측정하니 section height738.71875, 모바일 native snap 이동 도중 bottom692.71875→400ms 뒤699.71875로 정상 정착했다. 실제 스크롤 구현은 바꾸지 않는다.

Playwright1.62.1에 대해 Context7 `/microsoft/playwright`의 공식 wheel/자동 재시도 assertion 문서를 확인했다. `mouse.wheel`은 스크롤 완료까지 기다리는 API가 아니다. 기존 `scrollY`가 조금 증가했다는 조건은 정착 완료 증거가 아니었다. 고정698 단발 검사 대신 실제 `innerHeight`와 섹션 bottom의 차이가2px 미만이 될 때까지 `expect.poll`로 확인하도록 보정했다. 끝까지 읽기/라우트 복원/본문 포커스 검사는 유지한다. 수정 뒤 lint/typecheck exit0. 해당 파일 PC·모바일 각3회(18건) 중 변경한 긴 섹션6건은 모두 통과했으나 별도의 PC 앵커 이동에서1회 실패(weekly top615,5초 timeout)로17통과/1실패였다. 원인을 확정하지 않고 trace retain-on-failure를 켠 동일18건 재검사는 모두 통과했다(1.4분). 앞선 PC 간헐 실패는 최종 반복에서 재현되지 않았으며 원인 확정 없이 한계로 기록한다. 실제 앱 코드를 추측으로 변경하거나 해당 검사를 제외하지 않는다. 테스트 assertion과 문서만 보정 커밋으로 push하고 CI/배포를 다시 확인한다. 제품/서버 실행 코드가 같으므로 이번 로컬 full check·Preview dry-run 결과는 유지하고, test-only 수정에는 관련 반복/lint/typecheck를 적용했다. 새 GitHub CI가 full check와 전체 브라우저를 재실행한다.
