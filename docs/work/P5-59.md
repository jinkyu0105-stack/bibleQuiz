# P5-59 — 첫 제출 전 발행 철회의 로컬 연결

2026-09-23. **로컬 구현·필수 검사·상태 문서 갱신 완료.** 부모 Phase 5 진행 중. P5-58 완료 상태와 기존 미커밋 변경을 이어받았다.

## 구현 경계

- [철회 service](../../workers/_shared/services/quiz-withdrawal.ts) · [관리 DTO](../../shared/api/admin-withdraw.ts) · [0023 migration](../../migrations/0023_phase5_withdrawals.sql). 첫 제출 전의 아직 마감되지 않은 published 세트만 철회한다. 모든 난이도·과거 revision의 제출을 조회하며 visible/hidden/deleted를 모두 성공 제출 이력으로 센다. 정정 번호·발행 시각을 commit 시 재검증한다.
- 영구 발행 자료와 최신 제목·설교일을 새 검수 revision 시작 자료로 복사한다. 요약·공식 장절 링크·두 난이도 격자/단서·근거·정답을 보관하며 초안 본문과 관리자/참여자/비용 정보를 새 DTO에 복사하지 않는다. 완전한 정식 자료가 있는 옛 snapshot 없는 발행도 지원한다. 입력 원본/기존 초안은 되살리거나 덮어쓰지 않는다.
- 불변 `quiz_withdrawals`를 삽입할 때 세트 `review_ready + paused`, 기존 active variant `withdrawn`, 필요한 featured 재선정을 수행한다. 최신 열린 published가 우선이며 없으면 최근 archived를 읽기 전용으로 선정하고, 둘 다 없으면 빈 featured로 준비 안내를 허용한다. 기존 featured가 다른 세트라면 변경하지 않는다. 감사 저장까지 같은 D1 batch이며 실패하면 전부 취소한다.
- 최초 snapshot·정정 이력·문제/정답·slug·발행/접수 기간·참여/순위·비용은 보존한다. 과거 발행 요청 재생과 직접 상태 변경으로 철회본을 다시 공개하지 못하도록 한다. 기존 0018/0022 guard를 수정하지 않는다.
- [관리 API](../../workers/app/app.ts)는 Access JWT·private no-store·same-origin JSON/16KB·strict/query/method 경계를 적용한다. POST는 동일 key/내용/관리자만 성공을 재생한다. GET 단건은 관리자 전용 정답 포함 검수 자료, 목록은 제목/철회 시각/검수 번호만 제공한다.
- [화면](../../src/features/admin-sermon-input/WithdrawPublication.tsx)은 기존 승인 테마와 입력 요소를 사용한다. 사유와 확인/취소, 실패 때 사유 보존·같은 요청 재확인, 목록 재조회, 새로고침 후 철회 자료 조회를 연결했다. 기존 생성 화면도 철회 상태를 별도로 읽어 옛 초안/발행 버튼 대신 검수 자료를 안내한다. 재발행·문제 수정 버튼은 이번 범위에 없다. 검수본을 실제로 편집·재검증·재발행하는 흐름은 P5-60에서 연결한다.
