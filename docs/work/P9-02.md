# P9-02 — 승인 시안에 맞춘 공개·관리자 UI 개편

2026-10-06. 부모는 **Phase9 진행 중**이다. P9-01 조사 뒤 받은 직접 구현 지시에 따라 P9-02에서 구현한다. P9-03 구현 제안은 통합했으며 번호를 재사용하지 않는다. 사용자가 918dba4의 시안 재현을 거절하고 재작업을 요청했다. 이전 기능 검사 통과를 디자인 승인으로 취급하지 않는다. 현재 재개와 최종 검사는 [STATUS](../STATUS.md)·[HANDOFF](../HANDOFF.md)를 따른다.

## 이번 범위와 완료 조건

- Phase7A 원본8종과 MD를 기준으로 공개·관리자 화면을 구현한다. 특히 장년/어린이는 패널 위치만 바꾸는 동일 구조로 만들지 않는다.
- 사용자가 지정한 Phase7B 배경 master4종을 Phase7A 01/02 입력 이미지에서 새로 만든다. 내장 imagegen4회로 가로2장/별도 세로2장을 제작했다. [생성 지시 요약](../design/phase-7b/replacement-2026-10-06.json)·[현재 자산 목록](../design/phase-7b/assets.json)을 보존한다.
- `celebration.png`와 화면/인쇄 파생본, Phase7A 원본, 기존 garden-v1, 출력 TTF/fontkit을 보존한다. 새 배경은 garden-v2로 실제 연결한다. API가 제공하는 별도 주간 이미지 경로의 우선순위도 보존한다.
- 시안에 자리가 없더라도 기존 정보를 삭제하지 않는다. 실제 요약 전문/고지, 사람 확정, 저장/충돌, 원문·이전 결과, 비용, 발행 확인, 제출/삭제/출력 권한을 유지한다.
- 관련 브라우저 검사, lint/typecheck·완료 단위 `pnpm check`, 실제 화면 비교, 문서·로컬 커밋까지 진행한다. 사용자 화면 검토 전에는 같은 P9-02를 검수 대기로 유지한다.
- 서버 정책·migration·실제 자료·키·유료 결과를 변경하지 않는다. 실제 설교 AI 실행·main push·Preview/Production 배포는 제외한다. 완료한 실제 입력/PDF/백업/청구/출시 검수는 반복하지 않는다.

`design-taste-frontend`를 읽고 기존 화면부터 검토했다. DESIGN_VARIANCE5 / MOTION_INTENSITY3 / VISUAL_DENSITY5. 승인된 구도와 기능 보존 조건이 새 브랜드를 만드는 일반 규칙보다 우선한다. 같은 구도에 색만 바꾸는 접근은 폐기했다. UI의 빈 막대는 이미지에 글자를 합성하지 않고 실제 HTML 정보로 채운다.

## 코드 진입점과 기능 보존

- `src/features/quiz/SermonHero.tsx`: 별도 Adult/Child 구조. `QuizArtwork.tsx`: 새 최적화본/mobile 선택. `public-page.tsx`·`preview-page.tsx`에서 연결하며 요약 전문은 `sermon-details`에 보존한다.
- `src/styles/sermon.css`와 `fonts.css`: 전체 배경/두 구도/서체/반응형/글자 대비. `src/app/screens.tsx`: 경로별 공통 배치.
- `quiz.module.css`: 실제 격자·결과·참여 표시. 기존 입력/IME 조합·임시 저장·초기화·부분 제출·정답 공개/삭제·연습 채점은 같은 구현을 유지한다. CSS 변화로 격자를 잘라내지 않는다.
- `ArchiveCards.tsx`와 `archive.module.css`: 최신/목록 표시만 변경. 검색·정렬·페이지 계약은 유지한다.
- 관리자 CSS: 현재 상태/다음 행동 강조, 녹색 메뉴, 파란 현재 단계. 이전 P9-02의 선택본 우선·의도9항목/근거/과거본/품질·재생성 접기와 요약/어린이/장년 전환을 유지한다. 편집기를 숨겨 저장 실패 입력을 보존하고 사람 확정/발행 확인을 제거하지 않는다.

## 검사와 관찰

모든 앱 검사는 로컬 격리 D1·합성 응답이다. 실제 설교·개인정보·키·유료 결과를 캡처하지 않았다. [현재 화면](../design/phase-9/README.md)과 [측정 요약](../design/phase-9/verification.json)이 현재 근거다. 이전 918dba4의 Lighthouse93/접근성100은 이전 구현 수치이며 이번 결과에 재사용하지 않는다.

- 관련 공개/제출/참여/지난 퀴즈/관리자 Chromium36건 통과.
- 새 데스크톱 구도·전체 요약 보존·풀이 이동 검사와 기존 반응형/이미지 실패/키보드/모션/대비 검사: Chromium·모바일 Chromium·Firefox18건 통과. WebKit6건 통과.
- WebKit 첫 실행은 브라우저 부재, 다운로드 후 host 라이브러리 부재로 시작하지 못했다. 공식 Ubuntu 라이브러리를 `/tmp`에만 풀고 실제 WPE ELF 의존성 누락0을 확인했다. 별도 실행 파일 경로로6건 통과했다. 시스템 설치·원본 브라우저/프로젝트 설정 수정·실제 기기 재검수는 없다.
- 결과/참여의 합성 캡처는 기존 동작 검사를 실행해 촬영했다. 초기 캡처 보조 코드가 결과를 숨긴 뒤 촬영하려던 오류와 애니메이션 도중 촬영한 이미지는 폐기하고, 실제 표시 상태·애니메이션 종료 뒤 다시 촬영했다.
- `pnpm check` exit0(unit308/Worker2195/Workflow4/recoveryCLI2/Node14/Python7·lint/typecheck/Drizzle/build), 최종 글꼴 변경 뒤 typecheck/build와 구도/320px·200% reflow2건 통과.
- 최종 로컬 모바일 가정 측정은 장년/어린이 성능75·접근성100. 글꼴 전송 약806→282KB, 최초 표시3.3→2.7초. LCP5.4초는2.5초 기준 미달이고 배포 전 같은 P9-02에서 검토할 한계다. 운영/실기기/INP 수치가 아니다. 검사만으로 사용자 시각 만족도나 실제 기기 검수를 완료했다고 하지 않는다.
