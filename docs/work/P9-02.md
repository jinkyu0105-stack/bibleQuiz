# P9-02 — 승인 시안에 맞춘 공개·관리자 UI 개편

2026-10-06. 부모 Phase9 진행 중. 사용자는 `docs/design/`에 있는 대로 `design-taste-frontend`를 사용해 실제 프런트엔드를 수정하라고 요청했으며, 시안에 자리가 없는 기존 기능도 누락하지 않고 배치를 유연하게 조정하도록 명시했다. [P9-01](P9-01.md)의 조사 전용 범위 이후 받은 별도 구현 지시다. 현재 검사 결과·재개 상태는 [STATUS](../STATUS.md)·[HANDOFF](../HANDOFF.md)를 따른다.

## 이번 범위와 완료 조건

- 기존 Phase7A 시안8종과 Phase7B 배경/축하 자산·폰트·테마를 재사용한다. 공개 첫 화면·풀이·결과·참여 현황·지난 퀴즈와 관리자 공통 메뉴/주간6단계를 함께 맞춘다.
- 이미지와 같은 위치를 만들기 위해 기존 정보를 삭제하지 않는다. 사람 확정, 저장/충돌, 원문·이전 결과, 비용, 발행 확인, 제출/삭제/출력 권한을 유지한다.
- 관련 브라우저 검사, lint/typecheck와 완료 단위 `pnpm check`, 화면 비교, 문서·로컬 커밋까지 진행한다. 사용자의 화면 검토가 남으면 같은 P9-02를 검수 대기로 유지한다.
- 서버 정책·자료형·migration·실제 자료·키·유료 결과·폰트/fontkit은 보존한다. 격자 자동 제안·후보 생성 조건·Supadata 사용량·영문 알림·반복 시험 등 별도 보류를 구현하지 않는다.
- main push·Preview/Production 배포·실제 AI/imagegen 호출은 이번 범위 밖이다. 이미 끝난 실제 입력·PDF·백업·출시 검수는 반복하지 않는다.

사용자가 시안을 기준으로 직접 구현하도록 요청했으므로 별도 시안 승인만 기다리지 않고 P9-02에서 구현한다. 기존 **P9-03 구현 제안은 P9-02에 통합**하며 별도 완료나 새로운 작업으로 재사용하지 않는다. P9-04 운영 반영은 로컬 결과 검수와 배포 승인 후의 작업으로 남긴다. Phase8 완료는 유지한다.

## 기능을 보존한 방법

- 공통 관리자 메뉴를 RootLayout으로 옮겼다. 주간 운영·필터·문의/삭제·발행/수정 도구·비용/백업·매뉴얼의 기존 경로와 기능을 유지한다. PC에서는 항상 보이고 모바일에서는 키보드로 열고 닫는다.
- 작업 제목·저장/보관 정보·현재 상태·선택본·다음 버튼을 위에 정리했다. 다음 버튼은 기존 단계 잠금과 저장 확인을 그대로 거친다. 잠금 이유도 단계표에 남는다. 단계표와 비용 표시가 서로 덮지 않는다.
- 의도9항목은 모두 남기고 중심 메시지를 기본으로 펼친다. 원문 위치 확인·교체·추가/삭제·출처, 비판 지적, 품질 평가/메모, 개별/전체 재생성·이전 결과 불러오기를 상세 영역에서 제공한다.
- 요약/어린이/장년을 전환할 때 편집기를 제거하지 않고 숨긴다. 같은 자료ID의 편집 상태를 유지하므로 저장 실패 후 다른 대상을 봤다가 돌아와도 입력이 남는다. 저장 성공/버전 변경과 기존 선택 무효화 정책은 그대로다.
- 선택본의 저장·확정/검수 버튼은 긴 본문 앞에, 발행 버튼은 최종 미리보기 앞에 둔다. 기존 필수 체크·유료 실행 확인·사람 확정·발행 영향 확인창은 제거하지 않는다.
- 참여 현황의 장식용 전환 복사본이 화면 폭 변경 중 가로 스크롤을 만들던 문제는 목록 밖 장식만 잘라 해결했다. 실제 카드·답안 내용은 유지한다.

React19.2.8의 숨긴 자식 상태 보존/제거 시 초기화 동작은 Context7 공식 저장소 자료로 확인했다. 새 라이브러리나 유료 서비스를 추가할 이유가 없었다.

## 관찰·검사 기록

동일한 P9-01 합성 자료에서 의도 화면 기본 높이는 PC13,421→2,703px, 모바일14,795→3,081px다. 전체 내용을 펼친 상태의 길이 제한이나 성능 점수가 아니다. 현재 선택본·9항목·원문 근거는 모두 남아 있다. PC1366×768/모바일390×844의7상태14캡처에서 page error·외부 요청·쓰기 요청0이며 관찰 폭 가로 넘침0이었다. 공개 장년/어린이·지난 퀴즈의 밝은/어두운6화면에서도 오류/가로 넘침0이었다.
