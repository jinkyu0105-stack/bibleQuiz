## 범위와 확인한 문제

사용자는 사이드바는 이해할 수 있지만 콘텐츠 안에서 각 기능의 역할을 알기 어렵다고 했다. 기존 도구 화면은 서로 다른 6개 도구와 상세 편집 폼을 모두 같은 위계로 펼쳐, 첫 사용자가 평소의 퀴즈 만들기와 예외적인 발행 수정을 구분하기 어려웠다. 다른 메뉴도 목적·순서·조치 결과를 각자 추론해야 했다.

`design-taste-frontend`의 기존 화면 점검/가독성 원칙을 참고했다. 해당 스킬의 주요 대상에서 밀도 높은 관리자 화면이 제외되므로 랜딩 페이지 구성·새 UI 라이브러리·이미지 생성은 적용하지 않았다. 기존 Air 유리 재질/색상/공통 버튼을 유지하고 새 안내는 낮은 시각적 변화·움직임 없음·중간 정보 밀도로 구현한다.

## 구현

- `src/components/AdminGuide.tsx`의 `AdminIntro`, `AdminSteps`, `AdminTool`로 목적 설명, 짧은 사용 순서, 필요한 도구만 펼치는 구성을 재사용한다. native details/summary를 사용하고 자식 폼을 언마운트하지 않아 접을 때 입력을 버리지 않는다. 여러 도구를 동시에 열 수 있다. 새 효과/의존성/요청 계층은 없다.
- `/admin/tools`: 공개 퀴즈 수정과 초안/입력 점검을 나눈다. 제목·오탈자, 제출 전 철회, 제출 후 오류, 초안 보관 조회, 상세 입력자료, 장절 확인의 용도·조건을 먼저 보여준다. 기본은 접힘이고 새 퀴즈를 위한 주간 운영 진입을 안내한다. 기존 내부 제목/실제 API/폼/확정/잠금은 보존한다.
- 주간 운영: 만들기/이어서 하기 우선은 유지하고 준비→검수·발행→참여 확인 순서, 대표 퀴즈/초안/공개 퀴즈의 의미와 빈 목록의 다음 행동을 안내한다.
- 폼 배치: 입력칸 옆에서 세로로 늘어나던 버튼을 입력 항목 다음 줄로 옮기고, 단순 재조회 버튼의 전체 너비 늘어남을 없앤다. 체크박스는 라벨과 함께 읽도록 배치한다. 버튼 자체의 재질·상태·최소 높이는 그대로다.
- 이름·문구 필터: 선택한 등록 종류의 목적과 입력 방법, 시험의 비저장 성격을 설명하고 목록의 범위/일치 방식을 한국어로 표시한다.
- 문의: 내용 확인→실제 조치→답변 저장 흐름과 상태 변경만으로 삭제되지 않는 점을 안내한다. 제출 기록: 퀴즈 선택/필터 빈 결과, 숨김·복원·복구 불가능한 삭제의 차이를 설명한다.
- 비용·백업: 상태 확인·상세 조회·월간 점검 순서와 상세 화면의 사용량/백업/요금 확인 구획을 설명한다. 기존 가격/한도/경고와 확인 절차는 바꾸지 않는다. 매뉴얼은 자주 찾는 작업 링크와 서비스 사전의 역할을 안내하고 문서 검증 정보는 접는다.
- 발행 6단계: 이번 단계의 목적과 다음 단계로 갈 조건을 짧게 안내한다. 공개된 퀴즈의 운영 화면/Top N 표시 인원도 설명한다.

서버/API·DB/migration·권한·원문/유료 결과·키·자산·패키지·사이드바는 변경하지 않는다. 원격 배포는 P9-12의 Preview 소스2d2b1aa/version7f09d123, Production P9-04를 유지한다. 새 UI는 로컬 적용이며 push/배포하지 않는다.
