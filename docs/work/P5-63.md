## 연결한 동작

- `/admin` → 발행 정보 정정 → 퀴즈 선택 → `마감 일시 변경`. [관리자 폼](../../src/features/admin-sermon-input/QuizDeadline.tsx)은 한국 시간 입력을 UTC로 변환하고 기존/변경 마감·남은 시간·전체 성공 제출과 공개/숨김/삭제 표식 수·사유를 확인한다. 입력이 바뀌면 확인을 해제한다. 실패 시 입력과 동일 요청을 유지하고 명시적 영향 재조회/최신 마감 조회를 제공한다.
- [DTO](../../shared/api/admin-deadline.ts) · [서비스](../../workers/_shared/services/quiz-deadline.ts) · [API](../spec/api.md#p5-63-일반-마감-변경-api). Access·same-origin JSON·기존 16KB·strict/query/method·private no-store 경계를 적용한다. 미리보기는 읽기만 수행하고 기존 SESSION_PEPPER를 사용하는 별도 `quiz-deadline-v1` 서명 토큰에 대상·관리자 digest·사유·요청 시각·현재 상태를 묶는다. fallback secret·새 secret·새 의존성은 없다.
- 기존 `audit_logs`의 필수 entity ID 제약을 원자 저장의 조건 검사로 재사용한다. 현재 상태/마감/접수·문제 버전·전체 성공 제출/상태별 수·오류 처리 주기/결과·마감 변경 수를 commit 때 비교한다. stale 상태면 감사·마감 변경을 함께 rollback한다. 같은 requestKey·내용·관리자만 기존 성공을 재생하며 후속 변경을 되돌리지 않는다.
- 일반 미래 변경은 `quiz_sets.closes_at/updated_at`와 새 감사만 변경한다. 이미 시간상 마감했거나 archived인 퀴즈를 연장하지 않는다. 미리보기 때 미래였던 요청 시각이 저장 전 지나도 자동으로 즉시 마감하지 않고 재확인을 요구한다.
- 과거/현재 요청은 명시적인 `close_now` 확인을 받아 [기존 finalizer](../../workers/_shared/services/quiz-finalization.ts)에 조건부 감사 insert를 같은 batch의 선두로 전달한다. 실제 저장 시각에 마감하고 원래 finalizer의 두 난이도 snapshot·archive·close_now 감사와 함께 commit/rollback한다. 과거 시각으로 소급하여 제출을 삭제하거나 재채점하지 않는다.
- 오류 처리 중에도 일반 마감 변경은 가능하며 `paused`와 불변 오류 원본의 옛 마감은 그대로 둔다. 이후 오류 교체는 현재 세트 마감을 사용한다. 원래 정답/제출·성적·확정 순위·발행 snapshot·비용·slug·featured와 다른 퀴즈는 보존한다.
- 새 migration 없음. 기존 0028 및 이전 migration/schema/trigger를 그대로 사용한다. 실데이터·유료 호출·원격 적용·배포·출력 없음.
