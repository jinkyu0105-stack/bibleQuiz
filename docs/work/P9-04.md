## 배포 명령

프로젝트 루트에서 실행한다. 아래 `VITE_TURNSTILE_SITE_KEY`는 기존 운영 설정의 공개 사이트 키이며 Secret이 아니다. 실제 실행에서는 같은 값을 `wrangler.production.jsonc`에서 읽어 빌드 프로세스 환경에 전달했다.

```bash
VITE_TURNSTILE_SITE_KEY=0x4AAAAAAFLreMZWWeiwpbxO pnpm run build:production
pnpm exec wrangler versions upload --config dist/biblequiz_app/wrangler.json --dry-run --strict
pnpm exec wrangler versions upload --config dist/biblequiz_app/wrangler.json --strict --tag p9-04-37b7254 --message 'P9-04 approved UI release; source 37b7254; CI 21b81de'
```

업로드는 후보 버전을 만들고 아직 운영 트래픽을 바꾸지 않는다. 출력된 Worker Version ID를 확인하고 기존 설정과 대조한 뒤 적용한다. 이번에 실제 사용한 적용 명령은 다음과 같다. 다음 배포에는 아래 ID를 그대로 쓰지 않고 **그때 새로 업로드한 ID**를 사용한다.

```bash
pnpm exec wrangler versions deploy 7aea6843-5288-42da-9bef-bc673e1d9dfe@100 --config wrangler.production.jsonc --yes --message 'P9-04 user-approved UI release, source 37b7254, CI 37604052032'
```

`@100`은 방문 요청100%에 해당 버전을 적용한다는 뜻이다. 기본 `wrangler.jsonc`나 Preview 설정을 운영 명령에 섞지 않는다. 일반 코드 변경이어서 trigger 배포·새 DO 등록·D1 migration은 필요하지 않았다. 이 절차는 Cloudflare 공식 [versions 안내](https://developers.cloudflare.com/workers/versions-and-deployments/deployment-management/)와 설치 Wrangler4.125.0의 CLI 옵션을 대조했다.
