# P9-06 새 하늘 대표 UI 시안

2026-10-08. **시각 검수 대기**. 기존 숲·종이·색상 기준을 종료하고 Astra·Max로 처음부터 다시 만들라는 사용자 지시에 따른다. P9-06 대표 화면과 검토 동작을 만들었으며 사용자 시각 확인/보정이 남아 있다. 앱 연결과 배포는 완료로 보고하지 않는다. P9-04와 이전 Phase9 승인 범위 완료는 유지한다.

## 사용자에게 보이는 결과

[새 검토본](../design/phase-9/sky-v2/README.md): `http://localhost:4189/docs/design/phase-9/sky-v2/`. 기본 낮이며 오른쪽 네 버튼으로 새벽/낮/노을/밤을 비교한다. 스크롤하면 구름 사이를 지나 들판에 가까워진다. 하단 검토 메뉴에서 공개·풀이·관리자로 이동한다. Codex 브라우저 패널 열기를 요청했으며 도구 응답은 `queued`였다.

공개는 큰 한글 제목, 이번 주 두 난도 선택, 지난 퀴즈를 구성했다. 풀이는 모바일 전체 격자/단서/예시 한글 입력·이전/다음·초기화를, 관리자는 기존 운영 메뉴/6단계/요약과 두 난도 탭·편집 미리보기·검토 확인을 보여 준다. 실제 원문/설교/AI 결과 대신 명시한 예시만 쓴다. 예시 편집은 메모리 안에서만 유지하며 새로고침하면 초기화된다. 시안 범위 밖 관리 메뉴는 안내창이며 실제 작업을 실행하지 않는다.

대표 이미지 5개는 낮/밤/지면/풀이/관리자를 각각 가로 한 장씩 만들었다. 별도 투명 구름3종을 추가해 하나를 반복하는 모양을 보완했다. 이미지 안에 글자를 합성하지 않았으며 최종 한글/입력/버튼은 HTML이다. 최적화 자산 전체는1,316,918bytes(약1.26MiB), 원본8개는 생성 위치와 `.wrangler/design-references/p9-06-air/masters/`에 보존했다. 정확한 프롬프트·생성 파일·해시·용량은 [assets.json](../design/phase-9/sky-v2/assets.json)에 기록했다.

## 참조와 구현

- [Air](https://air.inc/)를 Linux Playwright로 다시 열어 Sun/Moon과 실제 스크롤1600/3800 지점을 관측했다. DOM canvas는 Three.jsr176이다. P9-05 원본 관측도 재사용했다. 새 디자인은 원본과 동등한 완성도/같은3D 구현이라고 주장하지 않는다.
- Refero는 P9-05에서 확인한 공개 DESIGN.md/CSS Variables 수동 참조다. 이번에 Refero MCP/설치/결제/Tailwind export를 사용하지 않았다. 원본 코드·cloud.png·3D 모델·유리 로고·Control 폰트는 가져오지 않았다. 토큰 전체의 정확한 준수도 주장하지 않는다. 차이는 [현재 디자인](../spec/design.md)에 명시했다.
- `imagegen-frontend-web`/`imagegen`은 이미지 방향·원본 제작, `design-taste-frontend`는 공개 화면의 구성/구현에 적용했다. 풀이/관리자는 현재 제품의 읽기/기능 기준을 우선하며 별도 UI 패키지를 설치하지 않았다. 공개 dials7/7/3.
- [world.js](../design/phase-9/sky-v2/world.js)는 독자 WebGL billboard다. 투명 구름3종을8개 깊이/위치에 배치하고 깊이별 투영, 시간에 따른 완만한 흐름과 하나의 하강 카메라를 사용한다. 원경 이미지의 이동/투명도와 지면의 접근도 같은 진행도를 공유한다. 사진 교체만으로 움직임을 구현하지 않았다. Air의 실제3D 잔디·유리 모델을 재현한 것은 아니다.
- native CSS/JS, 기존 Playwright1.62.1과 Node24.18.0/pnpm11.14.0을 사용했다. 새 production dependency·서비스 없음. transient `pnpm dlx`로 Context7 및 Lighthouse13.5.0을 사용했으며 package/lockfile은 변경하지 않았다. `ctx7 library lighthouse` → `/googlechrome/lighthouse` → docs로 기존 Chromium/CLI 옵션을 확인했다. [공식 Lighthouse 설명](https://github.com/GoogleChrome/lighthouse/blob/main/readme.md), [WebGL texture](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/Tutorial/Using_textures_in_WebGL)를 참고했다.
- 실제 Noto Sans KR400 파일/Unicode 범위를 연결했다. Chromium CDP에서 custom font의 실제 한글15glyph 사용을 확인했다. 내부 이름은 `Noto Sans KR Thin`/`NotoSansKRThin-Regular`이나 기존 fontkit으로 대표 파일의 OS/2 weightClass400·variable axes 없음도 확인했다. 이름만 보고100굵기라 판단하지 않는다. font-synthesis:none이며 없는500/900을 요청하지 않는다. OS 폴백의 실제 Windows/macOS 모습은 별도 검수 대상이다.

## 검사와 보정

증거는 Git 제외 `.wrangler/design-references/p9-06-air/`의 `verification.json`, `final-refinements.json`, `lighthouse-desktop.json`, `lighthouse-mobile.json`, `review/*.png`다.

- Chromium: 네 시간대·하나의 선택 표시, 실제 구름 시계 진행/멈춤/재개, 하강 카메라/지면 접근, 320/390/768/1440px 세 화면 가로 넘침 없음·격자 정사각형,44px 시간대 터치 목표, 실제 custom 한글 폰트, 예시 입력/이전/다음/초기화, 관리자 편집/탭 초안 유지/재확인 gate/설명창, 장식 이미지 실패·WebGL 손실/복원, 외부 데이터/API/font 요청 없음, runtime error0.
- 움직임 감소: 자동 시계 정지·시간대/스크롤 유지, 사용자 멈춤이 OS 설정 왕복 뒤에도 유지된다. 숨은 탭 중단은 visibility 이벤트/hidden 값을 **모의 처리해 검증**했으며 실제 OS 탭 전환/배터리 측정으로 쓰지 않는다.
- Firefox:390px 밤 풀이 한글 입력·가로 넘침·WebGL renderer smoke 통과. WebKit은 런타임이 libgtk-4/libgraphene/GStreamer 등 시스템 라이브러리 부족을 보고해 시작하지 못했다. 별도 시스템 패키지 변경 없이 Chromium/Firefox로 검토를 진행했다. WebKit 통과라고 기록하지 않는다.
- 최종 node 구문 검사, `pnpm run lint`, `pnpm run typecheck`, `git diff --check`, 변경 문서의 로컬 링크/사실을 확인한다. 최종 근거는 HANDOFF에 둔다. Phase/배포 완료가 아니므로 기존 `pnpm check`·출시 E2E·IME/PDF/백업·유료 호출을 반복하지 않았다.
- 첫 lint는 standalone JS의 `structuredClone` global 선언 누락으로 실패했으며 수정 후 통과했다. 첫 시각 검수에서 밤 배경을 가리던 stacking, 반복된 구름 모양, 모바일 시간대 겹침과 작은 본문을 수정했다. 최종 밤 격자는 밝은 입력칸/짙은 막힌칸으로 구분하고 입력 중 검토 메뉴를 숨겼다. WebGL 복원 시 이전 texture 참조도 비웠다.
- 최초 Python/Pillow 및 후속 fontTools 모듈 부재는 기존 Windows bundled Pillow와 저장소 fontkit으로 해결했다. 패키지를 앱에 추가하거나 출력 fontkit을 변경하지 않았다.
