## 구현 경계

- [관리자 폼](../../src/features/admin-sermon-input/SermonDrafts.tsx): 새 등록·미발행 목록·정보 수정·요일/추천일·정규 장절/선택 입력·확인 체크·중복/충돌/오류 안내. 기존 승인된 관리자 색/간격/폼을 재사용했다. `design-taste-frontend`의 관리자 화면 적용 범위에 따라 디자인 시스템 교체·새 이미지/패키지는 하지 않았다.
- [입력 화면](../../src/features/admin-sermon-input/AdminSermonInput.tsx): 선택한 작업의 현재 입력/이력을 읽고 생성으로 연결한다. 기존 ID 진입을 보존하고 작업 전환 때 임시 입력을 초기화한다. metadata 저장 후 생성 검수 화면을 재조회한다.
- [공유 계약](../../shared/api/admin-sermon-drafts.ts)·[URL/날짜](../../shared/sermon-registration.ts)·[서비스](../../workers/_shared/services/sermon-drafts.ts)·[API](../../workers/app/app.ts): Zod/기존 장절 파서, Access/동일 출처/JSON·query/method 검사를 사용한다. 실제 외부 호출은 없다. URL 파서는 기존 자막 adapter와 공유한다.
- [metadata 저장소](../../workers/_shared/repositories/sermon-metadata-repository.ts): 기존 정규 snapshot 검증/CAS를 유지하며 관리자 저장에 미발행·발행/철회 이력 없음·정리 전 조건을 같은 SQL로 재검증한다. 기존 기반 저장 API의 동작은 유지했다.
- sermon/quiz/metadata 생성은 원자 batch다. 날짜가 같아도 다른 영상은 등록 가능하며 동일 영상은 기존 작업을 반환한다. 새 임의 문자 6자리와 최초 slug 미확정 정책을 적용한다. 원본 sermon/입력·옛 생성 결과·검수/비용을 재작성하지 않고 metadata revision만 증가시킨다. 만료 시계는 0021 기존 trigger를 사용한다.

- 첫 타입/lint에서 성경 book 자료형 필드명과 URL 파서 추출 후 사용하지 않는 상수를 고쳤다.
