2026-10-01. 사용자 지적 후 PDFium 실제 렌더에서 한글·숫자·격자 답안 누락을 재현했다. 이전 PNG·텍스트 추출/형식 검사를 PDF 표시 검수로 확대한 완료 판단은 철회한다. 그 뒤 fontkit 정렬 패치·배치 교정·필수 검사·실제 PDF 렌더 검수까지 마쳤다. 현재 P6-01 로컬 완료, 부모 Phase6 구현·교정·로컬 검수 완료, 다음 P7B-01. 원격 적용·배포·main push·유료 호출은 실행하지 않았다. P5-72 새 운영 화면과0037 역시 원격 미적용이며 기존 Preview는 P5-71이다.

- 현재 퀴즈는 같은 난이도 제출 브라우저만, archived는 공개다. 두 난도 출력은 모두 권한 확인 후 생성한다. 숨김/삭제/부분 답안은 벽보에서 제외하고 기존 확정 순위의 빈 자리를 승격하지 않는다. Top N 밖의 완전 정답자도 전부 이어서 출력한다. 생성 시각·포함 인원·Top N·쪽수가 footer에 남는다.
- `shared/api/quiz-export.ts`: 엄격한 공개 Zod DTO, 기존 화면/출력의 공통 Top N 투영, 단서 복사. `workers/app/app.ts`: 공개 `export-data`, 기존 board 검증을 재사용하는 `top-n-export`. 관리자 신원·세션·점수·코멘트·원문·공식 정답 자료를 투영하지 않는다.
- `src/features/export/`: 공통 배치/SVG, vector PDF와 wasm PNG, ZIP, 공개 자료/출력 route, 버튼·복사 fallback. `src/features/quiz/ParticipationBoard.tsx`·`QuizWorkspace.tsx`·`public-page.tsx`와 `src/app/router.tsx`가 연결점이다. 신규 migration/저장 계층/서비스는 없다.

## PDF 표시 오류 재현과 교정

사용자 지적 후 최초 실제 PDF를 PDFium으로 렌더링해 한글·숫자·격자 글자의 다수 누락을 재현했다. 이전에는 별도 SVG→PNG의 정상 모습과 PDF ToUnicode 텍스트 추출/페이지/형식만 확인했다. 이를 PDF 표시/시각 품질 검수 완료로 확대한 보고는 철회한다. 최초 통과 검사 수는 이 오류를 반증하지 않는다.

확인된 원인은 fontkit1.1.1의 TTFSubset이다. Google Regular TTF에는 길이가 홀수인 glyph record가 있고, 글자 subset의 glyf를 붙일 때 정렬 padding이 없었다. 짧은 loca는 offset을2로 나눈 정수라 위치가 잘려 다른 byte부터 글자 모양을 읽었다. [OpenType loca 공식 기준](https://learn.microsoft.com/en-us/typography/opentype/spec/loca)과 설치 source·대표34glyph 중 홀수15개의 재현을 대조했다. [pdf-lib의 기존 CJK 누락 보고](https://github.com/Hopding/pdf-lib/issues/1232)는 같은 증상의 공식 저장소 근거이며 이 저장소의 정확한 원인은 위 재현으로 판단한다.

[패치](../../patches/@pdf-lib__fontkit@1.1.1.patch)는 ESM/UMD의 `_addGlyph`에서 홀수 buffer 끝에0 byte 하나만 채운다. library 자체 Buffer를 사용하며 `pnpm-workspace.yaml`의 patchedDependencies와 lock의 patch hash로 배포/재설치에도 동일하게 적용된다. 새 패키지/서비스·폰트 교체·전체 폰트 embedding·PDF bitmap 전환은 없다. 원본 Regular TTF hash를 보존한다. 첫 수정의 일반 Uint8Array는 library stream이 허용하지 않아 실제 생성 검사에서 실패했고 내부 Buffer로 바로잡았다. OTF 대체 시험도 CJK 누락이 재현되어 `/tmp` 실험만 남기고 채택하지 않았다.

대표 한글·숫자·기호의 원래/축소 후 vector path 동일성 검사를 추가했다. 깨진 outline은 ToUnicode가 남아도 검사가 실패한다.1~3명은 승인 시안의 가로형 카드,4명은2열로 확대하고 답 글자를 실제 font 폭으로 가운데 배치했다. 많은 인원은 기존12명 분할/순위/공개 범위를 유지한다.

교정 실제 파일은 `/tmp/p6-01-corrected-topn.pdf`(어린이/장년2쪽)이며 PDFium과 PDF.js로 각각 직접 렌더링했다. `/tmp/p6-01-pdfjs-review-1.png`에서 제목·이름·시각·순위·정답격자와 footer를 확인했다. 실제 Chromium 다운로드의4쪽 PDF도 PDFium으로 렌더링하여 글자/격자를 확인했다. 이전 별도 PNG만 본 검수와 구분한다. PC/모바일 신규 출력18개 재검사 통과, 로그 `/tmp/p6-01-browser-repaired.log`. 교정 뒤 최종 `pnpm check` 종료0: 단위297·Worker2125·Workflow4·복구CLI2·Node14·Python6, lint/typecheck/build·lock/Drizzle/합성 fixture 통과. `/tmp/p6-01-check-repaired.log`와 검증 JSON의 pdfDisplayCorrection에 둔다.

기능 교정·필수 검사·실제 PDF 렌더 시각 검수를 모두 마쳐 P6-01은 로컬 완료다. 사용자 확인을 별도 완료 조건으로 추가한 `검수 대기` 표기는 철회했다. 사용자에게 같은 검수를 다시 요구하거나 다음 번호 대신 교정본 재검수를 반복하지 않는다. 사용자의 추후 피드백은 실제 발견된 문제에 따라 처리한다. 원격/유료 실행은0이며 실제 자료·키·paid 결과를 다시 열거나 변경하지 않았다.
