## 구현

- [0022](../../migrations/0022_phase5_display_corrections.sql)·[schema](../../workers/_shared/db/schema.ts): 초안 FK 없이 quiz set만 참조하는 별도 불변 이력. 기존 snapshot·표·guard 변경과 backfill 없음. Drizzle generate로 SQL/snapshot/journal을 생성한 뒤 insert/update/delete guard를 검토해 추가했다.
- [공개 컬럼](../../workers/_shared/repositories/published-display-columns.ts)·[공개 읽기](../../workers/_shared/repositories/public-quiz-repository.ts)·[archive](../../workers/_shared/repositories/archive-repository.ts): 최신 제목/날짜를 표시·검색·정렬·연월 선택에 사용한다. 최초 slug·기간·문제/정답·요약·장절·참여/순위·비용·발행 provenance는 그대로다. 초안 정리 후와 기존 snapshot 없는 발행 자료도 지원한다.
- [API](../../workers/app/app.ts): Access JWT·same-origin JSON/16KB·strict/query/method·no-store. GET 발행 목록/정정 이력과 PATCH display-text. 문제 변경 필드는 SEMANTIC_CORRECTION_REQUIRED, 충돌/형식/저장 실패는 안전한 409. 관리자 이메일/digest·요청 번호·정답을 DTO에 넣지 않는다.
- [화면](../../src/features/admin-sermon-input/PublishedMetadata.tsx): 승인 테마·기존 입력 요소 재사용. 발행/지난 퀴즈 선택, 제목/설교일/사유 폼, 요일·한국 시각, 수정 전후 이력. 읽기 오류/빈 상태, 실패 때 입력 보존·동일 요청 재확인·최신 내용 불러오기. 새 UI 라이브러리·AI 호출 없음.

- 실제 mock 생성→검수→발행→초안 정리 후 정정 **2건 통과**(기본/선택 배치). 합성 참여자·답안·코멘트·순위를 채워 정식 표·비용 원장·provenance 전체 보존을 대조했다. 두 난이도 공개 응답은 제목/설교일만 변하며 최초 slug 유지. 정정 제목 검색·새 연월 필터/선택도 확인했다.
- 실제 Chromium/모바일 Chromium **6건 통과**: 목록/상세 재시도, 저장 응답 유실 후 동일 key 재생, stale 저장 시 입력 유지·최신 조회, 이력/새로고침/빈 목록. 라이트 데스크톱·다크 모바일 캡처를 시각 확인했고 가로 넘침 없음.
- 검색 보완 후 아카이브·정정·합성 발행/정리 보존 관련 **3파일/22건 통과**(선택하지 않은 기존 26건은 skipped로 구분). 최종 **`pnpm check` exit 0**: unit **30파일/271건**, Worker **66파일/1,902건**, Content Workflow **1파일/3건** 통과. 설정·Drizzle·임시 fixture·lint·typecheck·빌드 모두 통과. 최종 로그 `p5-58-check-final.log`. 문서 링크·git diff --check도 확인했다. 미해결 필수 검사 실패 없음.

초기 실패: fixture가 snapshot 없이 draft→published 전환을 시도해 보호 trigger가 차단했고, 수정 과정에서 한 설교당 세트 하나라는 unique 조건도 확인했다. 최종 fixture는 설교만 준비한 뒤 기존 발행 합성 행을 직접 seed한다. 브라우저 2건 실패는 성공/로딩 status 동시 선택 오류로 선택자를 명확히 했다. 보존 통합 2건 실패는 UUID+한글 제목 검색이 D1 LIKE 패턴 한도를 넘은 문제였다. 처음에는 짧은 검색어로 검사를 통과했으나 기존 60자 계약 안의 입력도 실패함을 확인했다. P5-58에 필요한 정정 제목 검색 일관성을 위해 literal instr/lower 검색으로 보완하고 한글·특수문자 포함 정확히 60자/61자와 ASCII 대소문자 검사를 추가했다. 검색 길이 정책과 DB 보호는 유지한다. 첫 파일 필터 구분자가 전체 Worker 실행으로 해석되어 알려진 실패 확인 후 수정 전 실행만 종료했다. 검색 보완 전 전체 검사도 중단했으며 최종 전체 검사는 별도 로그로 구분한다.
