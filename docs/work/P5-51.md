# P5-51 — 실제 provider·Content Workflow 연결

상태: **완료 — 로컬 연결·필수 검사·상태 문서**. 부모 Phase 5 진행 중. 교정과 전체 v3 생성의 로컬 연결을 구현했다. P5-50 완료 경계와 기존 0014 보존 검사 기록을 유지한다.

## 연결된 사용자 흐름

1. 확정한 본문에서 관리자 화면으로 분석·비판 검토를 요청한다. 기존 OpenAI Responses API의 `gpt-5.6-terra/high`, `store:false`, strict `{ draft }` 출력과 기존 Zod·원문 근거 검증을 사용한다. 새 SDK/서비스를 추가하지 않았다.
2. 실제 Content Workflow가 분석·비판을 D1에 저장하고 사람의 검수를 기다린다. 관리자는 최초 분석과 비판 수정본을 비교하고, 선택·직접 수정·별도 확정한다. 비교용 `availableCritique`를 선택 또는 사람 확정으로 간주하지 않는다.
3. 관리자가 명시적으로 재개하면 Workflow가 요약·어린이·장년 후보를 생성하고 다시 검수를 기다린다. 관리자는 요약·답·단서를 수정하고 후보의 사용/반드시 포함/제외를 선택하며 각 자료를 별도로 검수 완료한다.
4. `배치·최종 검사`는 요청 때 정한 두 난이도 배치 설정으로 기존 퍼즐 엔진을 실행하고 현재 ticket을 저장한다. P5-50의 실제 입력·검수·정답/격자·공개 누출 검사와 `completeFinalValidation → finish`를 통과하면 작업이 `review_ready`가 된다. quiz는 `draft`로 유지하며 발행하지 않는다. 최종 AI 감사 호출은 없다.
5. 명시적 새 생성은 기존 선택본·비교본·사람 기록·비용을 보존한다. 새 분석을 사람이 선택·수정·확정하면 하위 자료의 검수 표시만 무효화한다. 새 요약·후보도 자동으로 이전 선택본을 덮지 않으며 사람이 선택한다. 응답 유실은 자동 재호출하지 않고, 확인된 불확실 결과 또는 만료한 실행만 이전 작업 ID를 지정한 명시적 새 요청으로 대체할 수 있다.

교정은 별도 선택 작업이다. 실제 Workflow가 문서형 제안을 저장하고 기존 관리자 문서 비교·수정·채택·별도 확정 화면으로 연결한다. 제안 생성만으로 원본/현재 문서/확정본을 바꾸지 않는다. 원고·제공 요약에는 교정을 적용하지 않는다.

## 구현 진입점과 저장 계약

- [전송](../../workers/_shared/services/openai-draft-transport.ts), [가격 계산](../../workers/_shared/services/openai-draft-cost.ts), [교정 실행](../../workers/_shared/services/content-generation.ts), [전체 생성 실행](../../workers/_shared/services/content-intent-generation.ts): durable request/dispatch/step/call/usage/outcome을 재사용한다. 호출 직전 기록, 본문 해석 전 usage 관측, 자동 재호출 금지, 늦은 usage 정산을 유지한다.
- [Workflow](../../workers/content/index.ts): step 자동 재시도 0회, step 30분/provider 호출당 9분. 전체 생성은 `waitForEvent`로 사람의 의도/내용 검수를 기다리고 저장된 dispatch를 확인해 재개한다. private 초기 intent v2와 full v3는 구분한다.
- [D1 reader](../../workers/_shared/services/generation-domain-reader.ts), [domain 저장](../../workers/_shared/repositories/generation-domain-storage.ts), [사람 명령](../../workers/_shared/services/content-human-generation.ts): 봉인된 실제 원문·AI/사람 payload·context·usage 증거·참조 계보와 앞뒤 head를 확인한다. D1에서 검증한 불변 자료만 쓰기 준비에 사용한다. envelope/snapshot hash, 시간 자막 원본/문서 hash를 구분하며 기존 payload를 다시 쓰지 않는다. 소수점 근거와 큰 문서를 기존 기술 범위에서 저장한다.
- [검수 재개 증명](../../workers/_shared/services/generation-domain-wait.ts): 대기 이후의 봉인된 사람 명령을 원래 순서대로 다시 검증해 공유 reducer로 재현한다. 전체 invalidation chain이 일치할 때만 하위 검수 무효화를 인정한다. 옛 bridge의 보수적인 비교 규칙은 완화하지 않았다.
- [최종 완료](../../workers/_shared/services/content-generation-final.ts), [관리자 조회](../../workers/_shared/services/content-generation-view.ts), [관리자 화면](../../src/features/admin-sermon-input/ContentGeneration.tsx): 현재 버전의 사람 검수와 요청의 불변 배치 설정으로 최종 검사한다. 실행 전 예시 비용, 서울 월요일 기준 주간 누적/현재 작업 관측 비용, 사용량 미확인 횟수를 표시한다. 잃어버린 POST 뒤 requestKey를 자동 변경하지 않는다.
- [관리자 API](../../workers/app/app.ts): Access와 same-origin JSON을 요구한다. `/generation/content` 조회/전체 요청, `/generation/:jobId/review`, `/resume`, `/finish`는 서버가 설교·미발행 quiz·full v3 소유 관계를 확인한다. 공개 preview에는 정답/비공개 근거를 보내지 않는다.
- [0015](../../migrations/0015_phase5_domain_content_lineage.sql): Drizzle 생성 후 검토한 불변 계보 표와 관련 guard 5개의 확장이다. 최초 분석·비판 수정본·사람 편집의 원래 root와 선택 대상을 구분한다. 기존 0014/옛 migration 파일·옛 행·감사·비용은 수정하지 않으며 backfill은 없다. 로컬 fixture에만 적용했다.

## 완료 범위와 운영 경계

이번 작업은 **교정 + full v3의 실제 provider adapter/D1/Workflow/관리자 검수 연결**이다. HTTP만 mock으로 바꿔 로컬에서 전체 흐름과 재생성을 검사한다. 유료 실호출·실제 설교 품질 판정·원격 migration/secret 설정/배포/발행은 실행하지 않는다. 코드 연결 완료가 공급자 실서비스 가용성이나 운영 적용 완료를 뜻하지 않는다.

Phase 5 전체는 아직 완료가 아니다. 생성 후 배치 설정 변경/대안 격자 선택, 요약·난이도별 개별 재생성의 관리자 실행 경로, 발행 전 최종 화면과 발행 연결은 제품의 남은 범위다. 이번 full 요청은 시작할 때 배치 설정을 고정한다. 순수 계약의 지원을 곧바로 관리자 실행 완료로 기록하지 않는다.

## 비용과 대안

새 외부 서비스를 추가하지 않고 기존 명세의 OpenAI API를 사용한다. 현재 테스트의 API 비용은 **USD 0**이다. 무료 대안은 기존 자막 직접 수정/사람 확정과 모의 HTTP 검사다. 낮은 비용으로 실서비스를 확인하려면 사용자가 선택한 짧은 공개 자막으로 교정 한 번만 실행하고 관측 토큰을 확인할 수 있으나, 아직 승인·실행하지 않았다.

2026-09-22 [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.6-terra)에서 확인한 일반 context 단가는 입력 USD 2/100만 token, cached input USD 0.20/100만, 출력 USD 12/100만이다. 예를 들어 비캐시 입력 10,000+출력 5,000 token이면 약 **USD 0.08/호출**이며 실제 token 수·reasoning에 따라 달라진다. reasoning은 output에 포함되므로 다시 더하지 않는다. 272,000 input token 초과 시 입력 2배·출력 1.5배를 반영한다. 가격표 version은 `openai-terra-2026-09-22`로 저장한다. 이는 청구서가 아닌 관측 usage 기반 예상 비용이다. 배포/실호출 전에 가격·모델 가용성을 다시 확인한다.

키는 브라우저/문서/로그에 넣지 않았다. test profile의 `synthetic-test-key`는 모의 문자열이고 모든 provider fetch를 가로챈다. `wrangler.generation-local.jsonc`만 실행한다고 AI가 활성화되지 않는다.

## 검사

최종 종합 검사와 문서/보존 확인을 완료했다. [검증 JSON](P5-51-verification.json)과 [STATUS](../STATUS.md)에 기록한다.

- 실제 full v3 양성 통합: 분석/비판 → 사람 선택·확정 → Workflow 재개 → 요약/두 후보 → 사람 검수 → 두 배치/현재 ticket/최종 검사/full finish. 두 번째 전체 재생성에서 기존 선택·비용 보존과 사람 직접 수정까지 확인했다.
- 실제 로컬 Workflow/API: 교정, 초기 intent, 전체 v3의 사람 이벤트 대기·재개·완료. provider HTTP만 mock이며 Cross-Origin 거절과 비용 누적을 확인한다.
- `node scripts/check-content-lineage-upgrade.mjs`: 채워진 0014→0015 업그레이드 **272개 검사 통과**, 기존 **59개 표**의 모든 행/셀/BLOB 동일, 수정 대상 외 guard 보존, FK/quick_check 정상. P5-50의 0014 검사를 반복한 결과가 아니다.
- Chromium/모바일 Chromium 실제 브라우저 **12건 통과**: 기존 교정 10건과 새 의도 비교·선택·수정·확정·재개·내용 검수·최종 검사 2건. 목록 조회와 구분한다.
- 전체 **`pnpm check` 통과**: lock/Cloudflare 설정/Drizzle/fixture/lint/typecheck, unit 30파일 271건, Worker 63파일 1,867건, 실제 Workflow 1파일 3건, build. 최종 API 재요청 스키마 보완 뒤 관련 재요청 검사 1건과 lint/typecheck도 통과했다. `git diff --check`와 문서 링크·보존 SHA 대조도 완료했다.

수정한 실패: 원본/문서 checksum 혼동, D1 UNION 참조 조회의 compound SELECT 한계(종류별 IN 조회로 변경), selected critique의 SQL 계보, 재생성 검수 무효화 증명의 과거 명령/검수 자료 누락, 최종 ticket의 서로 다른 캡처 버전, 브라우저로 서버 codec을 가져온 타입 의존, E2E의 미확정 fixture/편집 필드 선택자. 전체 병렬 Worker의 DB 검사에는 30초 timeout을 적용했다. 의도적 FK 위반 테스트의 Miniflare stderr는 suite 결과와 구분한다.
