# P5-69 — 실제 provider·AI 품질 시험과 운영 승인 계획

2026-09-24. **준비 문서·검사 완료 / Phase 5 진행 중.** 실제 시험 결과는 아직 없다. 이번 사용자 승인은 자료·평가 기준·예상 비용·운영 승인·rollback 조건의 문서화에 한정된다. 아래 표본 수·예산·합격 기준은 실행 전 운영자가 선택할 **시험안**이며 새 제품 제한이나 실행 승인이 아니다.

## 시험 자료와 사전 기록

실제 영상 URL·원문·권리 증빙은 아직 선정/수집하지 않았다. 운영자가 사용 가능한 자료를 정하고 비공개 위치에 보관한다. Git에는 아래 자료 별칭과 비민감 결과만 남긴다. 참여자 이름·답안·코멘트, 관리자 이메일·키·인증 정보, 성경 본문 전문은 시험 입력/로그에 넣지 않는다. 자료가 이 경계를 충족하지 않으면 교체하거나 보류하며 AI로 빈 내용을 보충하지 않는다. 원고/제공 요약본을 임의 편집해 시험 자료로 만들지 않는다.

| 자료 별칭 | 선정 조건 | 사람 기준답·검사 목적 |
|---|---|---|
| 대표 자막 | 권리 확인된 교회 설교 1편, 공개 수동 한국어 또는 사람이 확인한 붙여넣기 자막, 30,000자 이하 | 중심 주장·청중 반응·논지·반복 강조·적용/주의점 각각의 실제 근거 위치를 사람이 표시한다. 첫 유료 시험은 이 1편만 제안한다. |
| 어려운 자막 | 다른 교회 설교 1편, 자동 자막 오인식·고유명사·부정/숫자·예화가 있는 자료. 가능하면 상한에 가까운 실제 분량 | 교정 전후 의미 보존, 예화와 중심 주장의 구별, 앞/중간/끝 누락을 확인한다. 길이를 채우려고 반복·조작하지 않는다. |
| 제공 요약본 | 사용 허락을 받은 요약본 1편, 시간 정보 없는 부분 자료 | 원문 불변, `partial_notes` 고지, 없는 시간/전문 내용을 생성하지 않는지 확인한다. 이 자료에는 AI 교정을 실행하지 않는다. |

각 자료의 비공개 시험표에 출처/허락 범위·검수 담당 역할·source type/coverage·SHA-256·문자 수·시간 유무·검토 장절·기준답의 원문 위치를 기록한다. 자료/최종 검수 담당은 기본안으로 운영자 1명을 제안하며 다른 검수자가 필요하면 역할을 확정한다. 아직 담당자 확정/권리 확인 완료로 기록하지 않는다. 의미가 애매한 곳은 정답을 지어내지 않고 사람 확인 필요로 남긴다.

공개 자막 별도 표본은 **교회/기타 사용 허락된 공개 영상 × 수동/자동 한국어의 4종**, 한국어 자막 없음 1종을 제안한다. 교회 표본은 위 두 자막과 겸용할 수 있다. 각 양성 표본을 서로 다른 시각에 명시 조회 2회(8회), 음성 표본 1회, 두 교회 자막 원본 저장 각 1회(2회): 최대 **11회 논리 취득** 계획이다. 한 취득은 watch/player/timed-text 최대 3 HTTP 요청이며, 차단되면 반복 표본 수를 채우려고 계속 요청하지 않는다. 원본 저장은 조회와 별개로 다시 취득하므로 비용·시도 기록에 포함한다. 자료/track이 없으면 해당 칸은 미검증이며 다른 종류의 성공으로 대체하지 않는다.

## 평가·판정 방법

기존 관리자 `좋음`·`수정 후 사용`·`재생성 필요`와 비공개 메모를 사용한다. 점수를 자동 생성하는 새 AI 평가 호출은 추가하지 않는다. 다음은 이 소규모 시험의 제안 기준이며 화면의 새로운 필수 체크박스가 아니다.

| 대상 | 확인 방법 | 통과·보류 기준안 |
|---|---|---|
| 자막 가용성 | Preview의 정확한 app 버전·환경·시각·track 종류·시도/성공 수·오류 분류·소요 시간 기록. 정상 취득의 segment 수와 앞/중간/끝 각 3구간을 화면과 대조 | 양성 8회 모두 올바른 한국어 track/영상, 누락·시간 불일치 없음. 자막 없음은 명확한 실패/붙여넣기 안내와 원본 무기록. 한 실패라도 해당 자동 취득 경로 채택은 보류한다. 작은 표본 100%를 장기 성공률로 일반화하지 않는다. |
| 자막 교정 | 원본↔제안↔사람 채택본 비교. 특히 부정·수치·인명/지명·구간 ID/순서와 시간을 확인 | 의미 반전·창작·본문 보완·근거 없는 구간 변경 0건. 맞춤법만 손보면 `수정 후 사용`, 의미 재구성이 필요하면 `재생성 필요`. 원고/요약본 교정 시도는 하지 않는다. |
| 의도·비판 | 사람이 준비한 다섯 관점과 모든 주장/근거를 대조. 원 분석과 비판 수정본의 잘못된 추가·누락도 비교 | 중심 주장·청중 반응·논지·반복·적용/주의점의 중요 왜곡/누락 0건, 모든 채택 근거는 실제 입력과 연결. 구조 검증 성공만으로 의미 품질 통과 처리하지 않는다. |
| 요약 | 사람이 확정한 의도와 문장별 대조 | 핵심 누락·원문 밖 주장·길게 반복한 원문 없음. 제공 요약본을 전체 영상 기반으로 표시하지 않음. |
| 어린이·장년 후보 | 생성된 후보 전부의 답/단서/근거·중복·정답 노출·난이도를 읽고, 최종 선택한 두 격자를 기존 코드로 검사 | 의미상 복수 정답·근거 없는 답·단서 내 정답 노출·불가능한 배치 0건. 어린이가 이해할 말과 장년의 설교 핵심 적합성을 사람이 판단. 목표 단어 수/격자 크기는 기존 설정을 사용하고 실패를 숨기려고 후보를 몰래 제외하지 않음. |
| 비용·실행 | call/job/revision, 정확한 응답 모델, prompt/schema/가격표 version, 입력·캐시·출력·추론, 관측/미확인 수, 단계 지연·사람 편집 시간을 기록 | 실제 HTTP와 원장 호출 수 일치, 중복 청구 의심 없음, 미확인 금액을 0으로 처리하지 않음. 공급자 사용량/청구 화면과 프로젝트·모델·기간을 맞춰 세전 API 사용액 대조. 반올림으로 설명되지 않는 차이는 보류하며 원장을 고치지 않음. |

첫 1편은 전체 결과를 운영자가 검수한 후 확장 여부를 결정한다. 전체 3편은 모두 `좋음` 또는 사람 수정과 재검토를 마친 `수정 후 사용`이어야 시험 통과로 제안한다. 첫 결과와 수정 후 결과를 별도 기록하고 재생성/실패도 분모에 포함한다. `재생성 필요`가 남거나 심각한 의미/근거 오류가 있으면 현재 선택을 확정하지 않는다. 모든 결과가 광범위한 사람 재작성에 의존하면 모델 품질 충분으로 판정하지 않고 프롬프트/모델 비교의 별도 제안으로 돌린다.

계측표 한 행: `자료 별칭 / 환경·버전 / 단계·시도 / source hash·revision / 모델·prompt·schema / 시작·종료 / 결과·오류 / 사용량·가격표·USD·미확인 / 사람 평가·수정 범위·시간 / 채택 여부`. 외부 응답 전문·signed URL·비밀값을 로그에 복사하지 않는다. 기존 본문 7일 정리 정책은 유지하고 평가용 보존 예외를 만들지 않는다. 필요한 검수는 만료 전에 마치며 Git에는 원문 없는 집계·판정만 남긴다.

## 예상 비용과 대안

**2026-09-24 공식 확인.** [OpenAI 요금표](https://developers.openai.com/api/docs/pricing)의 Standard Terra 단가는 100만 토큰당 입력 USD 2, 캐시 입력 0.20, 출력 12다. [모델 문서](https://developers.openai.com/api/docs/models/gpt-5.6-terra)는 Responses/구조화 출력/high를 지원하며 입력 272,000 토큰 초과 요청은 입력 2배·출력 1.5배 요금이다. 이는 모델 문서상 지원이며 현재 API 계정에서의 사용 권한·실호출 성공을 확인한 것은 아니다.

현재 코드의 짧은 문맥 계산식은 `((입력-캐시)×2 + 캐시×0.20 + 출력×12) / 1,000,000` USD다. 추론 토큰은 출력의 일부여서 두 번 더하지 않는다. 공식 단가와 현재 상수는 일치한다. 아래는 **매 호출마다 전체 프롬프트/스키마/누적 자료를 포함한** 입력 12,000~30,000, 출력(추론 포함) 4,000~10,000 토큰을 가정한 산술 예산이다. 실제 토큰 측정값·신뢰구간·강제 상한이 아니다. 글자 수를 토큰 수와 같다고 보지 않는다.

| 시험안 | AI 호출 수 | 가정 비용(USD, 캐시 할인 0으로 계산) |
|---|---:|---:|
| 첫 대표 자막: 선택적 교정+전체 생성 | 최대 6 | 0.432~1.080 |
| 전체 3편: 자막 2편 교정+각 전체 생성, 첫 1편 포함 | 최대 17(2+3×5) | 1.224~3.060 |
| 필요 시 명시적 부분 재생성: 의도 2회+문제 1회 | 별도 최대 3 | 추가 0.216~0.540 |
| 확장과 위 재생성까지 선택한 총량 | 최대 20 | 1.440~3.600 |
| 저비용안: 두 자막을 사람이 교정하고 3편 전체 생성 | 15 | 1.080~2.700 |

제안: 먼저 첫 1편에 **USD 2의 지출 검토 기준**을 정하고 결과를 본 뒤, 확장 시 첫 시험 포함 **USD 5의 검토 기준**을 선택한다. 이는 자동 차단 장치나 최대 청구액 보장이 아니다. 요청을 보낸 뒤의 비용은 중단해도 발생할 수 있고 출력/추론량이 가정을 넘을 수 있다. 각 사람 대기 구간에서 관측액·미확인 호출·다음 묶음 예상액을 확인한다. 초과 예상·미확인 청구가 있으면 추가 dispatch를 보류하고 운영자 결정을 받는다. 제품의 무제한 명시 재생성 원칙을 시험 예산으로 변경하지 않는다.

현재 호출은 explicit cache write·유료 도구·음성 전사를 요청하지 않는다. 캐시 쓰기 등 추가 청구 항목이 나타나거나 단가/모델이 달라지면 위 단순식으로 덮지 않고 새 비용 근거를 확인한다. 세금·환율·결제 최소 충전액은 위 API 사용액에 포함하지 않는다. Pro 구독의 Codex 사용량과 프로젝트 API 사용료는 별개로 관리한다. 과거 가격표/원장 값은 수정하지 않는다.

무료 대안은 기존 합성 provider 검수와 사람이 직접 붙여넣고 교정하는 자료 준비다. 실제 AI 품질 증거를 제공하지는 않는다. 저비용안은 교정을 사람이 하고 첫 대표 설교의 전체 생성 5회(USD 0.360~0.900 가정)만 실행하는 것이다. 첫 시험에서 모델을 동시에 바꾸면 품질 원인을 구별하기 어려우므로 기존 Terra/high를 유지한다. 다른 저가 모델·Batch·전사 서비스는 도입하지 않는다.

[Cloudflare Workflows 요금](https://developers.cloudflare.com/workflows/reference/pricing/)은 Free에서 하루 요청 100,000회(Workers와 공유), steps 3,000회, 저장 1 GB-month, CPU 10ms를 명시한다. [Workflow 한도](https://developers.cloudflare.com/workflows/reference/limits/)와 해당 계정의 잔여량·실제 전체 경로 CPU/메모리/DB 사용량을 실행 준비 때 확인한다. 네트워크 대기와 CPU는 다르다. 포함량 안에서 인프라 USD 0을 목표로 하되 이번 문서만으로 적합성을 보장하지 않는다. Free 초과 시 자동 유료 전환을 제안하지 않고 무료 경로의 수정/범위 축소부터 검토한다. 유료 플랜이 필요해지면 최신 견적과 대안을 별도로 제시한다.

## 환경별 승인과 실행 순서

아래 단계는 작업 하위 번호가 아니라 승인 범위 구분이다. **모두 준비 조건이며 이번에 실행하지 않았다.** 실제 승인에는 대상 자료·환경·정확한 변경 파일/버전·호출 수·지출 기준·중지/복원 담당을 함께 기록한다. 준비가 끝나기 전에 포괄적인 원격 승인을 요청하지 않는다.

| 경계 | 실행 전에 보여줄 구체 결과 | 현재 상태 |
|---|---|---|
| 자료·provider 선택 | 자료 별칭/권리·검수 담당, 수동 붙여넣기 또는 계정 없는 자막 사용 여부, 원문 없는 평가표 | 미선정·미승인. 자막 자동 접근의 플랫폼 조건과 콘텐츠 허락을 구별 |
| 격리 로컬 실제 AI 시험 | 기존 개발 D1과 다른 임시 저장 경로, 준비된 자료·토큰 추정·요청 본문 구조·모델/high·호출 수/예산·비공개 키 주입 방법 | 실행 도구/자료 준비와 별도 유료 호출 승인 필요. 기존 `.wrangler/state` 사용·키 출력 금지 |
| Preview 연결 준비 | 정확한 `biblequiz-app-preview`/`biblequiz-d1-preview`, 현재 활성 버전·binding/변수 이름, 미적용 migration 목록·SQL SHA·누적 diff, 생성 Worker/binding 구성안, 복원 기준 | 원격 상태 미조회. 없는 자원을 이미 배포된 것으로 표시하지 않음. `workers/content`·`workers/backup` 공개 route 생성 금지 |
| Preview migration·배포 | 합성 격리 D1에서 채워진 데이터 보존 리허설, 직전 정상 버전/복구 지점, schema 호환성·기존 표/행 보존 결과, `pnpm check`와 관련 브라우저 검사 | 별도 승인 전 실행 금지. 현재 이력 확인 후 검토된 미적용 파일만 번호순 적용. main push는 누적 코드의 Preview 자동 배포임을 사전 안내 |
| Preview 실제 provider·AI | Access 유지, 승인 자료만 별도 draft로 등록, 키/`AI_GENERATION_ENABLED`/`CONTENT_WORKFLOW` 대상 확인, 위 표본·비용·중지 조건 | 연결 완료와 실행 승인을 모두 확인해야 시작. 로컬 AI 성공은 Cloudflare 가용성 증거가 아님. 발행·제출·featured 변경 제외 |
| Production | 배포 트리거, 운영자 승인 방식, migration 선후관계, rollback/복원 범위를 먼저 합의하고 DECISIONS/implementation에 기록 | 전부 미합의·미승인. Worker·D1·R2·secret·도메인 생성/연결 금지 |

자동 자막 접근은 [YouTube 약관](https://www.youtube.com/static?template=terms)과 [공식 caption 다운로드 권한](https://developers.google.com/youtube/v3/docs/captions/download)을 근거로 판단한다. 공개 CC나 교회의 콘텐츠 사용 허락만으로 플랫폼 자동 접근 권한이 생기는 것은 아니다. 공식 다운로드는 영상 편집 권한을 요구한다. 운영자가 기존 명세의 플랫폼 위험을 수용할지 결정하기 전 실제 adapter 시험을 시작하지 않는다. 거절/차단 시 계정·쿠키·relay로 우회하지 않고 허용된 붙여넣기 자료로 AI 시험을 분리한다.

Production 운영안의 제안 순서는 **승인된 릴리스 commit/수동 트리거 → 운영자 확인 → 쓰기 중지·복구 지점 확보 → 검토 SQL의 순서 적용과 후검사 → 호환 app/Workflow 배포 → Access/권한/보존 검사 → 명시 활성화**다. 이는 합의 전 제안이며 main 자동 Production 배포를 만들지 않는다. additive 변경이라도 옛 app의 새 schema 읽기와 진행 중 Workflow 호환성을 확인해야 한다.

Phase 5 및 출시 완료에는 실제 품질 판단 외에도 [출시 명세](../spec/release.md)와 기존 운영 항목이 남는다. 실제 추가 예약명/금지 규칙/예외의 관리 UI·쓰기 경로는 현재 확인되지 않았고 정책 읽기/제출 필터와 구별해야 한다. 공개 요청 제한, Cron 활성화, R2 정상 백업 8개·복원 리허설, 운영 비용 대시보드, Phase 6 출력·Phase 7B 실기기 검수도 이번 계획/AI 시험만으로 완료되지 않는다. 현재 [backup Worker](../../workers/backup/index.ts)는 골격이다. 이 항목들의 후속 번호를 이번에 일괄 생성하지 않는다.

## 중지·rollback 조건

| 사건 | 즉시 중지할 동작 | 보존·복구 조건 |
|---|---|---|
| 자막 차단·잘못된 언어/영상·누락 | 해당 자동 취득과 추가 반복 시험 | 실패를 기록하고 붙여넣기 선택. 기존 원본을 덮거나 가짜 자막 저장 금지 |
| 의미 왜곡·가짜 근거·본문 생성·검증 실패 | 해당 결과의 채택/후속 재개·발행 | 원본/이전 선택본·실패 call·관측 비용 보존. 사람이 수정/새 요청을 명시하기 전 재호출 없음 |
| timeout·응답 유실·429·미확인 비용·예산 초과 예상 | 새 유료 dispatch | 저장된 job/call/usage와 lease부터 확인. 응답 유실을 실패=무과금으로 보지 않음. 진행 중 요청을 재전송하거나 옛 원장을 삭제하지 않음 |
| Access/비공개 경계 실패·원치 않은 데이터 변경·중복 호출 | 신규 쓰기/생성·공개 전환 | 승인된 차단/비활성화 경로로 멈추고 최소 진단 보존. 이미 실행 중인 Workflow/외부 호출이 설정 false만으로 취소된다고 가정하지 않음. 해당 instance의 중지·잔여 호출 확인 절차를 준비 |
| 배포 후 회귀 또는 migration 후 불변성/FK 실패 | 다음 migration/활성화 | 옛 app과 새 schema가 호환될 때만 정상 Worker 버전으로 rollback. DB를 되돌리는 효과로 취급하지 않음. 호환 불가면 중지 상태에서 전진 수정 또는 별도 DB 복원 계획 |

[Workers rollback](https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/)은 코드/설정 버전 복귀이며 D1 자료 복원이 아니다. binding 자원 변경 등으로 rollback 자체가 제한될 수 있으므로 실제 대상 버전으로의 가능성을 사전에 확인한다. DB 복원은 [D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/)의 현재 복구 지점과 Free 7일 범위를 확인하고, 복구 시점 이후 잃을 제출·삭제·감사·비용/호출 기록의 범위를 운영자에게 보여준 뒤 별도 승인한다. 과거 P4-23 bookmark를 현재 복구 수단으로 사용하지 않는다.

복원이 필요하면 영향을 받는 쓰기를 먼저 중지하고 현재 안전한 보존본과 PII 없는 삭제 manifest를 확보한다. 복원 뒤 삭제 manifest를 재적용해 개인정보를 되살리지 않으며 FK/행 보존·공개 권한·원장 중복 여부를 검증한 후 재개한다. AI 청구는 DB 복원으로 취소되지 않는다. 비용/불확실 call을 잃어 같은 요청을 다시 보내는 복원안은 채택하지 않는다. 실제 자료 삭제, migration 역실행, 원본 덮어쓰기, D1 전체 복원을 시험 후 자동 정리 방법으로 쓰지 않는다. 기존 7일 초안 정책과 불변 비용/감사를 보존한다.

## 다음 한 작업과 이번 검증

**다음 P5-70: 시험 자료·승인 선택 확정과 실행 준비.** P5-69의 계획과 실제 시험을 분리하기 위한 독립 번호다. 시작 시 사용량/문서/Git 확인 후 운영자에게 자료·검수 역할·자동 자막 사용 여부·첫 1편 예산안을 확인한다. 답을 기다리는 동안 격리 로컬 실행 방법·원문 없는 평가표·Preview 구성/현재 이력 확인 방법·중지 절차를 구체화할 수 있다. 유료 호출·자료 등록·원격 변경은 필요한 산출물/검사와 해당 행위의 명시 승인 전 실행하지 않는다. P5-70 시작 요청만을 금액/자료/배포의 포괄 승인으로 보지 않는다. 새 a/b/c 번호는 없다.

이번 시작 사용량은 Pro 29% 사용/71% 잔여, 별도 5시간 없음. 사용자 지정 Pro 5x 기준 Plus 환산 355%로 정상 문서 작업 범위다. 계정 응답의 내부 플랜 표기는 `prolite`이며 배수는 응답에 없으므로 사용자/AGENTS의 Pro 5x 기준을 적용했다. 종료 조회는 30% 사용/70% 잔여·Plus 환산 350%이며 별도 5시간 값은 없다.

검사와 보존 결과는 [P5-69 검증 기록](P5-69-verification.json)에 둔다. 문서만 변경해 `git diff --check`, 로컬 링크/anchor, 비용 산술, 코드·공식 출처 대조, 시작 기준선 SHA/실제 D1 파일 stat 비교를 수행했다. 코드 테스트·`pnpm check`·E2E는 재실행하지 않았으며 P5-68의 완료 결과와 혼동하지 않는다. 유료/실제 provider 호출, 실데이터 본문 열람·조작, 원격 조회/적용·배포·출력·stage/commit/push는 없다. 새 migration·의존성·서비스 없음.

폐기한 접근: 합성 성공을 실제 품질로 처리하기, 첫 소규모 표본을 장기 성공률로 일반화하기, 예상 비용을 확정 청구 상한으로 제시하기, 무료 입력 저장 계측으로 전체 Workflow 적합성을 단정하기, 준비 문서 완료를 운영 승인으로 해석하기. WSL bubblewrap 마운트 오류로 승인된 셸 명령을 사용했고 본문 내용 대신 D1 파일 크기/수정 시각만 대조했다.
