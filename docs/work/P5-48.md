# P5-48 — 간결한 생성 흐름과 기존 계약 검토 결과

**2026-09-22 문서 검토 완료.** 코드 전환·DB 적용·실제 AI 연결은 완료 범위가 아니다. 다음은 P5-49의 문서형 교정 로컬 저장·채택 연결이며 이번에는 시작하지 않았다. 새 하위 번호는 만들지 않는다.

## 확정한 연결 기준

정본은 [생성 연결 계약](../spec/generation.md#간결한-생성-결과의-연결-계약)이다. 교정은 문서 한 벌, 근거는 짧은 실제 위치, 최종 품질 판단은 사람, 재생성은 관리자 명시 요청이다. 앞단 의도 비판 검토와 코드 검사는 유지한다. 입력 자막 30,000자 및 기존 공개 요약/단서 기준은 유지하고 새 출력 총량 상한은 정하지 않았다.

기존 0009는 proposal에서 현재 document를 유지하고 merge에서 새 document와 비어 있는 confirmation, 원래 proposal 참조를 요구한다. 새 문서형 제안/채택도 이 관계를 재사용할 수 있다. 다만 기존 service/codec가 items를 읽으므로 **기존 코드 그대로 사용 가능하다는 결론은 아니다**. 원본·시간·현재 버전 검증을 유지하며 새 표부터 만들지 않는다.

## 후속 구현 검사

- 문서 출력: plain/timed 모두 원문·수정문 반복 없이 한 벌, 변경 없음 허용. 잘못된 구간 ID/순서/시간 주입·빈 본문·원고 수정·입력 30,000자 초과 거부.
- 사람 채택: 현재 바탕의 문서형 proposal만 읽고 한 번의 merge로 저장, 확정은 별도. AI 완료/채택 도중 직접 수정하면 자동 덮기·재적용 없음.
- 과거 호환: old items·decision·merge·final_audit·usage의 내용/hash/참조 보존, 새/옛 형식의 교차 적용 거부, 새 요청의 final_audit 미호출.
- 저장/비용: 제안·usage·결과 참조·필요한 새 대기의 원자 저장, 중복 요청 재생, 부분 실패/불확실 결과의 재조회, 알려진 usage 보존·미확인 값 0 치환 금지·자동 AI 재호출 없음.
- 최종 완료: 사람 검수·두 격자·final_validate의 실제 근거와 현재 버전이 맞을 때만 새 full finish. 누락/오래된 증거·열린 호출/명령/대기는 거부하고 감사 결과를 위조해 통과시키지 않음.
- 저장 자원: 현재 명령의 실제 결과와 선택 참조로 확인. 전체 과거 이력 반복 읽기나 완료한 P5-27 원격 부하 시험을 관성적으로 반복하지 않음.

관련 기존 회귀: [교정](../../workers/app/transcript-corrections.test.ts), [provider](../../workers/app/ai-draft-provider.test.ts), [domain](../../workers/app/generation-domain.test.ts), [lifecycle](../../workers/app/generation-lifecycle.test.ts), [lifecycle 저장](../../workers/app/generation-lifecycle-store.test.ts). 새 동작을 검증하면서 옛 형식의 보존 검사는 남긴다. 기능 변경에는 관련 테스트·lint/typecheck, Phase/배포 완료에는 전체 check를 적용한다.

## 완료 범위와 남은 구현

P5-48의 출력/저장 검토·사용자 방향 반영·문서 재구성·기존 계약 대조·문서/링크/사실/SHA 검사가 완료됐다. 출력 1MiB/4MiB 제안과 저장 실패 허용 승인 질문은 철회 상태다. 정상 출력 크기로 실패했다는 실측이 없으므로 새 제한·자동 분할·추가 AI 감사는 추가하지 않는다.

다음 P5-49는 문서형 교정의 로컬 provider 출력 계약→proposal 저장→관리자 채택/확정까지 기존 경로를 잇는다. 실제 API 호출·원격/운영 DB 적용·배포는 제외하고 모의 transport와 로컬 검사로 검증한다. 생성/저장 결과를 사람이 볼 수 있는 흐름을 기준으로 묶으며 이를 별도 작은 작업 번호로 나누지 않는다. final_audit 제외의 전체 생성/finish 구현은 이 검토 기준으로 Phase 5에 남으며 교정 연결 완료와 혼동하지 않는다.

현재 Content Workflow는 scaffold_only, provider는 주입식 adapter, 0013 full finish는 닫혀 있다. 이 문서만으로 동작하지 않으며 기존 가드를 우회해서도 안 된다. 일부 v1 adapter 검사는 0012 기준이므로 0013 호환 완료라고 할 수 없다.

마지막 코드 검사 기록은 P5-47 11파일 619건(기존545+추가74)·lint/typecheck, P5-45 전체 2,016건이다. 이번에는 코드 무변경으로 실행하지 않았다. [이번 검사](P5-48-verification.json)·[재구성 원문/이동표](../archive/2026-09-21-p5-48/README.md)·[재구성 당시 검사](../archive/2026-09-21-p5-48/verification.json)를 구분한다. 옛 14.3.16~32와 당시 상세 기록은 보관소에 그대로 있다.
