[Playwright 브라우저 의존성](https://playwright.dev/docs/browsers#install-system-dependencies), [Vite 로컬 빌드 확인](https://vite.dev/guide/static-deploy.html#testing-the-app-locally), [axe API](https://github.com/dequelabs/axe-core/blob/develop/doc/API.md)를 확인했고 Context7의 Playwright/axe/pdf-lib 공식 항목과 실제 버전을 대조했다.

## 노트10+ 로컬 접속과 실제 입력 결과

사용자가 노트10+ 보유와 PC/폰의 같은 공유기 연결을 확인했다. 새 기기를 요구하지 않고 기존 Windows/iPhone 증거를 재사용한다. 현재 Pro 사용6%/잔여94%·10080분 창 → 사용자 지정×10=940%다.

`http://192.168.219.102:4175/`는 Windows의 현재 공유기 주소에만 연결한 임시 **합성 입력 시험 화면**이다. `/`는 기존 어린이5칸 `/dev/quiz`로 이동한다. API/관리자 HTTP 경로·변경 요청·폴더 목록·실제 DB/키는 제공하지 않는다. 같은192.168.219.0/24 공유기의 접근만 받는다. PC 측 HTML·JS 응답200을 확인했고 이후 사용자가 노트10+ Chrome의 시험 화면/퍼즐 표시와 실제 입력을 확인했다. 방화벽/공유기 설정·포트 전달·원격/유료 호출은 변경하지 않았다.

기존 Vite8.2.2/React 코드에서 개발 시험 route만 켠 임시 정적 빌드다. `/tmp/p7b-01-mobile-build.mjs`는 configFile:false·빈 envDir·출력 `/tmp/p7b-01-mobile-client`를 쓰며 Worker/D1와 연결하지 않는다. 앱 파일·production config·의존성/lock은 수정하지 않았다. 실제 LAN 서버는 기존 Windows bundled Python3.12.14가 `\\wsl.localhost\Ubuntu\tmp\p7b-01-mobile-server.py`를 실행한다. 서버는 이번 휴대전화 검수 뒤 종료했다. 같은공유기 외부의 공개 배포 주소가 아니다. [Vite build/define](https://vite.dev/config/shared-options.html#define)·[Python 임시 HTTP 서버](https://docs.python.org/3/library/http.server.html)와 Context7 Vite 문서를 확인했다.

사용자는 Chrome에서 `값갑세`가 `값 | 갑 | 세` 세 칸으로 정상 입력되고, 가로 회전 시 키보드가 닫히지만 세로 복귀 뒤 글자가 유지된다고 확인했다. 세로 상태에서 선택 칸을 재터치하면 키보드가 다시 열리고 칸이 키보드 위에 보였다. 입력·회전 보존·재터치/가림 보정은 통과다. 회전 내내 키보드가 유지됐다고 기록하지 않는다.
