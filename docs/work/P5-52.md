# P5-52 — 생성 결과의 배치 선택·발행 전 검토

상태: **완료 — 로컬 구현·필수 검사·STATUS/HANDOFF**. 부모 Phase 5 진행 중. 실제 발행·원격 migration·배포·유료 호출은 제외한다.

## 사용자 흐름

검수한 요약·두 난이도 후보로 격자 크기(5~10, 복수 선택)와 목표 단어 수를 시험한다. 기존 결정적 엔진의 최대 3개 추천/대안을 비교하고 두 배치를 함께 저장·검사하며 내용 검수 단계에서는 기존 무료 finish까지 이어간다. 후보 pool, seed와 옵션이 같으면 같은 배치를 재현한다. 설정 범위를 임의 확대하지 않는다. 실패 이유·탐색 미완료·빠진 후보·제외 후보·실제 단어/활성 칸/교차 수를 표시한다.

선택은 새로고침 후 복원되고 기존 배치로 돌아가는 재선택도 별도 이력으로 남는다. 입력·metadata·내용 검수·다른 선택이 바뀌면 오래된 화면의 저장은 거부한다. 본문 변경 또는 조회 실패 때 화면의 낡은 검토 결과를 비운다. 요약/후보 변경 뒤에는 옛 선택 기록은 보존하되 현재 최종 미리보기로 쓰지 않는다.

최종 검토는 두 난이도의 문제/관리자 정답 격자, 가로·세로 번호/단서, 설교일·제목·성경 장절·공식 읽기 링크, AI 요약/고지를 표시한다. 기존 테마·격자 스타일과 크게 보기/모바일 폭을 재사용한다. 단서 복사는 정답을 제외한다. 발행 버튼·공개 snapshot 저장·PNG/PDF 출력 구현은 이번 범위에 없다.

## 코드와 저장 경계

- [배치 실행](../../workers/_shared/services/content-placement.ts): 현재 서버 자료에서 trial, 현재 버전/metadata/선택 revision으로 선택 저장. 좌표·정답·검사 결과는 요청으로 받지 않는다. 기존 후보 정렬/안전한 entry ID·엔진을 사용한다.
- [관리자 DTO](../../shared/api/admin-placement.ts), [공통 설정](../../shared/api/placement-options.ts): Zod strict 요청과 기술 탐색 budget, 공개 격자/관리자 solution 분리. worker의 실행 모듈을 브라우저 schema에서 가져오지 않는다.
- [선택 reader](../../workers/_shared/repositories/generation-placement-store.ts), [0016](../../migrations/0016_phase5_placement_selections.sql): 불변 선택 행은 기존 봉인된 final ticket을 참조한다. unique `(job_id,revision)`와 insert trigger가 현재 입력/content/metadata, 작업·quiz 소유 관계, 편집 가능 상태, 가장 최근 full 작업, 이전 선택 revision을 원자 확인한다. row update/delete, backfill, 기존 표/trigger 변경은 없다. 응답 유실 시 같은 requestKey로 이력을 확인할 수 있고 다른 내용으로 key를 재사용할 수 없다.
- [최종 검사](../../workers/_shared/services/content-generation-final.ts), [최종 검증](../../workers/_shared/services/generation-final-validation.ts), [lifecycle 저장소](../../workers/_shared/repositories/generation-lifecycle-store.ts): 최초 요청과 완료 증거는 보존한다. reader/물리 조건부 검사에서 불변 선택 행의 최신 revision을 유효 설정으로 확인한다. 생성 완료 전 선택한 배치는 그 ticket으로 v3 finish한다. 완료 후 재배치는 최신 선택 ticket을 다시 코드 검사해 보여주며 과거 generation 완료 증거를 다시 쓰지 않는다. `review_ready`와 별개로 현재 preview의 유효성을 확인한다. 공개용 `preview`에는 정답이 없고 Access 관리자 `reviewLayouts`만 solution을 가진다.
- [화면](../../src/features/admin-sermon-input/ContentPlacement.tsx): 시험 결과는 저장 전 선택본을 바꾸지 않는다. 설정 변경/시험 실패 때 해당 임시 결과를 비워 저장을 막는다. 두 난이도를 모두 시험한 뒤 선택을 저장한다. 원래 `배치·최종 검사`의 기본 선택 경로도 유지한다.
- P5-51의 후보 `set_status` 연결은 기존 writer가 요구하는 base snapshot 대신 target을 보내고 있었다. [사람 명령](../../workers/_shared/services/content-human-generation.ts)을 수정해 현재 pool을 base로 전달하며 기존 writer/DB guard는 완화하지 않았다. 상태 변경은 새 pool을 만들고 해당 검수를 무효화한다.

## 후속 범위

다음 한 작업은 **P5-53 — 요약·난이도별 개별 재생성 실행 연결**이다. 현재 전체 생성/무료 재배치와 구별하며 기존 명세의 남은 범위를 한 번호로 기록한다. 자동 재호출 금지·관측 비용 보존·이전 선택본과 새 결과의 구별·수정 후 재검수/배치 무효화를 확인해야 한다. 실제 발행 연결과 운영 적용, 출력 기능은 아직 남아 있다.

선택 이력을 별도 저장하지 않고 브라우저에만 두거나, 과거 generation 요청/완료 증거를 최신 선택으로 덮는 방식은 채택하지 않았다. 검증된 기존 저장/엔진/preview를 재사용하며 새 AI 단계·외부 서비스·production 의존성을 추가하지 않았다.
