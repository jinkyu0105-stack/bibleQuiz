## 확인 방법과 범위

AGENTS → PROJECT_CONTEXT → DECISIONS → STATUS → HANDOFF → implementation의 관련 명세/작업 기록 → Git 순서로 확인했다. 관련 정본은 [사용자·관리자2.6/2.7](../spec/users.md#26-관리자-대시보드-첫-화면), [생성11.2/11.5](../spec/generation.md#112-관리자-주간-절차), [반응형](../spec/responsive.md), [기존 P5-72](P5-72.md)다. 현재 명세의6단계·사람 판단·명시적 AI 실행/발행은 재사용한다.

시작 Git은 main·3e5e470·clean이었다. 56bb1bf→HEAD의 src/shared/workers 차이는 없었다. 현재 화면은 `.wrangler/releases/p8-02-cache-cost-20261006/production-dist/client`의 **배포 당시 보관 자산**을 로컬127.0.0.1에서 제공해 Chromium으로 직접 렌더했다. 현재 dist는 환경별 산출물이므로 덮어쓰거나 rebuild하지 않았다. Production Access 로그인이나 현재 사용자 브라우저를 연결해 본 것은 아니다.

합성 응답은 기존 관리자 E2E 형식과 현재 Zod 자료형을 재사용했다. 의도9항목에 한 문장씩, 최초 분석/비판 수정본, 현재/과거 요약1개씩, 어린이/장년 후보5개씩을 넣었다. 실제 설교·개인정보·키·유료 응답은 읽거나 복사하지 않았다. 모든 API는 로컬 합성 GET으로 응답했고 외부 요청과 쓰기는 차단했다. 생성 실행·선택·저장·발행 버튼은 누르지 않았다.

PC1366×768/모바일390×844에서 생성 중·비판 수정본 선택·최초 분석 선택·내용 검수·배치·최종 확인·발행 전의7상태를 관찰했다. 첫 캡처14화면에 page error·외부 요청·쓰기 요청0, 관찰 폭에서 가로 넘침0이었다. 이는 화면 조사 결과이며 출시 E2E 재실행·실기기 검수·운영 API 검증의 통과 기록이 아니다. 추가 본문 캡처는 PC 일부를 저장한 뒤 버튼 대기30초 timeout으로 중단됐다. 첫14화면 측정 JSON과 필요한 상단/선택본/확정 버튼 이미지의 직접 확인은 완료했으며 추가 캡처 전체 성공으로 쓰지 않는다.

임시 도구와 이미지는 `/tmp/biblequiz-admin-ui-audit.mjs`, `/tmp/biblequiz-admin-audit-server.py`, `/tmp/biblequiz-admin-ui-audit-20261006/`에 있다. Git에 포함하지 않으며 영속 증거는 아래 관찰 요약이다. 임시 파일의 향후 존재를 보장하지 않는다.

## 추천 개편 범위 — 승인 전 제안

추천은 **기존6단계를 유지하고 작업 내용을 단계/대상 중심으로 재배치하는 안**이다. 모든 내용을 접는 간단한 수정은 버튼 소속·상태 전환 문제까지 해결하기 어렵고, 관리자 앱 전체 재작성은 필요 범위를 넘는다. 기존 테마·폰트·승인 자산·화면 컴포넌트·저장/API를 재사용한다.

1. `/admin`은 이어서 할 작업 하나와 확인 필요 사항을 먼저 둔다. 비용·백업·최근 발행 등 운영 정보는 짧은 요약과 기존 상세 경로로 연결한다. 생성 workspace의 중복 제목/메뉴를 줄여 첫 화면에 현재 단계와 다음 행동을 보여준다.
2. `/admin/quiz/:id`의 고정 작업 영역에는 현재 단계, `생성 중/사람 검토 대기/다시 확인 필요/완료`, 선택본 역할, 저장 상태와 주 버튼을 함께 둔다. 단계 이동은 화면 이동, AI 호출/확정/발행은 기존 명시적 동작으로 구별한다. 최초본 선택 상태의 해결 버튼은 `비판 수정본 확인·선택`으로 안내하며 프로그램이 임의로 선택하지 않는다.
3. 의도 검수는 현재 선택본의 핵심 메시지를 먼저 표시하고 나머지 항목·원문 근거·비판 지적·과거본 비교를 문맥에 맞게 펼친다. PC는 검수/근거를 나란히, 모바일은 대상 전환과 별도 펼침으로 비교한다. 과거 결과는 보존하고 선택 변경은 기존 검증 writer를 사용한다.
4. 요약/어린이/장년은 별도 검수 대상 전환과 각 완료 표시를 제공한다. 전환 후에도 편집본·자동 저장·실패 입력을 보존한다. 현재 대상의 검수 버튼과 미완료 이유를 가까이 둔다. 후보의 답·단서가 우선이고 근거·선정 설명·과거본은 필요할 때 열 수 있게 한다.
5. 생성 진행·불러오기·저장·사람 확정을 구분한다. 완료 후 무엇이 완료됐고 다음에 무엇을 할지 알린다. 호출0/비용0만으로 완료를 판단하지 않는다. 우선 기존 명시적 상태 확인을 재사용하며, 주기적 자동 GET 조회는 비용/요청 영향 검토 전 기본 범위에 추가하지 않는다. 실패·미확인·입력 변경·일부 조회 실패는 각 복구 행동과 받은 결과를 유지한다.
6. 배치/최종 확인/발행은 기존 무료 배치·검사·미리보기·발행 확인을 정돈한다. 현재 선택한 크기·개수·배치 결과와 기존 실패 이유를 간결하게 표시한다. 완료 후 공개 보기·운영하기를 먼저 제공한다. 가능한 크기 전체 자동 탐색과 후보 생성 조건 변경은 향후13절의 별도 범위다.

화면 구조 예시(시안이 아닌 정보 배치 제안):

```text
설교 제목 · 현재 단계                         비용 상세
현재 상태 · 마지막 저장/조회               [이번 단계 주 행동]
1 영상  2 의도  3 내용  4 배치  5 확인  6 발행

현재 검수 대상: [요약] [어린이 · 미완료] [장년 · 완료]
현재 선택본 내용                   [원문 근거 열기]
                                  [이전본과 비교]
```

새 DB/migration·production 의존성·외부 서비스·폰트 교체를 제안하지 않는다. 실제 필수 자료가 부족한 경우에는 재현 근거와 영향을 먼저 설명하고 같은 범위에서 해결할지 정한다. 계정/인증·정답 공개·1회 제출·사람 내용 판단·기존 발행 정책은 유지한다. 관리자 필터/제출/문의 화면 전면 개편, 공개 풀이/출력 디자인 변경, 격자 자동 제안/후보 프롬프트, Supadata 사용량, 영문 알림 재확인, 관리자 반복 시험은 이번 개편에서 제외한다.

## 완료 조건 제안

- PC1366×768·모바일390×844의 첫 화면에서 현재 단계·현재 상태·현재 선택본의 역할과 다음 주 행동 또는 실행 불가 이유가 보인다. 긴 본문을 읽는 중에도 해당 주 행동을 Ctrl+F나 Codex의 위치 안내 없이 찾을 수 있다. 고정 UI가 단계·버튼·입력/근거를 가리지 않는다.
- 선택본을 기본으로 보며 비교를 열어도 어떤 버전의 내용을 수정/선택/확정하는지 명확하다. 최초 분석의 확정 불가 이유와 비판 수정본 선택 경로가 함께 보이고, 새 결과 도착을 현재본 자동 채택과 혼동하지 않는다.
- 의도9항목, 요약, 어린이/장년 후보 검수와 근거 확인을 모두 수행할 수 있다. 비판 지적이나 미확인 근거가 접혀 있다는 이유로 사라지지 않는다. 모든 항목별 새 필수 승인 체크를 추가하지 않는다. 전체 페이지 높이를 숫자로 제한하거나 내용을 자르지 않고 현재 대상만 편하게 검토한다.
- 검수 대상/단계 전환·새로고침에서 현재 편집과 저장된 선택본을 잃지 않는다. `저장 중/저장됨/저장 실패`를 구분하며 저장 실패·버전 충돌 때 입력을 보존하고 이후 동작의 잠금 이유를 보여준다.
- 실행 대기/실행 중/사람 검토 대기/다시 확인 필요/발행 완료와 응답 미확인·일부 조회 실패를 구분한다. 상태 조회는 유료 실행 버튼과 구별되고 화면 진입/탭 전환/새로고침이 AI 호출·자동 선택·발행을 만들지 않는다.
- 저장된 후보로 기존 무료 배치·두 난도 선택·미리보기·최종 검사·발행 확인까지 이어진다. 크기/목표 개수는 관리자 선택 전 바뀌지 않고 실제 비용/과거 누락 안내·발행 영향 확인을 유지한다.
- 최소320px·키보드·200% 확대에서 핵심 기능을 사용하고 기존44/48px 조작 기준·라이트/다크·접근성 기준을 유지한다. 새 모바일 고정 UI가 입력 초점이나 근거 위치 이동을 가리지 않는지 변경 영향만 확인한다.
- 사용자가 합성 시안/로컬 화면으로 현재 상태 설명 → 올바른 선택본 확인 → 의도 확정 → 세 내용 검수 → 무료 배치 → 최종 확인 → 발행 확인창 → 완료 다음 행동을 위치 안내 없이 수행한다. 비용·사람 판단·공개 전 확인을 생략해 단계를 줄인 결과는 통과가 아니다. 실제 AI/운영 발행은 이 로컬 검수에 필요하지 않다.

구현 시 관련 상태/컴포넌트 검사와 `pnpm run lint`, `pnpm run typecheck`, 변경된 PC/모바일 브라우저 검사를 실행한다. 구현 완료 단위에는 `pnpm check`와 STATUS/HANDOFF·로컬 커밋을 포함한다. 완료한 출시·IME·PDF·백업 검사를 일괄 재실행하지 않고 변경 영향에 맞춰 확인한다. 시안과 동작의 사용자 검토가 남으면 같은 번호를 검수 대기로 유지한다.

## 새 작업 ID 제안

출시 후 관리자 UI 개편은 이미 시작한 **Phase9**이며 P9-01의 부모 작업이다. 이전 P5-72·P8-02 번호와 완료한 Phase8은 유지한다. P9-01은 완료했고 아래 P9-02~04의 범위·완료 조건은 사용자 검토용 제안이다. 후속 작업을 자동으로 시작하지 않는다.

| ID | 사용자 결과 | 완료 조건·현재 상태 |
|---|---|---|
| P9-01 | 현재 UI 문제·개편 범위·완료 조건·작업 제안 | 이번 조사·문서 검사·STATUS/HANDOFF·로컬 커밋 완료. 후속 구현 승인 아님 |
| P9-02 | PC/모바일 주간 흐름 시안·버튼/상태 문구 검토 | 기존 승인 디자인을 재사용한 시안에서 현재본/비교·긴 내용·진행/실패·다음 행동을 사용자가 확인. 아직 미착수. 새 이미지 유료 생성 필요 없음 |
| P9-03 | 혼자 주간 작업을 이어갈 수 있는 관리자 UI | 승인 시안에 맞춘 전체 주간 흐름 구현·관련/필수 검사·사용자 로컬 검수·문서·로컬 커밋까지 한 번호. 현재 미착수 |
| P9-04 | 검수한 UI를 운영에서 사용 | 검토 가능한 로컬 결과 후 환경·소스 커밋·검사·변경 범위·복귀안을 고정하고 해당 운영 반영 승인 뒤 실행. 이번 승인 없음. 새 실제 AI/실자료 발행은 별도 명시 범위 없이 실행하지 않음 |

다음 작업은 P9-02다. 사용자가 제안 범위를 검토하고 시작하도록 지시한 뒤 진행한다. 시안용 이미지를 생성하거나 외부 API를 추가하는 범위는 이번 제안에 포함하지 않는다. 무료 HTML/CSS 등으로 보여줄 수 있는 시안과 기존 자산을 우선한다.

## 이번 종료·보존

제품 소스·0000~0038·실제 자료·키·유료 결과·폰트/fontkit·pnpm lockfile·dist·배포 포인터는 수정하지 않았다. 운영 호출·배포·main push0, 위임0. 변경은 본 조사 문서와 현재 안내/상태 문서뿐이다. PROJECT_CONTEXT의 미완료 청구 문구와 ROADMAP의 과거 원격 대기를 P8-02 완료 근거로 정정했다. DECISIONS/spec/DELIVERY_PLAN의 확정 계약과 출시 완료 조건은 바꾸지 않았다.

최신 Pro는 사용19%·잔여81%·별도5시간 없음·7일 window다. 사용자 지정×10=810%로 이번 한 작업 조사에 충분했다. 공식 상품 배수나 실제 계정 잔여810%라는 뜻이 아니다. 실행은 기본 `/bin/bash`·login:false·명시workdir에서 셸 시작 전 ENOENT 후 같은pwd의 승인 검토 경로 성공을 확인해 사용했다. 승인 거절은 없었으며 경로 복구와 계정/배포 승인은 별개다.

이번에는 문서 링크·숫자/소스/운영 기록·Git 차이·`git diff --check`를 확인하고 로컬 커밋한다. 코드 검사·출시 E2E·유료 재실행은 하지 않는다. 후속 시안·구현·운영 검수는 미완료가 아니라 아직 승인/착수하지 않은 제안이다.
