# P9-05 — Air 실제 탐색·하늘 디자인 기준·움직임 검토본

2026-10-08. 사용자 요청: Refero의 Air 스타일을 참고해 공개/관리자 UI를 전면 개편하되 **밝은 하늘과 어두운 하늘 모두**, 원본 우측 시간대 선택, **같은 배경에서 구름의 이동으로 하늘→지면으로 내려오는 느낌**을 계승한다. 앞선 어두운 분위기만의 안내를 정정했다. 이번 고정 범위는 원본의 실제 상호작용 조사, 새 디자인 기준, 직접 조작할 독립 움직임 검토본이다. 전체 화면 시안·앱 반영·배포 완료가 아니다.

## 원본에서 확인한 사실

- [Air](https://air.inc/) 우측에는 Sunrise/Sun/Sunset/Moon 네 버튼이 있다. 데스크톱 Chromium1440×900에서 네 버튼을 실제 클릭하고 같은 위치의 네 화면을 캡처했다. 첫 관측은 낮이었다. 공개 코드상 초기 선택은 로컬 시계와 sessionStorage의 기존 선택을 사용하므로 항상 낮으로 시작한다고 일반화하지 않는다.
- 배경은 `three.js r176` 표시의 고정 canvas 한 개다. React/Three 계열 scene에 깊이별 구름을 배치한다. 구름은 시간에 따라 깊이 방향으로 움직이고, 약한 회전/크기 변화와 깊이에 따른 투명도로 접근감을 만든다.
- 스크롤은 연속 scene group의 y 위치를 바꾼다. 끝부분은 camera view offset도 사용한다. 따라서 단순 배경 영상 한 개 또는 섹션마다 다른 사진으로 바꾸는 구성이라고 설명하지 않는다.
- 시간대는 약1000ms 색 보간으로 하늘 상하단·구름·유리·잔디/꽃의 조명을 함께 바꾼다. 실제 낮의 파랑, 새벽의 푸른/따뜻한 빛, 노을의 보라/복숭아색, 밤의 짙은 파랑을 비교했다.
- 마지막에는 잔디·꽃·버섯·나비·입자가 같은 scene에 등장한다.1000×700 viewport에서 실제 휠 스크롤 최하단 `scrollY=maxScrollY=12716`을 대조하고 낮/밤을 캡처했다. 도입 애니메이션 전에 시도한 첫 최하단 캡처는 실제 scrollY870이어서 근거에서 제외했다.
-390×844 모바일에서는 시간대 선택이 가로 배치됐다. 버튼 위치/낮 화면은 확인했으나 밤 클릭이 hero에 가로채여 실패했다. 원본 모바일 전환 성공이라고 쓰지 않는다. 소프트웨어 WebGL의 stalled readback/bad image data 및 React hydration 경고는 이 탐색의 관측 한계다. 실제 기기 성능 검사나 Air 서비스 장애 판정이 아니다.

[Refero](https://styles.refero.design/style/d3289fe7-a85e-42d8-96b7-eb7faa62a104)는 원본 Air를 연결하고 공개 DESIGN.md/CSS Variables를 제공하지만 스타일 설명이 dark에 치우쳐 있다. 이번 시간대/하강 동작의 정본은 실제 원본 관측이다. 원본 JavaScript는 공개 동작을 이해하기 위해 `/tmp`에서 읽었으며 코드·cloud.png·3D 모델·Control 폰트·cubemap을 저장소 자산으로 복사하지 않았다. Refero 설치/결제0, 새 dependency0, 새 AI API 호출0.

## 독립 검토본과 기존 앱의 차이

[검토본](../design/phase-9/air-sky-study/index.html)은 기존 앱과 분리된 HTML/CSS/JavaScript다. 스크롤하지 않아도 구름이 흐르고, 내려가면 깊이/높이가 다른 구름을 지나 같은 하늘 아래 정원이 나타난다. 새벽/낮/노을/밤 선택은 하늘·구름·지면 색을 바꾸며, PC는 우측 세로/모바일은 하단 가로 제어를 쓴다. 멈춤·다시 시작과 시스템 움직임 감소 설정을 지원하고 비활성 탭에서는 그리기를 중단한다. 검토본은 새 theme를 외부나 앱 저장소에 쓰지 않는다.

구름은 자체 코드로 만든 noise texture를 Canvas2D에 투영하며, 지면은 자체 경로/풀잎이다. Air의 실제 3D 재질·원본 꽃/나비·사실적 최종 이미지와 동일하지 않다. 최종 이미지 시안을 대신하거나 원본의 시각 재현 완료로 판정하지 않는다. 구름의 깊이와 하강/시간대 전환을 검토하는 무료 기술 증거다. 글자는 HTML이고 배경에 성경 본문·문자·로고를 합성하지 않았다.

기존 앱은 `src/features/quiz/ThemeControl.tsx`의 기기/라이트/다크 선택과 `src/styles/index.css`의 기존 토큰, `src/features/quiz/QuizArtwork.tsx`의 garden-v2를 사용한다. 이번에는 src/public/DB/라우터를 변경하지 않았다. 새 방향은 [디자인 명세10.7](../spec/design.md#107-air-계승-하늘-방향--2026-10-08)·[D-042](../DECISIONS.md#d-042--air의-연속-하늘시간대-전환을-새-ui-방향으로-채택)가 정본이다. 기존 숲/종이/팔레트는 현재 배포된 구현 근거로 보존하고 다음 개편에서는 새 방향을 우선한다.

- 시작 Pro used4%/잔여96%, 별도5시간 없음, 사용자 지정×10=960%.
- Computer Use 스킬 초기화 도구는 `sandboxCwd is not a local file URI: file:///home/onegem/work/bibleQuiz`로 시작 실패했다. Windows 보안/앱 설정을 바꾸지 않고 기존 Linux Playwright1.62.1/Chromium으로 진행했다. 추가 설치 없이 Context7 `/microsoft/playwright`와 공식 문서 API를 대조했다.

## 종료와 다음 사용자 결과

P9-05의 실제 탐색·새 기준·동작 검토본은 완료한다. **새 UI 개편 전체는 진행 중**이다. 다음 P9-06은 `imagegen-frontend-web` 절차에 맞춘 별도 대표 화면 시안: 공개 첫 화면의 낮/밤, 풀이 모바일, 관리자 생성/검수다. 스킬 경로는 AGENTS의 현재 catalog에서 읽으며 시안 이미지는 글자를 합성하지 않고 의미 있는 구성/배경을 보여 주고 실제 한글 문구는 별도 HTML/명세로 다룬다. 사용자에게 같은 이미지에 여러 화면을 압축해 보여 주지 않는다. 이 시안 확인 뒤 전체 UI 구현/관련 검사로 이어간다. 새 production dependency/외부 서비스·유료 플랜·Refero 결제·실제 AI/DB·push/배포는 이번 작업에 추가하지 않는다.
