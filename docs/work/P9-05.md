# P9-05 — Air 실제 탐색·하늘 디자인 기준·움직임 검토본

2026-10-08. 사용자 요청: Refero의 Air 스타일을 참고해 공개/관리자 UI를 전면 개편하되 **밝은 하늘과 어두운 하늘 모두**, 원본 우측 시간대 선택, **같은 배경에서 구름의 이동으로 하늘→지면으로 내려오는 느낌**을 계승한다. 앞선 어두운 분위기만의 안내를 정정했다. 이번 고정 범위는 원본의 실제 상호작용 조사, 새 디자인 기준, 직접 조작할 독립 움직임 검토본이다. 전체 화면 시안·앱 반영·배포 완료가 아니다.

## 원본에서 확인한 사실

- [Air](https://air.inc/) 우측에는 Sunrise/Sun/Sunset/Moon 네 버튼이 있다. 데스크톱 Chromium1440×900에서 네 버튼을 실제 클릭하고 같은 위치의 네 화면을 캡처했다. 첫 관측은 낮이었다. 공개 코드상 초기 선택은 로컬 시계와 sessionStorage의 기존 선택을 사용하므로 항상 낮으로 시작한다고 일반화하지 않는다.
- 배경은 `three.js r176` 표시의 고정 canvas 한 개다. React/Three 계열 scene에 깊이별 구름을 배치한다. 구름은 시간에 따라 깊이 방향으로 움직이고, 약한 회전/크기 변화와 깊이에 따른 투명도로 접근감을 만든다.
- 스크롤은 연속 scene group의 y 위치를 바꾼다. 끝부분은 camera view offset도 사용한다. 따라서 단순 배경 영상 한 개 또는 섹션마다 다른 사진으로 바꾸는 구성이라고 설명하지 않는다.
- 시간대는 약1000ms 색 보간으로 하늘 상하단·구름·유리·잔디/꽃의 조명을 함께 바꾼다. 실제 낮의 파랑, 새벽의 푸른/따뜻한 빛, 노을의 보라/복숭아색, 밤의 짙은 파랑을 비교했다.
- 마지막에는 잔디·꽃·버섯·나비·입자가 같은 scene에 등장한다.1000×700 viewport에서 실제 휠 스크롤 최하단 `scrollY=maxScrollY=12716`을 대조하고 낮/밤을 캡처했다. 도입 애니메이션 전에 시도한 첫 최하단 캡처는 실제 scrollY870이어서 근거에서 제외했다.
-390×844 모바일에서는 시간대 선택이 가로 배치됐다. 버튼 위치/낮 화면은 확인했으나 밤 클릭이 hero에 가로채여 실패했다. 원본 모바일 전환 성공이라고 쓰지 않는다. 소프트웨어 WebGL의 stalled readback/bad image data 및 React hydration 경고는 이 탐색의 관측 한계다. 실제 기기 성능 검사나 Air 서비스 장애 판정이 아니다.

[Refero](https://styles.refero.design/style/d3289fe7-a85e-42d8-96b7-eb7faa62a104)는 원본 Air를 연결하고 공개 DESIGN.md/CSS Variables를 제공하지만 스타일 설명이 dark에 치우쳐 있다. 이번 시간대/하강 동작의 정본은 실제 원본 관측이다. 원본 JavaScript는 공개 동작을 이해하기 위해 `/tmp`에서 읽었으며 코드·cloud.png·3D 모델·Control 폰트·cubemap을 저장소 자산으로 복사하지 않았다. Refero 설치/결제0, 새 dependency0, 새 AI API 호출0.

## 독립 검토본과 기존 앱의 차이

[검토본](../design/phase-9/air-sky-study/index.html)은 기존 앱과 분리된 HTML/CSS/JavaScript다. 스크롤하지 않아도 구름이 흐르고, 내려가면 깊이/높이가 다른 구름을 지나 같은 하늘 아래 정원이 나타난다. 새벽/낮/노을/밤 선택은 하늘·구름·지면 색을 바꾸며, PC는 우측 세로/모바일은 하단 가로 제어를 쓴다. 멈춤·다시 시작과 시스템 움직임 감소 설정을 지원하고 비활성 탭에서는 그리기를 중단한다. 검토본은 새 theme를 외부나 앱 저장소에 쓰지 않는다.

구름은 자체 코드로 만든 noise texture를 Canvas2D에 투영하며, 지면은 자체 경로/풀잎이다. Air의 실제 3D 재질·원본 꽃/나비·사실적 최종 이미지와 동일하지 않다. 최종 이미지 시안을 대신하거나 원본의 시각 재현 완료로 판정하지 않는다. 구름의 깊이와 하강/시간대 전환을 검토하는 무료 기술 증거다. 글자는 HTML이고 배경에 성경 본문·문자·로고를 합성하지 않았다.

기존 앱은 `src/features/quiz/ThemeControl.tsx`의 기기/라이트/다크 선택과 `src/styles/index.css`의 기존 토큰, `src/features/quiz/QuizArtwork.tsx`의 garden-v2를 사용한다. 이번에는 src/public/DB/라우터를 변경하지 않았다. 새 방향은 [디자인 명세10.7](../spec/design.md#107-air-계승-하늘-방향--2026-10-08)·[D-042](../DECISIONS.md#d-042--air의-연속-하늘시간대-전환을-새-ui-방향으로-채택)가 정본이다. 기존 숲/종이/팔레트는 현재 배포된 구현 근거로 보존하고 다음 개편에서는 새 방향을 우선한다.

## 참조 경로·적용 범위·한글 글꼴 확인 — 2026-10-08

사용자의 후속 질문에 실제 참조 경로와 준수 범위를 확인했다. Refero 페이지의 공개 DESIGN.md 설명과 CSS Variables를 웹 열람으로 참고했다. Tailwind v4 출력은 읽을 수 있으나 저장소로 가져오거나 적용하지 않았다. 저장소에 Refero DESIGN.md 원문을 복제하지 않았다. 움직임 검토본은 직접 작성한 CSS/Canvas JavaScript다. Refero MCP·계정 연결·설치·결제는 사용하지 않았다. 실제 Air 탐색은 기존 Linux Playwright/Chromium이며 Context7은 그 도구의 공식 API 확인에 사용했다. Computer Use 초기화 실패/exec recovery는 위 실행 절을 따른다. 디자인/이미지 skill의 절차를 읽은 것과 실제 시안 생성/전체 앱 적용은 구분하며 이번 검토본에 이미지 생성을 사용하지 않았다.

[Refero 공개 페이지](https://styles.refero.design/style/d3289fe7-a85e-42d8-96b7-eb7faa62a104)도 값의 정규화와 역할/추천의 해석, 예제 HTML의 재구성을 명시한다. 현재 검토본의 시간대별 하늘색은 독립 조정값이고 Refero UI 팔레트의 일괄 적용이 아니다. 버튼8px·제어 패널12px 일부만 참고했고, 제목 크기/행간·본문/보조 문구·여백·그라데이션/스크림은 모션 검토용으로 별도 작성했다. max-width1150px·섹션 간격48px·카드20px 등 전체 토큰과 표면/색상/서체/가이드라인 대조는 대표 시안에 남는다. 실제 Air의 하늘은 색 보간 shader를 쓰므로 Refero의 dark·그라데이션 금지 설명을 원본 모든 시간대의 동작이라고 일반화하지 않는다.

### 추천 대체와 실제 CSS 폴백은 다름

Refero DESIGN.md의 Substitute는 Control→Inter/system-ui, Compressed→Anton/Druk Wide, Cursive→Caveat/Reenie Beanie, TNT→Inter/sans-serif다. 반면 공개 CSS Variables/Tailwind의 네 폰트 뒤에는 모두 `ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif`가 붙으며 위 추천 폰트들이 자동 포함되지 않는다. 이 일반 폴백이 한글을 표시하더라도 실제 선택은 OS/브라우저에 달려 있어 원본의 압축/필기체 느낌까지 재현하지 않는다.

| 참조 서체 역할 | 공식 한글 지원 확인 | 다음 시안의 대체 기준 |
|---|---|---|
| Control · Control TNT | Commercial Type의 Control collection 지원 목록에 한국어 없음. TNT는 해당 collection의 변형으로 안내 | 기존 Noto Sans KR 우선; Inter 유사 UI는 Pretendard 비교 |
| Control Compressed | Refero 명칭과 일치하는 독립 공식 서체/한글 지원을 확정하지 못함. 대체 Anton/Druk Wide는 공식 목록에 한국어 없음 | 한글 지원 제목 서체의 실제 굵기/폭을 비교. Pretendard 강한 굵기는 후보이며 압축 서체와 동일한 형태는 아님 |
| Control Cursive | 공식 Control collection의 한국어 미지원; 대체 Caveat/Reenie Beanie도 한국어 없음 | 한글 손글씨 강조 후보 Nanum Pen Script. 작은 강조에만 비교하고 본문/격자에는 쓰지 않음 |
| Inter 및 일반 sans 폴백 | Inter 공식 Google Fonts metadata에 korean subset 없음. system-ui/sans-serif는 특정 폰트가 아님 | 한글 글꼴을 명시하고 실제 렌더링/영문·숫자 혼용 확인 |

공식 확인: [Control collection](https://commercialtype.com/catalog/control), [Control Cursive/TNT](https://commercialtype.com/catalog/control/control_cursive/bold_tnt), [Druk Wide](https://commercialtype.com/catalog/druk/druk_wide), Google Fonts metadata [Inter](https://github.com/google/fonts/blob/main/ofl/inter/METADATA.pb)·[Anton](https://github.com/google/fonts/blob/main/ofl/anton/METADATA.pb)·[Caveat](https://github.com/google/fonts/blob/main/ofl/caveat/METADATA.pb)·[Reenie Beanie](https://github.com/google/fonts/blob/main/ofl/reeniebeanie/METADATA.pb). 미지원 판정은 공식 지원 목록 기준이며 Air의 유료/비공개 폰트 파일을 다운로드해 glyph 전체를 검사하지 않았다. Compressed의 미확인 상태는 지원 성공/실패 확정으로 바꾸지 않는다.

대체 후보의 공식 근거: [Pretendard](https://github.com/orioncactus/pretendard)는 Inter/본고딕 기반과 한글 바탕·9개 굵기/가변 글꼴을 안내한다. [Nanum Pen Script metadata](https://github.com/google/fonts/blob/main/ofl/nanumpenscript/METADATA.pb)는 handwriting·400·korean subset·OFL을 명시한다. 기존 [Noto CJK](https://github.com/notofonts/noto-cjk)는 KR 한국어 변형을 제공한다. 둘 다 비교 후보이며 새 파일 설치/최종 채택은 아직 하지 않았다.

### 현재 프로젝트의 폴백과 보완점

앱은 src/main.tsx에서 fonts.css를 로드한다. 현재 @font-face는 Noto Sans KR400·Noto Serif KR600이며, 기본 CSS 체인은 `Pretendard, "Noto Sans KR", system-ui, sans-serif`, 제목은 `"Noto Serif KR", serif`다. Pretendard 선언을 실제 자체 호스팅 다운로드로 혼동하지 않는다. 독립 검토본은 `"Noto Sans KR", "Apple SD Gothic Neo", "Malgun Gothic", sans-serif`를 선언하지만 fonts.css를 연결하지 않았다. 설치된 Noto가 없으면 OS 폴백이며, 검토본에서 요청하는500/600이 최종 파일 굵기 검증을 뜻하지 않는다. 다음 대표 화면은 실제 한글 폰트/굵기를 연결한 뒤 평가한다.
