## 공식 근거와 실행 환경

Context7 CLI의 library 조회로 `/cloudflare/cloudflare-docs`를 선택한 뒤 D1 export/R2/Rate Limiting을 조회했다. 프로젝트 CLI는 Wrangler4.125.0, Node24.18.0·pnpm11.14.0이다. 최신 공식 API/요금 문서를 직접 대조했다. 계정이나 플랜은 변경하지 않았다. OpenAI Docs로 요금과 조직 Usage/Costs의 Admin key 요구를 확인하고 새 광범위 key 대신 기존 앱 원장을 쓴다.

- [D1 export API](https://developers.cloudflare.com/api/resources/d1/subresources/database/methods/export/)·[Workflow 공식 백업 예제](https://developers.cloudflare.com/workflows/examples/backup-d1/): `result.result.signed_url`, polling bookmark, export 중 DB 일시 불가. URL은 callback 안에서만 사용하고 step state/DB/로그에 저장하지 않는다.
- [R2 Worker API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)·[FixedLengthStream](https://developers.cloudflare.com/workers/runtime-apis/streams/transformstream/): 압축 뒤 크기를 먼저 측정하고 정해진 길이 stream으로 업로드, 재다운로드 gzip이 다르면 정상 기록 금지. SQL을 전체 메모리 buffer로 옮기지 않는다.
- [D1 import/export](https://developers.cloudflare.com/d1/best-practices/import-export-data/)·[외래 키](https://developers.cloudflare.com/d1/sql-api/foreign-keys/): 참조 테이블 생성이 앞서야 한다. Wrangler SQL parser로 CREATE TABLE → INSERT → index/trigger 순서를 재배열해 격리 복원하며 index/trigger도 원본과 대조한다.
- [R2 요금](https://developers.cloudflare.com/r2/pricing/)·[D1 요금](https://developers.cloudflare.com/d1/platform/pricing/)·[Workers 요금](https://developers.cloudflare.com/workers/platform/pricing/)·[Workflows 요금](https://developers.cloudflare.com/workflows/reference/pricing/)·[DO 요금](https://developers.cloudflare.com/durable-objects/platform/pricing/): registry의 관측 기준이며 실제 계정 플랜/청구를 대신하지 않는다. invocation CPU/일일 step/GB-month를 다른 실행 단위로 환산하지 않는다.
- [Rate Limiting binding](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/): 위치별 비동기·permissive counter이고 정확한 총량/과금 방어가 아니다. 공개 활성화 전 플랜 지원·정상 공유망·무료 범위를 다시 확인한다.
- [Builds read API](https://developers.cloudflare.com/api/resources/workers_builds/methods/get_account_limits/)는 숫자 분 합계가 아니라 한도 도달 여부를 준다. [Builds API token](https://developers.cloudflare.com/workers/ci-cd/builds/api-reference/)은 user-scoped Workers CI Read 권한이 필요하다. [Access users API](https://developers.cloudflare.com/api/resources/zero_trust/subresources/access/subresources/users/methods/list/)에서 Access/Gateway seat 합계만 저장하고 개인 응답은 버린다. token 정책을 임의 넓히지 않는다.
- [OpenAI 가격](https://developers.openai.com/api/docs/pricing)·[Usage/Costs 공식 예제](https://developers.openai.com/cookbook/examples/completions_usage_api)·[GitHub Actions 비용](https://docs.github.com/en/billing/concepts/product-billing/github-actions)·[Access Free](https://www.cloudflare.com/sase/products/access/).

기본 exec 시작 ENOENT 뒤 codex-exec-recovery를 적용했다. 검증된 `/bin/bash`·login:false·require_escalated 승인 검토 경로에서 동일 pwd 확인 후 계속했다. pnpm이 PATH에 없어 허용된 WSL Node24.18.0/bin을 명령별 PATH에 사용했다. 앱 코드/CI에 기기 경로를 고정하지 않았다. 승인 거부 우회·WSL 재연결·보안 설정 변경 없음.

## 비용·운영의 실제 한계

새 production 의존성/외부 서비스0, AI/원격 변경 호출0. 사용량은 R2 계정/bucket, D1 계정/DB, Workers 계정/각 Worker, Workflow 관측 event, DO request, Builds 한도 도달, Access seat 합계를 읽는 adapter다. 누적 CPU·DO GB-s·Workflow state 저장/청구 steps·Builds 정확한 월 분/이력은 확인 불가 상태로 남는다. GitHub 공개/runner와 도메인 갱신은 공급자 관리 화면 점검을 안내한다. 자동 갱신을 가장하거나 빈 배열을0으로 쓰지 않는다. 실패 시 이전 scope 숫자를 보존하고 지연으로 표시한다. 5분 cache·동시 갱신 lease·31일 snapshot 정리는 원래 AI 원장을 지우지 않는다.

R2 자동 업로드는 새 객체와 계정 저장량8GB·최근31일 작업 A80만/B800만을 비교하고 관측 실패 때 중단한다. 달력 월 청구와 다른 기간을 고려해 업로드는31일 관측을 보수적으로 사용한다. 순간 저장 bytes와 지연된 analytics는 실제 GB-month/청구 hard cap이 아니므로 월USD0을 보장한다고 쓰지 않는다. 수동·migration 직전 사본은 주간8개를 밀어내지 않고 자동 삭제하지 않는다. 운영자가 필요성과 개인정보 보관 기간을 점검해 명시 정리하며 새 기간을 임의 확정하지 않았다.

manifest는 SQL 회전과 분리한 최신 누적본과 검증 사본이다. 독립 동기화 이전에 발생한 삭제나 원본 DB 소실을 재적용 성공만으로 보존했다고 주장할 수 없다. 복원 전 최신 원본/누적 manifest를 확보하고 freshness를 확인하지 못하면 공개 재개를 보류한다. 자동 복원/공개 버튼은 없다. 종료/불확실 Workflow 상태를 확인하기 전에 running 잠금을 자동 만료시키거나 새 ID로 재export하지 않는다.

문의 자동 삭제 기간은 미확정이며 기존 명세·D-040에 근거해 임의 기간/새 정리 정책을 넣지 않았다. 운영자는 미처리 문의를 확인하고 원격 정리 활성화 전 보존 기간·대상·감사를 함께 확정한다. 이번 Cron은 기존 승인된7일 초안/수정/오류/철회 정리만 호출한다.

## 원격 활성화 전 확인할 묶음

현재 `wrangler.jsonc`의 local/preview/root, content config와 backup config에는 신규 원격 자원·Cron·R2·rate limit·secret 연결을 넣지 않았다. backup은 workers_dev=false·preview_urls=false·route 없음. 실제 Preview는 P5-71 그대로이며0037/0038은 원격 미적용이다. Production은 생성하지 않았다.

합성 전용 `wrangler.p8-local.jsonc`는 배포 대상이 아니다. local UUID와 rate namespace 후보/마감 Cron만 있으며 실제 자료·키·R2·AI 연결 없음. 배포 단위에서 Production trigger/승인/migration/rollback 합의를 먼저 한다. 그 뒤 환경별 구체적 후보를 검토한다.

- 앱: DB·기존 AdminCompute 보존, 운영 환경/version metadata, 읽기 최소 권한 analytics token, 내부 BACKUP_WORKFLOW binding만. R2/export token은 앱에 주지 않는다.
- backup: 공개 route 없이 승인된 환경 D1·private Standard R2·export token·analytics token·환경 값·자기 Workflow. R2 활성화 checkout과 초과 과금 가능성은 먼저 사용자 결정.
- Cron 제안: 앱 마감 `*/5 * * * *`, 별도 삭제 기록 `*/10 * * * *`, 주간 SQL `0 19 * * SUN`(월요일04:00 KST). 시간/예산은 실제 Preview 소요 측정 후 확정한다. 삭제 sync2step×144회=288step/일 제안이며 계정 전체 소모/청구의 검증값이 아니다.
- 요청 제한 후보: session 발급과 guest100회/10초, active session6회/10초, route/variant별. 다른 주체50명이 같은 IP를 써도 동일 세션 counter로 합치지 않는다. cookie 삭제/IP변경·여러 위치 우회와 합성 시험의 한계를 공개 활성화 전 검토한다.
- 적용 전0037/0038 원격 목록·환경 확인, 현재 DB 보존, export 영향 안내, 검사 소스 일치, 적용/배포 범위와 rollback 조건을 한 묶음으로 승인받는다. 이 문서는 승인 자체가 아니다.

## 검사·실패와 폐기 접근법

`operations-backup.test.ts`는 workerd D1/R2에서 압축/전체 readback/회전/누적 manifest/예산/누락·손상/동시 실행/같은ID/Cron을 검사한다. `step.do` 호출 순서 검사는 callback 모의 실행이며 실제 Workflow checkpoint/remote CPU 완료로 표현하지 않는다. `operations-usage.test.ts`는 상태·cache·가격 확인·Access/Builds 응답/PII 차단과 native local RateLimit counters를 검사한다. submission/마감/기존 정리/연습/문의 회귀는 기존 fixture를 재사용한다. 관리자 브라우저는 실제Chromium PC/모바일이며 provider 응답만 합성으로 대체한다.

`check-isolated-backup-restore.mjs`는 인자를 허용하지 않는 합성 전용 재연이다. `/tmp` 아래에 DB2개를 만들고0000~0038·공개fixture·합성 제출만 적재한다. nativeSQLite 검사는 임시 DB만 읽고 원본/실제 보관 DB는 열지 않는다. SQLgzip/checksum→격리 restore→백업 이후 삭제manifest→재적용/별도gate→재실행/변형manifest거부→FK/quick_check·원본불변을 확인한다. 실제 원격 export/import와 복원 approval을 대신하지 않는다.

초기 오류: 시험 제출 key는 UUIDv7이어야 했다. Wrangler export의 미지원 `--persist-to`를 제거하고 설정 파일 기준 임시 persistence로 통일했다. raw export는 외래 키 때문에 직접 import 실패하여 공식 지침대로 schema/data/trigger 순서를 검토했다. R2는 크기 없는 gzip stream을 거부해 측정 길이의 FixedLengthStream으로 바꿨다. 빈 stream 실패에서 DigestStream의 digest promise도 함께 처리해 미처리 rejection을 제거했다. fixture fetch의 `/export` substring 판정을 endpoint suffix로 바로잡았고 Turnstile fixture는 요청 context마다 새 Response를 반환한다. 손상/유실을 정상 완료로 처리하는 대안·전체SQL buffering·원격 무료 성공 추정·새 유료 플랜은 채택하지 않았다.
