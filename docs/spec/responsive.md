## 3. 반응형 화면 사양

### 3.1 고정 수치

사용자가 수치를 별도로 정하지 않아도 되도록 아래를 구현 기준값으로 고정한다.

| 항목 | 값 |
|---|---|
| `body` 폭 | `100%` |
| 일반 페이지 헤더·본문 최대 폭 | `1376px` |
| 701px 이상 공통 프레임 | `min(1376px, 100vw - 216px)` 가운데 정렬. 설정 패널60px는 본문 오른쪽24px, 창 오른쪽 여유 최소24px. 700px 이하만 하단 팝업 |
| 데스크톱 본문 | P9-26: 격자 약 `55%`, 단서 약 `45%` |
| 데스크톱 열 정의 | `minmax(0, 1.2fr) minmax(280px, 1fr)` |
| 열 간격 | `24px` |
| 자동 1열 전환 | 뷰포트 `1024px` 미만 |
| 일반 셀 크기 | `min(격자에 쓸 수 있는 내부 폭 / 한 변 칸 수, 80px)` 정사각형 |
| 크게 보기 셀 크기 | `min(격자에 쓸 수 있는 내부 폭 / 한 변 칸 수, 112px)` 정사각형 |
| 최소 터치 영역 | 일반 조작 버튼 `44×44px`, 이전/다음·방향 버튼 최소 `48×48px`; 퍼즐 셀은 전체 표시를 위해 더 작아질 수 있음 |
| 지원 폭 | 최소 `320px`, 기준 수동 검수는 `360px`부터 |

일반 페이지 콘텐츠 컨테이너와 헤더는 위 공통 프레임으로 맞추고 좌우 대칭으로 축소한다. 메인 히어로의 전체 화면 배경과 편집형 섹션 내부 구성은 유지한다. 초광폭 화면에서 격자와 단서가 무한히 벌어지지 않게 한다.

2026-10-08 당시 결정(D-042)은 콘텐츠 최대 폭1440px였다. 2026-10-20 C안 승인으로 헤더·일반 본문 공통 프레임은 위1376px 기준을 사용한다.2560px 이상의 화면에서는 전체 화면 배경의 지형 범위·구름 배치·사진 해상도를 보정하며 본문/격자/단서 폭을 확대하지 않는다. 하늘 검토본은2560×1080과2560×1440을 모두 확인하고3840px에서도 지형 끝이나 구름 자산의 직선 경계가 노출되지 않도록 한다.

2026-08-31 사용자 결정(D-015): 작은 화면에서는 **칸을 줄여 퍼즐 전체가 한눈에 보이는 것**을 우선한다. 기존 56px/60px 최소 셀 크기를 강제하지 않으며, 페이지나 격자를 가로로 스크롤하거나 일부 열을 잘라 표시하지 않는다. 내부 폭은 격자 테두리까지 제외해 계산하고, 번호·입력 음절·방향 표시가 서로 겹치지 않도록 비례 축소한다. 320px 화면에서도 현재 레이아웃의 실제 내부 폭과 격자 테두리를 제외한 공간에 10×10 전체가 들어가야 한다. 셀 크기를 과거 여백 기준의 28.6px로 고정하지 않으며, 자동 검사는 실제 가용 폭·정사각형·전체 칸 표시·가로 넘침 없음으로 확인한다.

### 3.2 `크게 보기`

- 기본 데스크톱: 격자와 단서를 약55:45 두 열로 배치한다.
- `크게 보기` 활성화: 격자와 단서를 각각 전체 폭인 2행 1열로 배치한다.
- 버튼은 `aria-pressed` 상태를 가지며 활성 시 이름을 `기본 보기`로 바꾼다.
- 1024px 미만은 원래 1열이므로, 이 버튼이 글자·단서 간격을 확대하는 접근성 모드로도 작동한다. 셀은 여유 폭이 있을 때만 커지며 전체 격자가 들어가는 상한을 넘지 않는다.
- 상태는 `localStorage`에 저장하되, 저장 실패가 기능을 막지 않는다.

### 3.3 다크모드

- 첫 방문은 운영체제 `prefers-color-scheme`을 따른다.
- 사용자가 전환하면 `light | dark | system` 값을 로컬에 기억한다.
- 페이지 루트의 CSS 변수 세트 하나로 전환하며 섹션마다 제각각 반전하지 않는다.
- 새 UI의 숲/Everforest·갈색/Gruvbox 팔레트 기준은 2026-10-08 사용자 지시로 종료했다. 밝은/어두운 하늘과 새벽·낮·노을·밤은 [현재 디자인](design.md#106-새-토큰과-한글-타이포-초안)을 따른다. 기존 앱의 저장값 호환과 자동 초기 시간 정책은 실제 연결 단계에서 정리한다.
- 새 하늘 검토본의 문제 패널은 두 모드 모두 글자가 안정적으로 읽히는 유리 표면을 쓴다. 사용자 선택인 Apple 참고안의 역할별 밀도·입력 받침·투명도 감소는 [디자인10.8](design.md#apple-참고-유리-검토본의-재현-기준)을 따른다. 운영 앱의 기존 표면은 실제 연결 전까지 유지한다.
- 출력용 주보 PNG와 A4는 브라우저 다크모드와 무관한 고정 인쇄 테마를 쓴다.

### 3.4 접근성 기준

- WCAG 2.2 AA 대비를 목표로 한다.
- 격자 셀은 행·열, 단어 번호, 방향, 현재 입력값을 스크린리더에 전달한다.
- 색상만으로 활성·정답·오답을 구분하지 않고 테두리·기호·텍스트를 함께 쓴다.
- 모든 기능은 키보드만으로 사용할 수 있어야 한다.
- `prefers-reduced-motion`에서는 장식 애니메이션을 끈다.
- 200% 확대에서도 가로 스크롤 없이 핵심 기능을 사용할 수 있어야 한다.
- 퍼즐 셀이 작아지더라도 단서 선택, 48px 이상 이전/다음·방향 버튼, 키보드 입력을 제공한다. 작은 셀의 직접 터치만을 유일한 입력 경로로 만들지 않는다.

P9-26의 제목/메타 도구·인덱스·본문/제출 배치는 [디자인 정본](design.md#p9-26-공개-풀이-화면--2026-10-16)을 따른다. 셀 크기는 테두리를 뺀 컨테이너 폭으로 계산하며 외곽 폭은 실제 렌더된 셀 트랙 합계로 맞춘다. Firefox에서 분수 픽셀 트랙과 별도 계산 폭의 반올림 차이로 내부1px 넘침이 생기는 경우를 방지한다.

### 초광폭 확인 — P9-26

사용자는2560px를 기본으로,3440px 전체 화면과 분할 창도 사용한다. 검수 폭320·375·425·768·1024·1440·2560·3440px를 포함한다.2026-10-20에는 세 일반 페이지24상태 및 네 시간대의 목록/주제 폼/선택창36상태에서 가로 넘침0을 확인했다. [측정값과 변경하지 않은 현재 배치/대안](../design/phase-9/layout-audit/review.html). 이는 C안 승인 전 비교 기록이다. 이후 사용자 승인에 따라 아래 기준을 적용했다.

CSS viewport와 물리픽셀을 구별한다.1440 CSSpx·DPR1.25에서1800px PNG가 생성되지만 scrollWidth/innerWidth는 모두1440일 수 있다. 캡처 너비만으로잘림을판정하지않고 documentElement.scrollWidth와innerWidth, 실제요소경계를비교한다. 이는사용자기기의실제배율을확인했다는뜻이아니다.

2026-10-20 C안 승인: 701px 이상에서는 헤더와 풀이·지난 퀴즈·관리 전체 본문이 같은 폭과 중심선을 공유한다. 3440/2560px에서는1376px,1440px에서는1224px,1024px에서는808px,768px에서는552px다. 우측 설정 패널은 본문 오른쪽24px에 떨어뜨리고, 700px 이하에서만 기존 하단 설정 팝업으로 전환한다. 1024px 이하 전환은 과거 제안이며 적용하지 않는다. 메인의 전면 배경과 섹션 내부 편집 구성은 유지한다.

모바일 관리 목록은700px 이하에서 날짜·제목·더보기 버튼의3열로 구성한다. 상태는 제목 위 작은 표식, 긴 제목은 한 줄 말줄임이며 더보기 창에서 전체 제목과 참여 수·작업 이름을 읽을 수 있다. 원래 PC 바로 가기와 공개/초안/만료 상태별 권한은 보존한다. Live는 모든 폭에서 첫 행Live+날짜, 둘째 행제목+공개 링크다. [최종 실화면 검수](../design/phase-9/layout-audit/applied/review.html).
