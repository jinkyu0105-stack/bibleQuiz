## 10. 시각 디자인과 이미지 자산

### 10.1 공통 디자인 방향

2026-10-08 사용자는 이전 숲·종이·색상 기준을 종료하고 Air를 참고해 처음부터 다시 만들도록 지시했다. **새 UI는 밝은 낮과 깊은 밤을 가진 하나의 연속 하늘**을 따른다. 이전 Everforest/Gruvbox, 장년 숲·어린이 종이 정원, 황동/이끼/잎색 역할과 기존 시안 구도는 새 디자인의 제약에서 폐기한다. 과거 자산·결정·출력 폰트는 보존한다. 운영 앱은 별도 적용 전까지 기존 P9-04 소스를 유지한다.

교회 공동체가 매주 사용하는 퀴즈에 실제 하늘을 통과하는 공간감을 더한다. 공개 첫 화면은 큰 한글 제목과 여백, 구름의 거리·광원·지면까지 이어지는 장면을 중심으로 한다. 풀이와 관리자 화면은 읽기와 입력이 우선이다. 실제 제목·날짜·장절·안내·입력은 HTML이며 생성 이미지에는 글자·성경 구절·로고를 넣지 않는다.

### 10.2 어린이·장년의 관계

두 난도는 같은 하늘과 공통 UI 언어를 공유한다. 명확한 난도 이름, 단서의 표현, 읽기 크기와 정보 밀도로 구분한다. 숲과 종이처럼 서로 다른 세계로 나누지 않는다. 난도별 문제 정책·기능·정답 권한·한글 입력 동작을 디자인 이유로 바꾸지 않는다.

### 10.3 대표 화면과 적용 경계

대표 화면은 공개 낮/밤, 구름 사이의 이번 주 퀴즈, 지면 가까이의 지난 퀴즈, 모바일 풀이, 관리자 요약·문제 검수다. [P9-06](../work/P9-06.md)의 [독립 검토본](../design/phase-9/sky-v2/index.html)에서 먼저 구성·타이포·시간대·모션을 확인한다. 예시 문장과 연습 단어만 사용하며 실제 설교·AI 결과·공개 정답을 가져오지 않는다.

사용자는 공개 하단의 OriginKit Grass Field base 움직이는 잔디와 마우스 반응을 채택하고 먼 산을 실제 촬영 사진으로 추가하도록 요청했다. 잔디 뒤에 산 사진을 독립 층으로 두며 네 시간대와 같은 하강 진행도에 맞춘다. 기존 사진은 기본/즉시 복귀안으로 보존하고 산만 제외한 이전 잔디도 비교할 수 있다. 네 시간대·공유 멈춤·움직임 감소·오류 시 사진 복귀를 따른다. [MCP 출처와 조정 범위](../design/phase-9/sky-v2/ORIGINKIT.md). 2026-10-10 후속 명확화로 캔버스/풀 수를 일괄 절반으로 줄이는 방식을 폐기했다. 24,000개/9,000개 기준의 카메라·캔버스·큰 풀 크기를 복원하고, 먼 지형을 완만하게 낮춰 들판의 보이는 깊이를 줄인다. 한쪽으로 기울던 큰 언덕은 얕은 굴곡으로 대체한다. 기존 배치에서 깊이18 이내의 풀을 보존하고 사용자가 빈틈 보충을 요청한 뒤쪽/왼쪽 전경에 추가한다. 최종 PC19,200개·초기700px 이하7,200개이며 전체24,000개를 좁은 곳에 재배치하지 않는다. 산·기존 사진·바람/마우스·정지/감소는 유지한다. 프레임/전력 개선율은 측정하지 않았다.

시안 확인 후 기존 컴포넌트와 기능을 보존하면서 실제 앱에 연결한다. 독립 시안의 8×8 연습 격자·입력·예시 편집은 제품 엔진/한글 IME/제출/발행 검증을 대신하지 않는다. 현재 기능의 삭제나 별도 워크플로 추가를 시각 개선으로 정당화하지 않는다.

### 10.4 이미지 자산

- Air의 코드·cloud.png·유리 로고·3D 모델·Control 폰트를 복사하지 않는다. 실제 사이트의 공간과 빛을 관측하고 독자 자산·코드로 구현한다.
- 독립 하늘 원경·밤 원경·들판과 별도 풀이/관리자 참고 이미지를 보존한다. 활성 구름은 풍성한 투명5종으로 교체하며 기존3종은 복귀용으로 남긴다. 새 구름의 실제 원본은1672×941, 모바일은960px 변형이며4K 생성물이라고 보고하지 않는다. 산 사진은1600×900/3840×2160의 반응형 자산을 사용한다. 참고 화면 이미지는 실제 입력 UI로 쓰지 않는다.
- 원본 master와 생성 출처를 보존하고 WebP 등으로 최적화한다. 좁은 화면은 별도 크기와 구도를 실제 검수한다. 원경은 장식 배경이므로 무의미한 대체 텍스트를 노출하지 않는다.
- 기존 celebration/garden-v1/garden-v2, 출력 PNG/TTF와 fontkit 패치를 삭제하거나 덮어쓰지 않는다. 매주 새 하늘을 생성하는 기능/비용은 추가하지 않는다.
- 파일·용량·해시와 생성 정보는 [자산 목록](../design/phase-9/sky-v2/assets.json)에 둔다.

### 10.5 읽기와 움직임

- 모든 영역의 배경은 같은 세계이며 시간 흐름에 따른 구름 이동과 스크롤에 따른 시점 하강을 분리한다. 서로 다른 깊이의 구름과 지면이 같은 스크롤 진행도를 공유한다. 섹션마다 사진을 교체하는 것만으로 완료하지 않는다.
- 콘텐츠 최대 폭1440px는 유지하고 배경만 전체 화면에 펼친다.2560px 이상의 좌우에서도 잔디 지형이 연속되고, 같은 모양3개가 오른쪽에 겹쳐 보이지 않도록 구름 종류·위치를 나눈다. 자산의 투명 여백과 표시 크기를 지켜 잘린 경계와 과도한 확대를 피한다.
- 첫 화면은 원래 낮/밤 배경의 빽빽한 양옆 구름과 구도를 유지한다. 사진 비교/영상 실패 대안은 원본의12개 구름군 마스크 영역을 같은 위치에서 좌우로 움직인다. 네 시간대 첫 화면에는 사용자가 제공한4K 영상을 각각 연결했다. 구도 복원 뒤 움직임 개선을 요청한 후속 결정과 재생 기준은10.8을 따른다.
- 스크롤 하강 시 첫 구름 장면의 아래 경계를 자연스럽게 흐리며 독립 투명 구름5종의 깊이/위치로 이어진다. 지면도 같은 진행도에서 접근한다. 특정 3D 라이브러리 도입은 필수가 아니다.
- 장식과 입력 UI를 분리한다. 전체 UI의 시각 방향은 사용자가 선택한 Apple Liquid Glass 참고안이다(10.8). 헤더·탐색은 맑은 유리, 문제·단서·요약·폼은 읽기가 안정된 두꺼운 유리로 구현한 검토본을 사용한다. 모션이 글자나 입력칸을 흔들지 않는다.
- 대비 목표는 WCAG 2.2 AA다. 사진 위 헤더/제목에는 필요 시 밝은/어두운 받침을 사용하고 실제 장면을 확인한다. 맞음/틀림은 색만으로 전달하지 않는다.
- 명시적 멈춤, OS 움직임 감소, 숨은 탭의 애니메이션 중단, WebGL/이미지 실패 시 읽을 수 있는 단색 fallback을 지원한다. 터치 시간대 제어는 최소44px이다.
- 부드러운 스크롤은 사용자 스크롤을 가로채지 않는다. 이동/입력 컨트롤은 키보드와 터치로 사용할 수 있어야 한다. 모션 감소에서는 자동 움직임과 전환을 멈춘다.

### 10.6 새 토큰과 한글 타이포 초안

아래는 P9-06의 검토용 값이다. 사용자 시각 검수와 실제 앱의 대비·기기 검수를 거쳐 확정한다. 이전 에디터 테마 팔레트를 계승하지 않는다.

| 역할 | 낮 | 밤 |
|---|---|---|
| 기본 글자 | `#142b40` | `#f0f6ff` |
| 보조 글자 | `#365067` | `#c0d2e6` |
| 맑은 제어 표면 | `rgb(233 247 255 / .22)` | `rgb(10 27 48 / .38)` |
| 읽기 표면 | `rgb(247 251 255 / .62)` | `rgb(14 31 52 / .75)` |
| 입력 표면 | `rgb(252 254 255 / .72)` | `rgb(24 47 72 / .82)` |
| 경계 | `rgb(39 72 100 / .18)` | `rgb(192 218 245 / .20)` |
| 강조/초점 | `#095bac` | `#b8d9ff` |
| 주 버튼 / 글자 | `rgb(14 89 155 / .92)` / `#f7fbff` | `rgb(162 203 247 / .93)` / `#102c48` |
| 투명도 감소 표면 | `#eff6fc` | `#122a43` |

위 채움 값은 CSS alpha이며 실제 광학 투과율이 아니다. 반사와 굴절 층이 겹친다. 제어 채움은 새벽/노을24%, 읽기 표면은 새벽64%/노을65%다. 확장한 시간대 바는 기존 받침60%+불투명 색40%를 섞어 최종alpha 낮53.2%/새벽·노을54.4%/밤74.8%를 사용한다. 밝은 시간대의 작은 글자는#071725다. `menu-glass=off`의 밤 받침58%와 구분한다. 작은 헤더 글자는 낮 계열 `#102438`/밤 `#edf5ff`, 관리자 링크는 국소 받침을 더해 투명한 하늘 위의 대비를 보완한다.

새벽은 기존 청보라·따뜻한 수평선에 옅은 보라 유리, 노을은 기존 청록 하늘·살구빛 구름에 따뜻한 유리를 맞춘다. 새벽 보조 글자는 `#3d4c66`, 노을은 현재 `#715750`로 대비를 보정한다(아래 노을 전용 팔레트). 현재 색을 담은 영상 입력 자료의 색을 이번 UI 작업으로 바꾸지 않는다.

외곽 패널28~30px(작은 화면26px), 제어는 캡슐24~36px, 입력은14px 모서리를 쓴다. 외곽 유리 안의 입력·미리보기는 안정된 채움으로 구분하고 유리 필터를 중첩하지 않는다. 기존 콘텐츠 최대1440px와 대표 화면의 정보 순서·한글 제목2행·자연스러운 줄바꿈을 유지한다. 기본 형태·반응형은 [liquid-glass.css](../design/phase-9/sky-v2/liquid-glass.css), 현재 재질/토큰 보정은 [prismatic-glass.css](../design/phase-9/sky-v2/prismatic-glass.css), 상태/모션은 [liquid-glass.js](../design/phase-9/sky-v2/liquid-glass.js)를 따른다.

### 10.7 Air 계승 하늘 방향 — 2026-10-08

[Air](https://air.inc/)·[Refero Air](https://styles.refero.design/style/d3289fe7-a85e-42d8-96b7-eb7faa62a104)의 원리를 참고하며 동일 복제나 모든 토큰의 기계적 적용을 목표로 하지 않는다. 사용자 지시인 낮/밤·네 시간대·같은 하늘 속 하강과 한글 읽기를 우선한다.

시간대는 새벽·낮·노을·밤을 같은 구성에서 선택하고 하늘·구름·지면·전경/표면을 함께 바꾼다. 검토본은 기본 낮이며 URL로 시간대를 유지한다. 실제 앱의 기존 `system | light | dark` 저장 호환과 자동 초기 시간 정책은 앱 연결 시 명시적으로 정리한다. 원본의 시계/sessionStorage를 새 제품 결정으로 무단 이식하지 않는다.

진행은 원본 관측 → 별도 대표 시안/움직임 → 사용자 시각 검수·보정 → 전체 앱 연결/관련 기능 검사 → GitHub main 기반 Preview → 별도 요청 Production이다. P9-04와 이전 Phase9 완료를 철회하지 않는다. 실제 관측은 [P9-05](../work/P9-05.md), 새 시안·검증·남은 작업은 [P9-06](../work/P9-06.md)을 따른다.

#### 참조와 한글 서체 적용 기준

Refero는 공개 DESIGN.md/CSS Variables 수동 참조이며 Refero MCP·Tailwind 출력·유료 폰트 적용이 아니다. 독립 검토본은 native CSS/WebGL이다. [참조/폴백 근거](../work/P9-05.md#참조-경로적용-범위한글-글꼴-확인--2026-10-08)를 유지한다.

- 메인과 하늘 공통 조작부는 기존 자체 호스팅 **Noto Sans KR 400**과 `font-synthesis:none`을 유지한다. 메인을 제외한 콘텐츠는 아래 [P9-17](#내부-화면의-정보-계층--p9-17)의 명조 제목·본문 강조 기준을 따른다. 실제 파일과 `unicode-range`를 재사용한다.
- 폴백은 `Apple SD Gothic Neo`, `Malgun Gothic`, `sans-serif`이다. 첫 두 개는 해당 OS에 있을 때만 적용한다. 없는 파일을 내려받았다고 보고하지 않는다. OS별 실제 외형 검수는 별도로 남긴다.
- Control/Inter 등 한글 미지원 폰트 이름을 추가하지 않는다. Pretendard/Nanum Pen Script는 이전 비교 후보이며 이번에 설치·채택하지 않는다. 기존 한글 글꼴을 강제로 교체할 이유가 없으면 유지한다.
- Noto Serif KR 600은 P9-17 내부 화면의 제목에 사용한다. 메인의 하늘 제목과 출력 TTF/fontkit은 기존 구성을 유지한다. 영어 대문자의 무거운 압축 형태나 좁은 행간을 한글에 억지로 적용하지 않는다.

### 10.8 영상 하늘과 전체 UI의 유리 재질 — 조사 후 구현

2026-10-08 조사와 영상 입력 자료 전달 후 사용자는 **3번 Apple Liquid Glass를 선택하고 영상을 직접 준비하는 동안 UI 구현을 진행**하도록 요청했다. [조사](../work/p9-06/video-glass-research.md)를 이어 같은 P9-06의 공개·풀이·관리자 대표 검토본에 적용한다. 실제 앱 연결은10.3의 시각 검토/보정 순서를 따른다.

- 기존 정지 배경은 낮/밤 원본2장과 새벽/노을 필터·광원으로 구성된다. 사용자는 **Google AI Studio/Gemini API·4K 출력으로 직접 제작**하는 경로를 선택했으며,2026-10-09 제공한 새벽·낮·노을·밤 영상4편을 대표 검토본에 연결했다. 원래 이미지 방식은 `video=off` 비교와 실패 대안으로 유지한다. [영상 입력 자료](../design/phase-9/video-kit/README.md)에 현재 색을 담은 PNG4장·각 완성 프롬프트·시각적 유리 예제를 준비했다. 입력 PNG는1672×941이며4K는 영상 출력이다. 모델/최종 편수와 에이전트의 유료 실행 예산은 확정하지 않았다.
- 영상은 원래 빽빽한 구름과 가운데 여백을 유지한다. 현재 새벽 프롬프트는 사용자가 선택한12:30 결과의 원문 `billowing-v2`를 보존한다. 낮·노을·밤은 병렬 보완 결과 `billowing-v3`으로 구름 자체의 부풀음/국소 소멸·위치별 시차를 주 동작으로 강화했다. 움직임5/10·더 느린 카메라·전체 밀도/중앙 여백·시간대 색/빛/천체는 유지하고 개별 구름의 정확한 첫/끝 윤곽과 닫힌 카메라 복귀는 강제하지 않는다. v3은 시작 PNG만 입력하는 안내를 우선하며 완벽한 루프를 보장하지 않는다. [파생본 보완 근거](../design/phase-9/video-kit/PROMPT-REVISION.md). 프롬프트에 길이를 고정하지 않으며 현재 네 시간대 영상은 모두3840×2160·24fps·10초다. 현재 색을 담은 영상을 적용할 때 기존 시간대 필터를 중복 적용하지 않도록 한다. 기존 원본·정지/움직임 감소·하강 장면·산/잔디·콘텐츠1440px를 유지한다. 기존 새벽과 같은 방식으로 네 영상 모두 끝0.9초 동안 각자의 첫 장면 정지 이미지를 겹쳐 반복 경계를 완화한다. 이는 화면 합성이며 원본을 완벽한 루프 파일로 편집했다는 뜻은 아니다.
- 대표 공개/풀이/관리자 UI에 공통 유리 재질을 적용했다. 헤더/시간대/탐색/첫 버튼은 맑은 유리, 퀴즈/편집은 더 조밀한 읽기 표면을 쓴다. 모서리 반사·배경 흐림·선택 표시 이동을 같은 규칙으로 맞추고 입력 글자에는 굴절을 적용하지 않는다. 현재 토큰은10.6을 따른다.
- AI가 읽는 정본은 이 문서를 유지한다. 참고 DESIGN.md의 팔레트/영문 폰트를 그대로 적용하지 않고 현재 한글 폰트, 네 시간대, Spacing & Shape, 상태, 대비, 모션, 성능을 함께 문서화한다. 새 production 의존성은 필수가 아니며 이번에 추가하지 않는다.

#### 네 시간대 영상 재생 기준

2026-10-09 사용자가 제공한 낮(`daytime.mp4`)·노을(`sunset.mp4`)·밤(`night.mp4`)을 기존12:30 새벽 영상과 함께 독립 검토본에 연결했다. 새벽 기본은 `video=billowing`이며 이전11:50 버전은 `video=dynamic`, 최초는 `video=calm`으로 비교한다. 이 선택은 새벽 버전만 바꾸며 나머지 세 시간대는 각자의 영상을 사용한다. 이후 제공한 `Generated video 2.mp4`를 밤 기본v2로 교체했고 `night-video=v1`은 직전 밤 비교다. 기본/`night-video=v2`는 `assets/video/night-v2/`를 쓰며 URL/검토 화면 이동에 선택을 보존한다. 새 영상의 생성 프롬프트/모델 버전은 파일명만으로 확정하지 않는다.

- 원본은 `.wrangler/design-references/p9-06-video/masters/sky-{day,dusk,night}-4k-original.mp4`, 새 밤은 같은 위치의 `sky-night-v2-4k-original.mp4`에 파일 전체 SHA-256을 대조해 복사하고 Downloads도 보존한다. 최초 화면용4K는 영상 스트림을 복사해 소리만 제거했다. 2026-10-10 사용자가 승인한 현재 밤v2의 기본4K만 H.264 2pass/20Mbps 목표로 재압축해24,836,709bytes(23.69MiB)로 연결했다.3840×2160·24fps·10초·색 메타데이터를 유지한 손실 압축이며, 기존 무음4K29,403,913bytes와 master를 보존한다. `night-video=v2-original`은 재압축 전4K 비교, `v1`은 이전 밤이다. 재생 정보를 파일 앞에 둔다. 작은 화면용1080p와 첫 장면 정지 이미지2종을 별도로 만든다. 원본의 색을 재보정하지 않는다. [시간대별 파일·해시·명령](../design/phase-9/sky-v2/assets/video/README.md).
- 공개 상단 배경이 보이고 움직임이 켜진 때만 현재 시간대 MP4 하나를 요청한다. 최초700px 이하에서는1080p, 넓은 화면에서는4K를 사용한다. 같은 영상에서 넓어질 때 한 번 올리고 좁아질 때 다시 받지 않는다. 풀이/관리자·`video=off`에는 MP4를 요청하지 않는다.
- 시간대 전환은 하나의 video 요소를 재사용하며 이전 재생/포스터 처리의 늦은 완료를 무효화한다. 이전 파일을 멈추고 새 시간대의 첫 장면/영상으로 전환한다. 다른 세 영상을 미리 요청하지 않는다.
- 공통 멈춤, OS 움직임 감소, 상단이 사라진 스크롤, 숨은 탭에서 재생을 정지한다. 최초 움직임 감소 또는 멈춘 상태에서 시간대를 바꾸면 영상 파일 없이 해당 첫 장면만 보여 준다. 자동 재생이 거부되면 **하늘 영상 재생**으로 사용자 클릭을 받는다. 영상 실패는 첫 장면, 정지 이미지도 실패하면 기존 사진으로 표시한다. [MDN 재생 정책](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay).
- 영상에는 시간대 색과 햇빛/달빛이 포함되어 기존 필터/광원을 중복 적용하지 않는다. 하강 변환과 가장자리 마스크, 아래쪽 구름/산/잔디·콘텐츠1440px를 유지한다. `video=off`는 원래 사진/구름군 비교 경로이며 검토 화면 이동에도 유지한다.
- 실제 앱 연결과 사용자 시각 검수는 같은P9-06에 남아 있다. 현재4K 재생 확인은 실제 기기/모든 프레임이나 완벽한 루프 품질 보증이 아니다. [이번 검사와 한계](../work/P9-06.md#네-시간대-영상과-공개-카드-유리-보정--2026-10-09).

#### Apple 참고 유리 검토본의 재현 기준

[Apple의 공식 소개](https://developer.apple.com/videos/play/wwdc2025/219/)에서 제어와 콘텐츠의 구분, 빛·굴절·상호작용에 반응하는 재질 원리를 참고한다. 웹용 native HTML/CSS/JavaScript로 독자 구현하며 Apple SDK·시스템 Liquid Glass와 동일한 렌더러라고 표현하지 않는다. Apple 폰트/로고나 외부 유리 컴포넌트는 추가하지 않는다.

- 제어의 굴절은 배경 전용 가상 요소에만 둔다. 현재 기본은 맑은 유리+프리즘 보완안이다. Chromium의 헤더·시간대·첫 버튼·검토 바의 네 고정 표면에 크기별 정적 굴절 지도를 만들고 RGB 변위18/14/10과 screen 합성으로 가장자리 색 분산을 더한다. 지도 중앙은 중립이며 글자/입력은 이 필터 밖에 둔다. URL 구문 지원만 믿거나 `window.chrome` 존재만 요구하지 않고 Chromium 식별과 실제 렌더 검증을 함께 사용한다. 다른 엔진은6px CSS 흐림과 유색 반사 경계로 표시한다. 읽기 표면은14px 흐림이며 폼/격자 채움은 기존 가독성 값을 유지한다. [backdrop-filter의 공식 동작](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter).
- 프리즘은 얇은 경계와 방향성 있는 반사에 집중한다. 공개의 두 읽기 카드와 풀이 바깥 박스는 유색 경계와 테두리 전용 포인터 반사를 쓰며, 관리자 좌측/중앙 패널도 가까운 가장자리의 페더 반사를 쓴다. 조작부는 배경 굴절·청색/보라/샴페인빛 반사를 쓴다. 전체 화면/영상의 색을 바꾸거나 글자를 무지개색으로 칠하지 않는다. 매 프레임 굴절 지도를 다시 만들지 않고 크기가 달라질 때만 계산한다.
- 일반 선택 표시는 실제 선택 요소의 위치/크기에 맞춰430ms 수평/수직 이동한다. 아래 검토 바와 확장한 헤더/시간대/풀이 난도 메뉴는 다음의 탄성을 적용한다. 마우스 빛 반응은 fine pointer의 이동 때만 갱신한다. 공통 멈춤과 OS 움직임 감소에서 제어의 이동/반사를 멈추고 숨은 탭은 반응을 정리한다.
- 아래 **디자인 검토** 바의 기본/`dock-motion=elastic`은 유리 표시만 탄성 이동한다. 마우스가 올려진 메뉴 중심으로 이동하면서 포인터 방향 최대6px를 따라가고, 속도에 따라 가로가 늘었다가 복원된다. 위치/폭 spring380·감쇠27, 늘어남480·감쇠30, 부풀기360·감쇠25를 사용한다. 늘어남 목표 최대32%, hover 높이8%이며 미세한 탄성 초과가 가능하다. 실제 렌즈는 메뉴 구간 안에 제한한다. 글자/클릭 영역·`aria-current=page`는 변형하거나 hover로 바꾸지 않는다. 다른 메뉴 위에서는 작은 점이 현재 화면을 가리키며 클릭/Enter로만 이동한다. 렌즈가 떠난 현재 메뉴는 본문색으로 바꾸고, 밝은 시간대의 이 바 글자는 짙은 남색#071725를 쓴다. 이 바는 기존 맑은 유리60%+불투명 받침40%를 혼합한다(최종alpha 낮53.2%/새벽·노을54.4%/밤62.8%). 밝은 구름/어두운 잔디 위에서도 읽기를 유지하기 위한 보정이며 확장한 제어의 별도 받침 보정은 아래를 따른다. 이탈하면 키보드 초점 또는 현재 선택으로 복귀한다.
- 사용자가 채택한 아래 메뉴의 탄성은 유지하고 기본/`dock-material=convex`에 **볼록한 선택 유리**를 쓴다. 직전 밤의78% 파란 채움 대신 중심 tint를 낮12%/밤8%로 낮추고, 위쪽 흰 반사·아래쪽 빛과 음영·넓고 부드러운 프리즘 가장자리를 겹친다. 선택 글자는 이 바의 본문색을 사용하며 읽기 받침과 클릭 영역은 유지한다. 이동 속도에 따라 반사 중심만22~78% 범위에서 기울고 정착하면50%로 돌아온다. 기존 spring 계수/늘어남/부풀기 값은 바꾸지 않는다.
- 움직이는 캡슐의 굴절은 가로128×84/세로84×128 정규화 지도를 만들고 크기에 맞춰 함께 변형한다. 메뉴 배치의 축이 바뀔 때만 지도도 전환한다. `objectBoundingBox` 단위의 RGB 변위.28/.26/.24와 안쪽 샘플링으로 넓은 어깨 부분의 배경이 확대되어 보이게 한다. 지도/필터를 프레임마다 다시 생성하지 않으며 글자는 필터 밖이다. Firefox 등은.6px CSS 흐림과 같은 반사/음영으로 표시한다. `dock-material=flat`은 이전 재질+같은 탄성, `dock-motion=off`/`glass=soft/off`는 기존 경로다. 투명도 감소/강제 색상에서는 장식을 숨기고 선택을 구분한다. [SVG 좌표 단위](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/primitiveUnits) · [배경 변위](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/feDisplacementMap) · [비교/검사](../work/P9-06.md#볼록한-유리와-새-밤-영상--2026-10-09).
- 탄성 모션은 정착할 때까지의 `requestAnimationFrame`만 사용하며 급반전에도 현재 위치/속도를 이어받는다. resize/글꼴 로딩 때 위치를 다시 측정한다. 터치·공통 멈춤·움직임/투명도 감소·강제 색상에서는 현재 선택에 고정하고 숨은 문서/창 초점 이탈/pagehide에서 프레임을 취소한다. `dock-motion=off`는 직전 고정 선택 표시이며 URL/검토 화면 이동에 남긴다. `glass=soft/off`에서는 새 모션을 적용하지 않는다. 풀이 난도·관리자 검수 탭/운영 메뉴는 아래의 메뉴 확장을 따른다. [비교 링크](../design/phase-9/sky-v2/README.md#아래-검토-메뉴의-탄성-모션) · [검사](../work/P9-06.md#아래-검토-메뉴의-탄성-모션--2026-10-09).
- **헤더·시간대 메뉴 확장**은 기본/`menu-glass=on`이다. 채택한 하단 spring/빛/곡면 값을 공통으로 재사용한다. 헤더 두 링크는 실제 선택을 새로 만들지 않고 hover/키보드 초점에만 유리를 표시하며 이탈하면 숨긴다. 시간대는 실제 버튼 위치를 측정해 PC의 세로와700px 이하 가로 이동을 전환한다. hover는 미리보기이며 `aria-pressed`/URL/영상은 클릭/Enter 때만 바뀐다. 다른 목적지 위에는 실제 시간대 버튼의 오른쪽 위에 작은 점을 남겨 모바일 글자와 겹치지 않게 하고 이탈하면 복귀한다. 선택 변경은 해당 메뉴의 목표만 갱신해 다른 메뉴의 모션을 초기화하지 않는다.
- 헤더 **관리자** 링크는 같은 맑은 중심·넓은 굴절·위아래 반사의 정적 캡슐로 표현한다. 반사는 포인터를 따르고 두 장식 층은 글자 아래에 둔다. 중첩 포인터는 관리자만 반응해 헤더의 광원이 겹치지 않으며 실제 링크/크기/키보드 초점은 유지한다. `menu-glass=off`는 확장 전 헤더/시간대/관리자 링크·풀이 난도·관리자 검수 탭/운영 메뉴 모습이며 하단은 별도 `dock-motion`/`dock-material` 선택을 유지한다. URL/세 화면 이동·공통 멈춤/감소·CSS 대안을 공유하고 새 의존성은 추가하지 않는다. [비교 안내](../design/phase-9/sky-v2/README.md#헤더시간대-메뉴와-관리자-버튼) · [검사와 한계](../work/P9-06.md#헤더시간대와-관리자-유리-확장--2026-10-09).
- 헤더/검토 바의 반사광: 헤더는 **위·아래 테두리만 동시에 반응**한다. 포인터의 x좌표를 두 경계에 투영하고 y위치와 무관하게 같은 반사를 유지한다. 기존38px 원형 테두리 광원을 y=0/100%에 각각 두고 기존1.5px 경계 마스크로 중앙을 제외한다. 헤더 바탕 중앙의 추가 광원은 없으며 기존 테두리 반응을 유지한다. 메뉴/관리자 캡슐의 별도 반사와 구분한다. 아래 바는 원 반경30px/테두리38px의 `spot`, 표면 alpha16%/밤8% 그대로다. `glint=both`가 기본, `header`/`dock`은 한쪽만 현재 효과, `original`은 모양 실험 전 반사다. `header-glint` 생략/`edge`가 현재 테두리이고 `spot`/`straight`/`flare`는 이전 비교다. 선택은 URL/화면 이동에 유지하며 포인터 이탈/감소/정지 상태에는 추가 광원을 지운다. [현재 구현/검사](../work/P9-06.md#헤더의-위아래-테두리만-반응--2026-10-09) · [이전 원형 선택](../work/P9-06.md#헤더와-아래-바의-원형-광원-통일--2026-10-09).
- 공개 아래의 ‘이번 주 말씀’ 카드와 ‘지난 퀴즈’ 목록은 헤더와 같은 **맑은 가장자리/안쪽 읽기 표면**으로 나눈다. 바깥 채움은 헤더의 낮22%/새벽·노을24%/밤38%, Chromium 굴절은 헤더와 같은16px 지도·RGB18/14/10·1.5px 사전 흐림·saturate1.15를 사용한다. 색 경계도 헤더처럼1.5px다. 내부8px 여백의 장식 읽기 층은14px 흐림·낮/새벽30%·노을32%·밤36% 채움과10px 부드러운 마스크를 사용한다. 수치는 층별 alpha이며 실제 광학 투과율이 아니다. 글자/배치를 바꾸지 않고 포인터150px 반경에 가까운 경계만 반사한다. 포인터의 흰빛은 별도7px 링 장식에 alpha52%→18%(45% 지점)→0을 주고, 마스크를 적용한 자식 바깥에서4px blur로 흐려 넓고 연한 페더를 만든다. 기존1.5px 정적 프리즘 경계는 유지한다. 중앙 추가 광원은 없으며 기존 화살표 반응도 유지한다. Firefox는 바깥6px/안쪽14px CSS 흐림 대안이고, 선명하게/투명도 감소/강제 색상은 읽기 층을 숨기고 기존 불투명 표면을 쓴다. `glass=soft/off`를 유지한다. [현재 구현/검사](../work/P9-06.md#공개-카드의-부드러운-테두리-반사--2026-10-09).
- **풀이 바깥 박스**(`.puzzle-workspace`)는 공개 메인 카드와 동일한 `reading-header` 재질을 사용한다. 위 공개 카드의16px 외향 굴절·1.5px 사전 흐림/경계·맑은 채움·내부8px 여백의14px 읽기 층과 시간대별 색/페더를 그대로 공유한다. 기존22px 안쪽 굴절/전체62~75% 읽기 채움은 이 검토본에서 대체했다. 글자/격자/입력칸·난도 토글은 유지하며 관리자 패널의 현재 굴절은 변경하지 않는다. [검사](../work/P9-06.md#풀이-박스의-메인형-굴절-통일--2026-10-10).
- **관리자 좌측/중앙 패널**(`.admin-sidebar`, `.admin-main`)에도 같은 페더 반사를 공유한다. 기존 읽기 채움/흐림은 유지하며 새 SVG 굴절이나 읽기 층을 추가하지 않는다. 정적 프리즘 경계와 포인터 가까운 연한 반사를 쓰고 본문 중앙은 움직이지 않는다. 장식은 aria-hidden/pointer-events:none이며 편집과 메뉴 탄성·이탈/정지/감소·soft/off 대안을 유지한다. [검사](../work/P9-06.md#풀이관리자-패널의-페더-반사-확장--2026-10-09).
- **어린이·장년 난도 토글**은 기본/`menu-glass=on`에서 하단 검토 메뉴와 같은 탄성·볼록한 선택 렌즈를 재사용한다. hover/초점은 미리보기이고 실제 난도/`aria-current`/URL은 클릭/Enter로만 바뀐다. 이탈하면 현재 선택으로 복귀하며 미리보기 중 기존 선택에는 작은 점을 남긴다. 낮53.2%/새벽·노을54.4% 받침과 짙은 남색 글자, 밤74.8% 받침과 흰 글자를 쓴다. 밤 토글만 윗곡면 반사 alpha36%/중앙 tint4%로 낮춰 반사 위 글자 대비를 유지한다. 기존 spring/클릭 영역·정지/감소/터치 대안을 공유하며 `menu-glass=off`는 이전 토글이다. [구현/검사](../work/P9-06.md#풀이-박스와-난도-토글-유리--2026-10-09).
- **관리자 검수 탭/운영 메뉴**도 기본/`menu-glass=on`에서 같은 탄성·볼록한 렌즈를 사용한다. 검수 탭은 가로, 운영 메뉴는 PC 세로/700px 이하 기존3열 배치를 유지한다. 다중 행에서는 가장 가까운 버튼을 두 좌표로 찾고 위치/크기를 양축 spring으로 이동한다. 기존 탄성 계수와 글자/클릭 영역은 그대로다. hover/초점은 유리만 미리 보여 주며 검수 내용·초안·확인 체크는 바꾸지 않는다. 클릭/Enter로 기존 탭 전환/운영 메뉴 안내를 실행하며 운영 현재 위치는 `aria-current=page`로 표시한다. 이탈하면 현재 선택으로 복귀하고 미리보기 중에는 실제 선택의 작은 점을 남긴다. 읽기 패널 위 기존 받침을 재사용한다. 새벽/낮/노을의 두 관리자 렌즈는 중첩 SVG 배경 변위의 회색화를 피하기 위해 CSS blur(.6px)/saturate(1.18)와 기존 볼록한 반사 경계를 쓴다. 이 세 시간대의 두 메뉴에서는 실제 RGB 배경 변위를 적용하지 않는다. 밤은 기존 SVG 경로와 윗반사36%/tint4%를 유지한다. 편집 패널 자체의 재질과6단계 표시는 변경하지 않는다. `menu-glass=off`/`glass=soft/off`로 이전 제어를 비교한다. [구현/검사](../work/P9-06.md#관리자-검수-탭과-운영-메뉴-유리--2026-10-09).
- 어린이/장년 링크의40px 원형 화살표는 같은 계열의 유리와 `spot` 반사를 쓴다. 링크 안의 장식 요소로 남기며 별도 버튼/초점 이동을 만들지 않는다. 중첩된 카드와 화살표 중 포인터에 가장 가까운 표면만 반응하고 이탈/감소/멈춤에서 정리한다. 밤 첫 ‘이번 주 퀴즈’ 버튼의 hover는 불투명한 옛 하늘색 대신 현재 유리 채움을 유지한다. 새 영상 위의 대비를 위해 낮 구석 안내는 검정, 밤 재생 제어는64% 받침을 쓴다(확장한 시간대 바는74.8%).
- **선명하게** 버튼은 불투명 받침으로 전환하며 `clarity=high`를 같은 검토본의 URL/화면 이동에 유지한다. 지원 브라우저의 OS 투명도 감소도 적용하며 굴절/프리즘 장식을 숨기고 포인터 반사를 멈춘다. [OS 설정 지원 범위](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-transparency). 강제 색상 모드에서는 선택 윤곽을 남긴다.
- `glass=soft`는 직전의 더 뿌연 Apple 참고 유리, `glass=off`는 유리 이전 모습이다. 비교 선택은 검토본의 화면 이동에도 유지한다. 기본은 새 프리즘 재질이며 두 비교 경로에서 새 CSS 층을 비활성화한다. 원래 CSS·배경·잔디·산·폰트 파일을 되돌리거나 삭제하지 않는다. 실제 앱의 설정 저장 정책을 추가한 것은 아니다.
- 대비는 네 시간대의 실제 렌더 배경에서 확인한다. 배경 위의 작은 풀이 안내는 본문색을 쓰고, 밤 첫 설명 뒤에는 부드러운 국소 음영을 둔다. 자동 표본 검사는 전체 WCAG/실기기 검수를 대체하지 않는다. 현재 재질/선택 영상으로 다시 확인한 검사와 기기 한계는 [P9-06](../work/P9-06.md#맑은-유리와-프리즘-보완--2026-10-09)에 기록한다.

#### 유리 UI 재사용 컴포넌트

P9-06 독립 검토본의 토글/탭 메뉴, 본문 박스, 관리자 읽기 패널, 입체 버튼은 `sky-v2/components/`의 공통 native HTML/CSS/JS로 관리한다. 기존 재질·탄성·테두리 반사·읽기 채움과 접근성 대안은 위 기준을 유지한다. 화면은 역할·배치와 실제 선택/입력 동작을 맡고 공통 모듈은 장식·움직임·연결/해제만 맡는다. 같은 root 재연결 시 중복 효과를 정리하고 입력/선택을 보존한다. 사용 API·예제의 정본은 [컴포넌트 사용법](../design/phase-9/sky-v2/components/README.md)이다. 2026-10-10 사용자 지시로 실제 React 앱은 아래와 같이 같은 모듈을 사용한다. 독립 예제와 실제 앱/운영 배포는 구분한다.
### 실제 React 페이지 적용

2026-10-10 사용자 요청에 따라 새 하늘·유리 기준을 실제 앱에 적용한다. [React 사용법](../../src/components/README.md) · [구현과 검사](../work/p9-06/app-integration.md).

- `/`는 하늘 첫 화면 → 실제 발행된 이번 주 제목/날짜/요약 일부와 두 난도 선택 → 지난 퀴즈다. 요약은 기존 AI 고지를 표시하고 전체 내용은 풀이에서 제공한다. 내용이 없거나 API가 실패하면 기존 빈 상태/오류를 보여 주며 예시 내용을 공개 데이터로 대체하지 않는다.
- `/quiz/:slug?level=child|adult`와 기존 `/?level=…`는 같은 풀이/임시 답안 키를 사용한다. 한글 조합, 전체 격자, 난도 전환, 제출/결과 복원, 공개 정답 분리, 출력과 마감/연습 정책을 유지한다. 두 난도는 같은 하늘/유리 재질을 쓰며 밤에도 입력 격자는 밝다.
- 지난 퀴즈의 검색·더 보기·뒤로 가기 상태와 관리자 6단계·초안 저장·검수/발행 확인을 유지한다. 관리자는 안정된 읽기 패널, 운영 메뉴/검수 대상에는 공통 선택 유리를 쓴다. 모바일 운영 메뉴는 접고 펼치며 본문과 겹치지 않는다.
- `GlassPanel`은 reading/standard, `GlassMenu`는 버튼/링크/탭, `GlassLink`/`GlassArrow`는 입체 링크/화살표를 담당한다. React는 실제 DOM·상태·키보드 동작을 소유하고 native 모듈은 해당 root의 장식만 연결·해제한다. `aria-pressed`, `aria-current`, `aria-selected`를 관찰하며 hover는 선택을 변경하지 않는다.
- `SkyEnvironment`는 네 시간대, 움직임 멈춤, 선명하게, 잔디 표시를 연결한다. 시간 선택은 아래 P9-07의 서울 자동/탭별 수동 정책을 따른다. 저장 거부 시 현재 화면에서 계속 쓸 수 있다. OS 움직임/투명도 감소와 강제 색상을 존중한다. 모바일 풀이/관리자의 배경 설정은 본문 뒤에 놓아 키보드/입력을 가리지 않는다.
- 기존 네 영상·5종 구름·산·OriginKit 잔디의 엔진/재생 정책을 공유한다. 첫 화면에서만 보이는 영상 재생, 아래/다른 페이지/멈춤/감소 모드의 정지, 미디어 실패 시 사진 대안을 유지한다. 잔디 초기 수량은 PC19,200/모바일7,200이며 기존 원근 보정과 산 연결을 유지한다.
- 빌드는 선택된 네 시간대의 PC4K/모바일1080p와 해당 포스터만 가져온다. 밤 PC는23.69MiB 압축본이다. 원본/이전 비교 영상·폰트·출력 자산은 저장소에서 보존하며 신규 서비스/패키지는 추가하지 않는다. 개발 서버의 합성 데이터 검증과 운영 배포 완료를 혼동하지 않는다.

### 메인 첫 화면의 Mercury 반사 — P9-23

2026-10-15 사용자 확정. Mercury Veins의 흐르는 반사와 Veil Rays의 위에서 퍼지는 빛을 공개 미리보기로 관찰한 **독립 WebGL 효과**를 `/`의 첫 소개 구역에만 넣는다. 유료 원본 코드나 자산을 사용한 것이 아니다. 기존 영상 위·제목/설명/버튼 아래에 투명한 효과층을 두며, 아래 주간/지난 퀴즈·`/?level=…` 풀이·관리자·기타 페이지에는 적용하지 않는다. 영상·문구·배치·유리·기존 이동을 보존한다.

- `HeroEffects`·`hero-effects.ts/css`가 첫 구역 안에서만 연결된다. 세 효과는 한 캔버스와 같은 정지/복구 처리를 공유한다. 위치는 절대 배치, 포인터 이벤트는 통과시키고 접근성 트리에서는 장식으로 제외한다. 반사는 제목 주변의 강도를 낮추고 사방, 특히 아래쪽 경계에서 투명하게 사라진다. 빛줄기는 폭이 있는 광원에서 유기적인 여러 가닥으로 퍼지며, 밤에는 기존 달 쪽에서 왼쪽 아래로 부드럽게 번진다. 마우스에는 느린 변형을 주며 터치 스크롤은 건드리지 않는다.
- 새벽은 연한 은보라, 낮은 은청색, 노을은 따뜻한 금빛, 밤은 강도를 줄인 은청색 반사다. 새 검정 바탕을 덮지 않으며 기존 하늘이 비친다. 색과 글꼴의 제품 기준은 계속 기존 네 시간대 토큰을 따른다.
- 한 프레임 버퍼는 최대640×480px·최대DPR1, 그리기는 최대30fps다. 넓고 부드러운 반사는 고밀도 버퍼를 쓰지 않으며 노이즈 계산도 삼각함수 없이 처리한다. 영상·유리 조작과 함께 실행할 때 부담을 줄이도록 낮은 해상도를 화면에 부드럽게 확대한다. 텍스처/영상 복사·새 의존성·외부 호출이 없다. 실제 기기 성능의 보장값은 아니다.
- 기존 움직임 멈춤·OS 움직임 감소에서는 정지된 반사를 유지한다. 선명하게/투명도 감소·강제 색상에서는 효과를 숨기고 그리기를 멈춘다. 첫 구역의 보이는 면적이1% 이하거나 탭이 숨겨지면 정지한다. 페이지 이동 시 이벤트/관찰자/프레임·GPU 자원을 정리한다. GPU 미지원/컨텍스트 손실에서는 기존 배경을 유지하며 복구되면 다시 그린다.

직접 참고한 API 기준은 [MDN WebGL](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices), [컨텍스트 손실](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/webglcontextlost_event), [영역 관찰](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API)이며 React19.2.8의 외부 시스템 연결/정리는 Context7으로 확인했다. #### 효과 선택기와 Veil Rays

- 재생 버튼 바로 다음에 별 모양의 아이콘 버튼을 둔다. 보이는 ‘효과’ 문구는 없애고 접근성 이름 ‘배경 효과’를 유지한다. PC에서는50px 원형에서60×212px 세로 캡슐로 펼친다. 모바일의44px 버튼 자리는 유지하고 기존 바 바로 위에176×44px 선택 캡슐을 펼쳐 다른 버튼이 밀리지 않게 한다. 별도 ‘조절’ 버튼 없이 반사·빛줄기·비단결 세 항목을 둔다. 펼침은360ms, 항목 등장은180ms/80ms 지연이다. 시간대 선택기와 같은 `GlassMenu`·convex lens·spring 모션을 직접 재사용하며 글자와 입력 영역은 늘이거나 흔들지 않는다. 320px에서도44px 선택 영역을 보존한다.
- 마우스 진입/이동으로 열고 이탈180ms 뒤 닫는다. Enter·Space·터치·아래 화살표로도 열 수 있다. Tab으로 효과 버튼과 열린 수치 패널을 조작하고 Escape는 먼저 수치 패널을 닫아 해당 효과 버튼으로, 다음에 캡슐을 닫아 별 버튼으로 초점을 돌린다. 외부 클릭/초점 이탈은 닫는다. 수치 패널은 조작 중 포인터 이탈로 닫지 않으며, 포털로 표시해 낮은 PC의 스크롤 영역·모바일 유리에 잘리지 않는다. 숨긴 항목은 inert로 입력 순서에서 제외한다.
- 세 효과의 켜짐은 독립이며 체크·굵은 이름·pressed 상태로 표시한다. 기본은 반사 켬·나머지 끔이다. 하나만, 여러 개, 모두 끔을 허용한다. 각 효과를 누르면 켜지고 그 버튼 옆에 제어판을 함께 연다. 같은 열린 버튼을 다시 누르면 해당 효과만 끈다. 다른 효과를 누르면 제어판만 교체하고 앞선 효과의 켜짐과 수치를 유지한다. 닫기/Escape/외부 클릭은 제어판만 닫으며, 이후 다시 누르면 켜짐을 유지하고 제어판을 연다. Escape와 닫기는 해당 효과 버튼으로 초점을 돌린다. 공통 유리 받침의 호버/초점은 선택값을 바꾸지 않는다.
- 인접 제어판에서 **광원 너비0~100%·밝기10~100%·퍼짐0~100%·흐름 속도0~100%**를 native range로 조절한다. 모바일에서는 하단 시간대 바 위에 두고 PC에서는 빛줄기 버튼 옆에 화면 안으로 맞춘다. 기본값65/55/60/50은 표시 숫자와 셰이더에 즉시 반영한다. 키보드 방향키·Home/End, 마우스 드래그, 터치를 지원하고 ‘기본값으로’로 복원한다. 값은 기존 브라우저 저장에 보존하며 유효하지 않은 값은 기본값 또는 허용 범위로 정리한다. 저장 거부 시 현재 화면에서 계속 동작하고 안내한다.
- 낮·새벽·노을은 폭이 있는 상단 광원, 밤은 기존 하늘 자산의 초승달 위치를 기준으로 한다. 밤 원점은 `object-fit: cover`·PC/모바일 크롭을 반영해 화면 좌표로 옮긴다. 모바일에서 달이 잘려도 임의로 중앙에 옮기지 않고 화면 밖 달 쪽에서 이어지는 은빛을 사용한다. 새 발광 원판을 그리지 않으며 달 아래에서 서서히 밝아지도록 하고 낮보다 강도를 낮춘다. 입력값은 공유하되 시간대별 색과 광원 방향은 자동으로 맞춘다.
- 선택과 수치는 새로고침/다음 방문에도 유지한다. 모두 끄면 캔버스와 그리기를 숨긴다. 기존 멈춤·선명하게·OS 움직임/투명도 감소 정책이 우선한다. 멈춤 중 수치 변경은 정지 프레임만 갱신한다. 메인 첫 구역·한 캔버스·최대640×480/DPR1/30fps 기준을 유지한다.
- 반사 제어판은 **밝기10~100%·물결 크기0~100%·흐름 속도0~100%**다. 기본50/50/50은 직전 승인 효과와 같은 밝기·크기·속도다. 크기가 높을수록 물결이 커지고 속도0은 물결 흐름을 멈춘다. 속도는 매 프레임 누적해 조절 순간 무늬가 다른 시간으로 튀지 않게 한다. 기존 전체 멈춤·포인터·빛줄기 정책과 별개로 저장되며, `EffectControls` 하나가 세 제어판의 위치·초점·native range·기본값 복원·모바일 배치를 공유한다.
- [Veil Rays 공개 미리보기](https://getdesign.md/backgrounds?fx=veil-rays)의 밝은 원뿔·빛줄기·입자·느린 움직임을 재해석한 독립 구현이다. 검정 배경이나 유료 코드를 가져오지 않는다. 입력은 [HTML range](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/range), 셰이더 값 전달은 [WebGL uniform](https://developer.mozilla.org/en-US/docs/Web/API/WebGLRenderingContext/uniform), React19.2.8 입력/이벤트 정리는 Context7으로 확인했다. [구현·검사·실제 화면](../work/P9-23.md#광원-조절과-달빛-후속).

#### 비단결·오로라와 개별 흐름 속도 — P9-24

P9-24에서 비단결과 오로라를 추가했으나 **P9-25 사용자 요청으로 오로라를 제거**했다. 당시 참고·검사·영상은 [P9-24 기록](../work/P9-24.md)에 보존하며 현재 앱은 반사·빛줄기·비단결만 제공한다. 오로라의 선택 버튼·설정 읽기·GPU 함수/상태/색상 경로를 제거하고, 과거 브라우저의 오로라 값은 읽지 않는다. 다른 설정은 지우지 않는다.

- **비단결**은 옆으로 흐르는 넓은 주름이 여러 크기의 불규칙한 결로 갈라지고 가장자리에서 가는 잔광으로 풀린다. 표시값은 밝기10~100%, 주름 크기0~100%, 흐름 속도0~100%, 기본50/50/50이다. P9-25 후속으로 실제 수치를 기존 기준 밝기2.1~21%, 주름80~100%, 속도0~24%로 선형 환산한다. 밝기100%=기존21%, 주름0%=기존80%, 속도100%=기존24%다. 기존 저장값은 외관에 맞춰 새 표시값으로 환산하고 범위 밖만 제한한다. 같은 저장 위치에 version2를 넣어 재환산을 막는다. [Silk Flow 공개 미리보기](https://getdesign.md/backgrounds?fx=silk-flow)를 참고한 독립 셰이더이며 유료 원본 코드/자산은 포함하지 않는다.
- 빛줄기50%는 기존 기본 속도다.50% 위 구간은 비선형으로 넓혀100%는 기본의16배(이전 최고 속도의8배)이며, 반사100%는 기본의2배다. 비단결100%는 이전 속도24%(이전 기본의0.48배)다. 옛 빛줄기 저장값에 속도가 없으면50을 보완하고 너비·밝기·퍼짐은 유지한다. 각 효과의 속도0은 흐름 정지이고 시간을 따로 누적해 수치 변경 때 무늬가 다른 시점으로 뛰지 않는다.
- 비단결은 이동하는 다중 크기 밀도장을 쓰고 좁은 세로 화면에서도 전체 주름 모양을 볼 수 있도록 최소 가로 비율을 유지한다. 거친 점무늬를 피하고 기존 영상·유리·초기 로딩 정책을 보존한다.
- 세 효과는 공통 제어판·개별 저장·단일 캔버스·최대640×480/DPR1/30fps·화면 밖 정지·접근성·복구 정책을 공유한다. 반사만 기본 켜짐, 빛줄기와 비단결은 꺼짐이다.

### P9-25 모바일 헤더와 화면 설정

- 공통 모바일 헤더(700px 이하)는 높이60px 한 줄이다. 브랜드·이번 주 퀴즈·지난 퀴즈·원형44px 관리 링크를 유지한다.380px 이하에서 브랜드의 작은 보조 글자만 숨기며 전체 접근성 이름은 유지한다. 내비게이션의44px 터치 높이와 경로를 보존한다.
- 모바일 관리 링크는 본문 우측 원형 링크와 같은 얇은 테두리·투명 바탕·작은 그림자를 사용하며 글자 대신 네 칸의 관리 공간 아이콘을 둔다. ‘가 선명하게’는 반원이 채워진 대비 아이콘으로 표시한다. 접근성 이름·설정 상태·44px 입력 영역은 유지한다. 잔디는 다른 설정 아이콘과 같은 중립색(밤에는 밝은색)을 쓰고 원래 직선 모양을 보존한다. PC의 기존 글자·아이콘 색·재질은 바꾸지 않는다. 잔디 SVG 자체는 PC23px·모바일22px이며 바깥 버튼50/44px은 보존한다. 모바일 효과 열기 별 아이콘은19→20px로 키우고 PC22px과 효과 선택 항목19px은 유지한다. 메인 지난 퀴즈의 어린이·장년 원형 링크 사이 간격은8px로 통일한다.
- 메인 하단 `PageDock`은 홈·퀴즈·문의 뒤 네 번째 **화면 설정** 아이콘 버튼을 둔다. 기존 우측 설정은 PC에 유지하며 모바일에서는 이 버튼으로만236px 너비의 작은 팝업을 연다. 하단 바는 내용 너비240px로 맞추고 safe-area를 반영한다. 시간대 네 개, 재생/멈춤, 배경 효과, 선명하게, 잔디를 모두 포함한다. 모바일에서는 풀이·지난 퀴즈·문의·관리자 등 공통 레이아웃의 모든 페이지에서 같은 플로팅 바를 유지하며 본문 끝의 별도 설정 바는 없앤다. 설정 안의 메인 전용 효과는 계속 메인에만 표시한다. 출력 전용 문서는 기존 구성을 유지한다.
- 설정이 열리면 단일 유리 표시가 네 번째 버튼으로 이동하고 닫으면 현재 메뉴로 복귀한다. 홈·퀴즈·문의는 실제 경로에 맞춰 표시하며 해당 항목이 없는 지난 퀴즈/관리자에서는 잘못된 현재 메뉴를 표시하지 않는다. 별도의 단색 활성 배경은 두지 않는다. 기존 `GlassMenu`의 탄성 이동을 터치에서도 사용하며 움직임/투명도 감소 시에는 즉시 바뀐다. 홈 링크의 현재 페이지 의미와 설정 버튼의 열림 상태·키보드 초점은 유지한다.

### 메인 탐색과 서울 시간대 — P9-07

2026-10-15 마지막 구역 보정: 메인에서 별도 참여 가능 퀴즈 구역을 제거한다. 지난 퀴즈의 제목 크기는 보존하고 날짜/장절은PC12px·모바일11px, 행 간격은12px로 줄인다. 어린이·장년은 제목 오른쪽의44px 원형 투명 아이콘 링크와 작은 도움말로 제공한다. 푸터를 별도 휠 정지 지점에서 제외하고 실제 푸터 높이를 관찰해 마지막 구역 높이와 native snap 끝 여백에 반영한다. 한 화면에 들어오는 마지막 내용은 푸터까지 한 번에 도착하며 긴 모바일/확대 내용은 자연스럽게 끝까지 읽을 수 있다.

메인 스크롤 중에는 유리의 투명한 바탕·테두리·반사를 유지하며 SVG 굴절과 중첩 backdrop blur만 잠시 제외한다. 직접 휠 이동 시작과 native scroll에서 공통 표시를 켜고 마지막 이동240ms 뒤 원래 재질로 복원한다. 같은 값의 DOM 속성을 매 프레임 덮어쓰지 않는다. 개인 선명하게 설정·움직임 설정을 변경하지 않으며 다른 페이지에는 적용하지 않는다. 경로 이동 시 관찰자·타이머·CSS 변수를 정리한다. 배경을 표본 추출하는 범위는 [MDN backdrop-filter](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter), 실제 프레임 진단은 [Chrome 렌더링 성능 도구](https://developer.chrome.com/docs/devtools/rendering/performance)를 따른다. 측정 조건·한계는 [이번 검증](../work/P9-23.md#메인-목록과-스크롤-후속)에 구분한다.

근거: [NOAA 근사식](https://gml.noaa.gov/grad/solcalc/solareqns.PDF), [MDN scroll snap](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Scroll_snap/Basic_concepts), [MDN sessionStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage).

### 내부 화면의 정보 계층 — P9-17

2026-10-12 사용자가 메인 외 화면의 타이포·정보 분류·기능 발견성 개선을 요청했다. 메인 구성/재질/모션은 보존하고 관리자와 풀이·지난 퀴즈·문의의 콘텐츠를 같은 읽기 기준으로 정리한다. Refero Air의 얇은 구분선·일관된 여백·절제된 표면을 계승하되 영어 마케팅 화면의 대형 제목을 작업 화면에 적용하지 않는다. [현재 참조](https://styles.refero.design/style/d3289fe7-a85e-42d8-96b7-eb7faa62a104).

- 제목은 기존 실제 **Noto Serif KR 600**, 본문은 **Noto Sans KR 400**. 페이지 제목28px(작은 화면25px), 섹션20~21px, 목록 제목17~19px, 본문15~16px, 보조 정보12~14px. 본문 강조·라벨에만 600 굵기를 사용한다. Sans 실제 파일은400이므로 비메인 콘텐츠에서 `font-synthesis:weight`를 허용한다. Serif는 실제600을 사용하며 새 글꼴·패키지를 추가하지 않는다. 공통 헤더/시간대와 메인은 적용 대상에서 제외한다.
- 콘텐츠 안쪽32px(작은 화면18~22px), 구획 간24~28px, 레코드 간16px 또는 얇은 구분선을 사용한다. 숫자·상태·제목·보조 정보·행동을 서로 다른 줄/영역으로 나누며 문단을 버튼이나 목록 대신 쓰지 않는다. 기존 버튼 재질을 재사용하고 관리자 실행 버튼은44px 이상·14px·radius8px·내용에 맞는 너비로 통일한다. 주요 행동만 색 채움으로 강조한다.
- 관리 메뉴는 **퀴즈 관리 / 참여 기록 / 문의·삭제 요청**, 접을 수 있는 **도구와 설정: 수정·보관 도구 / 이름·문구 필터 / 비용·백업 / 도움말**이다. PC 폭220px, 좁은 화면에서는44px 조작부로 열고 닫는다. 선택된 메뉴는 하나이며 다른 그룹에 선택 유리를 남기지 않는다. 기존 포인터 유리·키보드·모바일 이동을 유지한다.
- `/admin`은 공개 중/작성 중/답변 대기 요약, 실제 홈 퀴즈, **단일 퀴즈 목록** 순서다. 목록은 상태 필터·제목/날짜 검색, 설교일·제목·상태·난도별 참여 수·마감·초안 편집/퀴즈 설정/참여 기록을 제공한다. P9-23 후속의 짧은 게시판 행·아이콘·말풍선 배치를 따른다. ‘계속 작업하기’, 중복된 작업 목록, 비용 패널, 상시1·2·3 안내는 제거한다. 비용은 별도 메뉴와 하단 링크로 접근한다. `/admin/new`의 기존 초안 재사용 동작은 보존한다.

## P9-22 시간대 색상과 승인 시안의 실제 적용

2026-10-13 로컬 적용 완료. 기존 [사이드바 시안](../design/phase-9/admin-sidebar/README.md)과 [매뉴얼 시안](../design/phase-9/manual-reader/README.md)을 재사용해 실제 React 화면에 적용했다. 이미지의 예시 문구를 가져오지 않고 기존 기능과 운영 문서를 표시한다.

- 사이드바는 기존 220px 패널·라우트·모바일 접기를 유지한다. ‘관리 공간’은 24px/700의 단색 고딕, ‘퀴즈 운영’과 ‘도구와 설정’은 13px/700의 실행 색상이다. 메뉴는 20px 선 아이콘, 48px 이상 행, 구분선과 그룹 간 여백을 사용한다. P9-23 후속 기준의 공통 `AdminMenu`를 사용한다. 활성 항목은 기본 글자색·굵기와 aria-current로 유지하고, 상단 반사와 낮은 그림자가 있는 선택 배경이 호버·키보드 초점 항목으로 이동한다. 왼쪽 강조선은 없으며 밤에는 회색 배경을 사용한다. 벗어나면 현재 메뉴로 돌아온다. 관리자 메뉴의 유리 렌즈/탄성 효과는 제거하고 공통 엔진은 변경하지 않는다. 도구 그룹은 기존의 현재 경로/사용자 조작에 따라 펼친다.
- 매뉴얼 목차는 48px 이상 버튼, 주제별 선 아이콘과 P9-23의 공식 회사 아이콘을 사용한다. P9-23 후속부터 사이드바와 같은 `AdminMenu`의 선택 배경을 공유하며 왼쪽 강조선은 없다. 760px 이하에서는 기존 ‘읽을 주제’ 선택과 본문 제목 초점 이동을 유지한다. 14개 문서 주제와 10개 서비스·다음 안내·안전한 텍스트 렌더링은 그대로다.
- 단계 번호는 32px 채움 원과 15px/700 숫자다. 단계 의미에 맞는 색과 `--ui-on-action`을 사용해 밤에는 밝은 원/짙은 숫자로 전환한다. 실행 단계는 파랑, 내용 확인은 호박색이다. 얇은 연결선, 고딕 18px/700 단계 제목(모바일 17px), 문단 여백을 사용한다. 본문은 읽기 영역 폭을 활용하고 문장 중간의 강제 개행을 넣지 않는다.
- 콜아웃은 느낌표 선 아이콘, 주의 색상의 글자/받침, 얇은 1px 전체 테두리와 16×18px 여백(모바일 14px)을 갖는다. 굵은 문장도 주의 색을 유지한다. 색상 없이도 ‘주의’ 접근성 이름·아이콘·경계로 구별한다.
- `AdminIcon`은 기존 관리자 선 아이콘의 계열을 목차·콜아웃과 공유한다. 아이콘은 장식이며 인접한 이름이 접근성 이름을 제공한다. P9-23 후속 요청에 따라 서비스 사전의 회사 표시는 공식 원본 자산을 사용한다. 새 의존성은 추가하지 않는다.

다섯 역할의 네 시간대 글자/받침 값은 위 P9-19 표를 그대로 사용한다. 새벽은 차가운 인디고·청록·보라, 낮은 선명한 파랑·초록, 노을은 구릿빛 실행색·따뜻한 초록·자주/붉은 색조, 밤은 어두운 받침 위의 밝은 파랑·민트·금빛·연보라·분홍으로 구별한다. [전체 색상 비교](../design/phase-9/admin-sidebar/palette.html).

강제 색상에서는 시스템 글자/경계/선택색을 사용한다. 기존 감소 모션·투명도 설정·직선 잔디·자료 보존 정책은 유지한다. 두 시안과 실제 네 시간대 PC/모바일 캡처를 대조한 범위, 자동 검사와 사용자 Windows 표시 확인의 구분은 [P9-22 검증 기록](../work/P9-22.md)을 따른다. 사용자 미감 승인이나 원격 배포 완료를 뜻하지 않는다.


## P9-23 관리자 이모지·용어 도움말·화면 예시

2026-10-13 후속 사용자 요청. P9-22의 하늘·유리·시간대 의미 색상·직선 잔디·관리 메뉴를 유지하면서 관리자 전체의 안내를 보완한다.

- **이모지**: 퀴즈 관리, 제작 6단계, 검수·발행·수정·보관, 참여·문의·필터·비용, 매뉴얼의 제목과 주요 안내에 의미에 맞는 작은 이모지를 쓴다. 글자 이름을 대체하지 않고 장식은 `aria-hidden`으로 읽기 중복을 피한다. 설교 원문·참여자 이름/코멘트·입력값·서비스 식별자는 변환하지 않는다. 사이드바와 일반 주제는 기존 선 아이콘을 보존하고 의미 색을 적용한다. 서비스 사전은 아래 공식 로고 기준을 따른다.
- **용어 도움말**: 초안/확정/검수/발행, 숨김/개인정보 삭제/문의 처리 완료, 예상 비용/미확인/백업 등의 차이를 짧은 한국어로 설명한다. 해당 작업의 용어 줄과 매뉴얼의 점선 밑줄에서 열 수 있다. 마우스 호버, 키보드 초점, 터치를 모두 지원하고 Escape·바깥 클릭으로 닫는다. 말풍선은 요소 위를 기본으로 하며, 위쪽 공간이 부족한 경우에만 아래로 표시한다. 요소와 8px 간격, 화면 가장자리 12px 여백을 기준으로 배치한다. 내용으로 포인터를 옮겨도 유지하며, 스크롤 시 위쪽 공간을 다시 판단해 위치를 맞추고 화면 밖으로 나간 용어의 설명은 닫는다. 기존 설명/위험 안내를 말풍선 안으로만 숨기지 않는다.
- `AdminHelp`는 명시된 정적 문구만 처리한다. 용어 버튼은 기존 입력 라벨·실행 버튼·링크·summary 안에 중첩하지 않는다. 완전한 기술 식별자는 그대로 표시하며, 코드 표기의 용어는 전체가 사전에 일치할 때만 설명한다. React 텍스트 이스케이프와 안전한 Markdown 부분 집합을 유지한다.
- **화면 예시 8종**: 퀴즈 목록, 설교 정보, 요약/난도 검수, 발행 후 설정, 참여 조치, 문의 답변, 필터 시험, 비용/백업. 실제 앱 컴포넌트에 합성 연습 자료를 넣고 캡처한다. 실제 설교·정답·개인정보·비밀값·운영 수치를 정적 이미지로 내보내지 않는다. ‘실제 화면 · 연습 자료 예시’임을 명시하며 현재 운영 상태의 증거로 취급하지 않는다.
- 매뉴얼은 관련 주제의 본문 뒤에 예시와 읽는 방법을 함께 보여 준다. 작업 화면은 ‘화면 예시로 살펴보기’ 안에서 열어 입력 영역을 간결하게 유지한다. 작은 이미지는 전체를 잘리지 않게 표시하고, 선택하면 중앙 모달에서 크게 본다. 화면 맞춤/원본 크기·스크롤, 닫기 버튼/Escape/배경 클릭, Tab/Shift+Tab 순환과 원래 버튼으로 초점 복귀를 지원한다. 예시 열기/닫기로 입력 폼을 언마운트하지 않는다.
- 네 시간대의 기존 안내/실행 토큰과 강제 색상 대안을 사용한다. 본문 강제 개행·외부 UI/글꼴 의존성을 추가하지 않는다. 후속 요청의 메뉴·탭 이동은 아래 기준을 따른다. 이모지 모양은 운영체제 글꼴에 따라 달라진다. 설명용 자산은 실제 UI의 로컬 정적 PNG다. 디자인 시안 생성은 아래 후속 요청의 별도 범위이며 실제 퀴즈 AI 호출·원격 쓰기·배포는 없다.

### P9-23 후속 — 퀴즈 목록과 안내 구획

- 퀴즈 관리의 용어 줄과 화면 예시는 한 안내 구역으로 묶어 중복 여백을 없앤다. 화면 예시의 접힌 제목은 기본 글자색을 쓰고 독립 위아래 마진을 두지 않는다.
- 홈 퀴즈의 작은 표제는 📡 Live다. 목록 위에는 구분선을 둔다. 새로고침은 공통36px 원형 선 아이콘 버튼(터치44px)이며 접근성 이름·조회/비활성 동작을 보존한다.
- 전체·작성 중·공개 중·지난 퀴즈는 목록과 이어지는 파일 인덱스형 선택 버튼이다. 선택 상태는 aria-pressed·윗선·배경으로 구분한다. 호버/키보드 초점에서도 모든 탭의 위치를 고정하고 바탕색으로 반응한다. 진한 상단 색 띠는 선택한 탭에만 둔다. 감소 모션에서는 전환 애니메이션을 없앤다. 좁은 화면에서는 컨테이너 폭에 맞춰 자연스럽게 배치한다.
- 목록의 상태 표시는10px·2×7px 여백이며 제목과 같은 행에서10px 간격을 둔다. 초안 편집·퀴즈 설정·참여 기록은 글자를 숨긴 공통 정사각형 선 아이콘 링크를 사용한다. 설명은 짧은 말풍선과 접근성 이름으로 제공한다.
- 관리자 사이드바와 매뉴얼의 공통 선택 배경은200ms ease-out으로 호버·키보드 초점을 따라 이동한다. 기존 탄성/볼록 유리 효과를 제거하며 감소 모션에서는 즉시 이동한다. 현재 경로와 모바일 접기/도구 그룹은 보존한다.
- 기능 검토 기록 링크는 매뉴얼 바닥에서 제거하고 **설정과 자료 보호 → 향후 기능**의 본문에 설명과 함께 둔다. 기존 주소와 돌아가기 링크는 유지한다.
- 서비스명 아래 짧은 역할 문구는 인라인 코드로, 소개 문단은 책 아이콘·얇은 전체 테두리·실행색 받침의 콜아웃으로 표시한다. 왼쪽 강조선은 두지 않는다. 사용/문제/확인 세 설명 사이에는 구분선과22px 안쪽 여백을 둔다. 회사 로고·문구·요금/정책 정보는 유지한다.

### P9-23 후속 — 게시판과 관리자 공통 규칙

사용자의 전체 관리자 검수 요청과 직접 그린 ‘어린이 | 공개’ 구조를 따른다. [별도 시안 두 장과 참고처 조사](../design/phase-9/admin-boards/README.md)는 실제 적용을 위한 참고이며 기존 투명 콘셉트·자료·기능을 바꾸지 않는다. Refero Styles는 AI용 시각 참고, Carbon·Geist는 목록/버튼의 규칙 참고로 쓰고 새 UI 패키지나 유료 자산은 추가하지 않는다.

| 역할 | 공통 기준 | 실제 적용 위치 |
|---|---|---|
| 페이지 제목 / 반복 도구 제목 | 퀴즈·참여·문의는 고딕26px·700(모바일23px), 매뉴얼은 고딕28px·700, 나머지 명조28px(모바일25px) / 도구 고딕16px·600 | AdminBoardHeader / interior / AdminGuide |
| 본문 / 보조 정보 | 15px / 12~14px, 설명은400·제목은600 | 기존 한글 폰트 재사용 |
| 페이지 구역 / 도구 안쪽 | 세 게시판16px, 나머지20px / 도구20px, 모바일16px | records·dashboard / weekly / AdminGuide |
| 입력·일반 버튼 | 최소44px 높이, 모서리8px, 버튼 아이콘·글자 중앙 정렬 | interior / Button |
| 새로고침 / 목록 작업 | PC36×36px·터치44×44px,18px 선 아이콘, 원형 / 모서리8px 정사각형 | AdminRefreshButton / AdminIconLink |
| 목록 필터와 본문 | 탭 사이 간격0·테두리0·상단 모서리4px·선택한 탭에만5px 강조선, 같은 높이/굵기와 불투명 본문 연결·본문 하단 모서리8px | AdminIndexedBoard |
| 게시판 행 | 접힌 행 PC14×18px·모바일12px 여백, 사이 구분선1px | AdminRecord |

- 참여·문의는 하나의 불투명 목록 표면에서 행을 얇은 선으로 구분한다. 개별 카드 테두리/큰 모서리/행 간격은 두지 않는다. 참여 목록 외곽만10px(모바일8px) 모서리로 묶고, 문의는 아래 공통 인덱스의 외곽을 사용한다. 이름은15px 고딕·600(모바일14px), 종류와 상태는 오른쪽 분할 표시 한 개다. 상태 이름도 함께 표시하며 긴 이름은 자연스럽게 줄바꿈한다. 좁은 화면에서는 장식 사람 아이콘을 생략하고 ‘삭제 요청’처럼 짧은 분류명을 사용한다.
- 날짜·점수·문제 버전은12px·400 보조 정보(모바일11px)로 모은다. 날짜의 초는 화면에서 생략하되 원래 `dateTime`과 데이터는 유지한다. 문의는 접힌 행에 한 줄 미리보기를 두며 원문 전체와 코멘트는 펼친 본문에서 그대로 읽는다.
- 행 전체를 native `details/summary`로 접고 펼친다. Enter/Space와 네이티브 펼침 상태를 지원하며, 답안·폼은 접어도 마운트 상태를 유지해 입력을 보존한다. 답안과 관리 패널을 번갈아 열던 별도 도구 버튼은 제거한다. 서로 다른 행을 강제로 닫지 않으며 서버 갱신·필터 변경의 기존 동작을 유지한다. 관련 퀴즈 링크는 행 클릭과 충돌하지 않도록 펼친 본문에 둔다.
- 참여 기록은 답안·코멘트를 왼쪽, 공개/개인정보 처리 폼을 오른쪽에 둔다. 좌우 사이에 얇은 구분선을 사용하며 처리 이력은 본문 아래에서 펼친다. 답안은 실제 좌표와 입력값만 표시하며 시안의 가상 정답/오답 색이나 인물 사진을 만들지 않는다.
- 문의는 전체 요청 본문 아래에서 처리 상태·삭제 주의사항을 왼쪽, 관리자 답변·저장을 오른쪽에 둔다. 760px 이하에서는 두 화면 모두 위아래로 배치한다. 삭제 경고·명시 확인·저장 충돌 보호·답안/처리 이력은 보존한다. 표 관계가 없는 혼합 콘텐츠는 의미 있는 목록으로 유지한다.
- 퀴즈·문의 필터와 본문은 동일 `AdminIndexedBoard`를 사용한다. selected `aria-pressed`·전체 윗선·받침을 함께 쓰며 경계선은 검색/새로고침 아래까지 이어진다. 선택 탭 아래 경계만 열고 탭과 본문의 바탕을 같게 해 한 폴더처럼 연결한다. 본문 앞 간격과 목록의 중복 외곽선은 없앤다. 빈 목록·조회 중·실패 안내도 같은 본문 안에 놓는다. 호버/초점에서도 탭과 본문의 연결을 유지하며 위치 이동은 하지 않는다. 감소 모션에서는 색·그림자 전환도 없앤다.
- 퀴즈·제출·문의·설교 작업 목록의 새로고침은 같은 대칭 화살표와 원형 버튼을 쓴다. 원격 조회/AI 실행 등의 비용·영향이 있는 ‘갱신’ 작업은 설명하는 글자 버튼을 유지한다.
- 관리자 공통 버튼은 실행 색상을 사용한다. 보조 버튼의 형태·색·정렬과 disabled/초점을 통일한다. 다섯 의미색/네 시간대, 강제 색상, 기존 투명도 감소를 보존한다.
- 용어 줄과 화면 예시는 같은 안내 구역으로 묶어 마진 중복을 없앤다. 도구는 굵은 제목과 보통 굵기의 짧은 설명, 내부 구분선을 갖는다. 정정 폼의 난이도 체크박스와 두 사유 입력칸도 분리하며 강제 `<br>`를 추가하지 않는다.
- 후속 AI는 이 표와 실제 공통 컴포넌트부터 재사용한다. 참고 사이트의 코드를 무작정 추가하거나 개별 페이지에 같은 버튼/필터 규칙을 다시 작성하지 않는다. 변경 후 실제 자료를 보존하며 네 시간대·320/390px·키보드·열린 폼까지 확인한다.


### P9-23 후속 — 설교일 게시판과 작은 아이콘

- 퀴즈 목록의 왼쪽 날짜는 항상 `sermonDate`다. 등록/수정/발행/마감일로 대체하지 않는다. `time[datetime]`과 화면 읽기용 ‘설교일 YYYY-MM-DD’ 텍스트를 함께 둔다.
- 목록은 행 간격 없는 연속 게시판이며 공통 인덱스의 본문 안에 연결한다. PC 행은 최소66px·10×16px 여백, 설교일/상태와14px 고딕 제목/참여·관리 순서다. 긴 제목은 자르지 않고 자연스럽게 줄바꿈한다. 모바일은10×12px 여백이며 작업 묶음을 아래 오른쪽으로 놓는다.
- 공개/지난 퀴즈의 어린이·장년 참여 수는 제목 아래 문장 대신 오른쪽의 각 선 아이콘과 숫자다. 데이터는 기존 `childVisibleCount`/`adultVisibleCount`를 그대로 쓴다. 접근성 이름과 말풍선에 난이도·인원 의미를 제공한다.
- 초안 편집·퀴즈 설정·참여 기록은 `AdminIconLink`로 통일한다. 링크 주소·키보드 실행은 보존하고 버튼을 중첩하지 않는다. 진행 단계·마감·홈 표시 정보는 상태 표시의 말풍선으로 모으고 화면 읽기용 설명 연결을 유지한다.
- `AdminTooltip`의 짧은 말풍선은12px·7×10px 여백·최대280px이며 용어 도움말과 `useAdminTooltip`의 배치/닫기 동작을 공유한다. 위쪽 우선, 공간 부족 시 아래쪽, 호버/키보드 초점·Escape·스크롤 재배치를 유지한다. 저장 내용 복원·실패 재시도·비용 갱신처럼 설명이 필요한 버튼은 글자를 유지한다.
- `AdminTool`의 접기 제어는 ‘열기/접기’와 문자 화살표를 없애고 제목과 설명을 포함한 접기 영역 전체의 세로 중앙에 맞춘20px SVG를 쓴다. native details/summary와 접힌 입력 보존을 유지한다. 관리자 사이드바의 ‘사이트 보기’만 제거하며 헤더의 홈 경로 이름은 ‘이번 주 퀴즈’다.
- 이름·문구 필터에는 평상시 새로고침 버튼을 두지 않는다. 목록 조회에 실패했을 때만 오류 안내와 글자 버튼 ‘다시 시도’를 표시한다. 재시도 중에는 불러오는 상태를 표시하고 성공하면 오류와 버튼을 없앤다. 저장 후 목록은 기존 저장 응답으로 즉시 갱신하며, 저장/시험 실패를 목록 조회 실패와 구별한다.
- 이미지 전달은 [브라우저 확인 페이지](../design/phase-9/admin-boards/review.html)를 함께 제공한다. 서버 HTTP/디코딩 성공과 사용자 표시 확인을 구분한다. 2026-10-13 사용자가 기존 실제 참여1장/생성 시안2장의 표시를 확인했다. 이미지를 다시 생성하지 않는다.

### P9-23 후속 — 시안에 맞춘 세 게시판

2026-10-14 사용자의 기존 생성 시안 재현 요청에 따른다. [비교 화면](../design/phase-9/admin-boards/review.html)에서 기존 참여/문의 생성 원본과 실제 세 React 화면을 구별해 볼 수 있다. 게시판 시안 원본은 재사용하며 새 의존성을 추가하지 않는다. 후속 도움말의 별도 시안은 아래 선택 표면·읽기 영역 절을 따른다. 퀴즈 제작·발행 설정에도 읽기 바탕을 통일한 현재 기준은 아래 [초안 6단계와 퀴즈 설정](#p9-23-후속--초안-6단계와-퀴즈-설정)을 따른다.

- `AdminBoardHeader`의 제목/설명/오른쪽 동작을 공통 사용한다. 용어와 화면 예시는 ‘용어·화면 안내’ 안에 보존한다. 모바일도 제목과 동작을 같은 첫 줄에, 설명은 그 아래 전체 폭에 둔다.
- 퀴즈 관리의 현황과 Live는 넓은 화면에서 **5:5**, 사이 간격12px로 놓는다. 현황은 공개 중·작성 중·답변 대기의 동등한 세 칸이며 각각 기존 시간대 토큰의 **초록·파랑·노랑 계열 바탕을 상시 표시**한다. 모서리는 직각이며 위아래1px 선만 둔다. 좌우 외곽선은 없애고 칸 사이는 위아래16px를 비운1px 점선으로 나눈다. 작은 이름과26px 숫자/건(모바일24px), PC84px·모바일78px 이상 높이를 사용한다. 호버/키보드 초점/선택 때는 칸 전체 바탕에 의미색12%를 더하고 선택한 현황의 이름을 의미색·700 굵기로 표시한다. 한쪽 굵은 선은 두지 않는다. 필터 버튼은 aria-pressed를 공유하고 문의 링크는 기존 경로를 유지한다. Live는 별도 투명 바탕·의미색을 섞은 얇은1px 전체 테두리·초록 채움 배지로 구분한다. 배지는 완료 색을 바탕으로, 해당 역할의 받침 색을 글자로 사용하며 왼쪽 강조선은 두지 않는다. 1100px 이하에서는 두 영역이 위아래로 이어지며360px 이하 현황의 장식 이모지만 생략한다. 설교일·참여 아이콘/수·작업 링크·말풍선은 유지한다.
- 관리자 사이드바는 세 게시판의 바깥 창과 같은 `--glass-clear`를 사용한다. 기존 반사·220px 폭·모바일 접기를 보존한다. 그룹 제목은 실행색과 기본 글자색을1:1로 섞고, 보조 제목은 보조색60%·기본 글자색40%를 사용한다. 사이드바와 매뉴얼의 선택/호버 배경은 아래 공통 `AdminMenu` 기준을 따른다. 메뉴 아이콘의 의미색과 공식 회사 로고, 투명도 감소·강제 색상 대안은 유지한다.
- **한쪽 강조선 규칙**: 작은 말풍선·큰 도움말·안내·경고·인용 상자의 한쪽만 진한 선을 두지 않는다. 균일한1px 전체 경계와 의미색 바탕·문구·배지로 구분한다. 둥근 모서리를 따라 선이 가늘어지는 형태도 쓰지 않는다. 사이드바·매뉴얼·Live는 한쪽 선 자체를 제거했다. 메뉴는 낮은 그림자와 선택 면, Live는 얇은 전체 테두리와 초록 배지로 구별한다. 키보드 초점 윤곽선과 강제 색상의 시스템 선택 표시는 보존한다.
- 세 게시판과 **도구·설정의 수정·보관 도구, 이름·문구 필터, 비용·백업, 도움말(기능 검토 기록 포함)**의 바깥 창은 `--glass-clear`(낮22%·새벽/노을24%·밤38% alpha)를 유지한다. 현황/목록의 공통 `--admin-board-surface`는 밝은 시간대에 기존 `--glass-solid`, 밤에는 회청색 `#43515c`의 불투명 바탕이다. 선택 탭과 본문에 같은 불투명색을 사용해 하늘 위치에 따른 경계 차이를 없앤다. 밤 보조 글자는 `#d2dfea`, 펼친 기록의 이동 링크는 `#ccdeff`로 밝힌다. 펼친 내용은 밝은 시간대의 기존 읽기 층을 유지하고 밤에는 밝은 색5.5%를 더한다. 밤 선명하게에서도 바깥 남색과 본문 회청색은 구분한다. 투명도 감소는 불투명 바탕, 강제 색상은 시스템 Canvas/LinkText로 전환한다. 네 도구 메뉴와 퀴즈 제작/발행 설정은 공통 `data-admin-clear` 표면 표시와 아래 공통 읽기 바탕을 사용하며 내부 입력칸·주의 안내의 역할은 보존한다. 맑은 창의 보조 글자는 기본 글자색88%와 불투명 바탕색을 섞어 대비를 높이고, 밤 게시판의 기존 보조 글자 값은 유지한다. 매뉴얼의 작은 구분 제목은 의미색/기본 글자색을1:1로 섞는다. 유리 테두리·굴절·의미색 역할은 유지한다.
- 공통 파일 인덱스는 사용자가 주석으로 지정한 [문의 생성 원본](../design/phase-9/admin-boards/inquiries-reference.png)을 따른다. 탭 사이 간격0, 모든 탭의 테두리0·상단 모서리4px·굵기600·동일한48px 이상 높이를 쓴다. 비선택 탭은 조용한 유리 바탕이며 진한 상단 띠와 상자 구분선을 두지 않는다. **선택한 탭에만5px 높이의 상단 강조선**과 양쪽 얇은 안쪽 경계를 둔다. 띠는 탭 안쪽에 놓는다. PC 최소116px 폭·좌우20px 여백이다. 모든 탭 묶음이 동일하게 전체 폭 기준선1px 위를 덮고, 선택 탭은 본문과 같은 불투명색으로 이어진다. 선택할 때만 경계 두께·패딩·글자 굵기·위치를 바꾸지 않는다. 호버는 배경색만 바꾸며 공통 버튼의1px 눌림 이동을 적용하지 않는다. 개수는 기존 작은 의미색 박스로 분리한다. 퀴즈 전체/작성 중은 파랑·공개 중은 초록·지난 기록은 자주색, 문의 답변 대기는 호박색·처리한 문의는 초록·전체는 파랑이다. 움직임 감소를 끈 상태의 마우스 누름/뗌·Space와 선택 전후에 탭 윗변뿐 아니라 실제 글자 기준선도 확인한다.1200px 이하에서는 검색을 탭 위로,600px 이하에서는 최소 폭을 해제해320/390px 한 줄 인덱스를 유지한다. 기존 필터의 `role=group`/`aria-pressed`를 보존하며 다른 ARIA 탭 동작으로 바꾸지 않는다.
- 참여 점수는 파란 작은 박스에 실제 수치를 표시한다. 실제 답안 칸은 입력이 있으면 파랑, 빈칸이면 호박색을 사용하며 좌표/제출값/빈칸 문구를 유지한다. 색으로 가상 정오답을 만들지 않는다. 기록 이름은 호버해도 기본 글자색을 유지한다. [비교 페이지](../design/phase-9/admin-boards/review.html)는 실제 낮/밤 화면6장과 기존 시안2장을 시간대 전환으로 비교한다.

### P9-23 후속 — 도구 읽기 면과 메뉴 동기화

2026-10-14 사용자의 세 도구 화면 통일·스크롤·아이콘 호버 보정 요청에 따른다. 도움말의 기존 승인 시안을 재사용하며 [실제 낮·밤 화면](../design/phase-9/admin-boards/review.html#tools)으로 대조한다.

- **공통 읽기 바탕**: 도움말 본문과 수정·보관 도구, 이름·문구 필터, 비용·백업은 `interior.css`의 `--admin-sheet`·경계·가로/세로 여백을 공유한다. `data-admin-sheet`와 도구 페이지 안의 기존 `AdminTool`에만 적용한다. 바깥 창은 기존 맑은 유리, 내용은 밝은 시간대 `--glass-solid`·밤 `#43515c`의 불투명 면이다. 모서리12px·얇은 전체 경계·작은 그림자, 기본24×28px/중간 폭22px/모바일20px/400px 이하16×14px 여백을 사용한다. 강제 색상은 Canvas/CanvasText로 바꾸고 그림자를 없앤다.
- **제목·작업 영역**: 세 도구 화면 제목은 고딕700, 펼침 제목18px(모바일17px), 상태/목록 제목20px(모바일18px)과 아래 구분선을 사용한다. 기존 공통 작업 버튼·원형 새로고침과 키보드 초점은 유지한다. 필터 규칙은 한 읽기 면 안에서 선으로 구분한다. 열린 성경 장절 도구와 설교 편집기 안에 큰 바탕 상자를 중첩하지 않는다. 설교 편집기의 모바일 단계 안내는 두 열로 줄인다. 비용 상세창도 같은 읽기 바탕과 제목 위계를 쓰며 닫기 버튼은 스크롤 중에도 보인다.

### P9-23 후속 — 초안 6단계와 퀴즈 설정

2026-10-14 사용자 요청. 도움말·도구의 승인된 투명 외곽과 불투명 본문을 초안 편집 여섯 단계와 발행 후 설정으로 확장한다. 새 시안이나 패키지를 추가하지 않고 [기존 도움말 시안](../design/phase-9/manual-reader/layered-reference.png)과 [실제 단계별 낮·밤 화면](../design/phase-9/admin-boards/review.html#workspace)을 대조한다.

- **재질과 읽기 위계**: `Workspace`는 `data-admin-clear`와 `data-admin-workspace`, 주간 편집기는 `data-admin-workflow`를 사용한다. 단계별 본문은 공통 `data-admin-sheet` 한 장에 놓고 내부의 큰 상자를 투명하게 정리한다. 발행 설정의 기존 `AdminTool`과 마감/순위 바로 가기, 발행 취소 검수 화면도 같은 읽기 바탕을 사용한다. 밤 본문은 회청색 `#43515c`이며 경계·그림자·여백은 위 공통 토큰을 따른다. 입력칸·위험 안내·검수 상태는 고유 역할을 유지한다.
- **제목·버튼·간격**: 바깥 제목23~28px, 단계 제목23px, 작은 본문 제목16px의 고딕700을 쓴다. 본문 제목 아래 얇은 선과16~20px 간격으로 구분하고 주요 구획은24px, 관련 작업 버튼은8px로 묶는다. 기존 공통 버튼·초점·비활성 표시를 재사용한다. 용어와 화면 예시는 기본적으로 접힌 ‘용어·화면 안내’ 안에 보존한다. 강제 개행이나 내용 삭제로 공간을 줄이지 않는다.
- **여섯 단계 안내**: 투명한 바탕의 안정된 안내 줄을 사용한다. 넓은 화면은6열, 중간 폭은3열,400px 이하는2열이다. 번호는28px, 완료는 초록·현재는 파랑이며 현재 단계의 면은 아래 공통 이동 배경 기준으로 확장한다. 기본 높이68px/작은 화면62px 이상을 유지한다. 현재 단계 문구를 완료 여부보다 우선하며 이동 잠금·사유·`aria-current=step`은 유지한다.
- **미리보기와 확인창**: 기본 ‘현재 시간대’는 네 시간대 색을 그대로 따른다. 명시적인 라이트·다크는 현행 하늘 계열 색을 사용한다. 색상 선택 문구와 select는 한 줄의 두 칸으로 놓아 글자가 한 글자씩 밀리지 않게 한다. 격자/정답·확대·모바일 폭·Top N 동작은 유지한다. 발행 확인창은 같은 읽기 바탕과 여백, 화면 중앙 정렬·내부 스크롤·Escape·닫은 뒤 초점 복귀를 사용한다.
- **보존과 검수**: 저장/자동 저장·유료 실행 확인·검수·배치·발행의 기존 조건과 API를 바꾸지 않는다. 접힌 패널은 마운트를 유지해 입력을 보존한다. 승인된 `AdminMenu`의200ms 선택 면/아이콘 받침 동작은 변경하지 않는다. 네 시간대와1440/1024/768/390/320px, 열린 설정·발행창·투명도 감소·강제 색상을 확인한다. 실제 UI를 합성 GET 자료로 촬영하며 운영 자료를 정적 이미지로 만들지 않는다. - **제목 옆 정보**: 설교일·상태·저장/보관을 달력·상태·DB 선 아이콘 세 개로 모아 제목과 같은 행 오른쪽에 둔다. 날짜·요일 글자는 평상시 숨기고 달력의 작은 말풍선에 `YYYY.MM.DD · 요일`로 보여 준다. 접근성 이름·설명과 `time[datetime]`은 유지한다. 하나의 유리 박스(1px 전체 경계·7px 모서리·2px 안쪽 여백) 안에서 각 아이콘 사이를 위아래9px 비운1px 구분선으로 나눈다. 버튼은 PC32×32px·터치44×44px이며 제목은 남은 폭에서 자연스럽게 줄바꿈한다. 마우스·키보드 초점·탭으로 말풍선을 열고 Escape/바깥 클릭으로 닫는다. 위쪽 우선, 저장 시각·보관 일정/확인 경로·공개/마감/만료/취소 상태는 보존한다. 위험 실행이나 저장 버튼을 숨기는 작업은 아니다.

### P9-23 후속 — 균일한 말풍선 경계

2026-10-14 사용자 정정. 작은 `AdminTooltip`과 큰 `HelpTerm`은 같은1px 중립 전체 테두리를 사용한다. 아래로 뜰 때의 꼬리도 같은 경계색을 사용하며, 위쪽만 다른 색이나 두께로 강조하지 않는다. 의미색은 용어 글자·범주 배지·주의 바탕에 남긴다. 관리자 안내/오류/인용, 공개 문의 상태·풀이 안내·결과/참여 상자도 한쪽 굵은 장식선을 제거한다. 운영 현황의 선택은 바탕과 이름 굵기로 구분한다. 앞서 사용자가 따로 확정한 **인덱스 선택 탭의 상단 색 띠**, 격자선, 키보드 초점 윤곽선은 해당 기능의 표시로 유지한다.

꼬리 접합부는 본체 쪽으로1px 겹쳐 마름모를 따로 붙인 듯한 돌출을 줄인다. 위에 뜰 때 큰 꼬리의 `bottom`은-5px, 작은 꼬리는-4px이며 아래로 뜨는 예외도 같은 값의 `top`으로 대칭 처리한다. 말풍선 본체와 요소 사이8px 간격·위쪽 우선·화면 가장자리12px 기준은 그대로다.


### P9-23 후속 — 문구·의미 색상·공식 아이콘

- 서비스 사전의 ‘언제 쓰나요?’·‘문제가 생기면?’·‘무엇을 확인하나요?’는18px/700, 모바일17px이며 각각 ▶️·⚠️·🔎를 앞에 둔다. 기존 실행/위험/확인 색상은 유지한다. 매뉴얼의 오류 네 상황, 월간 비용·백업 소제목과 관리자 본문 확인·검토 메모·비용 기록·참여 관리·사용 순서 등 정적인 제목은 `AdminLabel`/`AdminEmoji`로 의미에 맞게 구분한다. 원문/입력·참여자 제목·회사 로고·기존 메뉴 선 아이콘은 변환하지 않는다. 장식 이모지는 접근성 이름에 포함하지 않으며 줄바꿈을 강제하지 않는다.

- ‘오류가 났을 때’는 네 상황의 소제목 사이에 얇은 구분선과 윗여백24px·추가 간격18px를 둔다. 첫 소제목에는 선을 넣지 않으며 같은 상황의 문단은18px 간격으로 묶는다. ‘매월 비용 확인’의 경고 유지 이유·실제 청구 금액 차이·사용량 읽기 세 소제목 앞에도 같은 선과 여백을 적용한다. 다른 매뉴얼 주제와 본문 내용은 유지한다.

- 도움말이라는 페이지 분류만으로 강조를 자주색으로 통일하지 않는다. **실행·이동·선택은 파랑, 공개·완료는 초록, 확인·검수 대기는 호박색, 일반 개념 설명은 자주색, 삭제·오류는 장미색**이다. 용어 32종, 단계 번호, 목차와 관리자 메뉴 아이콘에 공통 역할 토큰을 적용한다. 본문과 기술 식별자는 기본 글자색을 사용한다. ‘발행’ 동작과 ‘발행 완료’ 상태를 구별한다.
- 말풍선은 읽기용 중립 바탕(낮 계열 `#FFFEFA`, 밤 `#182C41`)과 기본 글자색, 균일한1px 전체 경계·작은 의미색 범주 표시·요소를 가리키는 꼬리를 쓴다. 최대 폭340px, 화면 양옆12px, 안쪽16×18px, 14px/1.8 본문을 사용한다. **위쪽 우선과 공간 부족 시 아래쪽 표시를 유지**한다. 강제 색상에서는 시스템 색을 쓴다.
- 목차 호버·키보드 초점은 위의 공통 `AdminMenu` 선택 면을 사용한다. 현재 항목의 굵기와 aria-current는 유지하며 설정·자료 보호 주제의 아이콘은 의미색을 따른다. 주제 변경은 아래 메뉴를 포함해 화면 맨 위로 이동하고 새 본문 제목에 초점을 둔다.
- OpenAI Blossom·Cloudflare 회사 아이콘·GitHub Invertocat을 공식 파일 그대로 사용한다. 모양·색을 임의로 다시 그리거나 시간대별로 바꾸지 않는다. 밝은 받침으로 네 시간대에서 식별성을 유지한다. Cloudflare 소속 서비스들은 회사 아이콘을 공유하며 ‘서비스 주소’는 회사가 아니므로 지구본을 유지한다. [원본 출처](../../public/images/services/README.md).
- 관리자 메뉴·제작 6단계·발행 설정·참여/문의/필터/비용·매뉴얼14개 주제·서비스10종·기능 검토 기록을 문맥별로 검토한다. 화면 문구는 ‘설교 자료’, ‘발행 취소’, ‘예상 비용’, ‘다시 공개’ 등 같은 동작에 같은 이름을 쓴다. ‘정규화’처럼 어려운 말은 역할을 설명한다. 기술 식별자·가격 수치/확인일·자료 보관/삭제 정책·입력값은 바꾸지 않는다. 과거 기능 검토 기록은 현재 제공 기능과 구분한다.

### P9-26 공개 풀이 화면 — 2026-10-16

사용자 요청으로 웹/모바일 풀이·제출 시안4장을 먼저 생성한 뒤 실제 화면에 적용한다. [시안과 실제 화면](../design/phase-9/quiz-reader/review.html), [구현·검수](../work/P9-26.md). 생성 이미지의 가상 격자·글자 표시는 구도 참고이며 실제 데이터·성경 본문으로 사용하지 않는다.

- 투명한 외곽 창은 한 겹으로 두고, 난이도 인덱스와 본문을 같은 불투명 읽기 면으로 연결한다. 중첩된 유리 요약 바는 사용하지 않는다. 격자와 단서 사이에는 얇은 구분선만 둔다.

- 시간대별 의미색5종을 관리자와 공유한다. 실행·현재 단서는 실행색, 참여 가능은 완료색, 부분 제출 안내는 확인색, 정답은 도움말색을 쓴다. 입력 안내 버튼은 중립색을 사용한다. 오류의 기존 문구/상태는 유지한다. 노을은 기존 살구/구릿빛, 밤 읽기 면 `--quiz-sheet: #43515c`로 투명 남색 외곽과 구분한다.

- 저장/작성 진행/정확한 마감은 하나의 상태 줄로 묶는다. 정답 공개 조건·부분 제출·사람 확인·동의·제출/삭제/연습 결과는 기존 정책을 유지한다. 이름/한줄평은 PC에서 두 열, 모바일에서 한 열이다. 주보 출력 도구는 기본 접힘이며 기존 별도 출력 페이지는 유지한다. 펼친 내용은 짧은 제목/설명·난이도 선택, 같은44px 아이콘 버튼의 PNG/복사/미리보기, 접힌 SVG 설정으로 정리한다. PNG/SVG와 격자 크기는 인라인 코드로 표시하고 미리보기는 작은 격자와 키보드로 스크롤 가능한 문제 텍스트로 구성한다. 실제 파일·복사 대체 경로는 보존한다.
- 이번 주 풀이 아래에는 지난 퀴즈 목록을 반복하지 않는다. 주보 편집 자료 전체 다음에 구분선과 별도 투명 창을 두고, 그 안에 제출 전 참여 현황 안내/같은 난이도의 제출 확인 후 기존 참여 현황을 표시한다. ‘아직 참여할 수 있는 퀴즈’ 목록은 풀이 화면에서 제거한다. 이름·답안의 제출자 전용 접근과 삭제 후 비공개를 유지한다. 메인 소개의 지난 퀴즈 목록과 별도 아카이브는 유지한다.
- 제목 옆 두 아이콘의 호버 면은 접합부가 직각이며 첫 아이콘 왼쪽·마지막 아이콘 오른쪽만 외곽 테두리를 따라 둥글다. 제출 버튼은 최소48px 높이를 유지한다.
- 말풍선은 공용 Tooltip 부품과 위쪽 우선 배치를 재사용한다. 달력은 터치로 열고 Escape로 닫을 수 있다. 키보드 탭 전환, 초점, 움직임 감소/고대비 및 전체 격자 표시를 확인한다.

P9-26 공유: 제목 옆 달력 다음의 공유 아이콘은 현재 퀴즈·난이도의 고정 주소를 기기 공유 창으로 전달한다. 미지원/실패 시 주소를 복사하고, 복사도 실패하면 직접 선택할 수 있는 주소를 제공한다. 취소는 자동 복사하지 않는다. 조회 매개변수 전체나 해시를 공유하지 않는다.

제목 오른쪽에는 모바일에서도 달력·공유를 같은 행에 배치하며 제목은 자연스럽게 줄바꿈한다. 참여 마감의 한국 시간 계산은 유지하되 화면의 `(한국 시간)` 접미사만 생략한다.

격자 크기/낱말 수 요약 줄은 생략한다. 현재 단서의 왼쪽 시작점은 격자와 맞춘다. 참여 가능한 퀴즈의 안내 띠/하단선은 제거하고 상태를 인원 위에 아이콘과 함께 표시한다. 마감된 퀴즈는 기존 연습·임시 저장 안내를 전체 테두리 콜아웃으로 표시하며, 중지/시작 전 안내도 보존한다. 행/열/방향/입력 상태 영역은 화면 읽기 프로그램과 오류 전달을 위해 유지한다.

P9-26 풀이 여백: 데스크톱(1024px 이상) 풀이 열의 위 여백을12px 추가하고 격자 아래 이동 버튼 간격을8→14px로 조정했다. 현재 단서를 별도 격자 행으로 분리해 오른쪽 단서 패널과 왼쪽 격자의 상단을 정확히 맞췄다. 모바일은 세로 배치를 유지한다.

P9-26 단서 표시 후속: 데스크톱(1024px 이상)에서 격자 위 현재 단서의 시각적 반복을 숨겼다. 입력 aria-describedby가 참조하는 설명은 유지하고 격자/단서 목록을 같은 첫 행에 둔다. 모바일·태블릿 현재 단서에는 위10px/아래16px 여백을 준다. 가로·세로 제목과 개수는 아래 문제 행과 양끝이 맞는 하나의 컴팩트 코드형 박스이며 개수의 오른쪽 여백을 확보했다. 데스크톱 저장 안내는 가운데 열 중앙에 배치한다.

P9-26 조작부 간소화 후속: 모바일 현재 단서 아래 여백16→22px, 데스크톱 풀이 열 위 여백12→24px로 조정했다. 난이도 탭 문구를 어린이 퀴즈/장년 퀴즈로 바꾸고479px 이하에서는 장식 아이콘을 숨겨 긴 문구가 한 줄에 들어가게 했다. 주보 접힘 하단 padding8px·요약44px, 출력 조작부의 불필요한 최소 너비 제거/짧은 문구/PC36px 높이를 적용했다. 모바일·터치 높이는44px를 유지한다. 잔디 렌더링은 원래 home 조건으로 제한되어 있었으며 제어 버튼도 이제 메인에만 표시한다.

P9-26 단서 제목 최종 후속: 데스크톱 풀이 열의 추가 위 여백을24→40px로 늘렸다. 사용자 승인에 따라 단서 제목의 전체 박스 배경/테두리를 없애고 굵은 제목·작은 개수 받침·얇은 하단 구분선으로 바꿨다. 제목과 문제 행의 양끝 정렬, 숫자 안쪽 여백, 모바일과 접근성 설명은 유지한다. 이전 코드형 박스 제안을 대체한다.

P9-26 단서 간격 후속: 가로·세로 단서 그룹 사이 테두리는 없애고 기존 margin/padding 간격은 유지한다. 제목 바로 아래의 얇은 선은 유지한다.

P9-26 주요 동작 한 행: 정답 보기와 입력 확인을 공통2열 동작 영역으로 묶어 PC·모바일 모두 같은 행에 표시한다. 버튼 높이는48px이며 설명은 각 버튼 아래에 둔다. 중복 제목의 시각적 반복은 숨기되 접근성 이름은 유지한다. 제출 양식과 시험 확인 메시지는 동작 행 아래 전체 너비로 펼친다. 기존 정답 공개 조건·제출/삭제·지난 퀴즈 채점 상태는 유지한다.

### P9-26 지난 퀴즈 탐색 화면 — 2026-10-16

사용자가 공개 풀이와 같은 디자인으로 `/archive`의 웹·모바일 리디자인을 요청했다. 같은 공개 퀴즈 탐색 흐름의 P9-26 후속으로 기록한다. 생성 시안은 웹 가로1장·모바일1장이며 [비교 페이지](../design/phase-9/archive/review.html)에 실제 화면과 함께 보존한다. 기존 헤더·하늘·하단 메뉴와 홈의 축약 목록은 유지한다.
