## 10. 시각 디자인과 이미지 자산

### 10.1 공통 디자인 방향

2026-10-08 사용자는 이전 숲·종이·색상 기준을 종료하고 Air를 참고해 처음부터 다시 만들도록 지시했다. **새 UI는 밝은 낮과 깊은 밤을 가진 하나의 연속 하늘**을 따른다. 이전 Everforest/Gruvbox, 장년 숲·어린이 종이 정원, 황동/이끼/잎색 역할과 기존 시안 구도는 새 디자인의 제약에서 폐기한다. 과거 자산·결정·출력 폰트는 보존한다. 운영 앱은 별도 적용 전까지 기존 P9-04 소스를 유지한다.

교회 공동체가 매주 사용하는 퀴즈에 실제 하늘을 통과하는 공간감을 더한다. 공개 첫 화면은 큰 한글 제목과 여백, 구름의 거리·광원·지면까지 이어지는 장면을 중심으로 한다. 풀이와 관리자 화면은 읽기와 입력이 우선이다. 실제 제목·날짜·장절·안내·입력은 HTML이며 생성 이미지에는 글자·성경 구절·로고를 넣지 않는다.

### 10.2 어린이·장년의 관계

두 난도는 같은 하늘과 공통 UI 언어를 공유한다. 명확한 난도 이름, 단서의 표현, 읽기 크기와 정보 밀도로 구분한다. 숲과 종이처럼 서로 다른 세계로 나누지 않는다. 난도별 문제 정책·기능·정답 권한·한글 입력 동작을 디자인 이유로 바꾸지 않는다.

### 10.3 대표 화면과 적용 경계

대표 화면은 공개 낮/밤, 구름 사이의 이번 주 퀴즈, 지면 가까이의 지난 퀴즈, 모바일 풀이, 관리자 요약·문제 검수다. [P9-06](../work/P9-06.md)의 [독립 검토본](../design/phase-9/sky-v2/index.html)에서 먼저 구성·타이포·시간대·모션을 확인한다. 예시 문장과 연습 단어만 사용하며 실제 설교·AI 결과·공개 정답을 가져오지 않는다.

사용자는 공개 하단의 OriginKit Grass Field base 움직이는 잔디와 마우스 반응을 채택하고 먼 산을 실제 촬영 사진으로 추가하도록 요청했다. 잔디 뒤에 산 사진을 독립 층으로 두며 네 시간대와 같은 하강 진행도에 맞춘다. 기존 사진은 기본/즉시 복귀안으로 보존하고 산만 제외한 이전 잔디도 비교할 수 있다. 네 시간대·공유 멈춤·움직임 감소·오류 시 사진 복귀를 따른다. [MCP 출처와 조정 범위](../design/phase-9/sky-v2/ORIGINKIT.md).

시안 확인 후 기존 컴포넌트와 기능을 보존하면서 실제 앱에 연결한다. 독립 시안의 8×8 연습 격자·입력·예시 편집은 제품 엔진/한글 IME/제출/발행 검증을 대신하지 않는다. 현재 기능의 삭제나 별도 워크플로 추가를 시각 개선으로 정당화하지 않는다.

### 10.4 이미지 자산

- Air의 코드·cloud.png·유리 로고·3D 모델·Control 폰트를 복사하지 않는다. 실제 사이트의 공간과 빛을 관측하고 독자 자산·코드로 구현한다.
- 독립 하늘 원경·밤 원경·들판과 별도 풀이/관리자 참고 이미지를 보존한다. 활성 구름은 풍성한 투명5종으로 교체하며 기존3종은 복귀용으로 남긴다. 새 구름의 실제 원본은1672×941, 모바일은960px 변형이며4K 생성물이라고 보고하지 않는다. 산 사진은1600×900/3840×2160의 반응형 자산을 사용한다. 참고 화면 이미지는 실제 입력 UI로 쓰지 않는다.
- 원본 master와 생성 출처를 보존하고 WebP 등으로 최적화한다. 좁은 화면은 별도 크기와 구도를 실제 검수한다. 원경은 장식 배경이므로 무의미한 대체 텍스트를 노출하지 않는다.
- 기존 celebration/garden-v1/garden-v2, 출력 PNG/TTF와 fontkit 패치를 삭제하거나 덮어쓰지 않는다. 매주 새 하늘을 생성하는 기능/비용은 추가하지 않는다.
- 파일·용량·해시와 생성 정보는 [자산 목록](../design/phase-9/sky-v2/assets.json)에 둔다.

### 10.5 읽기와 움직임

- 모든 영역의 배경은 같은 세계이며 시간 흐름에 따른 구름 이동과 스크롤에 따른 시점 하강을 분리한다. 서로 다른 깊이의 구름과 지면이 같은 스크롤 진행도를 공유한다. 섹션마다 사진을 교체하는 것만으로 완료하지 않는다.
- 콘텐츠 최대 폭1440px는 유지하고 배경만 전체 화면에 펼친다.2560px 이상의 좌우에서도 잔디 지형이 연속되고, 같은 모양3개가 오른쪽에 겹쳐 보이지 않도록 구름 종류·위치를 나눈다. 자산의 투명 여백과 표시 크기를 지켜 잘린 경계와 과도한 확대를 피한다.
- 첫 화면은 원래 낮/밤 배경의 빽빽한 양옆 구름과 구도를 유지한다. 영상이 없는 시간대와 비교 모드는 원본의12개 구름군 마스크 영역을 같은 위치에서 좌우로 움직인다. 새벽 첫 화면에는 사용자가 제공한4K 영상을 연결했다. 구도 복원 뒤 움직임 개선을 요청한 후속 결정과 재생 기준은10.8을 따른다.
- 스크롤 하강 시 첫 구름 장면의 아래 경계를 자연스럽게 흐리며 독립 투명 구름5종의 깊이/위치로 이어진다. 지면도 같은 진행도에서 접근한다. 특정 3D 라이브러리 도입은 필수가 아니다.
- 장식과 입력 UI를 분리한다. 전체 UI의 시각 방향은 사용자가 선택한 Apple Liquid Glass 참고안이다(10.8). 헤더·탐색은 맑은 유리, 문제·단서·요약·폼은 읽기가 안정된 두꺼운 유리로 구현한 검토본을 사용한다. 모션이 글자나 입력칸을 흔들지 않는다.
- 대비 목표는 WCAG 2.2 AA다. 사진 위 헤더/제목에는 필요 시 밝은/어두운 받침을 사용하고 실제 장면을 확인한다. 맞음/틀림은 색만으로 전달하지 않는다.
- 명시적 멈춤, OS 움직임 감소, 숨은 탭의 애니메이션 중단, WebGL/이미지 실패 시 읽을 수 있는 단색 fallback을 지원한다. 터치 시간대 제어는 최소44px이다.
- 부드러운 스크롤은 사용자 스크롤을 가로채지 않는다. 이동/입력 컨트롤은 키보드와 터치로 사용할 수 있어야 한다. 모션 감소에서는 자동 움직임과 전환을 멈춘다.

### 10.6 새 토큰과 한글 타이포 초안

아래는 P9-06의 검토용 값이다. 사용자 시각 검수와 실제 앱의 대비·기기 검수를 거쳐 확정한다. 이전 에디터 테마 팔레트를 계승하지 않는다.

| 역할 | 낮 | 밤 |
|---|---|---|
| 기본 글자 | `#142b40` | `#f0f6ff` |
| 보조 글자 | `#365067` | `#c0d2e6` |
| 맑은 제어 표면 | `rgb(233 247 255 / .22)` | `rgb(10 27 48 / .38)` |
| 읽기 표면 | `rgb(247 251 255 / .62)` | `rgb(14 31 52 / .75)` |
| 입력 표면 | `rgb(252 254 255 / .72)` | `rgb(24 47 72 / .82)` |
| 경계 | `rgb(39 72 100 / .18)` | `rgb(192 218 245 / .20)` |
| 강조/초점 | `#095bac` | `#b8d9ff` |
| 주 버튼 / 글자 | `rgb(14 89 155 / .92)` / `#f7fbff` | `rgb(162 203 247 / .93)` / `#102c48` |
| 투명도 감소 표면 | `#eff6fc` | `#122a43` |

위 채움 값은 CSS alpha이며 실제 광학 투과율이 아니다. 반사와 굴절 층이 겹친다. 제어 채움은 새벽/노을24%, 읽기 표면은 새벽64%/노을65%다. 밤 시간대 선택기는 밝은 구름 위 작은 라벨을 위해58%의 국소 받침을 사용한다. 작은 헤더 글자는 낮 계열 `#102438`/밤 `#edf5ff`, 관리자 링크는 국소 받침을 더해 투명한 하늘 위의 대비를 보완한다.

새벽은 기존 청보라·따뜻한 수평선에 옅은 보라 유리, 노을은 기존 청록 하늘·살구빛 구름에 따뜻한 유리를 맞춘다. 새벽 보조 글자는 `#3d4c66`, 노을은 `#514157`로 대비를 보정한다. 현재 색을 담은 영상 입력 자료의 색을 이번 UI 작업으로 바꾸지 않는다.

외곽 패널28~30px(작은 화면26px), 제어는 캡슐24~36px, 입력은14px 모서리를 쓴다. 외곽 유리 안의 입력·미리보기는 안정된 채움으로 구분하고 유리 필터를 중첩하지 않는다. 기존 콘텐츠 최대1440px와 대표 화면의 정보 순서·한글 제목2행·자연스러운 줄바꿈을 유지한다. 기본 형태·반응형은 [liquid-glass.css](../design/phase-9/sky-v2/liquid-glass.css), 현재 재질/토큰 보정은 [prismatic-glass.css](../design/phase-9/sky-v2/prismatic-glass.css), 상태/모션은 [liquid-glass.js](../design/phase-9/sky-v2/liquid-glass.js)를 따른다.

### 10.7 Air 계승 하늘 방향 — 2026-10-08

[Air](https://air.inc/)·[Refero Air](https://styles.refero.design/style/d3289fe7-a85e-42d8-96b7-eb7faa62a104)의 원리를 참고하며 동일 복제나 모든 토큰의 기계적 적용을 목표로 하지 않는다. 사용자 지시인 낮/밤·네 시간대·같은 하늘 속 하강과 한글 읽기를 우선한다.

시간대는 새벽·낮·노을·밤을 같은 구성에서 선택하고 하늘·구름·지면·전경/표면을 함께 바꾼다. 검토본은 기본 낮이며 URL로 시간대를 유지한다. 실제 앱의 기존 `system | light | dark` 저장 호환과 자동 초기 시간 정책은 앱 연결 시 명시적으로 정리한다. 원본의 시계/sessionStorage를 새 제품 결정으로 무단 이식하지 않는다.

진행은 원본 관측 → 별도 대표 시안/움직임 → 사용자 시각 검수·보정 → 전체 앱 연결/관련 기능 검사 → GitHub main 기반 Preview → 별도 요청 Production이다. P9-04와 이전 Phase9 완료를 철회하지 않는다. 실제 관측은 [P9-05](../work/P9-05.md), 새 시안·검증·남은 작업은 [P9-06](../work/P9-06.md)을 따른다.

#### 참조와 한글 서체 적용 기준

Refero는 공개 DESIGN.md/CSS Variables 수동 참조이며 Refero MCP·Tailwind 출력·유료 폰트 적용이 아니다. 독립 검토본은 native CSS/WebGL이다. [참조/폴백 근거](../work/P9-05.md#참조-경로적용-범위한글-글꼴-확인--2026-10-08)를 유지한다.

- 실제 자체 호스팅 **Noto Sans KR 400**을 공개 제목/본문/격자/관리자 UI에 사용하고 `font-synthesis:none`으로 존재하지 않는 굵기를 합성하지 않는다. 기존의 실제 파일과 `unicode-range`를 재사용한다.
- 폴백은 `Apple SD Gothic Neo`, `Malgun Gothic`, `sans-serif`이다. 첫 두 개는 해당 OS에 있을 때만 적용한다. 없는 파일을 내려받았다고 보고하지 않는다. OS별 실제 외형 검수는 별도로 남긴다.
- Control/Inter 등 한글 미지원 폰트 이름을 추가하지 않는다. Pretendard/Nanum Pen Script는 이전 비교 후보이며 이번에 설치·채택하지 않는다. 기존 한글 글꼴을 강제로 교체할 이유가 없으면 유지한다.
- Noto Serif KR 600/출력 TTF/fontkit은 보존하며 새 하늘 제목의 의무 기준에서는 제외한다. 영어 대문자의 무거운 압축 형태나 좁은 행간을 한글에 억지로 적용하지 않는다.

### 10.8 영상 하늘과 전체 UI의 유리 재질 — 조사 후 구현

2026-10-08 조사와 영상 입력 자료 전달 후 사용자는 **3번 Apple Liquid Glass를 선택하고 영상을 직접 준비하는 동안 UI 구현을 진행**하도록 요청했다. [조사](../work/p9-06/video-glass-research.md)를 이어 같은 P9-06의 공개·풀이·관리자 대표 검토본에 적용한다. 실제 앱 연결은10.3의 시각 검토/보정 순서를 따른다.

- 기존 정지 배경은 낮/밤 원본2장과 새벽/노을 필터·광원으로 구성된다. 사용자는 **Google AI Studio/Gemini API·4K 출력으로 직접 제작**하는 경로를 선택했으며,2026-10-09 제공한 새벽 영상1편을 대표 검토본에 연결하도록 요청했다. 낮·노을·밤은 기존 이미지 방식을 유지한다. [영상 입력 자료](../design/phase-9/video-kit/README.md)에 현재 색을 담은 PNG4장·각 완성 프롬프트·시각적 유리 예제를 준비했다. 입력 PNG는1672×941이며4K는 영상 출력이다. 모델/최종 편수와 에이전트의 유료 실행 예산은 확정하지 않았다.
- 영상은 원래 빽빽한 구름과 가운데 여백을 유지한다. 현재 새벽 프롬프트는 사용자가 선택한12:30 결과의 원문 `billowing-v2`를 보존한다. 낮·노을·밤은 병렬 보완 결과 `billowing-v3`으로 구름 자체의 부풀음/국소 소멸·위치별 시차를 주 동작으로 강화했다. 움직임5/10·더 느린 카메라·전체 밀도/중앙 여백·시간대 색/빛/천체는 유지하고 개별 구름의 정확한 첫/끝 윤곽과 닫힌 카메라 복귀는 강제하지 않는다. v3은 시작 PNG만 입력하는 안내를 우선하며 완벽한 루프를 보장하지 않는다. [파생본 보완 근거](../design/phase-9/video-kit/PROMPT-REVISION.md). 프롬프트에 길이를 고정하지 않으며 선택 새벽 영상은3840×2160·24fps·10초다. 현재 색을 담은 영상을 적용할 때 기존 시간대 필터를 중복 적용하지 않도록 한다. 기존 원본·정지/움직임 감소·하강 장면·산/잔디·콘텐츠1440px를 유지한다. 새벽 영상의 첫/끝 구름 모양이 달라 끝0.9초 동안 첫 장면 정지 이미지를 겹쳐 반복 경계를 완화한다. 이는 화면 합성이며 원본을 완벽한 루프 파일로 편집했다는 뜻은 아니다.
- 대표 공개/풀이/관리자 UI에 공통 유리 재질을 적용했다. 헤더/시간대/탐색/첫 버튼은 맑은 유리, 퀴즈/편집은 더 조밀한 읽기 표면을 쓴다. 모서리 반사·배경 흐림·선택 표시 이동을 같은 규칙으로 맞추고 입력 글자에는 굴절을 적용하지 않는다. 현재 토큰은10.6을 따른다.
- AI가 읽는 정본은 이 문서를 유지한다. 참고 DESIGN.md의 팔레트/영문 폰트를 그대로 적용하지 않고 현재 한글 폰트, 네 시간대, Spacing & Shape, 상태, 대비, 모션, 성능을 함께 문서화한다. 새 production 의존성은 필수가 아니며 이번에 추가하지 않는다.

#### 새벽 영상 재생 기준

2026-10-09 후속 요청으로12:30 새벽 영상을 기본으로 교체했다. 사용자는 중간 강도의 구름 자체 부풀음/소멸과 아주 느린 카메라 이동을 요청했다. 이전11:50 버전은 `video=dynamic`, 최초는 `video=calm`으로 비교하며 최신 명시 선택은 `video=billowing`이다. 세 파일과 원본을 보존하고 새 원본은 해시 대조 복사해 Downloads도 유지한다. 재생 제어/색/반복 합성은 동일하다. 사용자가12:30 새벽 버전을 선택했고 해당 프롬프트를 네 시간대의 기준으로 확정했다. 낮/노을/밤 결과는 아직 수령하지 않았으며 실제 앱/운영 연결은 별도다.

- Git 제외 보관 원본은 파일 전체 해시를 확인해 이동한다. 승인된 화면용4K MP4는 영상 스트림을 다시 인코딩하지 않고 소리만 제거한다. 재생 정보는 파일 앞에 둔다. 작은 화면용1080p와 첫 장면 정지 이미지2종을 별도로 만들며 원본의 색을 재보정하지 않는다. [파일·해시·명령](../design/phase-9/sky-v2/assets/video/manifest.json).
- 공개 새벽의 상단 배경이 보이고 움직임이 켜진 때만 MP4를 요청한다. 최초700px 이하에서는1080p, 넓은 화면에서는4K를 사용한다. 넓어질 때 한 번 올리고 좁아질 때 다시 받지 않는다. 영상이 없는 시간대와 풀이/관리자에는 MP4를 요청하지 않는다.
- 공통 멈춤, OS 움직임 감소, 다른 시간대, 상단이 사라진 스크롤, 숨은 탭에서 재생을 정지한다. 최초 움직임 감소에서는 영상 파일 없이 첫 장면만 보여 준다. 자동 재생이 거부되면 같은 제어의 **새벽 영상 재생**으로 사용자 클릭을 받는다. 재생 실패는 첫 장면, 정지 이미지도 실패하면 기존 사진으로 표시한다. [MDN 재생 정책](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay).
- 새벽 영상이 표시될 때 기존 새벽 필터/광원을 중복 적용하지 않는다. 기존 하강 변환과 가장자리 마스크, 아래쪽 구름/산/잔디·콘텐츠1440px를 유지한다. `video=off`는 원래 사진/구름군 비교 경로이며 검토 화면 이동에도 유지한다.
- 이번 연결은 독립 대표 검토본에 한정한다. 실제 앱 연결과 나머지 영상 수령/색·반복 검수는 같은P9-06에서 이어간다. [동작 검사와 한계](../work/P9-06.md#새벽-4k-영상-연결--2026-10-09).

#### Apple 참고 유리 검토본의 재현 기준

[Apple의 공식 소개](https://developer.apple.com/videos/play/wwdc2025/219/)에서 제어와 콘텐츠의 구분, 빛·굴절·상호작용에 반응하는 재질 원리를 참고한다. 웹용 native HTML/CSS/JavaScript로 독자 구현하며 Apple SDK·시스템 Liquid Glass와 동일한 렌더러라고 표현하지 않는다. Apple 폰트/로고나 외부 유리 컴포넌트는 추가하지 않는다.

- 제어의 굴절은 배경 전용 가상 요소에만 둔다. 현재 기본은 맑은 유리+프리즘 보완안이다. Chromium의 헤더·시간대·첫 버튼·검토 전환4개에 크기별 정적 굴절 지도를 만들고 RGB 변위18/14/10과 screen 합성으로 가장자리 색 분산을 더한다. 지도 중앙은 중립이며 글자/입력은 이 필터 밖에 둔다. URL 구문 지원만 믿거나 `window.chrome` 존재만 요구하지 않고 Chromium 식별과 실제 렌더 검증을 함께 사용한다. 다른 엔진은6px CSS 흐림과 유색 반사 경계로 표시한다. 읽기 표면은14px 흐림이며 폼/격자 채움은 기존 가독성 값을 유지한다. [backdrop-filter의 공식 동작](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter).
- 프리즘은 얇은 경계와 방향성 있는 반사에 집중한다. 큰 본문 패널은 잔잔한 경계, 조작부는 배경 굴절·청색/보라/샴페인빛 반사를 쓴다. 전체 화면/영상의 색을 바꾸거나 글자를 무지개색으로 칠하지 않는다. 매 프레임 굴절 지도를 다시 만들지 않고 크기가 달라질 때만 계산한다.
- 선택 표시는 실제 선택 요소의 위치/크기에 맞춰430ms 수평/수직 이동한다. 마우스 빛 반응은 fine pointer의 이동 때만 갱신하고 자체 반복 타이머를 추가하지 않는다. 기존 공통 멈춤과 OS 움직임 감소에서 제어의 이동/반사를 멈춘다. 숨은 탭은 반응을 정리한다.
- 헤더/검토 바의 반사광: 사용자가 모래시계형을 채택하지 않고 **두 요소에 동일한 작은 원형 광원**을 선택했다. 같은 `spot` CSS를 재사용하며 원 반경30px/테두리38px, 흰색 alpha16%/밤8%다. 평소 반사는 고정하고 hover 때 포인터 주변의 빛만 움직인다. `glint=both`가 기본, `header`/`dock`은 한쪽만 원형, `original`은 모양 실험 전 반사다. `header-glint` 생략/`spot`은 현재 원형, `straight`와 `flare`는 이전 헤더 비교를 보존한다. 선택은 URL/화면 이동에 유지하며 포인터 이탈/감소/정지 상태에 추가 광원을 지운다. [현재 선택/검사](../work/P9-06.md#헤더와-아래-바의-원형-광원-통일--2026-10-09) · [이전 형태/재현 값](../work/P9-06.md#헤더의-잘록한-광원과-밝기-보정--2026-10-09).
- **선명하게** 버튼은 불투명 받침으로 전환하며 `clarity=high`를 같은 검토본의 URL/화면 이동에 유지한다. 지원 브라우저의 OS 투명도 감소도 적용하며 굴절/프리즘 장식을 숨기고 포인터 반사를 멈춘다. [OS 설정 지원 범위](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-transparency). 강제 색상 모드에서는 선택 윤곽을 남긴다.
- `glass=soft`는 직전의 더 뿌연 Apple 참고 유리, `glass=off`는 유리 이전 모습이다. 비교 선택은 검토본의 화면 이동에도 유지한다. 기본은 새 프리즘 재질이며 두 비교 경로에서 새 CSS 층을 비활성화한다. 원래 CSS·배경·잔디·산·폰트 파일을 되돌리거나 삭제하지 않는다. 실제 앱의 설정 저장 정책을 추가한 것은 아니다.
- 대비는 네 시간대의 실제 렌더 배경에서 확인한다. 배경 위의 작은 풀이 안내는 본문색을 쓰고, 밤 첫 설명 뒤에는 부드러운 국소 음영을 둔다. 자동 표본 검사는 전체 WCAG/실기기 검수를 대체하지 않는다. 현재 재질/선택 영상으로 다시 확인한 검사와 기기 한계는 [P9-06](../work/P9-06.md#맑은-유리와-프리즘-보완--2026-10-09)에 기록한다.
