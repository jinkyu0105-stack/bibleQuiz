## 11. 매주 발행 흐름

### P5-69 실제 품질 시험 준비 경계

P5-68까지의 로컬 연결·합성 검사는 실제 provider 가용성/AI 품질·청구액 검증과 구별한다. 기존 Terra/high·사람 확정·자동 AI 재호출 금지·원본/비용 보존 조건으로 [시험 자료·평가 기준·예상 비용·운영 승인 계획](../work/P5-69.md)을 정리했다. 실제 자료와 표본 수·시험 예산·합격 기준은 운영자가 실행 전에 선택할 제안이며 새 제품 상한이 아니다. 계획 문서화만으로 유료 호출·자료 등록·발행·원격 적용을 승인하지 않는다. 출시·환경별 연결은 [운영 게이트](release.md#p5-69-실제-시험과-운영-적용-게이트)를 따른다.


### P5-70 교정 실패 진단

교정 실행은 기존 callId와 고정 진단 코드, 실패 단계, HTTP 상태, 허용된 provider error.code만 서버 로그로 관측한다. 응답/오류 전문·원문·키·헤더·개인정보는 로그와 공개 API에 추가하지 않는다. 진단은 과금 증거나 영구 원장을 대체하지 않으며 usage 미보고는 unknown으로 유지한다. 오류 코드만으로 호출 원장을 고치거나 자동 재시도하지 않는다. Worker 전송은 `redirect: "manual"`을 사용하고 3xx를 본문 파싱 전에 실패 처리하여 키/입력을 다른 주소로 전달하지 않는다. network 진단은 fetch 호출 거절을 뜻하며 요청 옵션 오류도 포함할 수 있으므로 네트워크 장애로 단정하지 않는다. 기존 원문/정산·사람 검수 계약은 유지한다. [구현과 검사](../work/P5-70.md#첫-실패-이후-진단-보완).

### P5-70 복구 분석을 이용한 후속 생성

검증된 보관 분석이 현재 선택된 미확정 분석이면 관리자 조회가 `recoveredAnalysisId`를 제공한다. 새 전체 요청이 같은 ID를 명시하면 기존 재사용 경로로 **비판 1회 → 사람 확정 → 요약·어린이·장년 각 1회 → 무료 배치/종료 검사**를 진행한다. 교정·의도 분석·최종 AI 감사는 호출하지 않는다. 현재 입력, metadata, 소유 설교/quiz, 봉인된 복구 출처를 서비스와 SQL에서 확인하고 다른 원문·오래된 버전·동시 변경은 거절한다.

원래 실패 작업과 rejected outcome/call/usage는 바꾸지 않는다. 새 요청의 분석 단계는 무료 전이이며 가짜 AI 성공/usage를 만들지 않는다. 같은 요청/재개를 반복해도 추가 provider 호출을 만들지 않고, 불확실한 비판 응답은 기존 실행 규칙에 따라 중단한다. 새 재사용 ID는 이전 요청의 `supersedesJobId`와 동시에 보낼 수 없다. 일반 full 생성과 옛 intent 전용 비판 재시도는 기존 계약을 유지한다.

관리자 화면은 “보관 분석으로 생성 이어가기”를 표시하고 남은 네 호출을 안내한다. 비용 확인·입력 확정·사람 의도 확정·콘텐츠 검수·발행 전 검수는 유지한다. 의도만 재생성한 비교에서는 새 root 분석을 선택하지 않은 상태의 “반영 완료” 버튼을 비활성화한다.

실제 로컬 적용 계획 v2는 기존 0000~0029 시험 DB를 대상으로 0030·0031·복구 콘텐츠를 한 트랜잭션에 적용한다. 0031은 기존 trigger 세 개만 교체한다. protected 지문에서 이 세 정의만 제외하고 해당 표의 데이터와 원래 이력은 계속 대조한다. 실제 적용·유료 호출·로컬 발행은 별도 승인 범위다. [구현·검사·실행 준비](../work/P5-70.md#보관-분석-재사용-연결과-실제-실행-준비).

### 11.1 콘텐츠 상태

```text
draft → review_ready → published → archived
          ↘ needs_revision
```

- `draft`: 자막·메타데이터·AI 초안 수집 중
- `review_ready`: 두 난이도, 개역개정 장절·공식 링크가 모든 자동 검사 통과
- `needs_revision`: 조사, 교차, 성경 장절·링크, 자막 등 하드 게이트 실패
- `published`: 발행되어 독립적인 7일 참여 기간이 진행 중인 세트. 여러 세트가 동시에 `published`일 수 있으며, 그중 `featured_quiz_set_id` 하나만 메인 최상단에 노출된다.
- `archived`: 각 세트의 `closes_at` 도달 또는 관리자 `지금 마감` 처리 후 참여 제출·순위를 확정하고 신규 기록 제출을 종료. 정답·참여 현황·코멘트·확정 Top N·출력은 누구에게나 공개하고, 새 방문자는 기록되지 않는 연습 모드로 선택적으로 풀이·채점할 수 있다.

한 설교의 어린이·장년 variant가 모두 검수를 통과해야 주간 세트를 발행할 수 있다.

`quiz_set.status`와 별도로 현재 접수 상태를 `open | paused`로 둔다. `published + paused`는 문제 오류 확인이나 수정본 준비 때문에 신규 제출만 잠시 막힌 상태이며, 이미 저장된 본인 결과를 지우지 않는다. 첫 제출 전 발행을 취소하면 세트는 `review_ready`로 돌아가고 featured에서 빠진다. 다음으로 최신인 `published + open` 세트가 있으면 메인 featured를 그 세트로 바꾸고, 없으면 최근 `archived` 세트를 읽기 전용으로 보여주거나 준비 안내만 표시한다. archived 세트의 상태를 `published`로 되돌리거나 신규 제출을 받지 않는다.

발행 시 `opens_at = published_at`, `closes_at = published_at + 7일`을 기본값으로 저장한다. 시각은 DB에 UTC로 저장하고 모든 공개·관리 화면에서는 `Asia/Seoul`로 표시한다. 여기서 7일은 발행 순간부터 정확히 7×24시간이다. 관리자는 발행 확인창에서 마감 일시를 볼 수 있고 발행 후에도 사유를 적어 변경할 수 있다. 이미 제출이 있으면 연장·단축의 영향을 경고하고 감사 로그를 남기며, 과거 시각으로 단축하면 `지금 마감`과 같은 확인 절차를 거친다.

새 퀴즈 발행은 기존 published 세트의 `closes_at`, 접수 상태, 제출, Top N을 변경하지 않는다. 따라서 발행 간격이 7일보다 짧으면 여러 퀴즈가 동시에 정상 참여를 받을 수 있다.

#### 11.1.1 설교일·발행일·영구 slug

- `sermon_date`는 성도들이 주차를 구분하는 정본 날짜이며, v1 운영에서는 주일 설교일을 뜻한다. 아카이브 카드·검색·정렬과 공개 화면의 주 날짜에는 `sermon_date`를 사용한다.
- `published_at`은 관리자가 실제로 발행 버튼을 누른 시각이다. 참여 시작·기본 마감 계산과 감사 기록에 사용하며, 공개 화면에서는 필요할 때만 `발행 YYYY년 M월 D일`처럼 작은 보조 정보로 표시한다. 아카이브의 대표 날짜나 URL에는 사용하지 않는다.
- YouTube URL에서 metadata를 가져오면 영상 제목·게시일과 설교일 후보를 함께 표시한다. 게시일은 업로드 지연 때문에 설교일의 정본으로 바로 확정하지 않는다.
- `설교 일자(주일)` date input의 초기 후보는 AI 없이 결정적으로 정한다. 영상 제목 시작 부분의 유효한 `YYMMDD` 또는 `YYYYMMDD` 날짜가 있으면 이를 우선하고(`YY`는 `20YY`), 없으면 `Asia/Seoul`로 변환한 YouTube 게시일 기준 가장 최근 일요일, 게시일도 없으면 작업 생성일 기준 가장 최근 일요일을 사용한다. 제목 날짜가 실재하는지 검증하고 게시일과 31일 넘게 차이 나면 후보는 입력하되 관리자가 확인하기 전 발행할 수 없게 경고한다.
- 관리자는 발행 전 `sermon_date`를 언제든 수정할 수 있고 선택한 날짜의 요일을 input 가까이에 표시한다. 일요일이 아니면 실수 가능성을 경고하지만 특별예배를 막지 않도록 저장·발행 자체를 금지하지 않는다.
- draft 생성 시 Web Crypto로 혼동하기 쉬운 `0/o`, `1/i/l`을 제외한 소문자·숫자 기반의 고유 문자 6자리를 한 번 생성해 저장한다. 이는 AI 호출이나 별도 package 없이 만들며 충돌하면 서버가 새 값을 생성한다.
- v1 공개 slug는 발행 시 확정한 `sermon_date`와 위 고유 문자를 결합한다. 예: `/quiz/2026-08-23-k4m7q2`. 어린이·장년용은 각각 `?level=child`, `?level=adult`를 붙이고 출력은 `/quiz/2026-08-23-k4m7q2/print`를 사용한다.
- draft에서는 날짜를 수정할 때 같은 고유 문자를 유지한 채 slug 미리보기의 날짜 부분만 갱신한다. 발행 transaction에서 전체 slug를 확정하며, 발행 뒤 제목·설교일 표시를 정정하더라도 이미 공개된 slug는 바꾸지 않아 공유 링크와 archive 주소를 보존한다. 문제 수정 revision도 같은 slug에서 현재 유효 variant를 보여준다.
- 같은 `sermon_date`의 서로 다른 설교와 퀴즈 세트를 허용한다. 고유 문자가 URL을 구별하며, 같은 YouTube video ID를 다시 입력한 경우에만 중복 영상으로 판단해 기존 작업으로 안내한다.
- slug는 식별자일 뿐 인증 정보나 보안 장치가 아니다. 정답·참여 현황 접근 권한은 기존 session·상태 검사를 그대로 사용한다.

variant 공개 수명은 다음과 같이 관리한다.

```text
active → superseded   # 첫 제출 후 수정본으로 교체된 버전
   ↘ withdrawn        # 첫 제출 전에 교체·발행 취소된 버전
```

- `active`: 현재 풀이·제출에 쓰는 난이도 revision
- `superseded`: 첫 제출 후 오류가 확인되어 수정본으로 대체된 보존 revision. 일반 아카이브와 Top N 출력에서는 제외
- `withdrawn`: 제출이 하나도 없을 때 철회된 revision. 공개 목록에서는 제외

### 11.2 관리자 주간 절차

1. YouTube URL 입력
2. video ID 형식과 중복 여부 확인
3. 영상 제목·게시 정보와 공개 자막 가져오기
4. 영상 제목에서 분리해 자동 입력된 설교 제목·유효한 성경 장절과 `설교 일자(주일)`을 확인하고 필요한 항목만 수정한다. 원래 영상 제목·게시일·추천 근거를 함께 표시한다.
5. 성경 주소를 결정적 파서 또는 선택 UI로 정규화
6. 개역개정 장절을 정규화하고 대한성서공회 공식 읽기 링크 미리보기
7. 가져온 자막 원본을 보면서 직접 수정하거나 `AI 자막 교정` 실행
8. 교정된 문서 한 벌을 사람이 읽고 필요하면 직접 수정한 뒤 `자막 확정`
9. 확정 자막을 기반으로 설교 의도 분석과 별도 비판 검토
10. 관리자가 의도 분석을 직접 수정하고 `설교 의도 확정`
11. 확정된 의도에서 AI 요약과 어린이·장년 답·단서 후보 생성
12. 관리자가 요약·답·단서·자막 근거를 직접 수정하거나 필요한 범위만 재생성
13. 난이도별 5×5~10×10과 목표 단어 수를 시험하고 선택한 배치의 교차 하드 게이트 검수
14. 어린이/장년, 데스크톱/모바일, 라이트/다크, 크게 보기 미리보기
15. 빈 격자 이미지와 복사 단서 텍스트 미리보기
16. 현재 revision 전체 발행 확인
17. D1 트랜잭션으로 새 세트를 `published + open`, `opens_at = now`, 기본 `closes_at = now + 7일`, 새 featured 세트로 전환. 기존 published 세트는 변경하지 않음
18. 각 세트가 자기 `closes_at`에 도달하면 Top N snapshot과 archive 전환을 원자적으로 수행하고 정답·참여 현황·확정 Top N·출력을 공개하며 신규 방문자에게 기록 없는 선택적 연습 채점 제공

#### 11.2.1 마감 실행과 실패 안전장치

- 공개 API와 제출 API는 DB의 status만 믿지 않고 매 요청에서 서버 현재 시각과 `closes_at`을 비교한다. `now >= closes_at`이면 archive 작업이 아직 실행되지 않았어도 신규 제출을 즉시 거부한다.
- module Worker의 scheduled handler가 마감 대상 세트를 주기적으로 찾아 `finalizeDueQuizSet`을 실행한다. handler는 구현했지만 실제 Cloudflare Cron trigger는 아직 등록하지 않았다. 같은 함수는 마감된 세트 조회 시에도 lazy fallback으로 호출한다.
- `finalizeDueQuizSet`은 idempotent D1 트랜잭션으로 난이도별 Top N snapshot을 한 번만 만들고 `status = archived`, `archived_at`을 기록한다. 중복 실행돼도 snapshot이나 순위가 중복되지 않는다.
- 관리자의 `지금 마감`은 `closes_at = now`로 바꾸고 같은 finalization을 즉시 실행한다. 제출이 있는 경우 영향을 요약하는 확인창과 사유 입력을 제공한다.
- 예약 작업이 늦거나 실패해도 마감 시각 이후 제출은 저장되지 않는다. 관리자 대시보드에는 `마감 정리 지연`을 표시하고 다시 실행할 수 있게 한다.
- 이 처리에는 AI 호출이 없고 별도 유료 저장소도 필요 없다.

### 11.3 YouTube 자막

#### 현재 운영 제약과 v1 결정 — 2026-08-13 확정

현재 운영자는 교회 YouTube 채널 관리자 계정 권한을 받을 수 없다. 영상 플레이어에 CC 버튼이 보인다는 것은 일반 시청자가 사용할 공개 caption track이 있다는 뜻이다. `AccountlessPublicTranscriptProvider`는 채널 로그인 없이 그 track의 텍스트와 timestamp를 읽는 기술 spike다.

이 provider는 공개 영상의 player 응답에서 한국어 caption track을 찾고 YouTube 내부 player/timed-text 경로로 `text, start, duration` segment를 가져온다. 수동 한국어 자막을 우선하고, 없으면 한국어 자동 생성 자막을 사용한다. 다른 언어를 AI로 번역해 한국어 자막인 것처럼 저장하지 않는다.

이는 YouTube가 외부 개발자에게 안정성이나 사용 권한을 보장하는 공식 `captions.download` 계약이 아니다. 공식 API의 caption 다운로드는 해당 영상을 편집할 수 있는 OAuth 권한을 요구한다. 계정 없는 라이브러리는 watch/player/timed-text 내부 경로를 자동으로 읽는 방식이라 형식 변경이나 Cloudflare 데이터센터 IP 차단으로 CC가 있어도 실패할 수 있다. YouTube 이용약관은 명시적 허용이나 사전 서면 허가 없는 콘텐츠 다운로드·자동 접근을 제한하고, API 개발자 정책도 scraping과 시청각 콘텐츠 다운로드·오디오 분리를 제한한다. 따라서 이를 `CC가 있으면 별문제 없이 항상 성공하는 공식 기능`으로 설명하거나 출시 확정하지 않는다.

production 채택 전에는 다음을 모두 확인한다.

1. 실제 교회 영상의 저작권자 또는 운영 주체에게 이 개인 프로젝트가 공개 설교 자막·음성을 AI 분석에 사용하는 것에 대한 포괄적 허락을 받는다. 매주 원고 요청 대신 한 번의 운영 허락을 목표로 한다.
2. 계정 없는 자동 추출을 사용한다면 YouTube 약관 위험을 운영자가 이해하고 수용할지 결정한다. 교회 허락은 콘텐츠 권리 문제를 줄이지만 YouTube 플랫폼의 자동 접근 제한까지 없애지는 않는다.
3. 실제 Cloudflare 환경 성공률과 차단 여부를 측정한다.
4. 위험을 수용하지 않거나 성공률이 낮으면 관리자에게 YouTube의 `스크립트 표시` 내용을 직접 붙여넣게 하는 경로를 사용한다.

공식 참고: [YouTube 이용약관](https://kr.youtube.com/t/terms), [YouTube API 개발자 정책](https://developers.google.com/youtube/terms/developer-policies), [공식 captions.download 권한](https://developers.google.com/youtube/v3/docs/captions/download)

Phase 0의 Production 채택용 기술 검증은 로컬 성공만으로 통과시키지 않는다. P5-05는 2026-09-08 사용자 요청에 따라 합성 응답 기반의 로컬 adapter·실패 분류까지만 완료 대상으로 삼는다. 아래 실배포 검증은 별도 승인 후 수행할 출시 전 게이트로 유지한다.

1. 실제 Cloudflare Workers Preview 환경에 배포한다.
2. 교회 영상과 공개 한국어 영상에서 수동 자막·자동 자막을 각각 시험한다.
3. timestamp, 전체 segment 수, 앞·중간·끝 표본을 YouTube 화면과 비교한다.
4. 같은 영상을 여러 번 호출해 IP 차단과 일시 오류를 구분한다.
5. package를 쓴다면 license, 최근 유지보수, transitive dependency, Worker compatibility를 검토하고 버전을 고정한다.
6. YouTube 약관·교회 영상 이용 범위를 출시 전에 다시 검토한다.

무료 공개 CORS proxy는 자막 URL 유출, 무보장, 갑작스러운 종료 위험이 있어 production fallback으로 사용하지 않는다. headless browser를 상시 실행하는 별도 서버도 v1에 추가하지 않는다. 2026-10-03 사용자 요청으로 기존 로컬 Chromium의 화면 버튼 자동 클릭·스크립트 읽기·비공개 파일 저장 가능성을 실증했다. 이는 사용자 직접 복사로 목표를 바꾸는 결정이 아니며 새 상시 서버 채택도 아니다. 반복 운영의 실행 위치와 관리자 입력 연결은 아직 미완료다. [실제 근거](../work/p8-02/browser-transcript.md).

관리자 화면은 위의 사람이 읽기 쉬운 안내를 먼저 표시하고, 바로 아래에 접을 수 있는 `기술 정보`와 `AI에게 전달할 진단 정보 복사`를 제공한다. 운영자는 개발 용어와 상세 오류를 보는 것을 허용하므로 단순 code 하나만 보여주지 않는다.

`기술 정보`에 표시할 항목:

- 발생 시각(KST와 UTC), 배포 version·Git commit, Cloudflare colo
- video ID, provider 이름·고정된 version, 실행 단계와 attempt 번호
- `generationJobId`, Workflow instance ID, requestId, 오류 fingerprint
- 단계별 시작·종료·소요 시간과 `메타데이터 → player 응답 → caption track 탐색 → timed-text 요청 → parsing → 저장` timeline
- upstream HTTP status, content-type, 응답 byte 수, redirect 수, timeout·DNS·TLS·rate-limit 구분
- 발견한 caption track 수, 언어 code, 수동/자동 여부. 자막 URL 자체와 원문은 표시하지 않는다.
- parser 실패 위치, 기대한 field/path, 실제로 관찰한 key 목록, schema/version 불일치 정보
- 자동 재시도 횟수·다음 재시도 시각·마지막 실패 단계
- 비밀값을 제거한 stack trace의 상위 frame과 안전한 오류 cause chain

`AI에게 전달할 진단 정보 복사`는 위 내용을 구조화된 JSON 또는 plain text 한 덩어리로 clipboard에 복사한다. 관리자가 다른 AI 대화에 그대로 붙여넣어도 다음 값은 포함하지 않는다.

- Cloudflare Access JWT, cookie, session token, Turnstile token
- OpenAI·YouTube·Cloudflare API key와 Authorization header
- signed caption URL과 query parameter, visitor/session 식별값
- 전체 upstream raw body, 전체 자막, AI 응답 전문, 참여자 정보

형식 변경 진단에 응답 일부가 꼭 필요하면 raw body 대신 redaction 후 최대 4KB의 text excerpt, key shape, 전체 body SHA-256만 저장·표시한다. excerpt는 HTML로 해석하지 않고 code block의 text로 렌더링한다. secret·URL query·email·cookie 패턴을 제거한 뒤에도 안전성을 확신할 수 없으면 excerpt를 생략하고 hash와 구조만 남긴다.

관리자에게는 `다시 시도`, `진단 정보 복사`, `텍스트 직접 붙여넣기`를 함께 제공한다. 수동 다시 시도 횟수는 제한하지 않으며, 동일 attempt의 자동 재시도만 유한 backoff로 종료한다.

위 실패에서는 자막 내용을 추측하지 않는다. 최근 업로드라면 YouTube 자동 자막 처리가 끝나지 않았을 수 있으므로 `나중에 다시 확인`을 먼저 안내한다. 자동 자막은 한국어를 지원하지만 품질이 일정하지 않고 처리 완료 시점도 보장되지 않으므로 관리자가 원문과 표본을 확인한다.

계정 없는 v1 provider는 YouTube에 이미 공개된 수동 자막을 우선하고, 없으면 이미 생성·공개된 한국어 자동 자막 track을 읽는다. 우리 사이트가 YouTube에 자동 자막 생성을 요청하거나 즉석에서 생성하는 것은 아니다. YouTube의 공식 `captions.download`는 영상 편집 권한이 있는 OAuth 사용자를 요구하므로 현재 조건에서는 사용하지 않는다.

공개 자막이 끝내 없을 때의 fallback 우선순위는 다음과 같다.

1. 월 USD 0: YouTube `스크립트 표시` 전문, 받을 수 있는 설교 원고·요약본을 관리자 textarea에 직접 붙여넣는다. `YouTube 스크립트`, `설교 원고`, `설교 요약본` 중 source type을 선택하고 내용을 미리본 뒤 확정한다. 요약본만 사용한 결과는 `전체 영상 자막 기반`이라고 표시하지 않고 `partial_notes`로 남긴다. TXT·VTT·SRT 파일 업로드는 v1에서 제외한다.
2. 합법적으로 사용할 수 있는 MP3·MP4·M4A·WAV·WebM 등 원본 녹음 파일이 있다면 관리자 전용 `음성 파일 전사`를 실행한다. OpenAI 파일 전사 API는 YouTube URL이 아니라 실제 audio/video file upload를 받으며 현재 파일당 25MB 제한이 있으므로 긴 설교는 브라우저 또는 임시 처리 단계에서 분할해야 한다.
3. YouTube URL만 있는 경우 `gpt-transcribe`, `gpt-4o-transcribe`, Whisper에 URL을 직접 건네 전사할 수 없다. 먼저 YouTube audio bytes를 확보해야 하는데, yt-dlp류 downloader를 서버에 넣는 것은 기술적으로 가능해도 YouTube 자동 접근·다운로드 제한, 데이터센터 IP 차단, 형식 변경 위험 때문에 production 기본 경로로 만들지 않는다.
4. 추후 교회가 원본 녹음 파일 공유나 채널 OAuth를 허용하면 공식·안정 경로로 교체한다.

음성 전사는 `gpt-5.6-terra`가 직접 하는 일이 아니다. 별도의 speech-to-text 모델이 transcript를 만든 뒤 Terra가 그 텍스트를 분석한다. 파일이 확보되면 AI transcript 생성 자체는 확실히 구현할 수 있지만, 전사 문구의 100% 정확성은 보장할 수 없으므로 성경 인명·지명·고유명사는 검수한다. OpenAI 공식 문서는 현재 녹음 파일 전사에 `gpt-transcribe`부터 시작하라고 권장하며, 정확도·한국어·비용 비교에서 `gpt-4o-transcribe`, mini, Whisper도 시험한다. 공식 참고: [OpenAI 파일 전사](https://developers.openai.com/api/docs/guides/speech-to-text)

계정 없는 추출이 약관 검토에서 채택되지 않거나 production에서 반복 차단되면 22장의 후속 작업 순서에 따라 먼저 월 USD 0인 원고·요약본·YouTube 표시 스크립트 붙여넣기를 사용한다. 원본 음성 파일이 확보될 때만 AI 전사를 제안하고, 유료 transcript API 또는 residential relay는 URL 음원 획득의 약관 문제를 대신 해결해 주는 것이 아니므로 사용자 승인 없이 추가하지 않는다.

현재 참고 후보들은 공개 자막을 내부 player/timed-text 경로로 가져올 수 있다고 설명하지만, 일부는 Cloudflare Workers 같은 데이터센터 IP가 차단될 수 있음을 명시한다. 그러므로 실제 배포 spike가 출시 게이트다. 참고: [Cloudflare Worker 구현 사례](https://github.com/youtube-transcript-plus/youtube-transcript-api), [서버리스 IP 차단을 명시한 TypeScript 구현](https://github.com/hallelx2/youtube-transcript-ts), [YouTube 공식 자막 다운로드 권한 조건](https://developers.google.com/youtube/v3/docs/captions/download)

#### 입력자료 용어와 수정 범위 — 2026-09-15 확정

`설교 입력자료`는 설교 자막·설교 원고·제공받은 설교 요약본의 통칭이다. `설교 원고`를 세 종류의 통칭으로 쓰지 않는다. `제공받은 설교 요약본`은 처음 입력하는 자료이며 앱이 이후 생성하는 `AI 요약 초안`과 다르다. 처음 가져온 자료를 저장하는 것은 발행이 아니다.

| 입력자료 | 식별 기준 | 입력자료 내용의 수정·교정 |
|---|---|---|
| 설교 자막 | `public_unofficial` 또는 `manual_paste + youtube_visible_transcript` | 원본은 보존하고 별도 자막 작업본에서 직접 수정·선택적 AI 교정·수정본 복원 가능 |
| 설교 원고 | `sermon_notes + sermon_manuscript` | 목사님께 받은 그대로 사용. 직접 수정·AI 교정·교정 반영·편집본 복원 대상 아님 |

#### 저장 처리 범위 축소 — 2026-09-15 확정

D-031은 다음 네 가지를 채택한다. 아래 날짜가 붙은 P5-07~P5-27 구현 기록 중 초기 동일 내용 작업 revision 생성·매 저장 전체 이력 검사·정상 성공 뒤 본문 재조회 요구를 대체하며, 과거 완료/계측 사실은 삭제하지 않는다.

1. **최초 원본 단독 저장:** 자막을 처음 가져올 때 원본만 저장하고 같은 내용의 `imported` 수정본을 별도로 만들지 않는다. 실제 수정 내용을 저장할 때부터 수정본을 추가한다. 수정하지 않은 자막도 그대로 확인·확정할 수 있어야 하며 이를 위해 가짜 수정본을 생성하지 않는다. 확인/분석에 쓰는 현재 입력의 식별은 원본 또는 실제 수정본을 구별해야 한다. D-030의 목사님 제공 원고·요약본은 수정 경로를 제공하지 않는다. 기존 DB에 있는 초기 revision을 소급 삭제하지 않는다.
2. **저장에 필요한 범위만 검사:** 인증된 호출자·설교 소유권·현재 source/수정번호/version과 새 내용의 strict 형식/크기/Unicode 등 필요한 입력 검증을 유지한다. 자막 구간의 ID·시간 보존, AI 제안 반영 시 바탕 자막/선택 제안 등 해당 명령에 필요한 자료는 읽되 무관한 과거 본문·교정/확정 이력을 전부 읽어 재생·검사하지 않는다. 복원은 지정한 과거 본문만 필요한 참조와 함께 읽는다. 별도 전체 이력 검사 기능과 원본/수정 이력은 보존한다. 일반 저장에서 무관한 과거 손상을 발견하는 보장은 제거되며, 이를 기존과 동일한 전체 검증이라고 표시하지 않는다. 부분 배열을 기존 전체 state인 것처럼 반환하는 우회는 금지한다.
3. **정상 저장 뒤 본문 재조회 0회:** 원자 batch의 응답이 전부 있고 각 statement의 성공/실제 변경 행 수가 예상과 일치하면 저장을 완료한다. 단순 성공 boolean·현재 head·본문 hash 하나만으로 성공을 추측하지 않는다. 응답 유실·불완전 응답·결과 불일치는 해당 저장 시도의 durable 기록으로만 확인하고, 확인할 수 없으면 uncertain으로 중단한다. 다른 요청의 성공이나 이동한 최신 head를 자기 성공으로 사용하지 않으며 자동 replay하지 않는다. DB의 원자성/불변 제약과 실패 rollback은 계속 필요하다.
4. **diff는 요청 시 두 본문만:** 원본↔현재 수정본, 선택한 수정본↔다른 수정본, AI 제안 전↔반영 예정 내용 중 사용자가 요청한 한 쌍만 비교한다. 저장 때 diff를 미리 계산/저장하지 않는다. AI 제안의 대상 구간 검증은 저장 무결성이나 사용자용 diff 계산과 구별한다.

수정본 `현재 1개+직전 2개` 자동 삭제 안은 **폐기**한다. 보관 개수 cap을 도입하거나 오래된 수정본을 잘라내지 않는다. 기존 초안 7일 정리 및 source별 text 보존 조건, 사람 검수·상위 변경 시 재검토·발행 기록의 독립 보존은 변경하지 않는다.

**현재 구현 경계:** P5-28~30에서 원본 단독 저장·선택 읽기·자료별 수정 제한과 관리자 입력 API/UI·선택 문서의 브라우저 diff를 로컬 연결했다. 기존 전체 state 경로/이력은 보존하며 실제 AI·전체 Workflow·운영 DB 적용은 별개다. 최신 검사는 [STATUS](../STATUS.md)를 따른다.

- 형식이 맞는 초안의 품질은 관리자가 읽고 수정·채택한다. 마음에 들지 않거나 생성이 실패하면 관리자가 해당 작업 버튼을 눌러 새로 생성한다. 자동 재호출·자동 품질 판정 단계를 추가하지 않는다. 기존 결과와 관측한 비용은 보존하며, 단순 중복 요청과 관리자의 명시적 새 생성은 구분한다.
- **별도 최종 AI 감사 호출·불일치 경고 보고·발행 전 감사 비용은 제품 흐름에서 제외한다.** 요약과 답·단서의 최종 판단은 사람이 한다. 정답/격자 일치·공개 정답 누출 같은 코드 검사는 유지한다. 앞단 의도 분석의 기존 비판 검토는 이번에 제거하라는 지시가 아니므로 유지하고, 새로운 검토 호출은 추가하지 않는다.
- 현재 코드/테스트/DB 계약에는 과거 항목별 교정 호환과 `final_audit`가 남아 있다. 새 교정 결과는 문서형 로컬 경로로 저장한다. 보관소의 과거 구현 기록을 새 제품 흐름의 완료 증거로 쓰지 않는다. 문서 변경만으로 기존 DB guard를 우회하거나 운영을 연결하지 않는다.

v1 기본 제공자는 OpenAI API, 모델은 `gpt-5.6-terra`다. `reasoning.effort`는 설교 의도 파악을 우선해 `high`로 시작하고 Phase 0의 실제 설교 평가에서 품질·비용·지연 시간을 함께 기록한다. 코드에서는 `AiDraftProvider` adapter 뒤에 두어 향후 모델 교체가 전체 Workflow를 바꾸지 않게 한다.

AI에 보내도 되는 데이터:

- 공개 설교 자막
- 설교 메타데이터
- 난이도·명사·단서·배치 JSON 스키마

AI에 보내지 않는 데이터:

- 성경 본문 전문
- 참여자 이름·코멘트·답안
- 관리자 이메일과 비밀값

AI는 다음을 JSON structured output으로 반환한다.

- 설교의 중심 주장, 설교자가 청중에게 기대하는 반응, 논지 전개, 반복 강조, 적용과 주의점
- 위 분석에 근거한 설교 요약 초안
- 난이도별 명사 후보와 단서
- 각 후보의 자막 근거 구간
- 어린이/장년 난이도 설명

#### 간결한 생성 결과의 연결 계약

P5-48에서 정리한 기준이다. P5-49에서 교정의 로컬 경로를, P5-50에서 새 전체 생성/finish의 로컬 경계를 연결했다. 당시 검토 근거는 [P5-48 검토 결과](../work/P5-48.md)에 보존하며 현재 구현·남은 범위는 [STATUS](../STATUS.md)를 따른다.

**P5-51 현재 실행 연결:** OpenAI Responses HTTP transport는 기존 모델/high와 `store: false`, strict JSON Schema를 사용한다. 제공자에 보내는 최상위 객체는 `{ draft: <작업별 결과> }`이고 adapter가 draft를 꺼내 기존 Zod·출처 검사를 적용한다. AI 출력 schema에서 사람만 작성하는 `admin_context` 분기를 제외한다. 6개 작업의 전송 계약과 교정 전용 실행, 전체 v3의 분석·비판 → 사람 선택/수정/확정 → 명시적 재개 → 요약·두 후보 → 사람 내용 검수 → 배치·코드 최종 검사·finish를 실제 D1/Workflow와 관리자 UI/API에 연결했다. 초기 intent v2 진입점은 비공개 호환 함수로 유지한다. 옛 full/audit 작업은 새 실행기로 자동 이어가지 않는다.

Access 관리자 GET/POST `/api/admin/sermons/:id/generation/correction`은 실행 가능 상태 조회와 교정 요청, GET `/api/admin/sermons/:id/generation/:jobId`는 해당 설교 작업의 상태·관측 비용만 제공한다. POST는 same-origin JSON을 요구한다. 서버가 현재 입력·metadata·quiz 소유 관계를 읽고 명시적 requestKey 하나를 한 작업/전송/호출에 연결한다. 작업 상태 조회는 새 호출을 만들지 않는다. 별도 활성화 값과 Workflow 연결이 없으면 실행 버튼/API가 비활성이다. 전체 생성은 `/generation/content` GET/POST, 사람 검수는 `/generation/:jobId/review`, 명시적 재개는 `/resume`, AI 비용 없는 배치/최종 검사는 `/finish`를 쓴다. 요청은 배치 설정을 고정하고 화면은 예시 비용과 서울 월요일 기준 주간/작업별 관측 비용·사용량 미확인 횟수를 표시한다. 실제 실행기는 키도 요구한다. 현재 원격 설정은 변경하지 않았고 로컬 opt-in 설정도 기본 false다.

**P5-52 배치 선택·발행 전 검토 연결:** 최초 요청의 배치 설정은 불변으로 보존하며, 생성 후에는 검수된 요약·두 후보에서 AI 없이 설정을 바꾸고 추천/대안을 시험·선택한다. 관리자 `placement-trial`은 현재 자료와 설정으로 실제 격자·보고를 만들고, `placement-select`는 두 난이도의 선택을 현재 입력/metadata/선택 revision과 대조해 저장한다. 0016의 불변 `generation_placement_selections`는 기존 봉인된 final ticket과 관리자 digest를 참조한다. 현재 reader와 조건부 저장은 최신 선택 revision을 확인하며 옛 request context/job의 최초 설정 revision을 재작성하지 않는다. 생성 완료 전 선택은 v3 최종 검사/finish에 반영한다. 완료 뒤 재배치는 최신 ticket을 다시 검사하고 옛 완료 증거를 보존한다. 내용 변경 뒤 옛 ticket은 현재 검토를 통과하지 못하며 다시 검수/배치를 선택해야 한다. 관리자 최종 화면은 두 격자·정답 보기·단서·메타데이터·요약/고지를 보여주고 공개용 preview와 관리자 전용 solution을 분리한다. 실제 발행·출력 파일 생성은 별개다. [코드·검사](../work/P5-52.md).

**P5-53 개별 재생성 연결:** 요약/어린이/장년은 기존 v2 scope의 별도 작업으로 1회만 실행한다. 현재 확정 입력·의도를 캡처하고 같은 key 재생, 관측 usage, 근거 검증, 오래된 바탕 거절을 기존 lifecycle/domain 저장으로 확인한다. 기존 full 작업/최초 설정/선택본/검수/완료 증거를 덮지 않으며 생성 결과는 비교용이다. 사람 선택/수정 때 해당 검수가 무효화되고 현재 배치 ticket도 다시 검사한다. 비교 자료 추가도 content revision을 올리므로 옛 final ticket은 현재 preview로 쓰지 않는다. 0017은 full v3의 내용 검수 대기와 같은 설교/퀴즈의 부분 작업 하나만 공존하도록 단일 active index를 조정하고 별도 SQL guard를 추가한다. 다른 동시 실행과 부분 실행 중 full의 다음 단계/완료는 차단한다. 관리자 content 조회는 현재 선택·필요 의존 자료와 과거 결과 한 페이지만 읽고 이전 페이지로 비교 결과를 선택한다. 실제 유료 호출·발행·원격 적용은 별개다. [코드·검사](../work/P5-53.md).


Workflow step의 자동 재시도는 0회이며 현재 step 30분, provider 호출당 9분이다. 전체 경로는 의도 단계 두 호출, 사람의 명시적 재개 후 요약/후보 세 호출을 순차 실행하며 `waitForEvent`로 검수 대기를 이어간다. 각 단계가 공개 발행을 수행하지 않는다. provider 호출 직전 durable call을 저장하며, 사용량은 본문 해석보다 먼저 보존한다. 거절·잘못된 결과·입력 변경에도 관측 비용을 남기고 응답 유실은 사용량 미확인으로 표시한다. timeout 후 도착한 usage는 기존 호출에 정산하며 늦은 문서를 채택하지 않는다. 불확실한 호출의 명시적 새 요청은 옛 작업 ID를 `supersedesJobId`로 지정하고 옛 호출/비용을 보존한다. 중단으로 결과 기록이 없으면 실행 lease 만료를 확인해야 하며 진행 중 호출을 자동 재전송하지 않는다.

### P5-70 근거 문자 위치는 프로그램이 계산

2026-09-28 사용자가 위치 전체를 프로그램이 찾고, 찾지 못한 근거는 표시만 하며 저장과 후속 진행을 유지하도록 확정했다. 2026-09-25의 문자 위치 계산 정책을 확장한다. AI는 분석·비판·요약·후보의 내용과 짧은 실제 인용문 `quote`만 반환한다. 구간 ID·시각·`from/to`는 출력에서 요구하지 않는다. 새 프롬프트는 `sermon-draft-v3`, 출력 schema name은 작업별 `*_v3`이며 Terra/high·사용량 선기록·자동 재호출 금지는 유지한다.

프로그램은 호출 전에 고정한 전체 입력을 검색한다. 시간 자막에서는 모든 구간을 검색해 유일한 정확 일치의 구간 ID·start/duration과 구간 내 UTF-16 시작 포함/끝 제외 위치를 계산한다. 시간 없는 자료는 전체 본문의 위치를 계산한다. 공백·구두점·Unicode를 바꾸거나 서로 다른 구간을 합치지 않는다. 여러 구간의 중복과 겹치는 중복도 모호한 일치다. AI가 보낸 옛 위치값으로 첫 번째 일치나 특정 구간을 임의 선택하지 않는다.

없는 인용은 `locationStatus=unverified, reason=not_found`, 복수 일치는 `reason=ambiguous`로 저장한다. 인용문을 그대로 남기고 모든 위치값은 null로 둔다. 관리자에게 **위치 미확인**과 사유를 표시하고 정확한 원문/영상 위치 링크는 만들지 않는다. 수동 위치 교체는 가능하지만 의무가 아니다. 미확인 개수에 따른 새 상한·전체 저장 실패·추가 검수 승인·재생성 요구를 만들지 않는다. 위치 미확인은 인용 내용이 참이라는 보증도, 의미 해석의 `origin=unresolved`도 아니다.

의도 확정, 요약/후보 저장·검수·후속 생성·배치/발행은 위치 미확인만으로 막지 않는다. 요약/후보의 실제 의도 claim ID 연결은 검사하며 인용 위치 미확인 때문에 그 연결을 거부하지 않는다. 분석에서 사용한 인용과 요약/후보 인용이 같은 문장일 필요는 없다. 각각 확정 원문을 기준으로 검증한다. v4 provider schema는 제공된 transcript 주장 ID만 enum으로 허용한다. 보관 결과의 명백한 `warnings-N`→`warning-N` 오타는 실제 ID가 유일하게 존재할 때만 연결한다. transcript 주장 연결이 남는 문단/후보에서 함께 잘못 참조한 `unresolved` 항목은 근거에서 제외하고 처리 내역을 남긴다. unknown/admin ID를 추정하거나 미확정 근거만으로 결과를 정당화하지 않는다. 원래 문장과 인용문은 보존한다. Zod 형식·자료 출처/버전·동시 변경·이미 확인된 위치의 원문 일치 검사는 유지한다. 일반 사람 최종 내용 검수가 품질 판단이다. 공개 응답에 비공개 인용·상태가 섞이지 않는다. 이미 저장된 자료와 사람의 위치 선택은 재계산하거나 덮어쓰지 않는다.

보관 v1/v2/v3/v4 응답도 현재 규칙으로 무료 재검사한다. 원응답/요청 지문·실제 실패/호출/정산을 보존하고, 기존 실패를 성공으로 수정하지 않는다. 0032는 기존 복구·내용 저장·재사용·검수 대기 trigger 네 개를 확장해 보관 비판도 별도 복구 event로 저장한다. 새 표는 없다. `recoveredAnalysisId`에 대응하는 `recoveredCritiqueId`를 명시한 새 full 요청은 분석·비판 호출 없이 기존 사람 확정으로 넘어가고 요약·두 난도만 생성한다. 출처·같은 원문/metadata/분석 계보와 정산을 다시 확인한다. [D-034](../DECISIONS.md#d-034--ai-근거의-문자-위치는-프로그램이-계산) · [현재 구현·검사](../work/P5-70.md#전체-원문-위치-검색과-진행을-막지-않는-표시).

2026-09-27 로컬 복구 준비 도구는 보관 당시 파일 지문·원래 프롬프트 지문을 고정하고, 기존 lifecycle reader로 failed full v3의 rejected 분석/호출/정산 usage와 결과 부재를 검증한다. 원래 step 문맥과 현재 확정 입력·내용·metadata·선택, 응답의 토큰 수를 대조한 뒤 원래 응답을 현재 provider/domain 검사에 통과시킨다. 소수 timestamp가 있는 자막은 문맥용 정수 codec이 아닌 기존 domain codec으로 비교한다. 결과는 비공개 검수 파일과 준비 자료이며 저장 권한·사람 승인·비판 완료를 뜻하지 않는다. 보관 파일 지문은 기존 목록과의 일치 증거이고 provider 서명 인증은 아니다. DB를 readOnly로 열고 새 호출/usage/콘텐츠 event를 쓰지 않는다. 앱 복구 저장은 아래 별도 원자 저장 경로로 연결하며 실제 자료 적용 전에는 준비 단계로 남는다. [복구 준비·검사](../work/P5-70.md#보관-분석의-무료-복구-준비와-로컬-검수).

### P5-70 보관 분석의 별도 복구 저장

0033은 보관 요약에도 같은 경로를 적용한다. 기존 복구/내용 event 삽입 trigger 두 개만 확장하며 새 테이블은 없다. 원래 실패와 과금은 유지되고 요약의 무료 복구는 사람 내용 검수나 전체 작업의 finish 성공을 뜻하지 않는다. 이후 두 난도는 기존 개별 생성 경로를 사용할 수 있다. [실제 저장·두 난도 실행](../work/P5-70.md#보관-요약-무료-저장과-두-난도-실제-생성).

`commitArchivedIntentRecovery`는 인증된 로컬 운영 작업에서 호출할 내부 함수이며 공개/API/Workflow 자동 경로에 노출하지 않는다. 현재 검수 package를 저장 허가로 받지 않고 원래 request/response와 고정 지문을 다시 검사한다. 기존 domain 읽기/prepare/AI artifact 저장 계획을 재사용하고, 0030/0032/0033의 `generation_archived_intent_recoveries` 출처 기록과 새 AI 분석·비판·요약 event/payload/lineage/current를 같은 D1 batch에 저장한다. 원래 job은 failed, outcome은 rejected, provider call/usage는 원래 값으로 유지하며 새 call/usage/dispatch나 사람 확정을 만들지 않는다.

복구 기록은 원래 job/step 문맥/attempt/call/usage, 보관 파일·프롬프트·새 payload 지문, 적용한 운영자 digest/시각을 묶는다. 같은 source job에는 복구 1개만 저장하고 동일 자료/운영자로 재요청하면 검증 후 기존 결과를 반환한다. 입력·콘텐츠 head·metadata revision·선택 revision·미발행 상태·정리 여부·다른 실행 중 작업은 batch 안에서도 검사한다. 복구 기록과 event 사이의 지연 외래키 및 기존 봉인 규칙으로 둘 중 하나만 남는 것을 막는다. 여러 SQL assertion으로 D1 식 깊이 제한을 지키며 검사를 생략하지 않는다.

조회 시 정상 AI 결과는 기존 success 증거를 그대로 요구하고, 복구 event만 별도 불변 출처와 원래 rejected/정산 증거를 검증한다. 관리자 콘텐츠 조회에는 복구 결과가 나타나지만 원래 작업 상태를 검수 대기로 위장하지 않는다. 복구 자체는 새 비판 호출이나 사람 확정을 만들지 않으며 기존 failed 작업의 resume·재호출 제한도 완화하지 않는다. 이후 승인된 새 요청이 복구 분석/비판을 재사용해 기존 사람 확정·후속 단계로 이어간다. 실제 운영 적용과 유료 실행은 사용자의 현재 승인 범위를 따른다. [저장 구조](data-model.md#p5-70-보관-분석-복구-출처) · [구현·검사](../work/P5-70.md#보관-분석의-원자-저장과-앱-조회-연결).

로컬 시험 적용 도구는 `scripts/apply-archived-intent-recovery.mjs`다. plan은 실제 DB를 읽기 전용으로 검사해 코드/SQL/보관/DB 지문과 새 복구 event를 고정한다. 승인된 apply는 같은 OS 운영자/계획을 대조하고 검증된 개인 사본을 만든 뒤, 0030~0033 중 아직 적용되지 않은 migration과 복구 저장을 한 SQLite 트랜잭션으로 적용한다. 계획 v3는 기존 migration 목록을 고정하며 이미 적용한 SQL을 반복하지 않는다. 기존 원장 등 변경 대상 밖의 표를 재검사하고 실패 시 구조 변경까지 취소한다. 재실행은 출처가 일치하는 저장 결과만 반환한다. 추가 AI 호출/사람 확정/원격 적용을 포함하지 않는다. [실행·검증·rollback](../work/P5-70.md#원래-시험-db의-로컬-적용-도구와-사전-점검).

**P5-70 진단 보강:** 의도 경로는 provider/형식 실패와 domain/근거 검증 실패의 고정 코드를 구별한다. 로그에는 비공개 본문·임의 오류 메시지·비밀값을 포함하지 않는다. 실제 시험의 응답 보관/오프라인 재검사는 Git 밖 개인 폴더와 로컬 시험 entry에서만 명시적으로 연결하며 기본 앱/원격 환경에는 활성화하지 않는다. 검증·과금·자동 재호출 금지 계약은 유지한다. [연결 방법·검사·한계](../work/P5-70.md#추가-과금-없는-실패-진단응답-보관-보강).

시간 자막의 원본 checksum(텍스트+시간)과 작업 문서 checksum(텍스트)은 구분한다. 새 context input 참조는 필요할 때만 선택적 `sourceSha256`을 포함하고, 저장소가 봉인된 원본 payload에서 재검증한다. 옛 context의 필드·바이트·hash는 다시 쓰지 않는다. 교정 문서는 소수점 시간을 보존하는 codec과 기존 입력 저장의 16KiB chunk/64MiB 기술 범위를 사용하며 실제 byte/chunk/statement 수를 확인한다. 옛 일반 결과용 128KiB를 새 교정 출력 상한으로 쓰지 않는다. 분석·비판은 실제 D1 reader가 검증해 고정한 자료에서 준비한 domain 결과만 기존 content 저장에 넣고, 64KiB chunk·64MiB 기술 범위의 실제 크기를 측정한다. 저장 envelope hash와 snapshot hash를 별도로 검증한다. 새 content의 선택 필드 `availableCritique`는 비교할 비판 결과이고, `intent.critique`/confirmation은 선택된 내용/사람 확정에만 해당한다. 기존 context에는 이 필드를 보충하지 않는다. 같은 검증·저장 경계를 요약·후보와 사람 선택/수정/확정에 적용한다. 0015의 새 불변 계보 표는 비판 수정본과 사람 수정본의 원래 분석/비판을 기록하며 옛 행은 backfill하지 않는다. 검수 대기 뒤의 사람 명령을 실제 봉인된 기록에서 재현한 증명 연쇄가 맞을 때만 하위 검수 무효화를 인정한다. 이전 bridge의 일반 비교를 느슨하게 바꾸지 않는다. [코드 진입점·검사·남은 범위](../work/P5-51.md).

**교정 출력:** 시간 없는 자막은 `{ "format": "plain_text", "text": "교정한 본문" }` 한 벌을 받는다. 시간 있는 자막은 `{ "format": "timed_segments", "segments": [{ "segmentId": "원래 ID", "text": "교정한 구간" }] }`로 같은 문서의 각 구간을 한 번씩 받는다. 원문과 수정문·이유·confidence·riskFlags를 항목마다 출력하지 않는다. 구간별 start/duration은 서버가 보관한 값에서 가져오며 LLM이 시간을 다시 쓰지 않는다. 구간 ID·순서·개수 일치와 비어 있지 않은 본문을 검사하고, 변경할 곳이 없으면 같은 내용도 정상 결과로 받는다. 구간 결과는 관리자에게 한 문서로 보여준다.

프롬프트에는 자동 자막 오류만 교정하고 원래 의미·성경 용어·숫자·부정을 보존하도록 명시한다. 서버는 응답 형식·자료 종류·원래 구간 연결·기존 30,000자 기준을 검사한다. 문장의 의미를 기계적으로 보증한다는 주장은 하지 않으며 사람이 읽고 판단한다. 원고·제공 요약본 수정 금지와 직접 수정만으로 확정하는 경로를 유지한다.

**저장과 채택:** 기존 `sermon_input_events`의 `proposal`과 chunk 저장을 재사용한다. 새 payload는 `kind: "correction_document_v1"`로 구별하고 원래 source ID/hash·base document ID/hash·서버가 재구성한 `TranscriptContent`를 가진다. ID·버전·사람 신원·usage는 서버가 붙이며 LLM 출력에서 받지 않는다. 기존 `items` payload는 옛 형식으로만 읽고, 새 payload를 항목 목록으로 변환하거나 이유/신뢰도를 만들어 채우지 않는다.

생성 성공 시 제안·관측 usage/비용·호출 결과 연결·작업 성공을 기존 원자 저장 경계에서 함께 확정한다. 전체 작업 중 교정이면 기존 새 자막 검토 대기까지 함께 기록한다. 제안 등록은 입력 version만 올리고 현재 document/확정본은 그대로 둔다. 기존 `correction_proposal` 결과 참조와 event.kind를 재사용한다. P5-49에서 로컬 codec·검증·상세 응답은 새 payload를 구분하도록 연결했으며, 실제 provider/Workflow·원격 저장 호환 검증은 별개다.

관리자는 교정 문서를 읽고 필요하면 수정한 뒤 `이 교정본 사용`을 선택한다. 새 `apply_correction_document` 명령은 proposal ID·현재 version/source/document/hash·`reviewed: true`를 받고, 직접 고친 경우 수정 content도 받는다. 서버가 저장된 제안의 원래 바탕과 현재 본문, 사람 권한·출처·구간·입력 제한을 확인한 뒤 **한 번의 조건부 저장**으로 `merge` 수정본을 만들고 `related_id`에 제안을 연결한다. 현재 document를 새 수정본으로 바꾸고 기존 confirmation을 비운다. 그 뒤 별도의 기존 `자막 확정`으로 사람이 최종 확정한다. 교정 항목별 decision 행은 만들지 않는다.

생성 중/채택 전에 바탕 본문이 바뀌면 자동 재적용하지 않는다. 이미 정상 저장한 제안·원본·비용은 보존하고 최신 본문에서 사람이 다시 작업한다. 채택하지 않은 결과도 기존 초안 보존 정책을 따른다. 화면에서는 새 교정 문서와 옛 항목별 이력을 구분하고, 과거 항목의 보기/결정/병합 호환을 유지하되 새 생성은 문서 형식만 사용한다. diff는 필요할 때 선택한 두 본문으로만 계산한다.

**최종 AI 감사 제외:** 새 전체 생성 순서는 `content_review → place_child → place_adult → final_validate → finish`로 끝난다. 앞단 분석·비판 검토와 사람 확인, 정답/격자/공개 누출 검사는 유지한다. 신규 요청은 `final_audit` task/scope를 받지 않으며 provider 호출·경고 보고·가짜 감사 성공이나 비용 0 행을 만들지 않는다. `review_ready`는 검토 가능한 상태일 뿐 자동 발행이 아니다.

현재 계약 v2 작업의 순서를 조용히 바꾸지 않는다. P5-50의 새 전체 요청은 기존 `generation_jobs.request_contract_version=2`를 유지하고 같은 원자 저장에 `generation_full_v3_requests` 표시 행을 더한다. 표시 행이 있으면 실행 계약 v3, 없으면 기존 v2로 읽는다. 부분 작업은 기존 v2이며 신규 `final_audit` scope는 거절한다. 과거 요청/context/outcome·감사 결과·비용을 당시 계약으로 읽고, 구버전 대기/실패 작업을 새 순서에 자동 연결하지 않는다. 기존 version 필드를 직접 3으로 바꾸는 방식은 채워진 D1의 순환 외래 키 때문에 테이블 재생성 시 보존 검사에 실패했다. 이 표시 행은 독립 실행 프레임워크가 아니라 기존 작업의 불변 계약 구분 자료다.

새 finish는 현재 입력·확정 의도·검수된 요약/후보·설정/선택·두 격자·최종 코드 검사 증거를 같은 작업과 버전으로 대조한다. 완료 prefix의 마지막 근거는 `final_validate`이고 감사 outcome·auditContext·warningCount를 요구하지 않는다. 모든 실제 AI 호출의 관측/정산과 미완료 호출·명령·대기 부재를 확인하며, 비-AI 검사에 AI usage를 만들어 붙이지 않는다. 내용 수정이나 선택 변경은 재검수 대상으로 남긴다.

**물리 저장 경계:** 0013의 `lifecycle_finish_proofs`와 `lifecycle_finish_scope`는 옛 작업에 계속 적용한다. 로컬 0014는 새 전체 작업 표시, 불변 `generation_final_validation_proofs`, v3 단계·완료 guard를 더한다. 기존 표와 행은 재생성하지 않는다. `completeFinalValidation`은 봉인된 현재 ticket을 읽고 현재 입력·확정 의도·검수 요약/후보·두 격자/정답 비공개 직렬화를 코드로 다시 검사한 뒤 전환 증거·검사 지문·작업 단계를 한 번의 D1 batch로 확정한다. `finish`는 그 증거와 현재 자료·미완료 호출/명령/전송 부재를 대조해 `review_ready`만 저장한다. 감사 outcome이나 가짜 usage 행을 만들지 않는다. 기존 AI 감사 표/열은 이력 읽기·비용 연결용으로 보존한다. 로컬 migration 검사는 원격 적용 증거가 아니다.

**출력과 저장 예산:** 새 문단 수·후보 수·출력 byte 상한은 정하지 않는다. 간결한 결과를 프롬프트와 구조로 만들고, 현재 작업에 필요한 입력·참조·새 결과만 읽고 저장한다. 기존 chunk/선택 읽기/조건부 저장을 재사용하며 자막 전문이나 전체 과거 이력을 반복 복사하지 않는다. 형식에 이론적인 최대값이 없다는 이유만으로 모든 정상 출력을 저장 불가로 판정하는 연결은 채택하지 않는다.

후속 writer는 실제 직렬화한 결과·envelope·선택한 참조의 byte/chunk/SQL statement 수를 기존 기술 예산과 대조하고, 해당 실행 환경의 제한을 확인한다. `domainStorageBudgetStatus`의 현재 일괄 `not_ready`는 지원하는 계약·실제 저장 경로·측정/저장 검증에 따른 판정으로 바꾸되 무조건 ready를 반환하지 않는다. P5-47의 보수적 직렬화 계산을 실제 heap/CPU 측정으로 부르지 않는다. 기술 보호값 확인은 구현 검사의 일이며 사용자에게 새 제품 상한을 정하게 하는 사유가 아니다.

응답 형식 오류·거절·중단·실제 저장 실패 시 기존 자료를 유지하고 해당 작업의 실패/불확실 상태를 표시한다. 이미 관측한 usage는 결과 저장 실패와 분리해 보존하고 모르는 비용을 0으로 채우지 않는다. 저장 성공 여부가 불확실하면 기존 동일 요청의 결과를 조회해 확인한다. 확인 전 provider를 자동 재호출하지 않으며, 관리자가 새 생성을 선택하면 별도 호출로 기록한다. 출력 잘라내기·몰래 부분 저장·자동 분할/추가 호출을 대안으로 넣지 않는다.

#### 설교 의도 분석 절차

한 번의 프롬프트에서 요약과 퍼즐을 동시에 성급하게 만들지 않는다. 기본 콘텐츠 생성 한 회는 아래의 AI 호출 5회로 분리하며, 격자 탐색은 AI 호출이 아니다. 자막 검수 단계에서 관리자가 `AI 자막 교정`을 누르면 앞에 별도 AI 호출 1회가 추가된다. 추가 재생성은 관리자 버튼으로 시작하는 새 작업이다. 별도 최종 AI 감사 호출은 제외한다.

1. AI 호출 1 — 자막 순서와 timestamp를 보존해 중심 명제, 설교 목적, 논지의 단계, 반복 표현, 예화, 적용, 경고를 근거 구간과 함께 분석한다.
2. AI 호출 2 — 별도 비판 검토로 `의도를 과장했는가`, `자막에 없는 결론인가`, `예화를 중심 주장으로 오해했는가`, `반대 설명을 본뜻으로 뒤집었는가`를 검사하고 분석 수정안을 만든다.
3. 관리자 승인 지점 — 관리자가 분석의 모든 필드를 직접 수정·자동 저장한 뒤 `설교 의도 확정`을 누른다. 여기에는 AI 호출이 없다.
4. AI 호출 3 — 확정된 의도와 자막 근거를 바탕으로 공개용 설교 요약을 만든다.
5. AI 호출 4 — 어린이용 답·단서 후보 pool과 각 근거를 넉넉히 만든다.
6. AI 호출 5 — 장년용 답·단서 후보 pool과 각 근거를 넉넉히 만든다.
7. 코드 작업 — 결정적 배치기가 관리자가 선택한 크기·단어 수 조합을 여러 번 탐색하고 형식·연결·교차 하드 게이트를 검사한다. API 비용이 들지 않는다.
8. 관리자는 **확정 의도 → AI 요약 → 답·단서 → 필요한 자막 근거 → 격자**를 확인하고 수정·재생성 또는 발행을 선택한다. 별도 최종 AI 감사는 호출하지 않는다.

AI가 설교자의 내면 의도를 완벽하게 보증할 수는 없으며, 공개 자막만으로는 억양·화면·현장 맥락 또는 자막 오류가 빠질 수 있다. 따라서 목표는 “완벽하다고 자동 선언”하는 것이 아니라 **모든 중요한 해석을 자막 근거에 묶고 관리자가 틀린 해석을 발견하기 쉽게 만드는 것**이다. 관리자 화면에는 필요할 때 설교자가 특히 강조한 의도·표현을 짧게 추가하는 선택 입력도 제공한다.

관리자는 결과가 마음에 들 때까지 전체 초안 또는 `의도 분석만`, `요약만`, `어린이 문제만`, `장년 문제만`, `이 답·단서만`을 횟수 제한 없이 다시 생성할 수 있다. 부분 재생성은 보통 해당 범위의 AI 호출 1회이며, 의도 분석은 분석+비판 검토 2회다. 격자 크기·단어 수 변경과 재배치는 AI를 호출하지 않는다. `최종 검사`는 코드로 확인할 수 있는 오류를 검사하고, 내용의 최종 품질은 사람이 판단한다. 별도 최종 AI 감사를 실행하지 않는다.

**P5-56 답·단서 하나 재생성:** 현재 선택한 어린이/장년 후보 목록의 한 문제를 지정한다. 서버가 목록 revision과 문제 ID를 요청에 봉인하고 현재 확정 입력·의도 및 대상과 나머지 문제를 읽는다. AI는 같은 문제 ID의 답·단서·짧은 설명·실제 근거 정확히 하나를 반환한다. 다른 문제·순서와 사용/반드시 포함/제외 상태, 기존 사람 수정 근거는 서버가 그대로 복사한다. 새 목록은 비교용 revision이고 자동 선택하지 않는다. 사람 선택 시 해당 난이도만 재검수하며 배치/완료 증거는 현재 자료로 다시 검사한다. 비교 뒤 현재 목록이 변경되면 오래된 비교본 선택을 거부하여 다른 수정이 덮이지 않게 한다. 기존 값 유지에는 새 AI 호출이 없다.

같은 요청 번호는 같은 대상만 재생하며 다른 대상으로 바꿀 수 없다. 실패·불확실 응답에도 관측 비용/미확인 호출을 보존하고 자동 재호출하지 않는다. 불확실 작업 뒤 현재 목록을 수정했어도 관리자가 비용을 재확인하고 같은 난이도의 새 요청을 명시하면 새로 선택한 대상에서 시작할 수 있다. 이전 작업은 종료 표식만 남기고 비용과 결과를 지우지 않는다. 기존 v2 child/adult 작업에 선택 대상만 추가하는 확장이며 DB schema/migration·새 서비스는 추가하지 않는다. [구현·검사](../work/P5-56.md).

AI 재생성 전후의 결과를 단순히 바로 전 하나만 남기지 않는다. 각 AI 생성, 관리자의 `초안 저장`, 과거본 복원을 새 revision snapshot으로 보관하고 이름·메모를 붙여 목록에서 비교·선택할 수 있게 한다. 자동 저장은 현재 편집본을 보호하되 키 입력마다 새 revision을 만들지는 않는다. 자막 source·작업본·교정 제안은 14.3의 transcript 전용 revision에 저장하고, 콘텐츠 revision에는 분석·요약·후보·배치 JSON과 참조한 확정 자막 ID/checksum만 저장하므로 같은 자막 전문을 매번 중복하지 않는다.

이 절에서 `초안`은 **아직 발행되지 않은 AI 생성·관리자 편집 revision과 그 비교 이력만** 뜻한다. 이미 발행된 최종 퀴즈, 정답, 격자, 단서, 설교 요약, 설교 메타데이터, 참여·순위 기록은 초안이 아니며 사이트 아카이브의 정식 데이터다. 초안 정리 정책으로 이 정식 데이터를 삭제하거나 만료시키면 안 된다.

모든 AI 초안 revision은 자동 삭제 대상이다. 여기에는 AI 자막 교정 제안과 그 비교용 transcript revision도 포함한다. 퀴즈가 발행되면 발행에 선택된 기초 revision을 포함해 해당 퀴즈의 미발행 초안 이력을 `published_at + 7일`에 삭제한다. 미발행 작업은 한 설교 초안 작업 전체의 마지막 저장·수정 시각부터 7일 동안 활동이 없으면 삭제한다. 삭제 하루 전부터 관리자 대시보드에 예정 목록을 표시하며, 자동 정리는 기존 Workflow Worker의 하루 1회 scheduled cleanup으로 수행하고 감사 로그를 남긴다. 불변 raw source와 최종 확정 text의 발행 뒤 보존은 source별 `retention_mode`를 따르며, text 삭제 대상이어도 checksum·provider·확정 기록·발행 provenance는 유지한다.

발행 트랜잭션은 AI 요약·답·단서·격자·정답과 필요한 설교 정보를 공개/정답 정식 테이블에 먼저 영구 아카이빙하고 성공한 뒤에만 상태를 `published`로 바꾼다. 정식 데이터가 누락되었거나 초안 FK에 의존하면 발행 자체를 실패시킨다. 이후 원본 초안 이력을 삭제해도 사이트와 아카이브가 동일하게 재현되어야 한다. 모델명, prompt/schema version, 자막 checksum, 최종 revision 번호, 비용, 발행 관리자·시각처럼 추적에 필요한 최소 provenance도 초안 FK가 아닌 발행 기록에 별도로 남긴다. 자동 삭제 예외와 기간 선택 UI는 두지 않는다.

### P5-57 로컬 초안 정리 연결

미발행 초안은 현재 서로 연결된 비교본·선택·검수를 포함한 **한 설교의 초안 작업 전체**를 단위로 삼는다. 해당 작업의 마지막 저장·수정(입력·콘텐츠·metadata·배치 선택·작업 상태)부터 정확히 7×24시간 뒤 정리 대상이 되며 하루 1회 scheduled 실행에서 처리한다. 개별 비교 revision에 독립 시계를 두어 작업 중인 의존 자료를 먼저 없애지 않는다. 발행된 작업은 발행 시각+7일을 사용한다. 같은 설교가 여러 세트에서 공유되면 마지막 발행 또는 남은 미발행 작업의 활동까지 함께 확인한다. 조회 자체는 기간을 늘리지 않는다. 원본만 등록되어 정리할 편집/비교 초안이 없는 작업은 만료 표식을 만들지 않고 그대로 읽고 사용할 수 있다. 2026-09-23 사용자가 설교 초안 작업 전체 단위를 선택했다. 기간·보관 개수의 새 상한은 추가하지 않는다.

`draft-cleanup.ts`는 정리 하루 전 예정 목록을 제공한다. 삭제는 본문 chunk에 한정하며 불변 ID·checksum·확정 기록·비용/usage·발행 provenance와 참조 관계는 유지한다. 원본과 source별 마지막 확정 문서는 `keep_private`로 보존한다. 명시적 `sermon_transcripts.retention_mode=delete_text_after_publish`와 checksum이 대응하는 source만 발행 뒤 본문을 정리하고, provider/checksum 등 최소 출처 정보는 별도로 남긴다. 대응 정책이 없는 새 입력 source에는 기존 기본값 `keep_private`를 적용한다. 원고·제공 요약본을 임의 교정하지 않는다.

0021은 `draft_cleanup_records`의 불변 정리 표식과 `draft_activity`의 앞으로의 저장 시각만 추가한다. 기존 표·행·본문을 migration으로 다시 쓰거나 삭제하지 않는다. 과거 metadata 저장 시각이 없는 미발행 작업, 영구 발행 snapshot/두 난이도 정식 자료가 부족한 작업, 진행 중인 호출은 정리를 보류한다. 과거 시각을 migration 시각으로 추정하거나 별도의 7일 유예를 발명하지 않는다. 읽기 후 저장·선택·발행·호출·보존 조건이 바뀌면 같은 batch에서 정리를 취소한다. 정리 표식·본문 제거·감사 로그는 함께 commit/rollback하며 재실행은 기존 완료를 재생한다. 감사 로그와 기존 비용 원장을 정리 대상으로 삼지 않는다.

정리 완료 후 옛 초안 편집/재생성 API는 `410 DRAFT_EXPIRED`를 반환하며 새 초안으로 시작하도록 안내한다. 옛 본문 재삽입과 새 provider 호출을 DB에서도 막는다. 기존 공개/아카이브·정답·참여·순위 읽기는 초안에 의존하지 않는다.

기존 Content Workflow Worker에 scheduled handler를 연결했다. 운영 계약은 하루 한 번 호출이며, `DRAFT_CLEANUP_ENABLED`는 기본 비활성이다. 실제 DB binding·Cron 등록·활성화·원격 migration·배포는 이번 범위에서 수행하지 않는다. 삭제 실행 HTTP API나 기간/예외 설정 UI는 없다. [P5-57 구현·검사](../work/P5-57.md).

### P5-58 로컬 발행 정보 정정

이번 연결 범위는 **설교 제목과 설교일**이다. published/archived 세트 모두 영구 자료로 정정하며 초안 정리 뒤에도 동작한다. 최초 slug·발행/접수 시각·접수 상태·문제/정답·요약/고지·장절·참여/순위·비용·최초 발행 provenance는 변경하지 않는다. 단서·요약 등 의미 판단이 필요한 변경은 문제 오류 처리로 안내한다. 더 넓은 비의미 오탈자는 후속 P5-62에서 별도로 연결했다.

0022의 `published_display_corrections`는 quiz set만 참조하는 불변 이력이다. 수정 전후 값·사유·관리자 digest·서버 시각·연속 번호와 Access 감사를 같은 D1 batch로 저장한다. insert guard가 공개 상태·직전 번호·수정 전 값을 다시 확인해 경합을 거부한다. 같은 요청 번호·내용·관리자의 재확인은 기존 성공만 재생한다. 최초 snapshot·초안은 재작성하지 않는다.

공개 latest/slug·다른 열린 퀴즈 목록과 archive 검색·정렬·연월 선택은 최신 정정값을 읽는다. 공개 주소와 DTO의 비공개 정보 분리 정책은 유지한다. 기존 snapshot 없는 발행 자료도 지원한다. 관리자 목록/폼은 오류 재확인·수정 전후 이력·한국 시각을 제공한다. [구현·검사](../work/P5-58.md).

### P5-59 로컬 첫 제출 전 발행 철회

아직 마감되지 않은 published 세트의 모든 난이도·과거 revision에 성공 제출이 0건일 때만 철회한다. hidden/deleted 표식도 성공 제출 이력이다. 저장 시 제출·현재 발행 시각·최신 표시 정정 번호를 다시 확인한다. 이미 archived이거나 마감에 도달한 세트는 이 경로로 되돌리지 않는다.

철회 시 영구 발행 자료와 최신 제목·설교일을 별도의 불변 검수 revision 시작 자료로 복사한다. 두 난이도 격자·단서/근거·정답·요약·공식 장절 링크를 포함하며 초안 정리 후에도 영구 자료로 복원한다. 최초 snapshot·정정 이력·원래 문제/정답·slug·기존 기간·참여/순위·비용은 보존한다. 기존 원본 자막이나 초안 기록을 덮거나 새로 만들어 복원하지 않는다.

복사 기록 삽입, 세트 review_ready + paused, 기존 active variant withdrawn, featured 재선정, Access 감사는 같은 D1 batch로 저장한다. 다른 열린 published 중 최신 세트가 우선이며 없으면 최근 archived를 읽기 전용으로 소개하고, 둘 다 없으면 준비 안내를 표시한다. 철회 세트가 featured가 아니면 다른 featured를 그대로 둔다. 제출 저장도 현재 공개/접수/lifecycle 조건을 commit 시 확인하므로 제출과 철회가 함께 성공하지 않는다.

관리자는 사유를 입력하고 영향 안내 뒤 취소/철회를 선택한다. 응답 유실 때 같은 요청을 확인하며 새로고침 후 관리자 목록에서 검수 시작 자료를 읽는다. 새 편집본의 실제 수정·재검증·재발행은 P5-60 연결 범위다. 옛 발행 요청이나 상태 변경만으로 기존 variant를 다시 공개하지 않는다. [구현·검사](../work/P5-59.md).

### P5-60 철회본 편집·재검증·재발행

관리자는 보존된 철회 자료에서 편집을 명시적으로 시작한다. 앞서 저장한 답·단서 수정은 첫 편집 주기에 가져오며, 만료된 주기는 복원하지 않고 원래 철회 자료에서 새 주기를 시작한다. 제목·설교일·교회명·장절·AI 요약·답·단서와 관리자 수정 근거를 저장한다. 원고/제공 요약본·자막 원본·이미 발행된 정답/문제는 변경하지 않는다. 수정한 답·단서에는 사람의 근거를 덧붙이고 기존 근거는 보존한다.

답 길이나 교차가 바뀌면 기존 무료 배치기로 선택한 5~10칸 격자를 시험하고 명시적으로 선택한다. 배치 번호를 바꿔 다른 배치를 비교할 수 있으며 AI 호출이 없다. 모든 기존 문제를 유지하고 단어를 몰래 제외하거나 길이를 자르지 않는다. 시험은 저장이나 검토 승인이 아니며 저장/배치 변경은 요약·어린이·장년 검토를 모두 무효화한다. 현재 저장본의 장절·요약/고지·한글 답·중복·격자 경계·교차·연결·밀도·채점 정합성과 수정 근거를 코드로 검사하고 세 영역을 사람이 다시 확인한다.

재발행은 현재 검토된 저장본을 다시 검사한 뒤 새 두 variant/문제/비공개 정답과 영구 발행 내용을 원자 저장한다. 현재 편집 번호·정정 번호·상태·전체 revision 제출 0건을 저장 직전에 재확인한다. 현재 퀴즈만 published/open으로 바꾸고 기존 발행 기본값에 따라 그 순간부터 정확히 7일의 참여 기간을 시작한다. 영구 slug와 옛 snapshot/문제/정답/정정/검수 증거·참여/순위·비용은 유지한다. 최신 재발행 뒤의 표시 정정만 덮어 읽으며 초기 발행 요청이나 옛 재발행 재확인으로 이전 문제를 되살리지 않는다.

다시 철회할 때도 전체 난이도·과거 revision의 제출/순위가 없어야 하고 마감 전이어야 한다. 새 발행 내용과 최신 표시 정정을 불변 시작 자료로 복사하며 다음 편집 주기를 연다. 첫 제출 후 오류 처리는 P5-61의 별도 범위다.

새 편집 주기들의 저장·배치 선택·사람 검토와 같은 설교 작업의 활동 중 마지막 시각부터 7일, 재발행하면 발행 시각+7일을 적용한다. 조회·배치 시험·성공 요청 재확인은 기한을 늘리지 않는다. 정리 때 새 주기의 본문과 남은 초기 편집/생성 초안을 같은 batch로 만료시키며 영구 발행/철회 자료와 식별·해시·검토 종류·감사·비용은 남긴다. 이미 정리된 초기 생성 자료는 다시 만지지 않는다. 기존 하루 전 예정 목록과 기본 비활성 스케줄러를 재사용한다. [API](api.md#p5-60-통합-편집검토재발행-api) · [저장](data-model.md#p5-60-반복-편집과-영구-재발행) · [검사](../work/P5-60.md).

### P5-70 보관 콘텐츠의 무료 검수·발행 재개

실패/중단된 full 작업의 확정 원문·의도·요약·어린이·장년 결과가 현재 버전으로 검증되면 관리자 `resume-stored` 명령이 새 full v3 요청에 `reuseCurrentContent`를 봉인한다. 원래 failed/stale 작업·receipt·과금·원응답은 변경하지 않는다. 새로운 AI receipt나 성공/비용 0 행을 만들지 않고 AI 실행을 차단한다.

0034는 요청에 봉인된 현재 원문·확정 의도·세 콘텐츠와 실제 head가 일치할 때 input_resolve에서 content_review로 이어지는 기존 trigger 조건만 추가한다. 사람 내용 검수, 무료 배치, 현재 최종 검사, 명시 발행의 기존 조건은 모두 유지한다. 동일 명령 재요청은 같은 작업으로 이어지며 원문/내용 변경·누락·다른 소유자는 거절한다. 현재 실제 검사와 미완료 사항은 [P5-70](../work/P5-70.md#내용-검수와-보관-결과의-무료-발행-연결)을 따른다.

### P5-54 로컬 발행 연결

검수된 신규 full v3 퀴즈의 발행은 `quiz-publication.ts`가 처리한다. 현재 기본/선택 배치의 ticket과 입력·내용·metadata·선택 revision을 다시 읽고 두 격자를 재현·검증한다. 두 `quiz_variants`, 정답 없는 `quiz_entries_public`, 비공개 `quiz_solutions`, `published_quiz_content`, published/open 상태·정확히 7일의 기간·최종 slug·featured pointer를 한 D1 batch로 확정한다. 마지막 snapshot insert guard가 읽기 이후 바뀐 검수/작업을 차단하고 어떤 저장 실패도 전체 rollback한다. 다른 발행 세트의 기간·제출·순위에는 쓰지 않는다.

0018의 `published_quiz_content`는 quiz set에만 FK를 둔다. 제목·설교일·교회명·장절·판본·공식 링크·요약·source별 고지, 자막 checksum, 입력/내용/metadata/선택 revision, ticket fingerprint, 발행자 digest·시각과 비용 기록을 영구 보존한다. 정답은 기존 비공개 정식 표에 저장한다. 발행 당시 코드의 prompt/schema 계약과 호출별 관측 모델/사용량/가격표/비용을 남기며, 과거 호출 원장에 기록되지 않은 호출 당시 prompt/schema version은 null로 명시한다. 발행 당시 계약값으로 과거 호출 version을 추정하지 않는다. 이후 초안/본문 변경에 공개·archive 읽기가 의존하지 않으며 기존 snapshot 없는 발행 자료의 읽기도 유지한다. 초안 자동 정리의 로컬 경계는 아래 P5-57 절을 따른다. 실제 데이터에 대한 실행·원격 활성화는 별도다.

관리자는 최종 검사를 통과한 기본 또는 선택 배치에서 `지금 발행`을 누른다. 확인창은 추가 체크박스 없이 취소/지금 발행 두 동작, 즉시 공개·참여 시작, 한국 시간의 예상 시작/마감, 기존 퀴즈 보존·첫 제출 뒤 잠금, 두 난이도 Top 3, 해당 quiz 전체의 관측 비용/미확인 호출을 보여준다. 실제 저장 시각은 서버가 정하며 성공 후 그 시각·공개 링크를 표시한다. 같은 requestKey·job·발행자·revision의 재확인은 기존 결과를 반환한다. 새로고침은 영구 snapshot의 발행 완료 상태를 반환한다. 발행 자체는 AI를 호출하지 않으며 생성 opt-in과 독립이다.

이 연결은 신규 세트의 최초 발행 범위다. 실제 Preview/운영 발행·원격 migration·배포·출력 구현은 실행하지 않았다. 명세의 철회/발행 후 메타데이터 정정/새 revision 발행 UI를 이번 구현으로 완료 처리하지 않는다. [구현·검사 기록](../work/P5-54.md).

보수적으로 revision 하나를 100KB, 매주 30개를 저장해도 1년에 약 156MB다. 실제로는 이보다 작을 가능성이 높고, 2026-08 현재 D1 무료 플랜의 총 저장 공간 5GB에 비해 충분히 작다. 이는 보장값이 아니라 설계 추정이므로 운영 화면에 revision 수와 DB 사용량을 표시하고 Cloudflare 가격·한도는 배포 시 다시 확인한다. 공식 참고: [Cloudflare D1 가격과 무료 한도](https://developers.cloudflare.com/d1/platform/pricing/)

승인된 자막 입력 30,000자(D-033)는 유지한다. AI 출력 토큰·월 비용에 새 임의 제품 상한을 추가하지 않는다. 공급자/플랫폼의 실제 요청 한도나 구조화 검증 실패가 발생하면 기존 자료를 유지하고 관리자가 해당 작업을 다시 실행하게 한다. 가정한 초과만으로 자동 분할·추가 AI 호출 체계를 만들지 않는다. 관리자 화면에는 생성 전 예상 비용과 완료 후 실제 입·출력·reasoning token 및 추정 USD 비용을 표시한다. 가격표 version과 모델명을 함께 저장해 나중에 계산 근거를 알 수 있게 한다.

관리자 화면의 고정 header에는 `이번 주 AI 예상 비용 $X.XX` pill을 항상 표시한다. 여기서 `이번 주`는 달력의 월~일이 아니라 현재 편집 중인 주간 `quiz_set`에 연결된 모든 AI 호출을 뜻한다. 따라서 다음 주 초에 지난 퀴즈를 다시 생성해도 그 퀴즈 비용에 합산된다. pill을 누르면 route 이동 없이 오른쪽 drawer 또는 modal이 열린다.

상세 화면에는 호출 시각, 작업 목적(`음성 전사`, `자막 교정`, `의도 분석`, `비판`, `요약`, `어린이`, `장년`, `개별 문제`), provider, 정확한 모델명, input/cached/reasoning/output token 또는 audio 사용량, revision, 건별 비용, 모델별 소계, 주간 총계를 보여준다. 서로 다른 모델과 전사 모델 비용을 합계에는 포함하되 반드시 그룹을 나눠 표시한다. 과거 최종 감사 호출 기록이 있다면 보존하되 신규 호출 목록에는 포함하지 않는다. 가격표가 바뀌어도 과거 계산이 변하지 않도록 호출 당시 `pricing_version`을 저장하며, 이는 API usage 기반 추정치라 실제 청구서와 소수점 차이가 날 수 있다고 안내한다.

### P5-68 로컬 비용 상세 연결

Access 관리자 `GET /api/admin/quiz-sets/:id/ai-costs`가 선택한 `quiz_set`의 호출 원장을 읽고, 호출 당시 관측값과 저장된 가격표 version/추정 비용을 그대로 반환한다. 현재 `ai_usage_observations`를 우선하고 옛 `ai_usage_events`는 해당 호출의 관측값이 없을 때만 읽어 중복 합산하지 않는다. 시작만 기록되고 사용량이 없는 호출은 토큰·가격표·비용을 `null`로 두고 미확인 횟수로 센다. 관리자 고정 pill과 상세 drawer는 호출 시각과 목적·모델·revision·사용량·건별 금액, 모델 소계와 퀴즈 전체 관측 합계를 보여준다. 어린이/장년 범위의 개별 문제 요청은 기존 불변 요청 맥락의 대상을 확인해 일반 범위 재생성과 구별한다. 달력 주간/현재 작업 비용은 기존 생성 패널에서 별도로 표시한다. 발행·초안 본문 정리 뒤에도 퀴즈 ID로 보존된 비용을 조회한다. 신규 호출이나 과거 금액 재계산, 원장 변경은 하지 않는다. 이 연결은 실제 청구서 또는 미보고 호출 비용을 검증한 것이 아니다. [API](api.md#p5-68-퀴즈-ai-비용-조회-api) · [검사](../work/P5-68.md).

API 요청은 `store: false`를 사용한다. OpenAI API key는 Cloudflare Secret에만 두고 브라우저로 보내지 않는다. 별도 동의 없이 API 데이터를 모델 개선에 공유하는 설정은 켜지 않는다. 가격·모델 동작은 바뀔 수 있으므로 배포 전 공식 문서를 다시 확인한다.

### 11.5 관리자 AI 검수 화면 — 2026-08-17 갱신

AI Workflow는 의도 분석과 비판 검토까지 완료한 뒤 한 번 멈춘다. 관리자가 그 결과를 직접 수정하고 `설교 의도 확정`을 눌러야 요약·문제 후보 생성을 계속한다. 관리자는 코드나 원본 JSON이 아니라 한 화면의 근거 중심 검수 흐름을 사용한다.

첫 실제 설교 품질 시험과 이후 관리자 revision 비교에는 공통 평가 상태를 둔다.

- `좋음`: 의미 수정 없이 그대로 사용할 수 있음
- `수정 후 사용`: 관리자가 고친 뒤 사용할 수 있음
- `재생성 필요`: 해석·근거·난이도 품질이 부족해 새 AI revision이 필요함

이 평가는 AI가 스스로 부여하는 점수가 아니라 관리자의 검수 기록이다. `수정 후 사용`은 수정 내용을 자동 저장하고, `재생성 필요`는 어떤 범위가 부족했는지 선택 메모를 남긴 뒤 해당 범위 재생성으로 연결한다. 단순 별점이나 평균 점수 하나로 설교 의도 정확성을 대체하지 않는다.

설교 의도 평가에는 최소한 `중심 주제`, `예화와 중심 주장의 구분`, `청중에게 요청한 적용`, `자막에 없는 결론 추가 여부`, `반복 강조 표현의 중요도 반영`을 표시한다. 체크박스를 모두 강제하는 발행 의식으로 만들지 않고, 각 항목을 근거 패널에서 확인한 뒤 위 세 상태와 관리자 메모를 기록하는 품질 시험·revision 비교 도구로 사용한다.

```text
① 설교 등록 → ② AI 의도 분석·비판 → ③ 관리자 수정·의도 확정
→ ④ AI 요약·문제 후보 → ⑤ 문제·가변 격자 검수 → ⑥ 미리보기·발행
```

#### 설교 등록

- YouTube 링크, 설교 제목·날짜, 성경 본문 주소
- 선택 입력 `설교자가 특별히 강조한 내용`
- 선택 입력은 AI 방향을 보완하는 관리자 메모이며 공개 화면에 자동 노출하지 않는다.

#### 설교 의도 분석 패널

- 핵심 메시지 한 문장
- 설교자가 이 말씀을 전한 목적
- 성경 본문과 핵심 메시지의 관계
- 설교 전개 순서
- 반복해서 강조한 표현
- 예화와 중심 주장의 구분
- 청중에게 요청한 적용과 반응
- 경고하거나 오해하지 말아야 할 내용
- AI가 자료만으로 확정하기 어려운 부분

데스크톱·태블릿은 왼쪽에 위 9개 편집 항목, 오른쪽에 영상과 자막·제공 자료 근거를 둔다. 항목은 접고 펼칠 수 있지만 핵심 메시지는 항상 보이게 한다. 각 해석에는 timestamp와 짧은 자막 근거를 붙인다. timestamp를 누르면 YouTube의 해당 시점으로 이동한다. 원고·요약본 source에는 timestamp를 만들지 않고 해당 문단을 보여준다. 근거가 없거나 약하면 신뢰도를 꾸며낸 백분율 대신 `근거 확인 필요`를 표시한다. 전체 자막은 옆 패널에서 해당 근거 주변으로 이동해 확인하되 공개 사용자에게 노출하지 않는다.

9개 항목은 모두 일반 입력란처럼 직접 수정·추가·삭제할 수 있고 자동 저장된다. AI 문장을 고치면 기존 근거 연결을 `근거 다시 확인`으로 표시하고 다른 구간·문단을 선택할 수 있게 한다. 관리자가 자막 밖의 확실한 맥락을 추가하면 `관리자 확인 내용`으로 구분해 AI 판단처럼 보이지 않게 한다.

`의도 분석만 다시 만들기`는 관리자 동작 한 번으로 내부의 1차 분석과 별도 비판 검토를 차례로 실행한다. 화면에는 `1차 의도 분석 완료`, `비판 검토 완료` 상태를 보여주고 비판 의견을 해당 항목에 연결한다. 두 번째 호출만 실패하면 첫 결과를 보존하고 `비판 검토만 다시 시도`할 수 있다. 재생성 결과는 현재 편집본을 덮어쓰지 않고 새 revision으로 저장해 이전본과 변경점을 비교한 뒤 선택한다. P5-55의 로컬 연결은 두 호출 실행·비교·선택/재확정과 저장된 첫 분석을 재사용하는 비판 검토 한 호출 재시도, 기존 선택 유지 후 비교 종료를 구현했다. [작업 상태](../work/P5-55.md)를 따른다.

`설교 의도 확정` 전에는 요약·문제 생성 버튼을 비활성화한다. 확정을 누르면 별도의 검토 질문이나 필수 체크박스를 보여주지 않는다. 간단한 확인창에는 `확정하면 요약·어린이 문제·장년 문제 생성을 시작합니다`라는 영향, 다음 AI 호출과 예상 비용만 표시하고 `취소`, `확정하고 다음 생성 시작` 두 버튼을 제공한다.

확정 뒤 의도를 다시 수정하면 기존 요약·문제의 근거가 오래될 수 있음을 표시하고 관련 범위를 다시 생성할지 선택하게 한다.

#### AI 요약 패널

- 실제 공개 화면과 같은 요약 미리보기
- 관리자의 직접 수정과 자동 저장
- `요약만 다시 생성`, 이전 revision 비교·복원
- 실제 source type에 맞는 필수 AI 고지 미리보기

의도 분석을 다시 만들면 현재 요약·문제와 근거 연결이 오래된 상태가 될 수 있음을 알리고, 관련 항목도 함께 다시 생성할지 선택하게 한다. 강제로 모두 폐기하지 않는다.

#### 어린이·장년 문제 검수 패널

설교 의도 확정 뒤 `요약`, `어린이 문제`, `장년 문제` AI 작업을 각각 독립 상태로 실행한다. 한 작업만 실패하면 성공한 결과를 보존하고 실패 범위만 다시 시도한다. 관리자가 요약·정답·단서를 직접 고치는 데에는 AI 비용이 들지 않는다.

난이도별 탭은 처음에 약 15개 후보를 제안하되 이를 생성 상한으로 쓰지 않는다. 각 후보의 `정답, 단서, 선정 이유, 설교 중요성, 자막·제공 자료 근거, 표시 글자 수, 공백 제거 격자 길이, 다른 후보와 공통 음절, 자동 검사, 격자 배치 상태`를 함께 보여준다. 관리자는 다음 조작을 할 수 있다.

- `어린이 문제만 다시 생성`
- `장년 문제만 다시 생성`
- `이 문제만 바꾸기`
- 후보 제외·복구
- 정답·단서 직접 수정
- 후보 잠금(배치에 반드시 포함)
- 격자 크기 5×5~10×10 선택, 목표 단어 수 변경, `배치 시험`
- 이전 revision과 비교·복원

후보 상태의 의미:

- `사용`: 다음 단계의 배치 후보 pool에 포함하되 최종 배치에서 빠질 수 있음
- `잠금`: 최종 완성 격자에 반드시 포함
- `제외`: 배치 탐색에서 제외

조사 포함 표현은 자동 탈락시키지 않는다. `display_answer`에는 원래 띄어쓰기를 유지하고 `grid_answer`에는 공백을 제거해 실제 격자 길이와 최소 가능 크기를 바로 표시한다. 긴 표현을 채택해도 막지 않고 다음 단계에서 더 큰 격자를 시험하게 한다.

여기서 `단서`는 사용자가 정답을 맞히도록 제시하는 문제 문장, 즉 힌트다. 단서를 수정해도 정답과 격자는 그대로이며 중복·난이도·근거 검사를 다시 한다. 정답을 수정하면 길이와 교차 글자가 바뀔 수 있으므로 결정적 배치와 모든 하드 게이트를 다시 실행한다. 수정 전 정상 격자를 그대로 정상으로 간주하지 않는다.

격자 크기·목표 단어 수·후보 포함 여부를 바꾸는 시험은 로컬/서버 배치 알고리즘만 실행하므로 AI 비용이 들지 않는다. 각 시험 결과는 실제 배치 단어 수, 빠진 후보, 활성 셀, 교차 셀, 다중 교차 단어 수, 실패 이유를 나란히 비교할 수 있게 한다.

#### 최종 미리보기·발행

- 어린이·장년의 desktop/mobile
- 기본/크게 보기, Everforest 기반 light / Gruvbox 기반 dark
- 문제 격자와 관리자 전용 정답 격자
- 빈 격자 출력·단서 텍스트 복사 미리보기
- Top N A4 벽보 레이아웃. 참여자가 아직 없으면 DB에 저장하지 않는 `미리보기용 예시 이름`임을 명확히 표시한다.
- 격자·명사·근거·성경 권리 등 자동 검사 결과
- 해당 revision의 모델, 예상 비용, 완료 후 token과 추정 실제 비용

`최종 검사`는 두 난이도 준비, 연결·교차 기준, 정답과 격자 일치, 가로·세로 번호, 허용 한글 형식, 설교 제목·일자·성경 장절, source별 AI 고지, 문제 근거, 빈 격자 산출물의 정답 누출을 검사한다. 코드로 확정 가능한 오류는 발행을 차단한다. 요약·정답·단서의 의미와 품질은 관리자가 읽고 최종 판단하며, 별도 AI 감사 호출이나 불일치 경고 보고를 추가하지 않는다.

`지금 발행` 확인창에는 별도 질문·체크박스를 두지 않고 다음 영향만 요약한다.

- 새 퀴즈가 메인에 공개됨
- 참여 시작 시각과 기본 7일 뒤의 정확한 마감 일시
- 기존 published 퀴즈는 각자의 마감 일시까지 그대로 참여 가능함
- 새 퀴즈는 첫 제출 뒤 정답·격자·채점 revision이 잠김
- 어린이·장년의 `winner_count`
- 이번 작업까지 실제 관측된 AI 생성 비용(별도 최종 AI 감사 호출 없음)

버튼은 `취소`, `지금 발행` 두 개만 둔다. 새 퀴즈의 공개 snapshot 저장, `published + open` 전환, `opens_at/closes_at`, `featured_quiz_set_id` 변경을 하나의 D1 transaction/batch 경계에서 처리한다. 기존 published 세트의 상태나 마감은 이 트랜잭션에서 건드리지 않는다. 하나라도 실패하면 기존 메인을 유지하고 일부 상태만 공개하지 않는다. 성공 뒤 `공개된 퀴즈 보기`를 제공한다.

발행을 막는 것은 위의 코드 하드 게이트와 데이터 무결성 오류다. 의도 분석의 모든 문장마다 승인 버튼을 요구하지 않는다. 최종 `지금 발행` 한 번이 현재 revision 전체에 대한 관리자 승인 기록이다.

직접 수정과 선택 상태는 자동 저장하되 발행은 자동으로 하지 않는다. 다시 생성, 명시적 `초안 저장`, 과거본 복원은 현재 편집본을 덮어쓰지 않고 새 revision을 만든다. 초안 목록에는 생성 시각, 마지막 수정 시각, 범위, 관리자 이름, 모델, 비용, 선택 메모, 자동 삭제 예정일을 표시하고 두 버전을 비교한 뒤 현재본으로 선택할 수 있다. 비용 표시는 정보용이며 버튼 비활성 조건이 아니다.

### 11.6 추후 YouTube 채널 자동화

현재 채널 관리자 권한을 받을 수 없으므로 이 절은 **구현하지 않는 후속 작업**이다. v1 출시 조건으로 요구하거나 운영자에게 다시 권한을 요청하지 않는다.

나중에 교회가 채널 관리자 권한 연결을 허용하거나 계정 없는 추출의 불안정성이 운영을 방해할 때 재검토한다. 안정적인 공식 방식은 관리자가 Google Cloud 프로젝트와 YouTube Data API를 설정하고, 해당 영상을 편집할 권한이 있는 Google 계정으로 OAuth 동의를 하는 것이다. 영상 목록 감지는 공개 API로 가능하지만, 공식 `captions.download`는 해당 영상을 수정할 권한이 있는 OAuth 사용자여야 한다.

필요 요소:

- Google Cloud 프로젝트와 OAuth 동의 화면
- YouTube Data API 활성화
- 교회 채널 관리자 계정 동의
- 필요한 최소 scope
- 암호화된 refresh token 보관·철회 UI
- 새 영상 발견 후 자동 발행이 아닌 관리자 검수 대기열
- 기존 `AccountlessPublicTranscriptProvider`와 동일한 출력 schema·checksum 비교
- 연결 해제 후 계정 없는 방식 또는 수동 입력으로 되돌아가는 fallback

공식 문서: [YouTube captions.download](https://developers.google.com/youtube/v3/docs/captions/download)

### P5-61 첫 제출 후 문제 오류 처리

로컬 연결 계약은 [P5-61](../work/P5-61.md)을 따른다. 관리자는 발행 목록에서 세트를 선택하고 공개·숨김·삭제 제출 수와 기존 확정 순위 수, 기존 마감을 확인한다. 사유·공개 중지 안내·오류 난이도를 확인한 뒤 세트 전체 접수를 중지하고 불변 원본에서 새 수정 작업을 시작한다. P5-59/60의 제출 0건 철회 조건은 변경하지 않는다.

- 한 난이도를 선택하면 해당 문제만 수정한다. 공통 제목·설교일·교회명·장절·요약을 수정하려면 두 난이도를 선택한다. 영향 없는 문제·제출·순위는 유지한다.
- 기존 무료 배치 엔진, 한글/길이/교차/공개 geometry/정답 정합성 검사와 요약·두 난이도 사람 검토를 재사용한다. 저장·배치 변경은 검토를 무효화한다. AI 호출은 없다.
- 검토한 현재 저장본·원본 variant·마감·표시 정정 번호·pause 상태를 commit 때 다시 검사한다. 기존 오류 variant만 `superseded + invalidated`로 바꾸고 새 정답·문제·영구 표시 snapshot·교체 계보·감사·접수 상태를 한 batch로 저장한다. 실패하면 기존 오류본 접수 중지를 유지한다.
- 진행 중 교체는 최초 `published_at`·`opens_at`·`closes_at`·slug·featured를 유지한다. 자동 7일 연장은 없다. 이 경로가 일반 마감 변경 기능의 완료를 뜻하지는 않는다.
- 마감 후 또는 수정 중 마감에 도달하면 기존 마감 writer로 당시 순위 snapshot을 먼저 확정한다. 이후 오류본 순위를 공개 조회에서 제외하고 수정본은 `active + non_ranked_correction`으로 연결한다. 새 제출·순위 없이 지난 퀴즈의 채점과 정답보기를 재사용한다. 기존 성적·순위 snapshot은 재계산하거나 옮기지 않는다.
- 실제 오류가 아니라는 명시적 취소 사유를 남기면 수정본을 발행하지 않고 기존 문제를 유지한다. 마감 전 접수만 재개하며 마감 뒤에는 열지 않는다. 처리 중 일반 resume은 DB에서도 거부한다.
- 오류본의 원래 문제·정답·당시 답안/성적은 관리자 및 해당 active 세션의 본인 기록 경로에서 확인한다. 숨김 제출도 본인에게만 복원하고 삭제 제출은 답안 없는 tombstone이다. 새 variant에는 같은 세션으로 다시 제출할 수 있다.
- 새 편집 본문은 기존 7일 정리 목록/기본 비활성 scheduler에 포함한다. 같은 설교의 새 활동·수정본 발행/취소 시각을 반영하고 마지막 head/본문 SHA·활동/lease를 commit 때 재확인한다. 원래 오류 자료·교체 이력·발행 snapshot·문제/정답·제출/순위·비용은 보존한다. 만료 후에도 접수 중지는 유지되며 명시적으로 새 주기를 시작하거나 오류 아님 취소를 할 수 있다.

원격 migration·실제 데이터 조작·유료 호출·배포·출력·Cron 활성화는 이번 연결에 포함하지 않는다.

### P5-62 일반 문구 오탈자 처리

발행/지난 퀴즈의 AI 요약과 어린이·장년 단서에 있는 철자·띄어쓰기·문장부호를 로컬 UI/API에서 정정한다. 기존 제목·설교일 정정은 유지한다. 관리자는 대상 하나의 수정 전후를 비교하고 비의미 오탈자 종류·사유·의미/난이도/정답 유도 불변 확인을 명시한다. 의미 변경 또는 판단 불확실 선택은 저장하지 않고 P5-61 문제 오류 처리로 안내한다. 코드·AI가 의미 안전성을 자동 보장하지 않으며, 사람 확인은 잘못된 의미 변경까지 검증해 주는 장치가 아니다.

별도 불변 표시 이력과 Access 감사를 한 D1 batch로 저장한다. 원래 발행 snapshot·문제/격자/정답·채점 revision·답안/성적·순위·비용·기간·slug는 그대로다. 저장 직전에 현재 문구·정정 번호·콘텐츠 버전·대상 소속·공개 상태를 비교한다. 오류 처리 진행 중(편집 만료 후 미완료 포함)에는 해당 처리에서 검토를 이어간다. 응답 유실은 같은 관리자·같은 요청/내용으로 재확인하고, 충돌은 입력을 보존해 최신 내용을 명시적으로 불러온다.

공개 현재/지난 퀴즈는 정정된 표시값을 읽는다. 요약은 해당 콘텐츠 버전, 단서는 해당 문제 ID에 귀속하므로 교체된 문제에 옛 정정이 되살아나지 않으며 영향 없는 난이도의 단서는 유지된다. 이후 철회·오류 처리의 시작 자료에는 현재 표시 문구를 복사하고 기존 정답을 유지한다. 새 본문은 초안이 아닌 영구 발행 표시 이력이므로 기존 초안 정리에 의존하지 않는다. 실제 데이터 조작·유료 호출·원격 적용·배포·출력은 제외한다. [구현·검사](../work/P5-62.md).

### P5-63 일반 마감 변경 로컬 연결

발행 정보 정정의 `마감 일시 변경`에서 한국 시각·사유를 입력하고 기존/변경 마감·남은 시간·기존 성공 제출 수를 재확인한다. 입력 변경은 확인을 해제한다. 실패 시 입력과 같은 요청 재시도를 유지하고 최신 영향/마감을 명시적으로 다시 조회한다. 마감 변경 이력은 기존 감사 로그에서 읽는다.

마감 전 published 세트의 연장/단축만 허용한다. 과거/현재 시각 요청은 기존 `지금 마감`처럼 실제 저장 시각에 종료하며 기존 제출을 소급 삭제하거나 재채점하지 않는다. 이미 `closes_at`이 지났거나 archived인 세트는 재개하지 않는다. 확인 뒤 새 제출·접수 변경·문제 교체·다른 마감 변경이 있으면 재확인을 요구한다. 미래 요청 시각이 확인 도중 지나면 자동 즉시 마감하지 않는다.

문제 오류 처리 중 마감 변경은 접수 중지·불변 오류 원본/옛 마감을 그대로 보존하며 이후 교체본은 현재 세트 마감을 따른다. 일반 변경 자체가 오류 처리를 취소하거나 접수를 재개하지 않는다. 기존 정답·제출/성적·확정 순위·최초 발행/기간 출처·비용·주소는 보존한다. [API](api.md#p5-63-일반-마감-변경-api) · [저장](data-model.md#p5-63-일반-마감-변경-저장) · [검사](../work/P5-63.md).


### P5-64 통합 검수의 현재 경계

2026-09-23의 로컬 통합 검수는 기존 설교/metadata/quiz가 준비된 뒤 본문 import·확정→합성 생성→사람 검수→배치/발행→표시 정정·제출·마감·정리의 연결을 확인한다. **새 설교 등록부터 관리자가 혼자 주간 발행을 시작할 수 있는 완성 상태는 아니다.** 등록/미발행 작업 선택·발행 전 메타데이터 저장, 공개 자막 취득의 관리자 연결, 근거 편집·확정 UX·비용 상세의 남은 동작은 [P5-64 점검표](../work/P5-64.md)에 구분한다. 이 문단은 P5-64 검수 당시 상태다. 등록/정보 저장은 P5-65, 공개 영상/자막 관리자 연결은 P5-66에서 후속 구현했다. 위 제품 요구와 사람 판단·자동 AI 재호출 금지·데이터 보존 정책을 변경하지 않는다. 운영 적용·실제 품질 판정·출력은 별도 범위다.

## P5-65 등록·작업 선택·발행 전 정보 저장

기존 주간 절차의 수동 진입을 로컬 연결했다. 관리자는 영상 링크·제목·설교일·장절을 입력하고 정규 장절·개역개정·공식 읽기 링크를 확인한 뒤 새 작업을 등록한다. 기존 URL 파서를 공유하며 동일 video ID는 새 행이나 덮어쓰기 없이 기존 작업으로 안내한다. 같은 날짜의 다른 영상은 허용한다. 제목의 유효한 YYMMDD/YYYYMMDD 날짜 추천 버튼과 한국 시간 기준 최근 일요일 후보, 요일/특별예배 안내를 제공한다. 이 시점에는 실제 영상 metadata/게시일과 공개 자막 자동 취득이 미연결이었으며 P5-66에서 후속 연결했다. 직접 입력한 제목을 외부에서 조회한 정보로 표시하지 않는다.

새 sermon·quiz·metadata revision 1은 하나의 D1 batch로 저장한다. reference-only 판본 행은 성경 본문 사용 승인을 뜻하지 않는다. 암호학적 난수의 고유 문자 6자리는 최초 한 번 저장하며 확인된 충돌만 새 값으로 시도한다. draft의 공개 slug는 저장하지 않고 현재 설교일+같은 고유 문자로 미리보기만 표시한다. 실제 발행 시 기존 publisher가 확정한다.

미발행 목록은 draft/review_ready/needs_revision 중 발행 이력이 없는 작업을 보여준다. 정리된 작업은 본문 정리 표시와 선택 잠금을 제공한다. 발행·철회 작업은 기존 발행 관리로 안내하며 새 metadata 경로로 되돌리지 않는다. 기존 ID 조회도 유지한다. 작업을 바꾸면 아직 저장하지 않은 입력자료가 다른 설교에 섞이지 않도록 입력 폼을 초기화한다.

제목·설교일·장절 수정은 기존 metadata 저장소의 정규화 검증을 재사용한다. 저장된 revision을 비교하고 실제 SQL 저장 시 발행·철회·정리 상태를 재검증한다. 같은 값은 revision과 정리 시계를 늘리지 않는다. metadata가 없던 기존 미발행 작업은 사람이 확인한 첫 저장에서만 생성하며 읽기 중 자동 변환하지 않는다. 저장은 원본 sermon/자막·기존 생성 결과/비용을 덮지 않는다. metadata revision 변경 뒤 옛 발행 ticket을 사용할 수 없고 현재 정보로 다시 배치·검토해야 한다. 새 metadata 저장도 기존 0021 활동 시계에 반영된다.

이 연결은 새 보존 정책·서비스·유료 호출·migration을 추가하지 않는다. [구현·검사](../work/P5-65.md). 실제 데이터·원격 적용·배포·출력은 제외한다.

## P5-66 공개 영상 정보·자막 취득의 관리자 연결

P5-65의 수동 등록 경로에 기존 계정 없는 공개 자막 adapter를 연결했다. 새 작업 화면에서 영상 링크를 명시적으로 조회하면 같은 video ID의 등록 여부를 먼저 확인한다. 중복이면 기존 작업만 안내하고 provider를 호출하거나 기존 정보를 덮지 않는다. 신규 영상이면 watch 페이지에서 공개 player 조회 키를 읽고 기존 ANDROID client의 player 요청을 한 번 수행해 제목·게시일과 한국어 공개 자막 상태를 읽는다. watch 안에 포함된 자막 주소를 우선 사용하던 변경은 같은 영상의 빈 응답이 재현돼 원래 요청 순서로 복구했다. 차단/형식 오류 응답 뒤에 다른 client나 경로로 자동 재시도하지 않는다. 요청 video ID와 일치하는 최소 제목/게시일은 자막 차단 때도 관리자 미리보기에 유지한다. 실제 운영 watch challenge가 제목도 누락시킨 경우, 미리보기에서만 YouTube 공개 oEmbed 기본 정보를 한 번 요청해 제목을 보완한다. 이 요청은 최대 3초·16KiB이고 인증·쿠키·redirect·자동 재시도 없이 JSON의 안전한 제목만 사용한다. oEmbed에는 게시일·자막이 없으므로 이를 만들어 내거나 기존 자막 실패를 성공으로 바꾸지 않는다. 기존 제목이 있거나 원본 import·중복·잘못된 영상 입력이면 추가 요청하지 않는다. JSON만 파싱하며 페이지 script나 oEmbed HTML을 실행하지 않는다. 조회는 설교나 입력자료를 저장하지 않으며 자막 전문을 미리보기 API에 보내지 않는다. 제목·게시일이 없거나 조회가 실패해도 관리자는 직접 입력할 수 있다.

가져온 원래 영상 제목은 별도로 유지하고 설교일 후보 계산에 사용한다. 등록 제목에서는 유효한 YYMMDD/YYYYMMDD 날짜 접두어와 구분자로 분리된 예배 구분, 제목 끝의 단일 유효 장절을 AI 없이 분리한다. 명시된 장절은 기존 결정적 파서의 66권·실재 장/절·같은 장 연속 범위 검증을 통과할 때만 자동 입력하고 책·장·시작/끝절 선택 UI를 동기화한다. 장절이 없거나 잘못되거나 여러 본문이 있으면 추론하지 않고 미입력으로 두고 직접 선택/입력을 안내한다. 다른 영상 조회 성공 시 이전 장절을 남기지 않는다. 원래 영상 제목은 미리보기에 표시하며 사람이 확인하기 전 등록은 하지 않는다. 제목이 비어버리는 정리는 적용하지 않는다. 이 자동 입력은 관리자 직접 검수에서 확인된 누락을 P8-02에서 보완한 동작이다.

가져온 제목은 설교일 후보 계산에 사용한다. 유효한 제목 앞 날짜가 우선이고, 없으면 게시일을 한국 시간으로 해석한 최근 일요일을 추천한다. 제목 날짜와 게시일이 31일 넘게 다르면 기존 경고를 표시한다. 게시일은 설교일의 확정값이 아니며 관리자가 제목·설교일·장절을 확인해야 등록된다. 특별예배의 일요일 아닌 날짜도 기존 정책대로 허용한다.

등록 후 아직 입력자료가 없는 미발행 작업에서 관리자가 공개 자막 원본 저장을 누르면 저장된 video ID로 provider를 다시 호출한다. 조회 당시의 자막이 그대로라고 가정하거나 브라우저가 보낸 자막을 원본으로 신뢰하지 않는다. 서버는 선택한 한국어 track의 시간 구간·텍스트·원본 SHA를 기존 설교 입력 저장소의 최초 불변 source에 저장한다. 자막은 30,000 Unicode code points까지 허용하며 초과분을 자르지 않는다. 저장 직후에도 사람 검토·확정은 별도다. 자동 AI 호출이나 자동 재호출은 없다.

자막이 없거나 조회가 차단·실패하면 실패 이유와 provider의 안전한 진단 필드를 보여준다. 차단은 반복 조회로 해결된다고 안내하지 않으며, 기본 정보가 채워져도 자막 원본은 아직 없음을 구분한다. 기존 직접 붙여넣기는 유지하고 자동 취득 완료로 간주하지 않는다. 다른 일시 오류에는 수동 다시 시도를 제공한다. 실패 중에는 원본 행을 만들지 않는다. 현재 진단은 provider가 실제로 측정하는 단계·시각·HTTP 상태·크기·track 수 등 안전한 부분집합이다. 11.3의 전체 운영 진단/실제 성공률 검증과 YouTube 약관·권리 검토는 Production 채택 전 별도 게이트다. 실제 영상·데이터 조작, 유료 호출, 원격 적용과 배포는 수행하지 않았다. 새 migration·의존성·서비스는 없다. ## P5-67 근거 검수·사람 의도 확정 연결

관리자 생성 화면은 현재 확정된 입력 원문과 선택한 불변 분석·요약·후보 snapshot의 source ID, 수정 ID, SHA, 확정 event를 대조한다. 일치하는 자료에서 인용 근거의 정확한 UTF-16 문자 범위를 원문에 표시하고, 시간 구간은 원래 segment의 시각을 보여준다. 공개 영상 원본일 때만 해당 YouTube 시각 링크를 제공한다. 원고·요약본·시간 없는 자막에는 시각을 만들지 않는다. 관리자는 현재 원문에서 구절을 선택해 근거를 교체·추가·삭제한다. 요약 문단의 마지막 근거는 교체해야 하고, 의도의 마지막 근거를 지우면 `근거 확인 필요`, 후보의 마지막 근거를 지우면 관리자 확인 내용을 작성해야 한다. 의도 문장을 수정하면 이전 근거를 확정 근거로 승계하지 않고 재확인 상태로 돌린다. 원본과 이전 snapshot은 수정하지 않는다.

선택한 revision에는 관리자 전용 `좋음`·`수정 후 사용`·`재생성 필요` 평가와 메모를 별도 불변 기록으로 붙인다. `수정 후 사용`은 실제 사람 수정 snapshot에서만 선택한다. 의도에는 다섯 검토 항목 각각 `아직 확인하지 않음`·`근거 확인`·`다시 확인 필요`를 저장하지만 모든 항목의 완료를 강제하지 않는다. 선택된 snapshot의 최근 평가가 `재생성 필요`이면 같은 자료의 사람 확정/검수·명시 재개·최종 검사/발행을 차단한다. 평가 변경이나 새 수정/재생성 결과는 사람이 명시적으로 선택한다. 첫 전체 작업의 의도 대기에서 재생성이 필요하면 이전 작업·관측 비용을 보존한 채 새로운 전체 초안 요청으로 앞단 분석·비판 2회를 다시 시작한다. 내용 검수 단계에서는 기존 범위별 재생성 버튼을 사용한다. 평가 저장만으로 AI를 호출하지 않는다. 평가 저장은 미발행 설교 초안의 기존 7일 활동 시계에 반영되고 만료 표식 뒤에는 저장할 수 없다.

`설교 의도 확정`은 필수 검토 체크박스 없이 영향·다음 호출/예상 비용을 확인창에 보여준다. 관리자가 `확정하고 다음 생성 시작`을 누르면 사람 확정을 먼저 저장하고, AI 연결이 켜져 있을 때만 후속 생성 dispatch를 명시적으로 요청한다. dispatch 실패/불확실은 확정과 분리해 표시하고 상태 확인 뒤 재개해야 한다. AI 연결이 꺼졌으면 확정만 저장한다. 비용 상세·실제 provider/AI 품질·실제 데이터 조작·원격 적용·배포·출력은 이 로컬 연결의 완료 범위가 아니다. [저장](data-model.md#p5-67-관리자-품질-평가-저장) · [API](api.md#p5-67-관리자-품질-평가) · [검사](../work/P5-67.md).
