# 구현 순서와 완료 기준

실제 현재 번호는 [STATUS](STATUS.md), 다음 한 작업은 [HANDOFF](HANDOFF.md)가 정한다. 2026-09-28 전수 조사·개선 요청으로 [완료 실행안](DELIVERY_PLAN.md)에 기존 미완료 요구를 7개 결과로 배정했다. 내부 단계마다 새 번호를 늘리지 않는다. 예정 목록은 개별 유료/실제/원격 실행 승인이 아니다.

| 영역 | 현재 위치 | 앞으로 확인할 사용자 동작 |
|---|---|---|

현재 부모 작업은 Phase9이며 P9-01 조사·제안은 완료했다. 사용자 직접 구현 요청에 따라 [P9-02](work/P9-02.md)에 기존 시안 재사용·공개/관리자 구현·로컬 검수를 묶었다. P9-03 제안은 여기에 통합하고 번호를 재사용하지 않는다. P9-04 운영 반영은 별도 승인 뒤 진행한다. 기존 Phase8 완료나 DELIVERY_PLAN의 종료 조건을 변경하지 않는다.

## Phase 5의 다음 연결 원칙

P5-48~69의 완료 기록은 STATUS와 각 work 문서에 보존한다. P5-70의 실제 한 편 완주와 P5-71 Preview 검수·P5-72 로컬 운영 구현은 완료됐으며 근거는 해당 work 문서에 보존한다. 금지어 관리·관리자 조치·Top N 설정·문의 처리 등 기존 누락 요구는 P5-72에 포함했다. 현재 번호의 실제 품질 시험과 전체 v1 완료를 혼동하지 않는다. 근거는 [감사](DEVELOPMENT_AUDIT_2026-09-28.md), 정확한 종료 조건·명세 20분야의 귀속은 [실행안](DELIVERY_PLAN.md)을 따른다.

기존 저장 경계의 호환 문제가 실제 연결을 막으면 필요한 부분을 수정한다. 검토할 때마다 저장 계층 전체를 새로 설계하거나 가정한 대용량 때문에 새 정책 승인을 요구하지 않는다. 실제 AI/외부 호출·migration·배포는 해당 작업 범위와 기존 권한을 확인한 뒤 실행한다.

## 완료 조건을 잃지 않는 방법

분야별 정책·API·데이터·[검사 명세](spec/testing.md)·[출시 게이트](spec/release.md)를 유지한다. 과거 단계별 체크리스트와 검수 상세는 [원문 17장](archive/2026-09-21-p5-48/implementation.md#17-구현-단계와-종료-조건)에서 해당 Phase만 확인한다. 최종 AI 감사 등 D-029로 대체된 요구는 다시 구현하지 않는다. 변경 영향이 없는 완료 검수는 새 증거인 것처럼 재실행·재기록하지 않는다.
