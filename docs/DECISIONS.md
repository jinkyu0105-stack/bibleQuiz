# 주요 결정 — 현재 기준

현재 결정의 짧은 목록이다. 상세 조건은 [명세 목차](../implementation.md), 선택 이유·변경 경과는 각 원문 링크에 보존한다. 과거 기록의 당시 상태는 [현재 STATUS](STATUS.md)를 대체하지 않는다. D-001은 문서 분리 결정을, D-029는 기존 계약의 부분 대체를 기록한다. D-029 새 경로의 로컬 연결은 P5-49~51에서 완료했으며 실제 품질 시험·운영 적용과 구별한다.

## D-001 — 상세 명세를 분야별로 분리하고 원문·링크를 보존

2026-09-21 사용자 문서 개선 요청으로 종전 단일 파일 유지 방식을 대체한다. 루트 implementation은 목차, docs/spec은 분야별 정본, STATUS/HANDOFF는 현재 상태, archive는 원문·과거 기록으로 나눈다. 기존 절·결정 ID와 링크를 보존한다. 반복 읽기와 현재/과거 혼동을 줄이기 위한 변경이다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-001--상세-명세는-루트-implementationmd에-유지).

## D-002 — Cloudflare Workers + Static Assets 단일 웹앱

React 정적 자산과 Hono API를 Cloudflare Workers + Static Assets로 제공한다. Pages로 되돌리지 않는다. 핵심 도메인 로직은 플랫폼과 분리한다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-002--cloudflare-workers--static-assets-단일-웹앱).

## D-003 — D1 + Drizzle + 검토된 SQL migration

D1 + Drizzle을 사용한다. schema 변경은 SQL migration을 생성·검토하고 환경별 적용한다. drizzle-kit push는 사용하지 않는다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-003--d1--drizzle--검토된-sql-migration).

## D-004 — Node 24와 pnpm 11 단일화

Node 24.18.0·pnpm 11.14.0을 local/CI/Workers Builds에 맞춘다. pnpm-lock.yaml만 사용한다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-004--node-24와-pnpm-11-단일화).

2026-10-07 사용자 요청으로 `pnpm dev`의 기본을 P9-02의 장년·어린이 UI 시험 실행으로 바꾼다. 별도 영속 로컬 저장소를 자동 준비해 매번 같은 화면을 확인하고 기존 자료/기록은 보존한다. 기존 로컬 실행은 `pnpm dev:local`, E2E 격리는 유지한다. 실제 콘텐츠·운영 반영·인증 우회 승인이 아니다. [로컬 개발 계약](spec/architecture.md#로컬-ui-개발-실행).

## D-005 — Preview와 Production을 물리적으로 분리

main은 Access 보호 Preview에 자동 배포된다. Production은 별도 자원과 수동 승인으로 배포하며, 운영 트리거·승인·migration·rollback은 아래 P8-02 합의를 따른다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-005--preview와-production을-물리적으로-분리).

P5-69는 기존 경계를 적용한 [실제 시험·환경별 승인·rollback 계획](work/P5-69.md)을 문서화했다. 자료/표본 수·예산·판정 기준과 Production 실행 순서는 운영자 결정 전 제안이며, 문서 완료를 유료 호출·실자료·원격 적용 승인으로 간주하지 않는다. 새 제품 제한·운영 합의는 추가하지 않았다.

2026-10-02 P8-02 승인: 사용자는 복잡한 문서 대신 쉬운 설명을 요청했고, “실제 운영용 서버/저장소 준비·관리자 로그인/백업 연결·완성한 프로그램을 올리고 공개”가 실제 Cloudflare 적용임을 설명한 뒤 **“승인합니다”**라고 답했다. 이에 수동 승인 배포, 백업 후 순차 SQL 적용, 심각한 회귀 시 공개/쓰기 중지와 호환 코드 복귀(데이터 복구는 손실 범위를 별도 확인)를 확정한다. 최초 Worker/SQLite DO 등록은 주소 비공개 deploy, 이후 일반 코드 변경은 version 업로드와 traffic 배포를 구분한다. main은 Preview 자동 배포로 유지하고 이번에 push하지 않는다. 무료 workers.dev 후보를 기본으로 진행하며 관리자 path 보호 검수 전 공개하지 않는다. 월USD0 목표·기존 실제 자료/키/유료 결과 보존·새 AI 호출0·Paid 전환/유료 구매 제외를 유지한다. 승인된 같은 범위의 내부 단계를 다시 승인받지 않는다. 계정 권한이나 R2 checkout 등 사용자의 UI 조작/새 비용 결정이 실제로 필요하면 확인 근거와 필요한 한 동작만 안내한다. [실행 범위·검수·복귀](work/P8-02.md). 현재 자원 존재/적용 완료 사실은 STATUS에서 별도로 판단한다.

2026-10-03 P8-02 AI 연결 추가 승인: 사용자는 기존 키를 비공개 콘텐츠 서버에만 표준입력으로 전달하고 앱/콘텐츠 설정 네 개를 켠 뒤 검사·배포하는 검토 묶음을 설명받은 후 **“알겠습니다. 다음 작업 승인합니다. 재개하세요”**라고 답했다. 새 로컬 키 사본은 만들지 않는다. 기존 nonprod 키의 승인된 재사용으로 OpenAI Project 청구가 합산될 수 있으며 앱의 Production 비용 원장은 분리한다. 기존 모델 gpt-5.6-terra/high·검수 결과를 유지하고 새 유료 AI 생성 시험·Paid 전환·구매·main push·실제 데이터 손실 복원은 제외한다. 이전 자동 승인 검토 거절은 실행되지 않은 과거 시도이며 이번 명시 승인과 구분한다. 실제 적용 완료는 STATUS/HANDOFF의 배포·보존 근거로 판단한다.

2026-10-07 사용자는 앞으로 Preview를 GitHub main 푸시를 통한 Workers Builds 자동 배포로 통일하고, 현재 변경을 먼저 푸시한 뒤 Preview 최신화를 확인하도록 승인했다. 일반 Preview 반영에 로컬 직접 배포를 사용하지 않는다. 자동 배포가 실패하면 원인을 확인하고 같은 Git 기반 경로를 복구하며 직접 배포로 조용히 대체하지 않는다. 운영 서버 최신화는 Preview 확인 이후 별도 요청으로 진행하며 이번 승인은 운영 배포·유료 호출·DB migration 승인이 아니다. [배포 계약](spec/architecture.md#preview-반영-경로).

2026-10-07 P9-04: 사용자는 CI 통과 뒤 별도 디자인 검수 단계를 추가하지 말고 운영 서버를 최신화하도록 정정했고, “운영 서버 배포하세요”로 실행을 명시 승인했다. 기존 수동 승인·versions upload/traffic 적용·직전 버전 복귀 계약을 사용한다. 앱 UI/자산/매뉴얼만 반영하며 DB migration·Secret 변경·content/backup 재배포·유료 호출을 추가하지 않는다. [실제 소스·명령·검증](work/P9-04.md).

## D-006 — 관리자 인증은 Cloudflare Access

관리자 UI/API는 Cloudflare Access로 보호하고 Worker에서도 JWT를 검증한다. 현재 계정 구성원 정책과 6시간 세션을 사용한다. 적용 범위는 현재 코드/환경으로 확인한다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-006--관리자-인증은-cloudflare-access).

## D-007 — 일반 사용자는 회원가입 없이 익명 세션

회원가입 없이 서버 발급 익명 브라우저 세션을 사용한다. 이름·답안·코멘트 공개/보관 동의와 문의·삭제 요청을 제공한다. 실명을 기술적으로 강제하지 않는다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-007--일반-사용자는-회원가입-없이-익명-세션).

## D-008 — 성경은 개역개정 장절·판본·공식 링크만 표시

v1은 개역개정 본문을 저장·복사·출력하지 않고 장절·판본·대한성서공회 공식 링크만 표시한다. AI가 본문을 생성·보완하지 않는다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-008--성경은-개역개정-장절판본공식-링크만-표시).

## D-009 — AI는 내용 이해, 코드는 퍼즐 배치

AI는 교정 문서·의도·요약·답/단서를 만들고, 사람 확인 뒤 결정론적 코드가 5×5~10×10 격자를 배치한다. AI가 최종 좌표를 결정하지 않는다. 간결한 결과·사람 최종 판단은 D-029를 따른다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-009--ai는-내용-이해-코드는-퍼즐-배치).

## D-010 — 설교 이해 품질을 AI 비용보다 우선

설교 이해 품질을 우선한다. non-production 모델 시작점은 gpt-5.6-terra이며 의도 분석과 앞단 비판 검토를 유지한다. 관리자 재생성 횟수·입출력 token을 임의 제한하지 않는다. 실제 usage와 모델별 비용을 표시한다. P5-68은 기존 호출 원장의 관측 금액과 당시 가격표 version을 퀴즈 단위로 읽고, 미보고 호출은 비용 미확인으로 분리한다. 과거 금액을 현재 가격으로 다시 계산하지 않는다. 이는 이번 Codex 작업 모델과 별개다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-010--설교-이해-품질을-ai-비용보다-우선).

## D-011 — 자막은 공개 CC 우선, 원본과 수정본을 보존

계정 없는 공개 CC adapter를 우선하고 실패 시 직접 붙여넣기를 제공한다. 원문은 불변이며 자막만 직접/선택적 AI 교정 후 사람이 확정한다. 교정 결과 형태는 D-029를 따른다. P5-66에서 영상 제목·게시일 후보의 조회와 공개 자막 원본 취득을 관리자 UI/API에 로컬 연결했다. 사람 확정·3만 자 제한·실제 provider 운영 게이트는 유지한다. [구현·검사](work/P5-66.md). [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-011--자막은-공개-cc-우선-원본과-수정본을-보존).

2026-10-03 P8-02 관리자 직접 검수에서 사용자는 수동 수정 안내에 대해 제목·장절 자동 입력이 목표임을 재확인했다. 기존 사람 확인은 자동 입력된 결과의 확인이며 매번 직접 입력하는 절차로 바꾸지 않는다. 제목의 명시 날짜/예배 구분/단일 유효 장절을 기존 코드 파서로 분리해 제목·날짜·장절/선택 UI를 자동 입력한다. 불명확·범위 오류·복수 장절은 추론하지 않고 직접 입력하는 fallback을 유지한다. AI·새 의존성·migration을 추가하지 않으며 Preview의 조회/날짜 추천/수동 장절 동기화와 누락된 제목 분리/장절 추출을 구분한다. [정본](spec/generation.md#p5-66-공개-영상-정보자막-취득의-관리자-연결).

2026-10-03 실제 운영 watch 차단이 영상 제목까지 누락시킨 것을 확인해 기본 정보와 자막 실패를 분리한다. 제목이 없는 차단 미리보기만 공개 oEmbed 제목을 제한적으로 보완하며, 원본 import·자막 실패 진단·사람 확인은 유지한다. 이는 자동 등록 목표의 복구이며 자동 자막 성공이나 수동 운영으로의 목표 변경을 뜻하지 않는다. [구현과 대안의 한계](work/p8-02/automatic-registration.md#자막-차단과-제목-조회-분리--2026-10-03).

2026-10-03 사용자는 ‘스크립트 표시 복사’를 사용자 수동 작업이 아니라 프로그램/AI의 브라우저 자동 취득으로 명확히 했다. 수동 복사 안내를 철회하고 자동화 목표를 유지한다. 기존 로컬 Chromium으로 실제 화면 자막 읽기·파일 저장을 실증했다. 운영 실행 위치나 새 서비스는 아직 확정하지 않는다. [실증](work/p8-02/browser-transcript.md).

2026-10-04 과거 실행본/보관 TS와 첫 운영 수정 전 지문을 대조하고 같은 영상의 로컬·Cloudflare 시험에서 과거 요청은 성공, watch 자막 주소 우선 경로는 빈 응답임을 확인했다. 사용자 요청에 따라 운영 앱을 기존 단일 player POST 경로로 복구하되 native fetch 수정과 차단 시 제목 보완은 유지한다. Browser Run은 별도 소규모 시험이며 새 운영 의존성으로 채택하지 않는다. [비교·실험 결과](work/p8-02/transcript-comparison.md).

2026-10-04 Supadata Free native 시험 성공 뒤 다음 작업 요청에 따라 운영 자막 공급자 연결을 로컬 구현한다. 한국어 기존 자막만 취득하고 auto/generate·유료 전환을 사용하지 않는다. 제목/날짜/장절 파서·중복 처리·불변 원본을 재사용하며 출처는 `supadata-native`, 자동/수동 미확인은 null로 보존한다. content도 새 출처 읽기 호환 버전이 필요하므로 content→app 순서로 적용하고, 저장 후 복귀 시 새 출처 읽기 호환 코드를 유지한다. 사용자가 구체적 묶음에 “진행하세요 그리고 두 서버가 어디어딘지 알려주세요”로 후속 승인해 기존 키를 app Secret에 연결하고 content→app 순서로 적용했다. 새 AI/유료 전환/main push는 제외하며 관리자 조회·원본 저장 검수만 native 최대2크레딧 범위로 진행한다. [정본](spec/generation.md#p8-02-supadata-운영-연결) · [검토 묶음](work/p8-02/supadata-integration.md).

## D-012 — 출력은 웹 데이터에서 재현하고 AI를 다시 호출하지 않음

빈 격자 PNG/SVG, 복사할 단서, Top N A4 PNG/PDF를 웹 데이터로 만든다. 출력 때문에 AI를 다시 호출하지 않는다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-012--출력은-웹-데이터에서-재현하고-ai를-다시-호출하지-않음).

## D-029 — 현재 생성 계약을 보존하는 D1 저장·Workflow 연결 경계

2026-09-21 최신 방향: 교정은 수정된 문서 한 벌, 분석/요약/후보는 간결한 내용과 짧은 실제 근거, 품질 최종 판단은 사람이다. 별도 최종 AI 감사·경고 보고를 제외한다. 앞단 의도 비판 검토와 코드 검사는 유지한다. 관리자 명시 재생성만 허용하며 자동 AI 재호출은 하지 않는다. 기존 결과·관측 비용·원본/시간·자료별 수정 제한을 보존한다. 출력 1MiB/4MiB 제안·초과 저장 실패 동의 요청은 미채택 철회다. [P5-48 연결 계약](spec/generation.md#간결한-생성-결과의-연결-계약) 검토를 2026-09-22 완료했다. P5-49에서 문서형 교정의 로컬 저장·사람 채택을 연결했다. P5-50에서 감사 없는 새 full finish의 로컬 경계를 코드 검사 증거에 연결했다. 채워진 D1에서 기존 작업 표의 버전 CHECK를 변경하려는 테이블 재생성은 순환 외래 키 보존 검사에 실패했으므로, 기존 v2 행·비용·감사를 그대로 두고 동일 원자 저장의 불변 `generation_full_v3_requests` 행으로 새 실행 계약을 구분한다. 이 방법은 [생성 연결 계약](spec/generation.md#간결한-생성-결과의-연결-계약)에 기록했다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-029--현재-생성-계약을-보존하는-d1-저장workflow-연결-경계).

P5-51은 D-029의 기존 자동 재호출 금지·사용량 보존 계약을 실제 교정과 full v3의 분석·비판·요약·두 후보 HTTP/Workflow 및 사람 검수/명시적 재개에 적용한다. 0015의 불변 계보 표와 관련 guard 확장으로 비판 수정본·사람 수정본 선택을 지원하며 옛 행/0014는 그대로 둔다. 기존 bridge를 완화하지 않고 봉인된 사람 명령을 공유 reducer로 재검증한 연쇄로 재생성의 검수 무효화를 증명한다. DB에 있는 비교용 비판과 사람이 선택한 수정 분석을 구분하기 위해 새 content capture에 선택적 `availableCritique`를 기록한다. 이 필드가 사람 선택·확정을 대신하지 않는다. 새 제품 출력 상한이나 새 서비스 결정을 추가하지 않았다. 원본 시간 자막과 작업 문서의 서로 다른 hash는 새 context 참조의 선택 필드로 구분하며 기존 context 바이트/옛 비용은 변경하지 않는다. 구현 경계는 [생성 연결 계약](spec/generation.md#간결한-생성-결과의-연결-계약), 남은 작업은 [P5-51](work/P5-51.md)을 따른다. 유료 실호출/원격 적용은 승인하지 않은 상태다.

P5-52는 기존 무료 재배치·사람 최종 판단 계약을 실제 생성 자료에 연결했다. 최초 generation 요청/완료 증거를 덮지 않고, 새 불변 선택 행이 기존 final ticket을 참조하도록 0016을 추가한다. 현재 선택과 검토 유효성은 입력·metadata·검수·선택 revision으로 재검증한다. 생성 완료 전 선택은 v3 finish에 반영하며 완료 후 재배치는 최신 선택을 별도로 검증하고 과거 완료 증거를 보존한다. 공개 preview는 정답 없는 형식을 유지하고 관리자 정답 DTO는 Access 안에서만 반환한다. 새 제품 제한·서비스·AI 호출 단계는 추가하지 않았다. [P5-52 구현 경계](work/P5-52.md).

P5-53은 같은 계약을 요약·어린이·장년 각각의 기존 v2 실행에 연결한다. full의 내용 검수 대기도 active 작업으로 분류되어 부분 실행을 막던 제약은 0017에서 index 조건과 좁은 공존 guard로 조정한다. 검수 대기 full v3 + 부분 작업 하나만 허용하며 다른 동시 실행은 유지 차단한다. 새 결과는 자동 채택하지 않고 사람 선택/수정의 기존 검수 무효화와 배치 검토를 재사용한다. 기존 행·비용·선택/완료 증거를 보존하며 새 제품 정책·서비스를 추가하지 않는다. [구현·검사](work/P5-53.md). P5-55는 같은 명시 재생성/비용 보존 계약으로 의도 분석+비판 검토의 별도 실행·비교·사람 재확정을 로컬 연결했다. 두 번째 호출 실패 시 불변 출처 행으로 첫 분석을 재사용하는 비판 검토 한 호출 재시도와 사용자가 승인한 기존 선택 유지 비교 종료를 추가했다. 실제 유료 호출·새 서비스 결정은 없다. ## D-031 — 저장 한 번의 처리 범위를 줄이고 수정본 3개 자동 삭제는 폐기

최초 import는 원본만 저장한다. 저장 시 이번 명령에 필요한 자료만 검사하고 정상 성공 뒤 본문 재조회를 생략한다. 선택한 두 문서의 diff는 요청할 때 계산한다. 수정본 3개 자동 삭제는 폐기한다. 별도 승인된 AI 초안 7일 정리 정책까지 취소한 것은 아니다. 새 경로는 로컬 UI/API에 연결됐고 기존 데이터 자동 변환/원격 적용은 별개다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-031--저장-한-번의-처리-범위를-줄이고-수정본-3개-자동-삭제는-폐기).

P5-57은 기존 7일 정책을 초안 본문 정리에 연결한다. 미발행은 서로 의존하는 한 설교 초안 작업의 마지막 저장·수정 시각을 사용하며, 발행은 발행+7일을 유지한다. 2026-09-23 사용자가 설교 초안 작업 전체 단위를 선택했다. 0021의 불변 정리 표식으로 본문만 만료시키고 ID/checksum·확정·비용·영구 발행 자료는 보존한다. 과거 metadata 저장 시각을 알 수 없거나 영구 발행 자료가 부족하면 추정 삭제하지 않는다. 새 기간·보관 cap·서비스를 추가하지 않았으며 실제 데이터 정리·Cron 등록·원격 적용은 제외했다. [정책](spec/generation.md#p5-57-로컬-초안-정리-연결) · [구현·검사](work/P5-57.md).

P5-60의 0025는 같은 7일 정책을 새 철회 편집본에 적용한다. 과거 생성 초안 정리와 새 편집 작업을 구별하고 마지막 편집 저장부터 기한을 계산한다. 본문만 비우며 원본 철회/발행·편집 식별/해시·감사·비용은 보존한다. 새 정책·기간 예외는 없고 로컬 연결/임시 합성 D1 검증만 수행했다. [상세 경계](spec/data-model.md#p5-60-철회-편집-본문-정리).

[현재 계약](spec/generation.md#p5-60-철회본-편집재검증재발행).

## D-034 — AI 근거의 문자 위치는 프로그램이 계산

2026-09-25 문자 위치 계산을 채택했고, 2026-09-28 사용자가 **구간/시간까지 프로그램이 전체 원문에서 찾고, 못 찾은 근거는 표시만 하며 저장·진행을 유지**하도록 확정했다. AI에는 짧은 인용문만 요구한다. 유일한 정확 일치만 위치를 연결하고, 없음/복수 일치는 원문을 바꾸지 않은 `위치 미확인` 자료로 보존한다. 특정 개수 이상 차단하거나 항목마다 별도 승인을 요구하지 않는다. 기존 사람 최종 검수와 입력/버전/공개 정보 분리는 유지한다. 보관된 비판은 재호출 없이 같은 규칙으로 받아들이되 원래 failed/rejected/비용은 보존한다. 당시 프롬프트/schema는 v3이며 현재는 아래 참조 정정을 포함한 v4다. [상세 계약](spec/generation.md#p5-70-근거-문자-위치는-프로그램이-계산) · [구현·실제 기록](work/P5-70.md#전체-원문-위치-검색과-진행을-막지-않는-표시).

D-034의 2026-09-27 구현 보완: 재부팅 후 기존 교정안/분석/키를 재사용하고 추가 호출 없이 보관 분석의 출처·확정 문맥·정산 이력을 검사하는 로컬 복구 준비 도구를 추가했다. 이는 새 분석 채택 정책이나 실패 job 수정 승인이 아니며, 실제 자료 적용/비판은 미완료다. [복구 준비](work/P5-70.md#보관-분석의-무료-복구-준비와-로컬-검수).

D-034의 복구 저장 연결: 기존 실패·비용을 그대로 둔 새 AI 분석 event와 0030의 불변 출처 기록을 원자 저장한다. 동일 source의 중복 저장을 막고 현재 문맥을 저장 시점에 재검사한다. 정상 생성의 success 증거를 완화하지 않고 복구 결과에만 원래 rejected/정산 출처를 별도 검증한다. 복구 자체는 AI 비판·사람 확정·후속 유료 실행이 아니다. [계약](spec/generation.md#p5-70-보관-분석의-별도-복구-저장) · [검사](work/P5-70.md#보관-분석의-원자-저장과-앱-조회-연결).

D-034 로컬 적용 준비 보완: 실제 DB 읽기 전용 계획과 별도 apply 도구를 구분한다. 검토한 계획의 지문과 같은 로컬 OS 운영자를 기록하고, 사본 검증 뒤 0030과 복구 콘텐츠를 하나의 트랜잭션으로 적용한다. 구현/합성 검사·사전 점검은 실제 자료 쓰기 승인과 구별한다. 새 유료/원격 권한은 없다. [적용 도구·검사](work/P5-70.md#원래-시험-db의-로컬-적용-도구와-사전-점검).

D-034 후속 생성 연결 보완(2026-09-28): 새 full v3 요청의 `recoveredAnalysisId`로 검증된 복구 분석을 명시 재사용한다. 기존 재사용 표와 생성 경로를 확장하고 0031은 trigger 세 개만 교체한다. 원래 failed/rejected/비용은 보존하며 새 분석 호출이나 가짜 success 기록을 만들지 않는다. 사람 확정 뒤 기존 요약/두 난도 생성과 종료 검사를 사용한다. 로컬 적용 도구는 0030·0031·복구를 함께 적용하거나 취소한다. 실제 실행 승인은 별도다. [계약](spec/generation.md#p5-70-복구-분석을-이용한-후속-생성) · [이번 구현](work/P5-70.md#보관-분석-재사용-연결과-실제-실행-준비).

D-034의 2026-09-29 참조 검사 정정: 분석/요약/후보가 같은 인용문을 공유해야 한다는 구현 제한을 제거했다. 각 인용은 같은 확정 원문으로 검증하고, 새 v4 출력은 제공된 transcript 주장 ID만 선택하게 한다. 보관 요약의 명백한 참조 철자 3개와 다른 원문 주장에 함께 잘못 연결한 미확정 해석 1개를 기록하며 정리했고 요약/인용 문장은 그대로 보존했다. 0033으로 기존 복구 저장을 요약에 확장했다. 새 평가/승인 단계나 유료 호출은 추가하지 않는다. [현재 계약](spec/generation.md#p5-70-근거-문자-위치는-프로그램이-계산) · [실제 두 난도 저장](work/P5-70.md#보관-요약-무료-저장과-두-난도-실제-생성).

D-034의 보관 콘텐츠 재개 보완(2026-09-29): 이미 저장한 요약과 두 난도의 후보를 검증해 새 full v3 요청의 내용 검수 단계로 이어간다. 원래 실패/유료 이력은 그대로 두고 새 요청에서는 AI를 호출하지 않는다. 0034는 기존 stage trigger만 확장하며 기존 사람 검수·배치·최종 검사·발행 조건은 유지한다. [계약](spec/generation.md#p5-70-보관-콘텐츠의-무료-검수발행-재개).

## D-035 — 다중 교차 비율을 발행 차단에서 주의 표시로 변경

## D-036 — 생성 조회 재사용의 범위와 검수 완료의 원자 저장

2026-09-29 P5-71에서 반복 조회로 최초/후속 생성·최종 완료의 D1 통신량이 커지는 문제를 재현했다. 한 요청 또는 실제 Workflow 단계 안에서만 불변 자료의 검증 결과를 재사용하고 독립 읽기를 묶는다. 현재 상태·선택·metadata·정리/품질은 새로 확인하며 크기 검사·출처·해시·비용·사람 확정·저장 시점 조건을 유지한다. 검수된 full 작업은 기존 단계 증거와 완료 proof를 하나의 조건부 거래로 저장한다. 새 영속 캐시/표나 제품 제한은 추가하지 않는다. 자동 AI 재시도는 계속 금지이며 기존 중간 단계 작업의 재개도 유지한다. 로컬 50회 통신 제한 통과는 원격 무료 운영 판정이 아니다. [구조](spec/architecture.md) · [구현·검증](work/P5-71.md#반복-조회-수정과-제한-검사).

관리자 표시 조회는 현재 선택·한 이력 페이지·필요 의존 결과의 봉인/길이/SHA·소유자·출처 기록을 확인한다. 정상 AI 결과의 성공·context 연결, 복구 결과의 별도 출처, 사람 기록과 현재 head/정리 상태를 유지하되 과거 모든 생성 문맥과 원문을 재구성하지 않는다. 이 읽기는 표시용 자료만 반환하고 쓰기 권한에 쓰는 DomainBasis나 검증 witness를 만들지 않는다. 미리보기는 현재 ticket·metadata·선택·품질에 연결된 결과로 표시한다. 수정·검수·생성 재개·최종 완료·발행은 기존 전체 출처/원문/현재성 검증을 계속 수행한다. 입력 교체 뒤의 이전 결과는 비교용으로 보이며 재사용 권한이 되지 않는다.


P5-71 후속 구현은 같은 표시/쓰기 경계 안에서 관리자 조회를 상태·비용·내용·생성 이력·배치의 독립 HTTP 요청으로 나눈다. 화면은 도착한 부분부터 보여 주되 서로 다른 저장 버전은 합치지 않는다. 부분 실패 때 받은 내용은 보존하고 편집 잠금·명시 재조회를 제공한다. 새 표/캐시나 계산 위치 변경은 없으며 원격 CPU 통과 여부는 별도로 실측한다. [조회 계약](spec/api.md#p5-71-관리자-콘텐츠의-분할-조회).


## D-037 — Preview 합성 실행의 범위와 실패 응답 보관

2026-09-29. P5-71의 원격 승인은 지정된 Preview와 합성 시험에 한정한다. app 전체 AI flag를 여는 대신 정확한 Preview origin과 합성 자료 UUID 허용 목록을 사용하고, 비공개 Workflow도 고정 합성 입력을 확인한다. 실제 provider key는 연결하지 않는다. [구조](spec/architecture.md) · [데이터](spec/data-model.md#p5-71-비공개-요청응답-전문-보관).

D-036/D-037의 무료 운영 보완(2026-09-29): CPU 실패 후 사용자가 “무료로 계속”을 선택했다. 동일 작업의 무료 CPU 수정·검증으로 진행하며 유료 플랜 선택을 재개 조건으로 두지 않는다. 이후 사용자가 “승인 — 기존 Preview에 0035 적용”을 명시했고 기존 Preview에만 적용했다. 기존 82개 표/219개 행 보존·FK 0·quick_check ok를 확인했다. 실제 AI 호출은 승인되지 않았으며 무료 검증만 계속한다.


D-036/D-037 실행 장소 확정(2026-09-29): 사용자는 PC가 켜져 있을 때 생성하는 대안을 거절하고 **PC 의존 없이 Cloudflare에서 모두 실행**할 것을 명시했다. 월 USD 0 우선과 실제 AI 별도 승인 경계를 유지한다. 큰 최종 검사를 HTTP 요청에서 기존 비공개 Content Workflow의 최종 검사 전용 실행으로 옮기고 화면은 Access 보호 상태를 조회한다. 같은 requestKey는 같은 검사만 재사용하고 AI 생성·공개 발행은 하지 않는다. 이 단계에는 새 DB 표나 외부 서비스를 추가하지 않았다. `CONTENT_FINAL_CHECK_WORKFLOW_ENABLED` 기본값은 false이며 검증된 Preview에서만 별도로 켠다. 30,000자 기존 결과의 원격 최종 검사/원래 Workflow 완료와 중복 방지를 확인했다. 완료 HTTP/상태 조회 CPU는 5~7ms다. 관리자 조회의 후속 저장 방식은 D-038을 따른다.

## D-038 — 관리자 조회는 저장된 내용과 격자를 재사용

2026-09-30. 조회 분할 뒤에도 정상 자료의 내용 29~71ms·배치 46~69ms를 측정했다. 콘텐츠는 불변 작업 봉투에 저장돼 있지만 GET이 전체 구조를 다시 읽었고, 최종 ticket은 선택 조건만 저장해 GET이 격자를 다시 탐색했다. 같은 P5-71의 반복 계산 제거 요청에 따라 **검증된 쓰기의 결과를 기존 D1에 표시용 사본으로 함께 저장**한다. 0036은 비공개 `generation_display_snapshots`·`generation_display_finals` 두 표만 추가한다. 새 외부 서비스·AI 호출·PC 의존·제품 제한은 추가하지 않는다. 요청 안에서만 재사용하는 D-036 방식으로는 다음 HTTP 요청의 재계산을 없앨 수 없어 영속 표시 사본을 선택했다. 매번 원본을 복원하는 대안은 재현된 CPU 병목을 남긴다.

AI 결과·사람 편집의 기존 조건부 거래에 내용 사본을, 배치 선택·최종 검사 거래에 이미 계산한 난도별 격자를 넣는다. 사본은 원본 식별자·소유자·원본 fingerprint·사본 SHA에 연결된다. GET은 사본의 SHA/구조/소유자/봉인된 원본 fingerprint와 현재 head·metadata·품질을 확인하고, 원본 조각·provider 문맥 복원·격자 탐색·자동 쓰기를 하지 않는다. 사본 손상/누락은 실패로 반환하며 비싼 복원으로 자동 우회하지 않는다. 사본은 DomainBasis/witness가 아니며 생성·복구·편집·최종 검사·발행의 원본 전체 검증은 유지한다. 사본의 교체/복구는 검증된 쓰기나 명시적 준비에서만 수행한다.

기존 자료는 AI 없이 원본 자료별·격자 난도별 Cloudflare Workflow 단계로 한 번 준비한다. 완료 proof가 있는 기존 격자만 재현하고 조합한 미리보기 fingerprint를 원래 proof와 대조한다. 새 준비는 별도 비활성 flag와 정확한 설교 UUID 허용 목록을 요구하며 실제 AI flag/합성 생성 허용 목록을 열지 않는다. 기존 기록·migration·비용은 덮어쓰지 않는다. **0036 원격 적용·새 app/content 배포·기존 세 자료의 표시 사본 준비는 새로운 구체적 승인 전 실행하지 않는다.** 이전 조회 분할 배포 승인을 이 변경의 승인으로 확대하지 않는다. 로컬 비교 성공을 무료 CPU 통과로 쓰지 않는다. 이후 사용자가0036·Preview 배포·기존 세 자료 준비·CPU 검사 범위를 확인하고 “시작하세요”로 승인해 해당 범위를 실행했다(2026-09-30). 준비 flag는 다시 비활성화했고 실제 결과는 P5-71의 최신 기록을 따른다. [구조](spec/architecture.md#p5-71-저장된-표시-자료의-재사용) · [데이터](spec/data-model.md#p5-71-표시용-내용격자-사본) · [재개](work/P5-71.md).

D-038 구현 확정(2026-09-30): 기존 사본을 다시 만들지 않고 목록→내용 한 건씩·격자 난도별 독립 요청으로 읽는다. 상태/비용의 SQL 왕복과 DTO 중복 검증을 줄이고 공개 Access 검증키만 짧게 재사용한다. 실제 토큰/신원과 원본 자료는 요청 간 캐시하지 않으며 매 요청 서명/claim·SHA·소유자·현재성·geometry 검증은 유지한다. 이전 전체 응답과 동일한 표시/비용·첫/후속 native CPU·실제 화면/원본 보존을 확인했다. 새 표·서비스·유료 플랜·PC 의존 없이 기존0036/Preview 안에서 완료했으며 상세 수치는 P5-71 최신 근거에 둔다.

## D-039 — 관리자 요청의 계산을 비공개 Durable Object로 분산

2026-10-01 사용자가 공식 CPU 분석·최적화·Durable Objects·작은 요청 분할을 적용하라고 명시했다. 기존 분할 조회는 유지하고 관리자 API의 인증·자료 처리·명령 검증을 같은 앱의 내부 `AdminCompute` 클래스에서 실행한다. 앱 Worker는 요청/응답 스트림을 전달하며 자료를 다시 파싱하지 않는다. 공개 풀이·제출과 Cron 경로는 기존 구현을 사용한다. 전송 실패는503으로 돌려주고 명령을 자동 재실행하거나 기존 Worker로 fallback하지 않는다.

SQLite 기반 DO는 Workers Free에서 사용 가능하며 기본 CPU 한도는 요청당30초다. 요청100,000/일·실행13,000GB-s/일 등 별도 무료 사용량 안에서 운영한다. 제한 초과 때 Free 작업이 실패하는 조건을 유료 자동 전환으로 해석하지 않는다. 계산의 CPU 사용량 자체가 줄어든다는 뜻은 아니며 일반 Worker의10ms 상한을 변경하지 않는다. [공식 한도](https://developers.cloudflare.com/durable-objects/platform/limits/) · [무료 사용량](https://developers.cloudflare.com/durable-objects/platform/pricing/).

D1은 계속 영속 자료의 정본이며 DO 저장소·알람·토큰/내용 캐시는 사용하지 않는다. 자원 식별자로 고정8개 shard와 목록용1개를 선택해 관리자 요소 요청을 분산한다. 같은 자원의 서로 다른 부분은 별도 요청이며 기존 버전 대조·서명/claim·SHA·출처·소유자·저장 거래를 유지한다. 생성/최종 검사는 기존 Workflow 단계 분할을 재사용한다. 새 AI 호출·D1 표·SQL migration0037·라이브러리·PC 서버는 추가하지 않는다.

## D-040 — 주간 운영은 기존 저장·조치 경로를 재사용하고 문의 조회키는 재시도 시 복구

2026-10-01. P5-72의 첫 화면과 여섯 단계는 기존 D1 입력·내용·배치·발행 상태를 연결한다. 자동 저장과 명시적 초안 저장은 기존 버전 검사의 불변 수정본 쓰기를 재사용한다. 별도 편집 저장 계층이나 AI 재호출을 추가하지 않는다. 발행 전 Top N은 기존 `site_state`를 사용하고 발행/재발행 시 난도별 값으로 저장한다. 마감/확정 순위는 바꾸지 않는다.

문의는 기존 명세에 필요한 `privacy_requests` 표가 없어 **0037에 그 표와 두 인덱스만 추가**한다. 접수 UUID·내용 hash로 중복을 구분하고 기존 SESSION_PEPPER의 HMAC에서 충분히 긴 비밀 조회키를 복구한다. 서버에는 조회키 원문을 저장하지 않으므로 응답 유실 때문에 새 문의나 새 비밀값을 요구하지 않는다. 공개 조회는 종류·시각·상태·답변만 제공한다. 문의의 이름/설명과 관리자 신원은 공개 조회에 넣지 않는다. 관리자 답변과 실제 제출 삭제는 별도 명시적 조치다.

임의의 문의 보존 기간·새 운영 제한·새 서비스/의존성을 결정하지 않았다. 공개 요청 제한·문의 정리 실행·서비스 metric/백업은 기존 P8-01 범위다. 0037·새 앱의 원격 적용은 구체적 승인 전 실행하지 않으며 기존 Preview/0000~0036·실제 자료·키·유료 결과를 보존한다. [실제 API](spec/api.md#p5-72-주간-운영의-실제-연결-계약), [검사와 인계](work/P5-72.md)를 따른다.

## D-041 — 운영 자료는 기존 원장·삭제 gate를 재사용하고 원격 활성화는 분리

2026-10-01. P8-01 지시에 따라 명세의 운영 기록 4개 표만 0038에 추가한다. 같은 run ID와 환경별 running 고유 제약으로 export를 직렬화한다. 새 파일 전체의 gzip SHA·크기와 verified 기록 뒤 주간 정상본 8개의 초과분만 회전한다. 수동·migration 직전 사본으로 주간 정상본을 밀어내지 않으며 새 자동 삭제 기간을 임의 확정하지 않았다. SQL·signed URL은 Workflow step state에 넣지 않는다. 개인정보 없는 누적 삭제 manifest와 기존 격리 재적용·공개 gate를 쓴다. 전체 SQL buffering, 불확실한 export의 자동 재시작과 원클릭 복원은 채택하지 않았다.

Cron은 기존 마감·7일 정리 guard를 재사용한다. 공개 요청 제한은 native binding과 안정적인 session/route, 보조 IP HMAC을 쓰며 성공 재생을 counter보다 먼저 복원한다. 빈 값·조회 실패는 미확인으로 표시한다. OpenAI는 기존 관측 원장·당시 가격을 사용하고 새 Admin key, 유료 호출, 원장 삭제를 하지 않는다. 한국 시간 월간 정책 확인은 실제 사용량·장애·백업 경고를 숨기지 않는다.

운영 매뉴얼은 사용자의 P8-01 범위에 맞춰 로컬 정본부터 작성하며 실제 배포·QA 완료로 확대하지 않는다. P8-01 당시 후보 횟수·Cron은 Production 확정 승인이 아니었다. ## D-042 — Air의 연속 하늘·시간대 전환을 새 UI 방향으로 채택

2026-10-08 사용자는 Refero/Air를 참고한 전체 UI 개편의 시작 순서에 동의하면서 **밝은 하늘과 어두운 하늘 모두**, 우측 시간대 제어, 같은 구름 배경에서 하늘→지면으로 내려오는 연출을 명시했다. 기존 숲/종이 정원과 어두운 분위기만의 제안을 새 개편 기준으로 고정하지 않는다. 네 시간대와 연속 구름 공간을 기준으로 하고 먼저 독립 움직임 검토와 대표 시안을 만든다. 전체 기능·한글 입력·정답 권한·실제 자료·출력/폰트는 보존한다. 원본 코드/매체/유료 폰트를 복사하거나 Refero 설치/결제를 추가하지 않는다. 새 무료 도구 설치는 필요 시 사용자 요청 범위에서 검토하되 production 의존성/서비스의 기존 결정 경계를 유지한다. 기존 P9-04 완료·배포는 유지하며 Production 변경은 별도 요청, Preview는 main push 자동 경로다. [새 상세 기준](spec/design.md#107-air-계승-하늘-방향--2026-10-08) · [탐색/검토본](work/P9-05.md).

2026-10-08 후속 글꼴 지시: 원본/추천 대체까지 한글 지원과 실제 폴백을 확인하고, 미지원 원본을 채택하기 위해 기존 한글 글꼴을 바꾸지 않는다. 한글을 지원하며 역할/형태가 가까운 무료 대체를 대표 시안에서 비교해 적용한다. 구체적 후보의 검토는 최종 채택/설치와 구분한다. 기존 디자인 문서는 보존하고10.7의 새 시각 방향을 우선한다. [서체 기준](spec/design.md#참조와-한글-서체-적용-기준) · [확인 근거](work/P9-05.md#참조-경로적용-범위한글-글꼴-확인--2026-10-08).


2026-10-08 P9-06 재시작 지시: 사용자는 이전 숲·종이·색상 기준이 더 필요하지 않다고 명시하고 Astra·Max로 처음부터 재작업하도록 요청했다. 해당 규칙은 새 UI의 기준에서 종료하고 [이전 명세](archive/2026-10-08-pre-sky-design.md)로 보관한다. 기존 자산/운영 배포를 삭제·변경하는 승인은 아니다. 공개 낮/밤·연속 하늘/지면·풀이/관리자 대표 검토본을 새로 만들고 한글은 실제 자체 호스팅 Noto Sans KR400을 재사용한다. 상세 값과 적용 경계는 [현재 디자인](spec/design.md), 검토 근거는 [P9-06](work/P9-06.md)을 따른다.

2026-10-08 P9-06 잔디 비교: 사용자는 새 하늘 시안에 긍정적으로 응답하고 OriginKit Grass Field base를 하단에 시험하되 되돌릴 수 있게 하도록 요청했다. 설치된 OriginKit MCP 반환 잔디 코드를 독립 검토본에 연결하고 기존 사진을 기본/복귀안으로 보존한다. 앱 적용·최종 채택·배포와 구분하며 새 패키지/서비스/결제는 추가하지 않는다. [비교·조정·복귀 근거](design/phase-9/sky-v2/ORIGINKIT.md).

2026-10-08 P9-06 원경 보정: 사용자는 OriginKit 잔디/마우스 반응에 만족하며 이를 유지하고 멀리 일반 사진의 산을 추가하도록 요청했다. 실제 촬영·사용 조건이 확인된 산 사진을 별도 층으로 연결한다. 잔디 코드/기존 자산을 보존하며 산만 끈 이전 모습과 비교할 수 있다. [사진 출처/조정/복귀](design/phase-9/sky-v2/ORIGINKIT.md#먼-산-사진--2026-10-08).

2026-10-08 P9-06 넓은 화면 보정: 사용자는 처음의 폭 확장 요청을 정정해 **콘텐츠 최대 폭1440px를 유지**하고2560px 화면에서 어색한 배경만 손보도록 확정했다. 기존 퀴즈/관리자 배치와 격자 폭은 바꾸지 않는다. 전체 화면 지형의 양끝 노출을 수정하고, 잘린/앙상한 반복 구름을 풍성한5종으로 교체하며 첫 화면도 독립 구름의 흐름을 강화한다. 산 사진은 같은 출처의3840×2160 파일을 추가하고 기존 자산을 보존한다. ## D-049 — 관리자 설명은 용어 가까이, 화면 예시는 실제 앱으로 만든다

2026-10-13 P9-23. 사용자가 관리자 전체에 적절한 이모지, 중요 개념의 말풍선, 확대 가능한 유용한 스크린샷을 요청했다. 제목·단계·주요 안내에 장식 이모지를 쓰고 원문/사용자 입력은 변환하지 않는다. 설명은 마우스뿐 아니라 키보드와 터치로도 열 수 있게 하며 기존 위험 안내와 실행 확인은 유지한다. 같은 날 후속 요청에 따라 말풍선은 요소 위를 우선하고 위쪽 공간이 부족할 때만 아래로 표시한다.

화면 예시는 실제 React UI에 합성 자료를 표시해 8종을 캡처한다. 실자료/유료 결과를 정적 자산에 포함하지 않으며, 예시임을 화면에서 밝힌다. 실제 UI로 필요한 화면을 모두 만들 수 있어 선택적으로 제공된 `imagegen-frontend-web`은 읽고 참고했지만 새 가상 이미지 생성은 하지 않았다. 기존 시안·모바일·의미 색상·저장 동작은 유지한다. [정본](spec/design.md#p9-23-관리자-이모지용어-도움말화면-예시) · [작업](work/P9-23.md).


2026-10-13 P9-23 후속 정정: 관리자 전체 문구를 문맥에 맞게 검토하고 같은 동작의 이름을 통일한다. 도움말에서도 실행/완료/확인/일반 설명/위험의 의미에 따라 네 시간대의 다섯 의미 색상을 사용한다. 문장 서술부 전체를 묶던 `nowrap`은 제거하고 용어와 바로 붙은 조사·어미만 같은 단어로 유지한다. 서비스 사전은 사용자 요청에 따라 공식 회사 로고 원본을 사용하며 색과 모양을 임의로 바꾸지 않는다. 말풍선은 중립 바탕과 의미색 강조로 개선하고 위쪽 우선 정책을 유지한다. 잔디의 수평선·세 수직선은 보존하며 선만1.35px로 줄인다. 기존 시안을 재사용하고 실제 UI에서 대조한다. [정본](spec/design.md#p9-23-후속--문구의미-색상공식-아이콘).

2026-10-13 P9-23 후속 사용자 정정: 관리자 사이드바의 탄성 유리 호버를 평평한 선택 받침 이동으로 대체한다. 현재 메뉴의 글자 강조와 접근성 상태는 유지한다. 기능 검토 기록은 매뉴얼의 ‘설정과 자료 보호 → 향후 기능’으로 옮겨 설명과 연결한다. 퀴즈 목록의 간격·Live·탭·버튼 및 서비스 사전 구획은 [디자인 정본](spec/design.md#p9-23-후속--퀴즈-목록과-안내-구획)을 따른다. 기존 경로/기능·자료와 원격 경계는 바꾸지 않는다.

2026-10-13 P9-23 후속 사용자 정정: 투명 콘셉트를 보존하며 참여 기록·문의 요청을 개별 카드에서 연속 게시판으로 바꾼다. 종류/상태는 한 분할 표시로, 목록 필터·원형 새로고침·도구/버튼 간격은 공통 컴포넌트로 통일한다. 한 행의 도구는 하나씩 펼치되 입력을 보존한다. 사용자가 이번에는 시안 생성을 명시해 참여/문의 가로 시안을 각각 생성했다. 이는 앞서 설명용 화면 예시에 가상 UI를 대신 넣지 않기로 한 결정과 다른 용도이며, 설명용 PNG8종은 계속 실제 React UI와 합성 자료로 캡처한다. `last30days`와 공식 문서를 조사해 Refero Styles를 시각 참고로, Carbon·Geist를 운영 UI 규칙 참고로 선택했다. 다른 디자인 시스템의 패키지·유료 자산·폰트를 추가하지 않는다. [정본](spec/design.md#p9-23-후속--게시판과-관리자-공통-규칙) · [근거](design/phase-9/admin-boards/research.md).

2026-10-13 P9-23 후속 사용자 정정: 퀴즈 목록을 설교일 고정의 짧은 게시판으로 바꾸고 참여 인원과 정사각형 작업 아이콘을 오른쪽에 모은다. 새로고침은PC36px·터치44px의 공통 크기, 설명은 위쪽 우선의 짧은 말풍선을 사용한다. 접기 화살표는SVG로 통일하고 열기/접기 글자는 제거한다. 사이드바 사이트 보기 제거·헤더 이번 주 퀴즈 문구를 반영한다. 필터 새로고침의 이유 질문은 삭제 승인으로 보지 않는다. 이미지가 안 보인다는 보고에는 기존 자산의 확인 페이지와 Windows 사본을 제공했고 사용자가3장 표시를 확인했다. [정본](spec/design.md#p9-23-후속--설교일-게시판과-작은-아이콘).

2026-10-13 P9-23 후속 사용자 확정: 이름·문구 필터의 평상시 새로고침을 제거하고, 목록 조회 실패 때만 ‘다시 시도’를 표시한다. 저장 시 응답으로 즉시 갱신하는 동작은 유지한다. 접기 SVG는 제목 줄 기준 대신 제목과 설명을 포함한 클릭 영역의 세로 중앙에 둔다. 이는 직전 이유 질문 뒤 사용자가 명시한 변경이다. [정본](spec/design.md#p9-23-후속--설교일-게시판과-작은-아이콘).

2026-10-14 P9-23 후속 사용자 확정: 이미 생성한 두 시안에 맞춰 퀴즈 관리·참여 기록·문의 요청을 다시 구현한다. 행의 여러 도구를 하나씩 여는 방식은 전체 행 접기로 대체하고, 참여는 답안/관리, 문의는 상태/답변을 좌우에 배치한다. 입력은 접어도 보존한다. 세 화면 제목은 고딕으로 통일하고 상시 안내와 큰 요약 영역을 줄인다. 모바일에서 행 클릭과 관련 퀴즈 링크가 충돌한 재현 결과에 따라 링크는 펼친 본문으로 옮긴다. 기존 유리·의미 색상·실제 기능/데이터를 보존하고 시안의 가상 정오답이나 아바타를 제품 기능으로 만들지 않는다. [정본](spec/design.md#p9-23-후속--시안에-맞춘-세-게시판).

2026-10-14 P9-23 후속 사용자 확정: 세 게시판의 창 전체에 읽기 바탕을 까는 대신 바깥 창은 맑은 유리로, 핵심 현황·목록·펼친 내용은 더 선명한 바탕으로 구분한다. 퀴즈 관리의 공개 중·작성 중·답변 대기와 Live 한 건은 넓은 화면에서 한 행으로 합친다. 작은 화면에서는 같은 영역 안에서 자연스럽게 두 줄로 놓고 기존 동작을 보존한다. [정본](spec/design.md#p9-23-후속--시안에-맞춘-세-게시판).

2026-10-14 P9-23 후속 사용자 확정: 운영 현황 세 항목을 구분선·칸 전체 호버·숫자 중심의 표시로 바꾸고 Live와 같은 행에서 형태를 구별한다. 밤의 본문은 회청색으로 밝혀 투명한 남색 창과 구분한다. 기존 시안의 인덱스와 작은 색 박스는 필터 개수·점수·답안 입력 여부에 적용하며 의미색과 실제 데이터를 유지한다. 답안 색은 입력 여부이며 정오답을 새로 추정하지 않는다. [정본](spec/design.md#p9-23-후속--시안에-맞춘-세-게시판).

2026-10-14 P9-23 후속 사용자 확정: 현황과 Live의 넓은 화면 비율을5:5로 맞춘다. 공개 중·작성 중·답변 대기는 기존 시간대 의미색의 초록·파랑·노랑 바탕을 평상시에도 표시한다. 퀴즈·문의 카테고리는 시안처럼 선택 탭과 본문이 이어지는 한 폴더로 구현한다. 선택 탭은 본문에 붙여 두고 비선택 탭의 호버 이동은 유지한다. 새 시안·의존성·자료 쓰기·원격 변경은 추가하지 않는다. [정본](spec/design.md#p9-23-후속--시안에-맞춘-세-게시판).

2026-10-14 P9-23 후속 사용자 확정: 비선택 인덱스도 호버 때 본문에서 떨어지지 않도록 위치 이동을 없앤다. 상단 색 띠를 넓히고 반사·그림자로 붙어 있는 입체감을 준다. 현황 세 칸은 직각 모서리와 위아래 선만 쓰며 가운데 두 경계는 점선으로 나눈다. 관리자 사이드바는 게시판의 콘텐츠 창과 같은 투명 재질로 맞추고 작은 글자 대비를 함께 보완한다. 기존 기능·5:5 비율·세 의미색을 유지한다. [정본](spec/design.md#p9-23-후속--시안에-맞춘-세-게시판).

2026-10-14 P9-23 후속 사용자 확정: 퀴즈·문의 인덱스의 탭 사이 간격을 없애 직접 맞붙인다. 사용자가 지칭한 윗부분은 “탭 상단 강조선”으로 부르며, 탭 안쪽으로 옮겨 돌출을 제거한다. 사이드바와 Live의 한쪽 강조선은 둥근 외곽선에서 분리한 일정 두께의 직선으로 바꾼다. 앞으로 추가·수정하는 관리자 강조선에도 모서리를 따라 가늘어지는 형태를 쓰지 않는다. 기존 시간대 색·배경·선택/초점 동작은 보존한다. [정본](spec/design.md#p9-23-후속--시안에-맞춘-세-게시판).

2026-10-14 P9-23 후속 사용자 확정: 사이드바·Live의 독립된 왼쪽 직선도 제거하고 면·얇은 전체 테두리·Live 채움 배지로 구분한다. 밤의 사이드바 선택 배경은 회색으로 바꾼다. 도구·설정 네 메뉴의 바깥 콘텐츠 창에도 같은 맑은 유리를 적용하고 입력/주의/상세창을 보존한다. 인덱스에 남아 있던 공통 버튼의1px 눌림 이동을 제외하며, 이후 확인에는 움직임 감소를 끈 상태의 누르는 중 동작도 포함한다. 모서리에서 가늘어지는 한쪽 강조선 금지 기준은 유지한다. [정본](spec/design.md#p9-23-후속--시안에-맞춘-세-게시판).


2026-10-14 P9-23 후속 사용자 확정: 탭의 좌표가 고정돼도 내려가 보이는 시각 문제는 남을 수 있으므로, 사용자가 주석으로 지정한 문의 생성 이미지를 직접 기준으로 삼는다. 비선택 탭의 상자 구분선·상단 띠를 없애고 선택 탭만 강조하며 높이·패딩·글자 굵기/기준선을 통일한다. 사이드바와 도움말의 모든 왼쪽 메뉴는 하나의 공통 선택 면을 사용한다. 왼쪽 선이나 굵은 외곽선 대신 밝은 면·윗빛·작은 그림자로 구별하고 밤에는 회색을 유지한다. 명시 요청에 따라 도움말 읽기 작업영역의 새 가로 시안 한 장을 생성하고, 투명한 목차와 불투명한 본문을 실제 React에 적용한다. 이는 기존 자료와 설명용 실제 UI 캡처를 가상 이미지로 대체하는 작업이 아니다. [현재 명세](spec/design.md#p9-23-후속--선택-표면과-도움말-읽기-영역) · [새 시안](design/phase-9/manual-reader/README.md#p9-23-투명-목차와-불투명-읽기-영역).
