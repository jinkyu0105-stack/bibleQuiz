# 주요 결정 — 현재 기준

현재 결정의 짧은 목록이다. 상세 조건은 [명세 목차](../implementation.md), 선택 이유·변경 경과는 각 원문 링크에 보존한다. 과거 기록의 당시 상태는 [현재 STATUS](STATUS.md)를 대체하지 않는다. D-001은 문서 분리 결정을, D-029는 기존 계약의 부분 대체를 기록한다. D-029 새 경로의 로컬 연결은 P5-49~51에서 완료했으며 실제 품질 시험·운영 적용과 구별한다.

## D-001 — 상세 명세를 분야별로 분리하고 원문·링크를 보존

2026-09-21 사용자 문서 개선 요청으로 종전 단일 파일 유지 방식을 대체한다. 루트 implementation은 목차, docs/spec은 분야별 정본, STATUS/HANDOFF는 현재 상태, archive는 원문·과거 기록으로 나눈다. 기존 절·결정 ID와 링크를 보존한다. 반복 읽기와 현재/과거 혼동을 줄이기 위한 변경이다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-001--상세-명세는-루트-implementationmd에-유지).

## D-002 — Cloudflare Workers + Static Assets 단일 웹앱

React 정적 자산과 Hono API를 Cloudflare Workers + Static Assets로 제공한다. Pages로 되돌리지 않는다. 핵심 도메인 로직은 플랫폼과 분리한다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-002--cloudflare-workers--static-assets-단일-웹앱).

## D-003 — D1 + Drizzle + 검토된 SQL migration

D1 + Drizzle을 사용한다. schema 변경은 SQL migration을 생성·검토하고 환경별 적용한다. drizzle-kit push는 사용하지 않는다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-003--d1--drizzle--검토된-sql-migration).

## D-004 — Node 24와 pnpm 11 단일화

Node 24.18.0·pnpm 11.14.0을 local/CI/Workers Builds에 맞춘다. pnpm-lock.yaml만 사용한다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-004--node-24와-pnpm-11-단일화).

## D-005 — Preview와 Production을 물리적으로 분리

main은 Access 보호 Preview에 자동 배포된다. Production은 별도 자원과 수동 승인으로 배포하며, 운영 트리거·승인·migration·rollback은 아래 P8-02 합의를 따른다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-005--preview와-production을-물리적으로-분리).

P5-69는 기존 경계를 적용한 [실제 시험·환경별 승인·rollback 계획](work/P5-69.md)을 문서화했다. 자료/표본 수·예산·판정 기준과 Production 실행 순서는 운영자 결정 전 제안이며, 문서 완료를 유료 호출·실자료·원격 적용 승인으로 간주하지 않는다. 새 제품 제한·운영 합의는 추가하지 않았다.

2026-10-02 P8-02 승인: 사용자는 복잡한 문서 대신 쉬운 설명을 요청했고, “실제 운영용 서버/저장소 준비·관리자 로그인/백업 연결·완성한 프로그램을 올리고 공개”가 실제 Cloudflare 적용임을 설명한 뒤 **“승인합니다”**라고 답했다. 이에 수동 승인 배포, 백업 후 순차 SQL 적용, 심각한 회귀 시 공개/쓰기 중지와 호환 코드 복귀(데이터 복구는 손실 범위를 별도 확인)를 확정한다. 최초 Worker/SQLite DO 등록은 주소 비공개 deploy, 이후 일반 코드 변경은 version 업로드와 traffic 배포를 구분한다. main은 Preview 자동 배포로 유지하고 이번에 push하지 않는다. 무료 workers.dev 후보를 기본으로 진행하며 관리자 path 보호 검수 전 공개하지 않는다. 월USD0 목표·기존 실제 자료/키/유료 결과 보존·새 AI 호출0·Paid 전환/유료 구매 제외를 유지한다. 승인된 같은 범위의 내부 단계를 다시 승인받지 않는다. 계정 권한이나 R2 checkout 등 사용자의 UI 조작/새 비용 결정이 실제로 필요하면 확인 근거와 필요한 한 동작만 안내한다. [실행 범위·검수·복귀](work/P8-02.md). 현재 자원 존재/적용 완료 사실은 STATUS에서 별도로 판단한다.

2026-10-03 P8-02 AI 연결 추가 승인: 사용자는 기존 키를 비공개 콘텐츠 서버에만 표준입력으로 전달하고 앱/콘텐츠 설정 네 개를 켠 뒤 검사·배포하는 검토 묶음을 설명받은 후 **“알겠습니다. 다음 작업 승인합니다. 재개하세요”**라고 답했다. 새 로컬 키 사본은 만들지 않는다. 기존 nonprod 키의 승인된 재사용으로 OpenAI Project 청구가 합산될 수 있으며 앱의 Production 비용 원장은 분리한다. 기존 모델 gpt-5.6-terra/high·검수 결과를 유지하고 새 유료 AI 생성 시험·Paid 전환·구매·main push·실제 데이터 손실 복원은 제외한다. 이전 자동 승인 검토 거절은 실행되지 않은 과거 시도이며 이번 명시 승인과 구분한다. 실제 적용 완료는 STATUS/HANDOFF의 배포·보존 근거로 판단한다.

## D-006 — 관리자 인증은 Cloudflare Access

관리자 UI/API는 Cloudflare Access로 보호하고 Worker에서도 JWT를 검증한다. 현재 계정 구성원 정책과 6시간 세션을 사용한다. 적용 범위는 현재 코드/환경으로 확인한다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-006--관리자-인증은-cloudflare-access).

## D-007 — 일반 사용자는 회원가입 없이 익명 세션

회원가입 없이 서버 발급 익명 브라우저 세션을 사용한다. 이름·답안·코멘트 공개/보관 동의와 문의·삭제 요청을 제공한다. 실명을 기술적으로 강제하지 않는다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-007--일반-사용자는-회원가입-없이-익명-세션).

## D-008 — 성경은 개역개정 장절·판본·공식 링크만 표시

v1은 개역개정 본문을 저장·복사·출력하지 않고 장절·판본·대한성서공회 공식 링크만 표시한다. AI가 본문을 생성·보완하지 않는다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-008--성경은-개역개정-장절판본공식-링크만-표시).

## D-009 — AI는 내용 이해, 코드는 퍼즐 배치

AI는 교정 문서·의도·요약·답/단서를 만들고, 사람 확인 뒤 결정론적 코드가 5×5~10×10 격자를 배치한다. AI가 최종 좌표를 결정하지 않는다. 간결한 결과·사람 최종 판단은 D-029를 따른다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-009--ai는-내용-이해-코드는-퍼즐-배치).

## D-010 — 설교 이해 품질을 AI 비용보다 우선

설교 이해 품질을 우선한다. non-production 모델 시작점은 gpt-5.6-terra이며 의도 분석과 앞단 비판 검토를 유지한다. 관리자 재생성 횟수·입출력 token을 임의 제한하지 않는다. 실제 usage와 모델별 비용을 표시한다. P5-68은 기존 호출 원장의 관측 금액과 당시 가격표 version을 퀴즈 단위로 읽고, 미보고 호출은 비용 미확인으로 분리한다. 과거 금액을 현재 가격으로 다시 계산하지 않는다. 이는 이번 Codex 작업 모델과 별개다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-010--설교-이해-품질을-ai-비용보다-우선).

## D-011 — 자막은 공개 CC 우선, 원본과 수정본을 보존

계정 없는 공개 CC adapter를 우선하고 실패 시 직접 붙여넣기를 제공한다. 원문은 불변이며 자막만 직접/선택적 AI 교정 후 사람이 확정한다. 교정 결과 형태는 D-029를 따른다. P5-66에서 영상 제목·게시일 후보의 조회와 공개 자막 원본 취득을 관리자 UI/API에 로컬 연결했다. 사람 확정·3만 자 제한·실제 provider 운영 게이트는 유지한다. [구현·검사](work/P5-66.md). [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-011--자막은-공개-cc-우선-원본과-수정본을-보존).

2026-10-03 P8-02 관리자 직접 검수에서 사용자는 수동 수정 안내에 대해 제목·장절 자동 입력이 목표임을 재확인했다. 기존 사람 확인은 자동 입력된 결과의 확인이며 매번 직접 입력하는 절차로 바꾸지 않는다. 제목의 명시 날짜/예배 구분/단일 유효 장절을 기존 코드 파서로 분리해 제목·날짜·장절/선택 UI를 자동 입력한다. 불명확·범위 오류·복수 장절은 추론하지 않고 직접 입력하는 fallback을 유지한다. AI·새 의존성·migration을 추가하지 않으며 Preview의 조회/날짜 추천/수동 장절 동기화와 누락된 제목 분리/장절 추출을 구분한다. [정본](spec/generation.md#p5-66-공개-영상-정보자막-취득의-관리자-연결).

2026-10-03 실제 운영 watch 차단이 영상 제목까지 누락시킨 것을 확인해 기본 정보와 자막 실패를 분리한다. 제목이 없는 차단 미리보기만 공개 oEmbed 제목을 제한적으로 보완하며, 원본 import·자막 실패 진단·사람 확인은 유지한다. 이는 자동 등록 목표의 복구이며 자동 자막 성공이나 수동 운영으로의 목표 변경을 뜻하지 않는다. [구현과 대안의 한계](work/p8-02/automatic-registration.md#자막-차단과-제목-조회-분리--2026-10-03).

2026-10-03 사용자는 ‘스크립트 표시 복사’를 사용자 수동 작업이 아니라 프로그램/AI의 브라우저 자동 취득으로 명확히 했다. 수동 복사 안내를 철회하고 자동화 목표를 유지한다. 기존 로컬 Chromium으로 실제 화면 자막 읽기·파일 저장을 실증했다. 운영 실행 위치나 새 서비스는 아직 확정하지 않는다. [실증](work/p8-02/browser-transcript.md).

2026-10-04 과거 실행본/보관 TS와 첫 운영 수정 전 지문을 대조하고 같은 영상의 로컬·Cloudflare 시험에서 과거 요청은 성공, watch 자막 주소 우선 경로는 빈 응답임을 확인했다. 사용자 요청에 따라 운영 앱을 기존 단일 player POST 경로로 복구하되 native fetch 수정과 차단 시 제목 보완은 유지한다. Browser Run은 별도 소규모 시험이며 새 운영 의존성으로 채택하지 않는다. [비교·실험 결과](work/p8-02/transcript-comparison.md).

## D-012 — 출력은 웹 데이터에서 재현하고 AI를 다시 호출하지 않음

빈 격자 PNG/SVG, 복사할 단서, Top N A4 PNG/PDF를 웹 데이터로 만든다. 출력 때문에 AI를 다시 호출하지 않는다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-012--출력은-웹-데이터에서-재현하고-ai를-다시-호출하지-않음).

2026-10-01 P6-01은 기존 출력 계약의 9.1 상세 흐름에 맞춰 PDF 기본 동작을 **새 탭 뷰어, 탭/뷰어 실패 시 다운로드**로 통일했다. 9.3의 무조건 자동 다운로드 문구는 수정한다. 사용자는 무료 pdf-lib·fontkit·resvg-wasm·자체 호스팅 한글 폰트 추가를 승인했다. 원격 적용·새 AI 호출·유료 서비스 승인은 아니다. 빈 격자/단서는 누구나, 현재 Top N은 exact 난도 제출자, 지난 Top N은 공개라는 조건과 확정 순위 빈자리·숨김/삭제 제외를 유지한다. 기본 첫 페이지 12명과 긴 metadata의 안전한 다음 페이지 연결, 후속 페이지 12명, 두 난도 별도 섹션을 같은 view model/배치 자료로 만든다. 공용 일러스트의 P7B 귀속을 유지하며 새 이미지를 생성하지 않는다. [출력 계약](spec/export.md) · [구현·검사](work/P6-01.md).

## D-013 — 정적 이미지는 Git, R2는 비공개 백업만

최적화한 정적 이미지는 Git/Static Assets에 둔다. R2는 비공개 주간 SQL 백업 정상본 8개 순환에만 사용한다. v1은 KV를 사용하지 않는다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-013--정적-이미지는-git-r2는-비공개-백업만).

2026-10-02 사용자는 D1 Edit가 현재 계정 데이터베이스의 변경·삭제 권한도 포함한다는 설명 뒤 “네 그렇게 하세요”로 백업 전용 토큰의 권한 확대를 승인했다. 기존 BibleQuiz D1 Backup Read 토큰의 현재 계정 범위를 유지하고 D1 Read만 Edit로 변경한다. 토큰은 biblequiz-backup의 기존 D1_REST_API_TOKEN에서 재사용하며 앱/content에 주지 않는다. 이는 SQL 백업·readback/checksum·격리 복원 검수 승인이고 실제 Production 데이터 손실 복원·유료 전환·새 AI·main push 승인은 아니다. 권한 설정의 실제 저장·export 성공은 별도 검증 전 미완료다. [백업 인증 범위](spec/architecture.md)·[현재 검수](work/P8-02.md).

## D-014 — 디자인은 시안 승인 뒤 구현

[구현·검사](work/P5-53.md). P5-55는 같은 명시 재생성/비용 보존 계약으로 의도 분석+비판 검토의 별도 실행·비교·사람 재확정을 로컬 연결했다. 두 번째 호출 실패 시 불변 출처 행으로 첫 분석을 재사용하는 비판 검토 한 호출 재시도와 사용자가 승인한 기존 선택 유지 비교 종료를 추가했다. 실제 유료 호출·새 서비스 결정은 없다. ## D-031 — 저장 한 번의 처리 범위를 줄이고 수정본 3개 자동 삭제는 폐기

최초 import는 원본만 저장한다. 저장 시 이번 명령에 필요한 자료만 검사하고 정상 성공 뒤 본문 재조회를 생략한다. 선택한 두 문서의 diff는 요청할 때 계산한다. 수정본 3개 자동 삭제는 폐기한다. 별도 승인된 AI 초안 7일 정리 정책까지 취소한 것은 아니다. 새 경로는 로컬 UI/API에 연결됐고 기존 데이터 자동 변환/원격 적용은 별개다. [이유·원문](archive/2026-09-21-p5-48/docs/DECISIONS.md#d-031--저장-한-번의-처리-범위를-줄이고-수정본-3개-자동-삭제는-폐기).

P5-57은 기존 7일 정책을 초안 본문 정리에 연결한다. 미발행은 서로 의존하는 한 설교 초안 작업의 마지막 저장·수정 시각을 사용하며, 발행은 발행+7일을 유지한다. 2026-09-23 사용자가 설교 초안 작업 전체 단위를 선택했다. 0021의 불변 정리 표식으로 본문만 만료시키고 ID/checksum·확정·비용·영구 발행 자료는 보존한다. 과거 metadata 저장 시각을 알 수 없거나 영구 발행 자료가 부족하면 추정 삭제하지 않는다. 새 기간·보관 cap·서비스를 추가하지 않았으며 실제 데이터 정리·Cron 등록·원격 적용은 제외했다. [정책](spec/generation.md#p5-57-로컬-초안-정리-연결) · [구현·검사](work/P5-57.md).

P5-60의 0025는 같은 7일 정책을 새 철회 편집본에 적용한다. 과거 생성 초안 정리와 새 편집 작업을 구별하고 마지막 편집 저장부터 기한을 계산한다. 본문만 비우며 원본 철회/발행·편집 식별/해시·감사·비용은 보존한다. 새 정책·기간 예외는 없고 로컬 연결/임시 합성 D1 검증만 수행했다. [상세 경계](spec/data-model.md#p5-60-철회-편집-본문-정리).

P5-60의 0026은 같은 정책을 반복 편집과 재발행까지 연결한다. 현재 저장본 검토를 새 증거로 보존하고 최초 발행 snapshot·철회 행을 재작성하지 않는다. 재발행은 기존 발행 기본값인 즉시 시작·7일 마감을 적용하고 같은 slug를 유지한다. 다음 철회도 성공 제출 0건일 때만 새 주기를 연다. 새 편집/검토와 재발행 시각을 정리 시계에 연결하며, 만료 후 원본 철회 자료에서 새 편집을 명시적으로 시작한다. 새로운 보존 예외·원격 권한을 만들지 않았다. [현재 계약](spec/generation.md#p5-60-철회본-편집재검증재발행).

## D-034 — AI 근거의 문자 위치는 프로그램이 계산

2026-09-25 문자 위치 계산을 채택했고, 2026-09-28 사용자가 **구간/시간까지 프로그램이 전체 원문에서 찾고, 못 찾은 근거는 표시만 하며 저장·진행을 유지**하도록 확정했다. AI에는 짧은 인용문만 요구한다. 유일한 정확 일치만 위치를 연결하고, 없음/복수 일치는 원문을 바꾸지 않은 `위치 미확인` 자료로 보존한다. 특정 개수 이상 차단하거나 항목마다 별도 승인을 요구하지 않는다. 기존 사람 최종 검수와 입력/버전/공개 정보 분리는 유지한다. 보관된 비판은 재호출 없이 같은 규칙으로 받아들이되 원래 failed/rejected/비용은 보존한다. 당시 프롬프트/schema는 v3이며 현재는 아래 참조 정정을 포함한 v4다. [상세 계약](spec/generation.md#p5-70-근거-문자-위치는-프로그램이-계산) · [구현·실제 기록](work/P5-70.md#전체-원문-위치-검색과-진행을-막지-않는-표시).

D-034의 2026-09-27 구현 보완: 재부팅 후 기존 교정안/분석/키를 재사용하고 추가 호출 없이 보관 분석의 출처·확정 문맥·정산 이력을 검사하는 로컬 복구 준비 도구를 추가했다. 이는 새 분석 채택 정책이나 실패 job 수정 승인이 아니며, 실제 자료 적용/비판은 미완료다. [복구 준비](work/P5-70.md#보관-분석의-무료-복구-준비와-로컬-검수).

D-034의 복구 저장 연결: 기존 실패·비용을 그대로 둔 새 AI 분석 event와 0030의 불변 출처 기록을 원자 저장한다. 동일 source의 중복 저장을 막고 현재 문맥을 저장 시점에 재검사한다. 정상 생성의 success 증거를 완화하지 않고 복구 결과에만 원래 rejected/정산 출처를 별도 검증한다. 복구 자체는 AI 비판·사람 확정·후속 유료 실행이 아니다. ## D-036 — 생성 조회 재사용의 범위와 검수 완료의 원자 저장

2026-09-29 P5-71에서 반복 조회로 최초/후속 생성·최종 완료의 D1 통신량이 커지는 문제를 재현했다. 한 요청 또는 실제 Workflow 단계 안에서만 불변 자료의 검증 결과를 재사용하고 독립 읽기를 묶는다. 현재 상태·선택·metadata·정리/품질은 새로 확인하며 크기 검사·출처·해시·비용·사람 확정·저장 시점 조건을 유지한다. 검수된 full 작업은 기존 단계 증거와 완료 proof를 하나의 조건부 거래로 저장한다. 새 영속 캐시/표나 제품 제한은 추가하지 않는다. 자동 AI 재시도는 계속 금지이며 기존 중간 단계 작업의 재개도 유지한다. 로컬 50회 통신 제한 통과는 원격 무료 운영 판정이 아니다. [구조](spec/architecture.md) · [구현·검증](work/P5-71.md#반복-조회-수정과-제한-검사).

관리자 표시 조회는 현재 선택·한 이력 페이지·필요 의존 결과의 봉인/길이/SHA·소유자·출처 기록을 확인한다. 정상 AI 결과의 성공·context 연결, 복구 결과의 별도 출처, 사람 기록과 현재 head/정리 상태를 유지하되 과거 모든 생성 문맥과 원문을 재구성하지 않는다. 이 읽기는 표시용 자료만 반환하고 쓰기 권한에 쓰는 DomainBasis나 검증 witness를 만들지 않는다. 미리보기는 현재 ticket·metadata·선택·품질에 연결된 결과로 표시한다. 수정·검수·생성 재개·최종 완료·발행은 기존 전체 출처/원문/현재성 검증을 계속 수행한다. 입력 교체 뒤의 이전 결과는 비교용으로 보이며 재사용 권한이 되지 않는다.


P5-71 후속 구현은 같은 표시/쓰기 경계 안에서 관리자 조회를 상태·비용·내용·생성 이력·배치의 독립 HTTP 요청으로 나눈다. 화면은 도착한 부분부터 보여 주되 서로 다른 저장 버전은 합치지 않는다. 부분 실패 때 받은 내용은 보존하고 편집 잠금·명시 재조회를 제공한다. 새 표/캐시나 계산 위치 변경은 없으며 원격 CPU 통과 여부는 별도로 실측한다. [조회 계약](spec/api.md#p5-71-관리자-콘텐츠의-분할-조회).


## D-037 — Preview 합성 실행의 범위와 실패 응답 보관

2026-09-29. P5-71의 원격 승인은 지정된 Preview와 합성 시험에 한정한다. app 전체 AI flag를 여는 대신 정확한 Preview origin과 합성 자료 UUID 허용 목록을 사용하고, 비공개 Workflow도 고정 합성 입력을 확인한다. 실제 provider key는 연결하지 않는다. CPU/보존 실패 때 추가 시험을 멈추고 기존 결과를 유지한다. 원격 CPU 실패는 확인됐으며 월 USD 0 우선 원칙이나 Workers Paid 전환은 변경하지 않았다. [실측](work/P5-71.md#실제-원격-시험-결과).

원격 실패 응답 전문 보존이라는 기존 완료 조건을 위해 별도 서비스를 추가하지 않고 기존 D1에 요청/응답 manifest와 chunk를 추가한다. 요청 선저장·중복 전송 차단·응답 검사 전 byte 보관·관측 usage 우선 보존·검증된 내부 회수를 사용한다. 기존 승인된 7일 초안 정리에서 원문 chunk를 같이 정리하고 비용/manifest는 남긴다. key/headers·공개 경로·자동 재시도는 추가하지 않는다. 0035와 flag는 로컬 검토 가능 상태로 준비하며 원격 적용과 유료 호출의 승인 경계는 그대로다. [구조](spec/architecture.md) · [데이터](spec/data-model.md#p5-71-비공개-요청응답-전문-보관).

D-036/D-037의 무료 운영 보완(2026-09-29): CPU 실패 후 사용자가 “무료로 계속”을 선택했다. 동일 작업의 무료 CPU 수정·검증으로 진행하며 유료 플랜 선택을 재개 조건으로 두지 않는다. 이후 사용자가 “승인 — 기존 Preview에 0035 적용”을 명시했고 기존 Preview에만 적용했다. 기존 82개 표/219개 행 보존·FK 0·quick_check ok를 확인했다. 실제 AI 호출은 승인되지 않았으며 무료 검증만 계속한다.


D-036/D-037 실행 장소 확정(2026-09-29): 사용자는 PC가 켜져 있을 때 생성하는 대안을 거절하고 **PC 의존 없이 Cloudflare에서 모두 실행**할 것을 명시했다. 월 USD 0 우선과 실제 AI 별도 승인 경계를 유지한다. 큰 최종 검사를 HTTP 요청에서 기존 비공개 Content Workflow의 최종 검사 전용 실행으로 옮기고 화면은 Access 보호 상태를 조회한다. 같은 requestKey는 같은 검사만 재사용하고 AI 생성·공개 발행은 하지 않는다. 이 단계에는 새 DB 표나 외부 서비스를 추가하지 않았다. `CONTENT_FINAL_CHECK_WORKFLOW_ENABLED` 기본값은 false이며 검증된 Preview에서만 별도로 켠다. 30,000자 기존 결과의 원격 최종 검사/원래 Workflow 완료와 중복 방지를 확인했다. 완료 HTTP/상태 조회 CPU는 5~7ms다. 관리자 조회의 후속 저장 방식은 D-038을 따른다.

## D-038 — 관리자 조회는 저장된 내용과 격자를 재사용

2026-09-30. 조회 분할 뒤에도 정상 자료의 내용 29~71ms·배치 46~69ms를 측정했다. 콘텐츠는 불변 작업 봉투에 저장돼 있지만 GET이 전체 구조를 다시 읽었고, 최종 ticket은 선택 조건만 저장해 GET이 격자를 다시 탐색했다. 같은 P5-71의 반복 계산 제거 요청에 따라 **검증된 쓰기의 결과를 기존 D1에 표시용 사본으로 함께 저장**한다. 0036은 비공개 `generation_display_snapshots`·`generation_display_finals` 두 표만 추가한다. 새 외부 서비스·AI 호출·PC 의존·제품 제한은 추가하지 않는다. 요청 안에서만 재사용하는 D-036 방식으로는 다음 HTTP 요청의 재계산을 없앨 수 없어 영속 표시 사본을 선택했다. 매번 원본을 복원하는 대안은 재현된 CPU 병목을 남긴다.

AI 결과·사람 편집의 기존 조건부 거래에 내용 사본을, 배치 선택·최종 검사 거래에 이미 계산한 난도별 격자를 넣는다. 사본은 원본 식별자·소유자·원본 fingerprint·사본 SHA에 연결된다. GET은 사본의 SHA/구조/소유자/봉인된 원본 fingerprint와 현재 head·metadata·품질을 확인하고, 원본 조각·provider 문맥 복원·격자 탐색·자동 쓰기를 하지 않는다. 사본 손상/누락은 실패로 반환하며 비싼 복원으로 자동 우회하지 않는다. 사본은 DomainBasis/witness가 아니며 생성·복구·편집·최종 검사·발행의 원본 전체 검증은 유지한다. 사본의 교체/복구는 검증된 쓰기나 명시적 준비에서만 수행한다.

기존 자료는 AI 없이 원본 자료별·격자 난도별 Cloudflare Workflow 단계로 한 번 준비한다. 완료 proof가 있는 기존 격자만 재현하고 조합한 미리보기 fingerprint를 원래 proof와 대조한다. 새 준비는 별도 비활성 flag와 정확한 설교 UUID 허용 목록을 요구하며 실제 AI flag/합성 생성 허용 목록을 열지 않는다. 기존 기록·migration·비용은 덮어쓰지 않는다. **0036 원격 적용·새 app/content 배포·기존 세 자료의 표시 사본 준비는 새로운 구체적 승인 전 실행하지 않는다.** 이전 조회 분할 배포 승인을 이 변경의 승인으로 확대하지 않는다. 로컬 비교 성공을 무료 CPU 통과로 쓰지 않는다. 이후 사용자가0036·Preview 배포·기존 세 자료 준비·CPU 검사 범위를 확인하고 “시작하세요”로 승인해 해당 범위를 실행했다(2026-09-30). 준비 flag는 다시 비활성화했고 실제 결과는 P5-71의 최신 기록을 따른다. [구조](spec/architecture.md#p5-71-저장된-표시-자료의-재사용) · [데이터](spec/data-model.md#p5-71-표시용-내용격자-사본) · [재개](work/P5-71.md).

## D-039 — 관리자 요청의 계산을 비공개 Durable Object로 분산

2026-10-01 사용자가 공식 CPU 분석·최적화·Durable Objects·작은 요청 분할을 적용하라고 명시했다. 기존 분할 조회는 유지하고 관리자 API의 인증·자료 처리·명령 검증을 같은 앱의 내부 `AdminCompute` 클래스에서 실행한다. 앱 Worker는 요청/응답 스트림을 전달하며 자료를 다시 파싱하지 않는다. 공개 풀이·제출과 Cron 경로는 기존 구현을 사용한다. 전송 실패는503으로 돌려주고 명령을 자동 재실행하거나 기존 Worker로 fallback하지 않는다.

## D-040 — 주간 운영은 기존 저장·조치 경로를 재사용하고 문의 조회키는 재시도 시 복구

2026-10-01. P5-72의 첫 화면과 여섯 단계는 기존 D1 입력·내용·배치·발행 상태를 연결한다. 자동 저장과 명시적 초안 저장은 기존 버전 검사의 불변 수정본 쓰기를 재사용한다. 별도 편집 저장 계층이나 AI 재호출을 추가하지 않는다. 발행 전 Top N은 기존 `site_state`를 사용하고 발행/재발행 시 난도별 값으로 저장한다. 마감/확정 순위는 바꾸지 않는다.

## D-041 — 운영 자료는 기존 원장·삭제 gate를 재사용하고 원격 활성화는 분리

2026-10-01.
