# 개발을 끝내기 위한 실행 기준

2026-09-28. 사용자의 개발 방식 전수 조사·개선 요청에 대한 실행안이다. [감사 보고서](DEVELOPMENT_AUDIT_2026-09-28.md)는 근거, 이 문서는 남은 범위와 종료 조건, [STATUS](STATUS.md)는 실제 진행 상태, [HANDOFF](HANDOFF.md)는 다음 첫 행동을 맡는다. 기존 제품 요구를 삭제하거나 유료 호출·실제 자료 변경·원격 적용을 승인하는 문서가 아니다.

## 판정과 이번 변경

**개발 방식에 중대한 문제가 있었다. 더 높은 요금제나 추론 설정만으로 해결할 문제가 아니다.** 실제 한 편을 끝내기 전에 내부 저장 구조를 넓게 만들었고, 부분 구현 완료를 제품 완료에 가까운 것처럼 안내했으며, 보존·실제 환경 검증을 늦췄다. 9월 21일에도 이를 지적했지만 반복을 막는 실행 기준이 부족했다. 사용자의 기획 노력이나 사용량 부족을 주원인으로 돌릴 근거는 없다.

- 긴 작업 159개에 기록된 시간 합계는 66.404시간, 주 대화 전체 완료 turn 합계는 79.106시간이다. 대기·계획을 포함하며 순수 코딩 시간이나 청구액은 아니다. 이번에 완료 turn ID 712개의 중복 없음도 대조했다.
- 앱 소스는 약 3.6만 줄이며 구현과 통과한 검사는 실제로 있다. 반면 DB 80개 테이블·303개 trigger와 여러 저장/이력 경계는 변경 비용을 높인다. 모든 테이블이 불필요하다거나 전면 재작성이 더 빠르다는 증거는 없다.
- 현재 명세는 퀴즈 생성만이 아니라 수정본 교체, 참여자 관리, 여러 출력, 백업·복원, 비용 대시보드까지 포함한다. 먼저 쓸 수 있는 생성기와 공개 v1의 완료를 구분하지 않은 진행 관리가 잘못이었다. 이번에는 기존 요구를 모두 남은 결과에 배정한다.
- 실제로 낭비된 시간·구독 비용의 정확한 비율, 정상 개발이라면 걸렸을 시간은 측정할 수 없다. 아래 결과 수를 대화 횟수·완료 시간·제품 완료율로 환산하지 않는다.

이번 개선은 **완료 조건 고정, 현재 결과 재사용, 실제 운영 조건 조기 검증, 반복 작업 제한**이다. 새로운 생성 엔진·일괄 DB 재설계·별도 감사 도구를 만드는 일이 아니다.

## P5-70: 다음 개발에서 실제로 해결할 것

### 완료 결과와 기준

P5-70은 2026-09-29 기존 한 편의 실제 AI 결과·사람 검수·두 난도 로컬 발행·브라우저 풀이/제출/채점·프로세스 재시작 후 보존까지 완료했다. 기존 실패·원응답·비용은 보존했으며 마무리의 새 AI 호출은 0이다. 자세한 증거와 다음 재개는 [작업 기록](work/P5-70.md#로컬-발행풀이채점재시작-완료)·[STATUS](STATUS.md)·[HANDOFF](HANDOFF.md)를 따른다. 아래 종료 기준과 나머지 결과 묶음은 변경하지 않는다.

### 한 번에 준비하고 검증할 범위

1. 실제 자료를 건드리지 않고 위 연결과 현재 검사 불일치를 구현한다. 기존 복구 CLI·원응답 보관기·화면/서비스를 사용한다. 운영자 신원을 임의로 꾸미거나 로컬 도구의 명령 허용 목록을 우회하지 않는다.
2. 합성 자료로 **복구 분석 → 비판 1회 → 사람 확정 → 후속 3회 → 기존 배치/finish**를 검증한다. 교정·분석 HTTP 요청은 0회, 재개/같은 요청 반복으로 추가 호출 없음, 원래 failed/usage 불변을 확인한다. 다른 원문·이전 version·잘못된 출처는 거절하고 정상 신규 생성·옛 비판 재시도도 보존한다.
3. 실제 DB/보관 지문과 최종 코드가 일치하는 적용 계획, 예상 호출/비용, 화면에서 검수할 결과까지 준비한 뒤 **실제 복구·비판·후속 생성·로컬 시험 발행 범위를 한 번에** 제시한다. 무료 구현을 승인받으려고 중간에 멈추지 않는다. 기존에 소진된 호출 승인을 재사용하지 않는다.
4. 승인된 범위 안에서 끝까지 진행한다. 사람의 의도 확정과 발행 전 검수는 필요한 제품 동작으로 남지만, 내부 helper/저장 단계마다 “다음 진행”을 요구하지 않는다. 사람 판단이 필요한 시점에는 검수 화면과 판단할 사항을 한꺼번에 제시한다.
5. 두 난도 생성·무료 배치·검토·승인된 로컬 발행/풀이/제출/채점 결과를 확인하고, 프로세스를 종료·다시 열어 저장된 결과로 재개한다. 전원 재부팅 시험을 했다고 바꾸어 쓰지 않는다. 교정 비교의 글자/공백/문장부호 단위 강조도 유지한다.

시험 통과 기준은 기존 평가표의 “사용 가능/수정 후 사용/사용 불가”와 사람 판단이다. 발행을 막는 내용·정답 오류는 고치되 첫 시험을 완벽한 설교 문장 품질 연구로 확장하지 않는다. P5-69의 추가 표본/반복 횟수 제안은 이미 승인된 의무로 취급하지 않는다.

### 남은 유료 호출과 보존

기본 경로는 **비판 1 + 요약 1 + 어린이 1 + 장년 1 = 총 4회**다. 교정 0, 의도 재분석 0, 최종 AI 감사 0, 자동 유료 재시도 0이다. Codex Astra 최대 추론 요청은 앱 API 모델 변경이 아니다. 기존 시험의 `gpt-5.6-terra`/high를 유지하며 바꾸려면 이유와 비교 조건을 먼저 제시한다.

2026-09-28 확인한 [OpenAI 공식 가격](https://developers.openai.com/api/docs/pricing/)은 Terra 표준 짧은 입력 기준 100만 토큰당 입력 USD 2, 캐시 입력 0.20, 출력 12다. 각 호출을 입력 1.2만~3만·출력 4천~1만으로 가정하면 4회 합계 **약 USD 0.288~0.72**다. 캐시 할인은 이 추정에 넣지 않았다. 입력/출력 길이 가정이며 확정 청구나 상한이 아니다. 과거 교정 출력 14,237토큰은 이미 이 가정을 넘은 사례다.

실제 승인안에는 요청별 입력 크기·모델·예상 금액과 누적 관측 비용을 표시한다. USD 1은 사용할 수 있는 **검토 예산 제안**이지 구현된 hard cap이나 이미 승인된 금액이 아니다. 개별 호출은 예상보다 비쌀 수 있다. 비판 1회 완료 뒤 관측 비용/원응답을 확인하고 후속 세 호출의 재개 여부를 판단한다. 후속 세 호출은 하나의 명시 재개로 실행되므로 금액에 따른 호출 중간 자동 차단은 구현돼 있지 않다. 실행 오류·사용량 미확인은 기존 실행기가 중단하며 새로 구매하거나 자동 재시도하지 않는다. D-010에 반하는 임의 출력 토큰 제한을 새로 넣지 않는다.

교정/원응답/분석/DB/검수 HTML은 기존 `~/.local/state/biblequiz/` 자료를 사용한다. 키는 값을 출력하지 않고 기존 파일 존재·권한만 확인한다. Access 로그인 만료는 파일 유실과 다르며 보호된 앱 이용 시에만 갱신한다. OpenAI 키를 재입력하거나 보관 결과를 재생성하는 것을 일상적인 재개 절차로 만들지 않는다. 현재 관측 USD 0.512988와 이전 유실 시험 USD 0.216028/unknown 2건은 별개 기록으로 보존한다.

## 무료 운영의 실증을 앞당긴다

[architecture 13장](spec/architecture.md)은 원래 Phase 0에서 전체 생성의 무료 한도 측정을 요구했다. 입력 저장 측정이나 로컬 Workflow 성공은 그 증거를 대신하지 못한다. 실제 구현·측정 상태는 [P5-71](work/P5-71.md)을 따른다. 생성 단계를 분리해도 관리자 요청의 CPU가 한도 안에 들어가는지는 별도로 측정한다.

Cloudflare 공식 표의 Free Workflow 한도는 단계당 CPU 10ms이고, 외부 API를 기다리는 시간은 CPU 사용에 포함하지 않는다. D1 표는 Free invocation당 query 50회를 안내하지만 Workers/Workflows 본문은 외부 50·Cloudflare 내부 1,000회로 구분한다. 보수적 로컬 통신 횟수 검사와 실제 배포의 query/CPU/오류 측정을 구별한다. [내부 서비스 한도](https://developers.cloudflare.com/workers/platform/limits/#subrequests). 이를 과거 입력 검사의 한계나 Paid 기본 CPU 값과 혼동하지 않는다. [Workflow 한도](https://developers.cloudflare.com/workflows/reference/limits/) · [Workflow 과금](https://developers.cloudflare.com/workflows/reference/pricing/) · [D1 한도](https://developers.cloudflare.com/d1/platform/limits/).

P5-71은 대표 설교 크기의 합성 응답으로 Preview의 실제 단계별 CPU/쿼리/저장·재개를 먼저 확인한다. 측정을 위해 AI를 반복 구매하지 않는다. 실제 provider의 네트워크/품질 확인은 별도로 최소 호출 범위를 제시한다. 실패하면 측정된 구간만 분리·최적화하고 확인한다. 가정한 최대 크기를 이유로 원문을 몰래 자르거나 후보 품질을 줄이지 않는다.

그 뒤에도 Free가 맞지 않으면 **제약과 실제 사용량, 무료 대안의 기능/운영 차이, Workers Paid 기본 월 USD 5와 AI 별도 비용**을 함께 제시한다. [공식 요금](https://developers.cloudflare.com/workers/platform/pricing/). 월 0달러를 지키려고 끝없는 설계에 들어가거나 임의 유료 전환하지 않는다. 로컬 생성 대안도 브라우저에서 주간 운영한다는 현재 요구에 미치는 영향을 설명하고 결정받는다.

## 검사와 시간 사용을 바꾸는 기준

- 현 실패를 P5-70 연결과 함께 고친다. `quiz-deadline.test.ts`는 HTTP/JWT와 일치하는 제어된 시계를 사용하고 지난 마감 거절 검사는 유지한다. 브라우저 6실패는 3시나리오×2환경이며, 옛 문구/영역을 실제 사용자 흐름에 맞춘다. 단언 삭제로 통과시키지 않는다.
- 기본 검사에서 빠진 응답 보관/로컬 세션/복구 준비/키 수신 도구 테스트를 검사 체인에 넣고, 명세의 Chromium CI 검사를 실제 실행하도록 연결한다. 현재 CI 15분 제한 안에 모든 것을 억지로 합치지 말고 브라우저 job을 분리한다.
- 기능 변경은 관련 검사·lint/typecheck, 화면 변경은 해당 브라우저 흐름을 실행한다. Phase/배포 완료에는 `pnpm check`를 실행한다. 코드·환경·실패 원인이 그대로인 동안 통과한 전체 검사를 반복하지 않는다. 이번 문서 작업은 앞선 감사의 검사 결과를 인용하고 코드 검사를 반복하지 않는다.
- 각 구현 turn은 정한 사용자 결과를 끝내거나 실제 입력/승인/환경/한도에 막힐 때까지 진행한다. 모델이 편의를 위해 작은 준비 단계 뒤 자발적으로 끝내지 않는다. 종료 때 **새로 작동하는 것, 남은 장애 하나 또는 병렬 독립 장애, 이번에 쓴 검사/호출**을 구체적으로 보고한다.
- 연속 두 구현 turn 동안 같은 장애로 사용자 결과가 전진하지 못하면 작업을 더 잘게 나누지 않는다. 그 자리에서 기존 접근·실패 증거·더 작은 대안을 비교하고 접근을 수정한다. 자동으로 새 감사 프로젝트나 번호를 만들지 않는다.
- 저장·보안·중복 과금 방지 검사는 유지하되, 추가 계층/테이블/외부 서비스는 현재 재현되는 장애 또는 명시 요구와 연결되어야 한다. 전체 테이블 축소나 옛 코드 삭제를 출시의 새 선행 조건으로 만들지 않는다.
- 비용/기간 예측은 실제 첫 완주와 Preview 측정 뒤 남은 결과별 근거를 붙여 갱신한다. 지금 새 완료일을 지어내거나 “최대 추론이면 몇 시간”이라고 보장하지 않는다. 새 설계 전에 먼저 현재 구현에서 재사용 가능한 경로를 확인한다.
- 미커밋 작업을 안전하게 보존하면서 검토된 목적별 로컬 commit으로 복구 지점을 확보한다. 대량 `git add`나 자동 main push를 하지 않는다. 사용자 변경·비밀값을 확인하는 작업은 현재 결과에 포함하며 별도 장기 정리 프로젝트로 만들지 않는다.

## 이번 조사로 확인한 것과 확인하지 않은 것

저장소 전체 파일 목록·명세 20분야·결정 34개·작업 기록·Git·대화 집계·앞선 실제 검사 결과를 대조했고, 현재 실패 분석의 재사용 경계와 무료 운영 조건을 코드/공식 문서로 추가 확인했다. 모든 코드 줄에 결함이 없다는 인증, 실제 청구 원장 감사, 현재 원격 자원 상태 조회, 전체 기기/유료 AI/Production 실행을 한 것은 아니다.

이번 변경은 문서와 진행 규칙이다. 제품 코드는 아직 달라지지 않았으며 P5-70/Phase 5는 진행 중이다. 다음 개발의 판단 기준은 **계획을 더 쓰는가가 아니라 보관한 분석으로 두 난도 퀴즈 완성에 실제로 가까워졌는가**다. 남은 실행 절차와 보관된 실제 적용 지문은 [HANDOFF](HANDOFF.md)에서 이어간다.
