# BibleQuiz 운영 매뉴얼

마지막 문서 갱신: 2026-10-13.

## 1. 이 사이트로 할 수 있는 일

한 주의 설교를 바탕으로 **어린이용·장년용 가로세로 퀴즈**를 만듭니다. AI가 초안을 도와주지만, 문제를 확인하고 공개하는 사람은 관리자입니다.

- 교인은 회원가입 없이 퀴즈를 풀고 답안을 제출할 수 있습니다. 다 풀지 않은 답안도 제출할 수 있습니다.
- 제출 뒤에는 내 답과 정답을 비교할 수 있습니다. 접수 중인 퀴즈의 참여 현황은 제출자에게, 마감된 퀴즈의 결과는 모두에게 공개합니다.
- 빈 격자 그림을 받거나 단서를 복사하고, 마감 뒤에는 설정된 상위 참여자의 결과를 출력할 수 있습니다.
- 지난 퀴즈는 연습용으로 다시 풀어볼 수 있습니다.

## 2. 원하는 기능 찾기

### 퀴즈를 만들거나 고치려면

관리자의 **퀴즈 관리**에서 제목 옆 버튼을 보세요. `초안 편집`은 아직 공개하지 않은 퀴즈를 이어서 만드는 버튼이고, `퀴즈 설정`은 공개한 퀴즈의 발행 정보나 접수 마감 등을 관리하는 버튼입니다.

`퀴즈 준비`를 누르면 만들던 초안이 있을 때 그 초안을 다시 엽니다. 홈에 표시되는 퀴즈도 이 화면에서 확인할 수 있습니다. **자동 선택**은 사이트가 공개 가능한 퀴즈를 골랐다는 뜻이고, **대표 지정**은 관리자가 직접 골랐다는 뜻입니다.

### 제출과 문의를 확인하려면

- **참여 기록**: 제출한 답안, 점수, 코멘트와 공개 여부를 확인합니다.
- **문의·삭제 요청**: 답변을 기다리는 문의를 읽고 답변하거나 처리 상태를 바꿉니다.
- **도구와 설정**: 수정·보관 도구, 이름·문구 필터, 비용·백업, 도움말을 모아 둔 메뉴입니다. 눌러서 펼칠 수 있습니다.

> **삭제 요청에 답변하는 것과 제출 자료를 삭제하는 것은 다른 일입니다.** 문의 상태를 ‘처리 완료’로 바꿔도 답안이 자동으로 삭제되지는 않습니다.

입력 중인 도구는 접었다 다시 펼쳐도 입력 내용이 유지됩니다. 본인 제출 삭제는 제출한 브라우저의 결과 화면에서 할 수 있으며, 삭제한 뒤에는 같은 퀴즈·난도에 다시 제출할 수 없습니다.

## 3. 퀴즈를 만드는 순서

### 자료 등록과 확인

1. **퀴즈 관리**에서 `퀴즈 준비`를 누르고 설교 영상이나 자료를 등록합니다.
2. 공개 자막을 가져오지 못하면 직접 붙여넣습니다. 받은 원본은 그대로 보관합니다.
3. 자막을 읽고 필요한 경우 교정한 뒤 확정합니다. 목사님이 제공한 원고나 요약본은 받은 그대로 사용합니다.

### AI 결과 검토와 발행

1. 설교 의도 분석과 비판 검토 결과를 읽고, 사람이 최종 의도를 확정합니다.
2. 요약과 어린이·장년용 답·단서를 확인합니다. 틀리거나 어색한 결과가 있으면 해당 항목을 수정하거나 다시 생성합니다.
3. 격자를 배치하고 두 난도의 문제를 확인한 뒤 발행합니다. 격자 배치는 저장된 후보로 계산하며 AI를 새로 호출하지 않습니다.

> **AI 작업이 멈췄다면 먼저 저장된 결과와 비용을 확인하세요.** 화면을 다시 열거나 컴퓨터를 다시 켰다는 이유만으로 이미 만든 결과를 다시 생성할 필요는 없습니다.

### 발행한 퀴즈를 고칠 때

- 제목·설교 날짜 또는 뜻이 바뀌지 않는 오타는 해당 정정 도구로 고칩니다.
- 문제의 의미나 정답이 잘못됐다면 접수를 중지하고, 검토한 교체본을 만드는 절차를 이용합니다. 기존 제출·성적·오류본을 덮어쓰지 않습니다.
- 출력할 상위 참여자 수인 `Top N`은 마감 전에 설정합니다. 마감 순위는 고정되며, 누군가 숨겨지거나 삭제돼도 다음 사람을 올려 빈자리를 채우지 않습니다.

## 4. 사이트 뒤에서는 무엇이 움직이나요?

브라우저에서 버튼을 누르면 **앱 서버**가 요청을 받고 **D1**이라는 자료 장부에서 퀴즈를 읽거나 저장합니다. 관리자의 계산 작업은 별도 작업 공간인 `AdminCompute`가 맡습니다.

AI 생성은 **콘텐츠 서버**, 자료 사본을 만드는 일은 **백업 서버**가 담당합니다. 여러 단계의 일을 이어서 진행하는 장치를 `Workflow`라고 합니다.

백업 서버만 비공개 파일 저장소 **R2**와 자료 내보내기 권한을 갖습니다. 백업·출력·복원은 AI를 새로 호출하지 않습니다. 각 서비스가 궁금하면 이 페이지 아래의 **서비스 사전**을 펼쳐보세요.

## 5. 연습용 서버와 실제 운영 서버

**Preview**는 수정한 화면과 기능을 확인하는 연습용 서버이고, **Production**은 교인이 사용하는 실제 운영 서버입니다. 코드 저장소는 같아도 퀴즈 자료와 연결 설정은 따로 관리합니다.

**로컬**은 내 컴퓨터에서 실행하는 화면입니다. `pnpm dev:demo`로 켜면 가상 관리자와 가짜 자료로 편집·제출·문의 처리를 연습할 수 있습니다. 연습 중 바꾼 자료는 서버를 다시 켜도 유지됩니다. 이 모드에서는 유료 AI 생성을 실행하지 않습니다.

### 연결 설정이 필요한 때

평소 운영을 위해 키나 연결 이름을 다시 입력할 필요는 없습니다. 설정 변경이 필요한 경우에만 대상 서버를 먼저 확인합니다.

Cloudflare 관리 화면에서 `Workers & Pages` → 대상 서버 → `Settings` → `Variables and Secrets` 순서로 찾습니다. `Secret`은 비밀번호처럼 숨겨 보관하는 값이고, `binding`은 코드가 데이터베이스 같은 자원을 부르는 연결 이름입니다.

> 비밀값은 채팅이나 문서에 붙여넣지 마세요. 서버를 바꾸거나 컴퓨터를 재시작하더라도 기존 보관 위치를 먼저 확인합니다.

### 현재 프로젝트의 연결 원칙

- 운영 AI 키인 `OPENAI_API_KEY`는 비공개 콘텐츠 서버에만 연결합니다. 관리자 화면의 생성·재생성 버튼을 눌러 사용할 때 비용이 생길 수 있습니다.
- 백업 저장소는 비공개로 유지하며 앱·콘텐츠 서버에 직접 연결하지 않습니다.
- 백업 설정에는 `OPERATIONS_ENVIRONMENT`, `CLOUDFLARE_ACCOUNT_ID`, `D1_DATABASE_ID`, `BACKUP_BUCKET_NAME`을 사용합니다. 자료 내보내기용 비밀 이름은 `D1_REST_API_TOKEN`, 사용량 조회용은 `CLOUDFLARE_ANALYTICS_TOKEN`입니다.
- 설정을 바꾸기 전 권한과 비용을 확인합니다. 전체 계정을 제어하는 키를 편의를 위해 추가하지 않습니다.

## 6. 매주 확인할 일

퀴즈를 발행한 뒤에는 **공개 화면에서 두 난도가 모두 열리는지**, 마감 날짜가 맞는지 확인하세요. 참여 기록과 답변 대기 문의도 함께 살펴봅니다.

마감과 일부 작업 내용 정리는 서버의 예약 기능인 `Cron`이 처리합니다. 운영 앱은 **5분마다** 마감과 정리 조건을 확인합니다.

정리 대상이 된 비교용 작업 내용은 마지막 저장 또는 발행 후 **7일**이 지나면 제거합니다. 설교 원본·확정본·공개 문제·제출·사용량 기록까지 지우는 기능은 아닙니다. 제출 삭제 표식도 퀴즈가 오래됐다는 이유로 지우지 않습니다.

문의의 자동 삭제 기간은 정하지 않았으므로, 문의를 일정 기간 뒤 자동으로 삭제하지는 않습니다.

## 7. 매월 비용과 사용량 확인하기

한국 시간으로 매월 1일부터 **비용·백업**에 월간 확인 안내가 나타납니다. 다음 항목을 확인한 뒤 `이번 달 확인 완료`를 누릅니다.

1. 서비스 계정의 현재 요금제와 공식 가격표를 확인합니다.
2. 사용량과 최근 백업의 성공 여부를 확인합니다. 여러 프로젝트를 쓰는 계정이라면 계정 전체의 사용량도 확인합니다.
3. 미처리 문의와 관리자 접근 권한을 살펴봅니다.
4. 서비스별 확인 항목을 선택하고 확인을 완료합니다.

### ‘확인 완료’를 눌러도 경고가 남는 이유

이 버튼은 **이번 달의 정책 확인 안내만** 닫습니다. 사용량 50% 확인·80% 주의, 조회 실패, 24시간이 지난 정보, 백업 실패 같은 경고까지 없애지는 않습니다.

`미확인`은 숫자를 읽을 수 없다는 뜻입니다. 사용량이 0이라는 뜻이 아닙니다. 조회 권한이 없거나 연결이 없을 때도 미확인으로 표시할 수 있습니다.

### 앱 비용과 실제 청구 금액의 차이

앱의 AI 비용은 **저장된 사용량과 당시 가격표로 계산한 추정액**입니다. 실제 청구는 OpenAI 계정의 `Costs` 화면에서 확인하세요. 같은 계정으로 다른 곳에서 쓴 비용이 함께 청구될 수도 있습니다.

실패한 AI 호출도 사용량이 확인되면 비용에 포함됩니다. 사용량 기록이 없는 호출을 무료로 단정하지 않습니다. 월간 숫자는 AI 재생성을 자동으로 막는 제한이 아닙니다.

### 사용량을 읽을 때 알아둘 점

- Cloudflare 무료 한도는 계정의 여러 프로젝트가 함께 사용할 수 있습니다. 이 사이트 숫자만으로 계정의 남은 무료량을 판단하지 않습니다.
- D1과 Workers의 일별 사용량은 UTC 날짜를 따릅니다. 월간 확인 안내는 한국 날짜를 따릅니다.
- R2의 저장 요금 단위인 `GB-month`는 저장량과 보관 기간을 함께 반영합니다. 앱의 현재 파일 크기만으로 청구액을 확정할 수 없습니다.
- Builds의 정확한 누적 실행 시간과 성공·실패 이력은 공급자 화면에서 확인합니다. 앱에서 읽지 못한 수치는 0으로 표시하지 않습니다.
- GitHub의 저장소 공개 여부·검사 실행 환경이나 별도 도메인의 갱신 비용도 해당 계정에서 확인합니다.

## 8. 사이트 코드를 수정하거나 배포할 때

퀴즈 내용을 편집하는 일과 **사이트 프로그램 자체를 고치는 일**은 다릅니다. 코드 변경을 서버에 올리는 것을 `배포`라고 합니다.

현재 `main`에 코드를 올리면 Preview가 자동 갱신됩니다. 실제 운영 서버 반영은 별도 절차입니다. 새 유료 기능이나 AI 실행까지 함께 승인된 것으로 보지 않습니다.

배포를 맡은 사람과 아래 내용을 확인하세요.

1. 어느 서버를 바꾸는지와 현재 실행 버전을 확인합니다.
2. 자료 구조 변경이 있으면 기존 자료 사본과 적용할 변경 파일을 확인합니다.
3. 코드 검사인 `pnpm check`와 필요한 브라우저 검사를 실행합니다. 검사 목록만 조회한 것은 검사를 실행한 것이 아닙니다.
4. 반영할 코드 버전, 결과 확인 방법, 문제가 생겼을 때 되돌릴 기준을 정합니다.

운영 서버는 `wrangler.production.jsonc` 설정을 사용합니다. 기존 자료 구조 변경 파일 `0000`부터 `0038`까지의 이력을 고치거나 순서를 바꾸지 않습니다. 정확한 소스와 배포 버전은 개발 기록 `docs/STATUS.md`와 `docs/HANDOFF.md`에서 확인합니다.

## 9. 오류가 났을 때 먼저 할 일

### 자막이나 AI 생성이 멈췄다면

작업 화면의 오류 안내와 저장된 결과를 먼저 확인합니다. 작업 번호와 비용 기록도 함께 보세요. 상태를 확인하기 전에 새 작업을 반복해서 실행하지 않습니다.

### 답안 제출이 안 된다면

입력한 내용을 유지하고 화면의 안내를 따르세요. `429`는 짧은 시간에 요청이 많이 몰렸다는 뜻입니다. **10초 뒤** 다시 시도합니다.

성공 안내를 받지 못했더라도 같은 내용·요청키로 재시도하면 기존 성공 결과를 먼저 찾습니다. 이를 위해 브라우저의 쿠키를 일부러 지우지 않습니다.

### 오류를 전달할 때

발생 시각, 문제가 생긴 화면 주소, 표시된 오류 코드와 요청 번호를 알려 주세요. 이름·답안·코멘트·로그인 정보·비밀키·설교 자막 전문을 진단 로그에 넣지는 않습니다.

### 마감이나 백업이 멈췄다면

마감은 기존 공개 페이지의 마감 처리 또는 관리자의 `지금 마감` 경로를 확인합니다. 예약 작업 일부가 실패했으면 전체 성공으로 보지 않습니다.

백업은 **마지막 정상 사본을 보존**합니다. `running`은 작업이 진행 중이라는 뜻이므로, 실제 작업이 끝났는지 확인하기 전에 잠금을 풀거나 새 백업을 겹쳐 실행하지 않습니다.

## 10. 백업과 복구

### 무엇을 언제 보관하나요?

주간 백업은 **매주 월요일 오전 4시, 한국 시간**에 실행합니다. 퀴즈와 제출 기록이 담긴 자료 장부를 압축 파일로 보관하고, 정상적인 주간 사본 **8개**를 유지합니다.

수동 백업과 자료 구조 변경 직전의 사본은 주간 사본을 밀어내지 않으며 자동 삭제하지 않습니다. 월간 점검에서 필요성과 개인정보 보관 기간을 검토해 별도로 정리합니다.

삭제된 개인정보가 복구 과정에서 다시 살아나지 않도록, **어떤 제출이 삭제됐는지 나타내는 별도 기록**도 10분마다 보관합니다. 이 기록에는 이름·답안·코멘트를 넣지 않습니다.

> 백업 중에는 자료를 내보내느라 사이트가 잠시 응답하지 못할 수 있습니다. 이 백업에는 데이터베이스 자료가 들어가며, 코드·로컬 키·서버 설정 전체가 들어가는 것은 아닙니다.

### ‘검증 완료’는 무엇인가요?

파일을 저장한 뒤 다시 읽어서 크기와 파일 지문인 `SHA256`을 확인했다는 뜻입니다. 화면의 `verified`도 이 상태를 말합니다. 실제 운영 서버에 복구까지 끝냈다는 뜻은 아닙니다.

저장 공간이나 작업 사용량이 예상 무료 포함량의 80%를 넘거나 사용량을 읽을 수 없으면 새 업로드를 중단합니다. 마지막 정상 사본은 유지합니다. 오래된 주간 사본은 새 사본의 검증이 끝난 뒤 정리합니다.

### 실제로 복구해야 한다면

관리자 화면에는 즉시 복원하는 버튼을 두지 않았습니다. 기존 자료를 보존한 별도 데이터베이스에서 먼저 확인하고, 결과를 검토한 뒤 운영 서버에 적용합니다.

최근 사고는 공급자의 `D1 Time Travel` 복구 기능도 검토합니다. 이용 가능한 기간은 실제 계정의 현재 조건을 확인하세요. 아래는 복구를 맡은 사람이 따르는 순서입니다.

1. 공개 접수·예약 작업·AI 실행을 멈추고, 사고 시각과 정상 실행 버전을 확인합니다.
2. 현재 자료 장부와 최신 삭제 기록을 별도로 보관합니다. 임시 다운로드 주소는 기록에 남기지 않습니다.
3. 선택한 압축 파일의 크기와 `SHA256`을 대조한 뒤 압축을 풉니다.
4. 기존 장부를 덮지 않는 별도 장부에 자료를 넣습니다. 표 생성, 자료 입력, 인덱스·자동 처리 규칙 순서와 외래 키 관계를 확인합니다.
5. 기존 삭제 처리 기능으로 과거 삭제를 다시 적용합니다. 삭제된 사람의 이름·답안·코멘트를 복구하지 않습니다.
6. 자료 관계, 원장, 어린이·장년 문제, 공개·비공개 구분이 유지되는지 검사합니다.
7. 검사 결과와 남은 문제를 운영자가 확인한 뒤 실제 적용과 공개 재개를 결정합니다.

### 복구 담당자가 확인할 기술 항목

삭제 기록을 `deletion manifest`라고 합니다. 삭제 감사 번호·제출 번호·문제 버전·삭제 시각을 포함하며, 최신 누적본과 검증한 사본을 주간 SQL 사본과 별도로 유지합니다. 최신 장부에서 자료가 사라졌다는 이유로 과거 삭제 표식을 빼지 않습니다.

SQL 입력에는 `PRAGMA defer_foreign_keys`와 기존 Wrangler SQL 해석기를 사용합니다. 자동 처리 규칙이나 문자열을 세미콜론으로 임의 분할하지 않고, 인덱스와 자동 처리 규칙의 원본도 대조합니다.

기존 `submission-deletion-retention` 기능으로 삭제를 다시 적용한 뒤, 삭제 표식 또는 행 부재, 정확한 삭제 감사, 결과 사본에서의 참조 제거를 모두 확인합니다. `foreign_key_check`와 `quick_check`, 표·행·원장 보존 검사도 실행합니다. 일부 삭제 적용이 실패하면 이미 지운 내용을 되돌리지 않고 같은 삭제 기록으로 재시도합니다.

원본 장부가 사라졌거나 삭제 기록의 동기화 사이에 누락이 있었는지 확인할 수 없다면 공개 재개를 보류합니다. 로컬의 가짜 자료 복구 검사는 실제 원격 자료를 복원할 권한이나 완료 증거를 대신하지 않습니다.

## 11. 개인정보와 성경 본문

제출한 이름·답안·코멘트는 동의와 공개·보관 정책에 따라 처리합니다. 문의 접수 뒤 본인 문의를 찾는 조회키는 접수한 브라우저가 보관하며, 서버에는 키 원문을 저장하지 않습니다.

문의 답변과 제출 삭제는 각각 실행해야 하는 별도 조치입니다. 문의에 이메일·전화번호·연락처·첨부 파일을 새로 수집하지 않습니다.

개역개정 성경 본문은 복사해서 저장하거나 AI로 생성하지 않습니다. 대신 **장절·판본 이름·대한성서공회 공식 읽기 링크**를 제공합니다. 비공개 설교 자막과 관리용 AI 결과도 공개 응답에 포함하지 않습니다.

## 12. 아직 제공하지 않는 기능

회원 로그인과 교회 계정 연동은 아직 제공하지 않습니다. 참여 현황에서 바로 `내 제출 삭제 요청`을 보내는 버튼도 향후 계획입니다.

아이디어가 기록돼 있다고 이미 구현된 것은 아닙니다. 새 서비스나 유료 도구가 필요하면 목적·비용·대안을 확인한 뒤 결정합니다. 자세한 검토 내용은 아래 **향후 회원 로그인·교회 계정 연동 검토**에서 확인할 수 있습니다.

## 13. 이 안내문과 검사 기록의 차이

**안내문 수정일**은 이 글을 고친 날짜입니다. **검사 기록**은 실제 기능을 시험했던 개발 기록을 가리킵니다. 안내문을 열었다고 현재 서버를 새로 검사하는 것은 아닙니다.

기존 출시 검사에서는 운영 서버 연결, 퀴즈 발행, 두 난도 제출과 결과 복원, 백업 파일 검증과 별도 장부 복구를 확인했습니다. 당시의 구체적인 결과는 `P8-02` 개발 기록에 보존합니다. 이후 화면 개선과 로컬 시험 모드의 상태는 `docs/STATUS.md`를 따릅니다.

이 페이지 아래 **안내문 수정일과 서버 정보**를 펼치면 서버가 제공한 정보를 볼 수 있습니다. 서버 종류나 배포 번호를 읽지 못하더라도 그것만으로 사이트 장애를 뜻하지는 않습니다.

## 14. 낯선 용어 빠르게 찾기

- **API**: 화면이 서버에 퀴즈 조회나 저장을 부탁하는 통로입니다.
- **Access**: 허용된 관리자만 들어오게 확인하는 로그인 문입니다.
- **D1**: 퀴즈·제출·문의가 저장되는 자료 장부입니다.
- **R2**: 비공개 백업 파일을 보관하는 저장소입니다.
- **Workflow**: 여러 단계의 작업을 순서대로 진행하고 상태를 남기는 장치입니다.
- **Cron**: 정해진 시각에 일을 시작하는 예약 기능입니다.
- **binding**: 코드가 서버 자원을 부르는 연결 이름입니다.
- **migration**: 자료 장부의 구조를 바꾸는 변경 파일입니다.
- **배포 version**: 서버에서 실행 중인 프로그램 묶음의 식별 번호입니다.
- **SHA256**: 두 파일이 같은지 비교할 때 쓰는 파일 지문입니다.
- **deletion manifest**: 복구할 때 과거에 삭제된 개인정보를 다시 지우기 위한 표식 목록입니다.
