# BibleQuiz 운영 매뉴얼

마지막 문서 갱신: 2026-10-03. 실제 설치·검사 결과는 P8-02 검증 기록(docs/work/P8-02-verification.json)을 따른다. 별도 Production D1에0000~0038을 적용하고 앱·콘텐츠·백업 서버, 관리자 로그인, Turnstile과 비공개 R2를 연결했다. 검토한 설교 한 편의 발행·두 난도 제출·결과 복원을 확인했고 SQL 백업과 격리 복원도 통과했다. 예약 운영은 아래 시각과 조건을 사용한다. 일반 공개200과 관리자4개 경로의 로그인 보호를 확인했다. 화면 상단의 환경과 실제 배포 version을 함께 확인한다. version binding이 없으면 미연결로 표시하며 Git HEAD를 실제 배포 version으로 대신하지 않는다.

## 1. 이 프로그램은 무엇인가

한 주 설교로 어린이·장년 가로세로 퀴즈를 만들고 회원가입 없이 풀이·부분 답안 제출·채점·내 답/정답 비교를 제공한다. 진행 중 참여 현황은 제출자에게, 마감 뒤에는 공개한다. 빈 격자 PNG/SVG·단서 복사·Top N 출력과 지난 퀴즈 연습도 가능하다.

## 2. 화면·기능 지도

일반 메뉴는 현재 퀴즈, 지난 퀴즈, 출력, 문의·삭제 요청이다. 본인 제출 삭제는 제출한 브라우저의 결과 화면에서 한다. 삭제 뒤 같은 퀴즈·난도에 다시 제출할 수 없다.

관리자 메뉴는 주간 운영, 이름·문구 필터, 문의·삭제 요청, 발행·수정 도구, 비용·백업, 운영 매뉴얼이다. 비용·백업 상세는 필요할 때 펼쳐 읽는다. 공개 방문자에게 비용·백업·원문·관리자 API를 열지 않는다.

## 3. 전체 구조

브라우저 → biblequiz-app(화면과 API) → D1(자료 장부)으로 연결한다. 관리자 계산은 기존 AdminCompute가 처리한다. 콘텐츠 Workflow는 OpenAI를 호출하고 결과와 사용량을 D1에 보존한다. 백업 Workflow만 D1 export token과 비공개 R2 연결을 갖는다. 앱과 콘텐츠 Worker에는 R2·export token을 주지 않는다. 백업·출력·복원은 AI를 호출하지 않는다.

## 4. 서비스 사전

비용 화면과 아래 서비스 목록은 src/config/service-registry.ts를 함께 사용한다. 각 서비스의 역할·실패 영향·무료 한도·설정 경로·비밀 이름·대안·점검 항목이 있다. 사용하지 않는 KV·유료 자막·Sentry를 사용 중처럼 표시하지 않는다. Turnstile·React·Vite·Tailwind·Hono·Drizzle은 현재 별도 과금 항목이 없다.

Cloudflare 무료 한도는 여러 프로젝트를 합산한다. 이 프로젝트 수치만으로 계정의 무료 잔여량을 판단하지 않는다. D1 일별 제한과 Workers 요청은 UTC 자정 기준이며 월간 정책 확인은 한국 시간 기준이다. R2 저장은 GB-month이고 순간 저장 bytes는 보수적인 업로드 중단 판단용이다. R2 월 작업 합계는 앱의 달력 월 관측이며 청구 주기가 다른 경우 Billable Usage에서 확인한다.

## 5. 직접 등록·연결한 항목

현재 계정의 운영자는 1명이다. Preview와 별도 Production Worker·D1·Access, 비공개 콘텐츠/백업 Workflow·AdminCompute를 기존 승인 범위에서 연결했다. 실제 등록일·version은 P8-02 검증 기록과 Cloudflare Dashboard를 따른다. 이 매뉴얼이 새 연결 승인을 대신하지 않는다.

새 설정이 승인된 뒤 Cloudflare Dashboard → Workers & Pages → 대상 Worker → Settings → Variables and Secrets에서 변수 이름과 환경을 확인한다. Secret 값은 해당 환경의 기존 보관 파일에서 안전하게 등록한다. 값 자체를 채팅·문서·로그에 복사하지 않는다. binding은 코드가 자원을 부르는 이름이며 비밀번호가 아니다.

사용자가2026-10-02 무료 포함량과 초과분 과금 화면을 확인해 R2 구독 추가를 완료했다. Standard 비공개 biblequiz-backups를 만들고 r2.dev 비활성·custom domain 없음과 BACKUP_BUCKET의 backup Worker 전용 연결을 확인했다. 앱과 콘텐츠에는 R2를 연결하지 않았다. 영속 export/사용량 인증, SQL 파일 저장·검증과 격리 복원 검수를 완료했다. 자동 백업은 아래 예약 일정과 사용량 중단 조건을 따른다. 무료 한도 초과분의 청구 가능성은 남아 있으며 유료 플랜으로 전환하지 않았다.

백업의 일반 변수는 OPERATIONS_ENVIRONMENT, CLOUDFLARE_ACCOUNT_ID, D1_DATABASE_ID, BACKUP_BUCKET_NAME이다. 백업 secret은 D1_REST_API_TOKEN, 사용량 읽기 secret은 CLOUDFLARE_ANALYTICS_TOKEN이다. export에 필요한 최소 권한은 연결 시 실제 계정의 token 정책에서 검토한다. 전용 export-only·단일 DB 권한이 지원된다고 가정하지 않는다. Global API Key나 OpenAI Admin Key를 추가하지 않는다.

Production AI 연결은2026-10-03 별도 승인 범위다. 기존 OpenAI 키는 비공개 biblequiz-content의 OPENAI_API_KEY Secret에만 전달한다. 운영자는 관리자 설교 작업 화면의 AI 생성·재생성 버튼으로 실행하며, 실행 시 AI API 비용이 발생할 수 있다. 기존 모델 gpt-5.6-terra·추론 high를 사용하고 결과·사용량을 Production D1에 보존한다. 키를 다시 채팅에 제공할 필요는 없다. 기존 키의 OpenAI Project 청구는 로컬 시험과 합산될 수 있으며 앱의 운영 원장은 별도로 표시한다. 연결 검수에는 새 유료 생성 시험을 포함하지 않았다. 실제 연결·활성화 상태는 P8-02 검증 기록을 따른다.

## 6. 매주 운영

주간 운영 → 이번 주 퀴즈 만들기에서 영상 또는 자료를 등록한다. 공개 자막이 없으면 직접 붙여넣는다. 원본은 유지한다. 자막은 확인·선택적 교정 후 확정하고 목사님 원고·요약본은 받은 그대로 쓴다.

설교 의도를 분석·비판 검토한 뒤 사람이 확정한다. 요약·두 난도 답/단서를 검토하고 무료 배치·최종 확인 후 발행한다. AI 실패나 응답 유실은 기존 작업·사용량을 먼저 확인하고 명시 재개한다. 저장된 결과를 세션 전환 때문에 다시 생성하지 않는다.

발행 뒤 제목·날짜나 비의미 오타는 기존 정정 메뉴로 수정한다. 문제 의미/정답 오류는 접수 중지·검토된 교체 경로를 이용한다. 제출·성적·옛 오류본을 덮지 않는다. Top N은 마감 전에 설정한다. 마감 순위는 고정되고 숨김/삭제의 빈자리를 승격으로 채우지 않는다.

Cron은 정해진 시각에 마감·7일 초안 정리를 실행하는 예약 장치다. 운영 앱은 5분마다 기존 마감 writer와 기존 정리 조건을 호출한다. 마지막 저장 또는 발행 후 7일이 지난 정리 대상의 비교용 작업 내용만 제거하며 원본·확정본·공개 문제·제출·사용량 기록은 보존한다. archive나 시간이 지났다는 이유만으로 제출 tombstone을 지우지 않는다. 문의 보존 기간은 확정하지 않았으므로 문의 자동 삭제를 넣지 않았다.

## 7. 매월 1일 확인

한국 시간 매월 1일부터 비용·백업 영역에 정책 확인 안내가 뜬다. 서비스별 공식 가격표와 현재 플랜을 확인하고, 사용량 계정 합계와 프로젝트 기여분·백업 정상본·미처리 문의·Access 관리자를 확인한다. 모든 서비스 확인 항목을 선택한 뒤 이번 달 확인 완료를 누른다.

확인 완료는 정책 안내만 닫는다. 50% 확인·80% 주의·갱신 실패/24시간 초과·백업 실패는 계속 표시된다. 조회 권한/연결이 없는 값과 빈 API 결과는 미확인이다. Builds 공식 API는 분 한도 도달 여부만 제공하므로 정확한 누적 분·성공/실패 이력은 Builds 화면에서 확인한다. Access 사용자 API는 숫자 합계만 남기고 응답의 이름·이메일은 저장하지 않는다. GitHub 공개 여부/runner와 도메인 갱신은 해당 관리 화면에서 직접 확인한다. 작업 수·CPU·Billing을 서로 대신하지 않는다. 실제 청구 금액은 공급자 Billing 화면에서 확인한다.

OpenAI는 앱에 남은 당시 가격표로 계산한 관측 추정과 미보고 호출을 표시한다. 월간 모델별 token/전사량도 앱 원장을 사용한다. 실패 호출도 실제 관측 usage가 있으면 비용에 포함한다. 관측 없는 호출은 무료라고 쓰지 않는다. 기존 퀴즈별 AI pill은 그대로 유지한다. 앱 추정과 공급자 청구는 차이가 있을 수 있다. 월간 숫자는 자동 재생성 제한이 아니다.

## 8. 배포·수정 전 확인

P8-02의 수동 release·사본 뒤 순차 migration·호환 코드 복귀 규칙과 실제 서버 준비/연결/배포/공개는2026-10-02 사용자 승인을 받았다. 추가 AI 비용·유료 전환·새 구매는 별도 결정이다. 기본 설정의 D1 placeholder는 유지하며 Production은 wrangler.production.jsonc를 명시한다. main push는 기존 Preview 자동 배포를 일으킨다.

원격 변경 전에 대상 환경, 기존 버전, DB 사본, 적용할 migration 목록, 결과 검수, 되돌릴 기준을 한 묶음으로 확인한다. Production과 Preview의0000~0038 적용을 확인했다. 이번 예약 활성화에는 새 migration이 없다. 기존0000~0037을 수정·재배열하지 않는다. 필수 검사는 pnpm check이며 브라우저 목록 확인은 실행 성공이 아니다.

현재 연결·예약 일정·검증 결과와 되돌릴 version은 docs/work/P8-02.md 및 P8-02 검증 기록을 따른다. CPU·export 소요·무료 포함량·공유망 요청·권한은 실제 원격 검사와 공식 한도 자료를 대조했다. 로컬 성공을 원격 무료 운영 검증으로 바꾸지 않는다.

## 9. 문제 발생 시

자막·AI 실패는 작업 화면의 오류/작업 ID와 비용을 먼저 확인한다. 새 명령으로 자동 재호출하지 않는다. 제출 오류는 화면 안내와 request ID·발생 시각·route·배포 version만 기록한다. 이름·답안·댓글·JWT·cookie·key·자막 전문을 로그나 AI에게 보내지 않는다.

429는 잠시 요청이 몰린 상태다. 입력을 유지하고10초 뒤 명시 재시도한다. 성공 응답 유실 뒤 같은 내용·요청키를 보내면 기존 성공을 먼저 복원한다. 세션 cookie를 일부러 지우는 방법을 안내하지 않는다. 같은 공유망에서50명이 서로 다른 참여자로 접근하는 조건은 원격 시험을 통과했다. 요청 제한은 Cloudflare 위치별로 적용되며 정확한 전 세계 공통 사용량·요금 상한은 아니다.

마감 실패는 공개 페이지의 기존 lazy 마감 또는 관리자 지금 마감과 같은 writer를 사용한다. Cron partial failure는 정상 완료로 표시하지 않고 로그의 안전한 code를 확인한다. 백업 실패는 마지막 정상본을 보존한다. running 상태의 Workflow가 끝났는지 확인하기 전 잠금을 풀거나 새 export를 시작하지 않는다. 중단 상태는 AI와 대상 run ID·Workflow 상태를 검토한 뒤 명시적으로 해제한다.

## 10. 백업·복구

최근 사고는 D1 Time Travel(현재 Free7일)을 먼저 검토한다. 장기 안전망은 주간 SQL gzip 정상본8개와 PII 없는 별도 삭제 기록이다. 삭제 기록은 10분마다 독립 동기화한다. 화면의 별도 삭제 기록 갱신은 독립 동기화 성공 시각으로, 수동 SQL 백업에 앞서 수집한 기록과 구분한다. D1 export 동안 DB가 잠시 요청에 응답하지 못할 수 있다. 관리자는 수동/수정 전 백업 버튼의 이 영향을 확인한다. 주간 SQL 백업은 월요일04:00 KST(일요일19:00 UTC)다. 예약 등록과 실제 삭제 기록 동기화를 확인하며, 첫 주간 예약 SQL 실행 전에는 기존에 검증한 수동 정상본을 유지한다.

새 SQL 파일은 압축 크기·SHA256을 측정하고 R2 계정 사용량을 확인한 뒤 저장한다. 예상 저장/작업 포함량80%를 넘거나 사용량을 읽지 못하면 자동 업로드를 중단한다. 저장 후 전체 파일을 다시 읽어 크기·SHA256을 확인하고 D1의 verified 기록을 확정한 뒤 오래된 정상 SQL만 회전한다. 성공한 주간 SQL만 8개 순환한다. 수동·migration 직전 사본은 주간 정상본을 밀어내지 않고 자동 삭제하지 않으며, 월간 점검에서 필요성과 개인정보 보관 기간을 검토하고 명시적으로 정리한다. 승인 전 새 보존 기간을 임의 설정하지 않는다. 실패·삭제 manifest는 주간 정상본8개 수에 넣지 않는다. 화면에는 object key·다운로드 URL·SQL이 없다.

삭제 manifest는 본인/관리자 삭제의 audit ID·submission ID·variant/revision·삭제시각만 포함한다. 최신 누적본과 확인된 사본은 SQL 회전과 분리해 유지한다. 과거 삭제 항목을 최신 DB에서 없다는 이유로 제거하지 않는다. 복구 전에는 가능한 원본 DB에서 최신 manifest를 먼저 수집한다. 원본이 사라졌거나 동기화 지연 동안 삭제가 있었는지 확인할 수 없으면 재적용 성공만으로 전체 삭제 보존을 주장하지 않으며 공개 재개를 보류한다.

복원 절차는 다음 순서다. 일반 화면에는 복원 버튼을 만들지 않는다.

1. 공개 접수·Cron·AI를 멈추고 대상 환경·사고 시각·마지막 정상 version을 확인한다.
2. 현재 DB와 최신 누적 manifest를 별도 보존한다. signed URL은 임시 다운로드에만 쓰고 기록하지 않는다.
3. 선택 SQL gzip의 크기·SHA256을 대조하고 파일을 해제한다.
4. 기존 DB를 덮지 않는 별도 격리 DB에 schema+data를 import한다. 외래 키 관계 때문에 SQL을 그대로 넣기 전 모든 CREATE TABLE, 데이터 INSERT, 인덱스·trigger 순서로 검토하고 PRAGMA defer_foreign_keys를 사용한다. trigger 본문이나 문자열을 세미콜론으로 임의 분할하지 않는다. Wrangler의 SQL parser를 재사용하고 index/trigger 원본도 대조한다. 최신 정상 manifest의 SHA256·version·환경·수집 시각을 확인한다.
5. 기존 submission-deletion-retention 서비스로 항목별 재적용한다. deleted tombstone 또는 행 없음, exact 삭제 감사, snapshot 참조 없음이 전부 확인돼야 한다. 이름·답안·댓글을 복원하지 않는다.
6. foreign_key_check·quick_check·표/schema/행 보존·원장·현재 두 난도·공개/비공개 경계를 검증한다. 삭제 실패 시 이미 제거한 내용을 되돌리지 않고 같은 manifest로 재실행한다.
7. 검증 결과·남은 삭제 freshness 문제·현재 자료 보존·traffic 전환/rollback을 운영자가 구체적으로 승인한 뒤 원격 적용/공개 재개한다.

로컬 합성 재연은 scripts/check-isolated-backup-restore.mjs와 Worker 검사에서 수행한다. 실제 자료·키·원격 DB를 입력하지 않는다. 이것이 실제 원격 복원 승인이나 실행 근거는 아니다.

## 11. 개인정보·저작권

제출 이름·답안·댓글의 공개/보관 동의와 본인·관리자 삭제 정책을 유지한다. 문의 조회키는 받은 브라우저가 보관하며 서버에 원문 저장하지 않는다. 답변과 실제 제출 삭제는 별도 조치다. 이메일·전화·연락처·첨부를 문의에 추가하지 않는다.

개역개정은 장절·판본·대한성서공회 공식 읽기 링크만 제공한다. 성경 본문을 AI로 생성·보완하거나 저장·출력하지 않는다. 자막과 AI 결과는 공개 DTO에 넣지 않는다. 최종 의도와 발행 품질은 사람이 판단한다.

## 12. 보류·향후 기능

회원 로그인과 교회 계정 연동은 현재 미사용이다. 향후 검토 기록은 docs/future/notes.md에서 읽는다. 어린이용·장년용 한/영 안내의 실사용 확인과 관리자 반복 시험 방법은 전체 구현 뒤 다시 검토한다. KV·유료 자막 provider·Sentry·상시 외부 알림은 필요와 비용을 설명하고 결정한 뒤 도입한다. 기존 무료 기능 때문에 추가 라이브러리나 서비스를 임의 설치하지 않는다.

## 14. 용어집

Access는 관리자 로그인 문이다. Actions는 GitHub 자동 검사다. D1은 퀴즈/제출 장부, R2는 비공개 파일 창고다. Workflow는 중단·재개 가능한 작업 순서다. binding은 코드와 자원의 내부 연결 이름이다. migration은 DB 구조 변경 파일이다. Cron은 정해진 시각에 실행하는 예약이다. SHA256은 백업 바이트가 같은지 확인하는 지문이다. deletion manifest는 과거 삭제를 복구 후 다시 적용하는 개인정보 없는 표식 목록이다. verified는 파일 저장/지문 검증이 끝났다는 뜻이며 실제 Production 복원 성공이라는 뜻은 아니다.
