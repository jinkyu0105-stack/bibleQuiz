## 선택한 프롬프트 v2

`prompts/dawn.txt`는 사용자가 선택한 새벽 프롬프트 `billowing-v2`의 원문이다. 움직임5/10·내부 부풀음/상승·가장자리 소멸·아주 느린 카메라 이동과 원문의 닫힌 반복 경로까지 그대로 보존한다. 선택 영상은12:30 생성본(`video=billowing`)이며 교체하지 않았다. 낮·노을·밤의 현재 정본은 아래 `billowing-v3` 파생본으로 구분한다.

프롬프트의 길이는 고정하지 않았다. 출력은4K·16:9로 지정하고 길이는 사용 모델의 지원 옵션에 맞춘다. 선택한 새벽은 실제10초이며 아래의 옛 Veo8초 안내와 구분한다. 새벽 원문의 문장·문단은 보존했고, 복사 버튼/화면/TXT가 같은 내용을 제공한다. [프롬프트 버전/해시](manifest.json).

## 구름 변화 보완 v3

기존 낮·노을·밤 v2 TXT에도 내부 부풀음/소멸·시차·카메라와 독립된 변화 지시는 이미 있었다. 따라서 누락이 아니라 **사용자가 보고한 결과가 의도를 충분히 표현하지 못한 문제**다. 해당 낮 영상과 생성 설정을 여기서 직접 분석하지 않았으므로 모델의 구체적 실패 원인은 확정하지 않는다.

v3은 구름 변화를 첫 지시이자 주 동작으로 두고, 왼쪽 덩어리의 둥근 부풀음/상승 → 조금 뒤 오른쪽 가장자리의 얇아짐/소멸 → 더 뒤 아래 구름 내부의 새 덩어리 형성이 서로 겹치되 시차를 두고 진행되도록 구체화했다. 카메라 이동을 제거해도 보이는 변화와 정상 재생에서 읽히는5/10 강도를 요청한다. 아주 느린 카메라·양옆/아래 밀도·중앙 여백은 유지하며, 정지 사진의 이동/확대나 고정 구름층의 시차만으로 움직임을 대신하지 않도록 했다. 낮·노을·밤의 색·빛·전체 밝기 문단과 밤의 달/별 조건은 v2 그대로다.

반복은 전체 구름량·중앙 여백·색·밝기·흐름의 연속성을 뜻하며 개별 구름의 윤곽·위치를 첫 프레임과 같게 되돌리라는 요구를 없앴다. 정확히 닫힌 카메라 경로도 강제하지 않는다. 기존의 원형 복귀 지시와 같은 마지막 PNG가 변화 억제로 해석될 수 있다는 **프롬프트 검토상 가설**에 따른 조정이다. [Google 공식 안내](https://ai.google.dev/gemini-api/docs/veo#using-first-and-last-frames)는 마지막 프레임을 도착 장면의 제약으로 설명하지만, 그것이 이번 경직의 원인이라는 증거는 아니다. 낮·노을·밤은 시작 PNG만 넣고 선택적인 마지막 프레임은 비워 두는 것을 기본으로 안내한다. 새벽 원문에는 이 변경을 적용하지 않는다.

세 파생본은 전체가 포함된 완성 프롬프트다. v2와 이어 붙이지 않는다. 구름 변화·시간대 보존·반복 품질은 실제 새 영상으로 확인해야 하며, 이번에는 프롬프트와 전달 일치만 검증한다. [변경·검사·공통 문서 인계](PROMPT-REVISION.md) · [버전별 파일/해시](manifest.json).

## 선택한 새벽 파일 확인

사용자가 제공한 `Generated Video October 09, 2026 - 12_30PM.mp4`는 **3840×2160·24fps·영상10초**다. 원본19,423,541bytes = **18.52MiB**(십진수19.42MB)이며 약18.5메가로 표시되는 파일과 일치한다. 데스크톱용은 영상 스트림을 다시 인코딩하지 않고 소리만 제거한19,235,669bytes = **18.34MiB**(19.24MB)다. 모바일700px 이하는 별도1080p4.28MB를 쓴다. [원본/재생본 해시](../sky-v2/assets/video/billowing/manifest.json) · [선택 영상](http://localhost:4189/docs/design/phase-9/sky-v2/?ground=grass&time=dawn&video=billowing).

## 직접 생성하는 순서

1. 시간대 하나의 PNG와 완성 프롬프트를 함께 사용한다.
2. PNG를 시작 이미지에 넣고 해당 완성 프롬프트 전체를 붙여 넣는다. 낮·노을·밤 v3은 마지막 프레임을 비워 두는 것을 기본으로 한다. 새벽 원문과 선택 결과는 그대로 둔다.
3. 영상 출력은4K·16:9로 설정하고 길이는 사용 중인 모델의 옵션에서 선택한다. 새벽 결과의 실제 모델/계정 설정/비용은 파일만으로 확정하지 않는다.
4. 원본 MP4를 저장한다. 카메라 이동을 제외해도 새 둥근 덩어리/얇아져 사라지는 가장자리가 보이는지, 서로 다른 위치에서 시차를 두고 변하는지 확인한다. 양옆·아래 밀도와 중앙 여백·시간대 색·밝기·반복 경계도 확인한다. 영상 수령/연결은 같은 P9-06의 후속 범위다.

## 이전 API 설정 참고 — 2026-10-08 조사

아래 모델/8초/비용 정보는 최초 자료를 준비할 때의 조사 기록이다. 현재 선택된10초 영상의 생성 모델이나 비용을 뜻하지 않는다. **아래의 같은 마지막 PNG 지시는 당시 기록이며, 낮·노을·밤 v3에는 위의 시작 이미지만 사용하는 안내를 우선한다.**


1. 사용할 시간대의 PNG 한 장을 저장하고 해당 프롬프트 전체를 복사한다. 네 이미지를 한 요청에 함께 넣지 않는다.
2. **Image-to-video의 시작 이미지/First Frame**에 PNG를 넣는다. API에서는 `image` 입력이다. 장면 소재를 묶는 `referenceImages` 입력과 구분한다. 마지막 프레임/`lastFrame`을 지정할 수 있으면 **같은 PNG**를 넣는다.
3. 모델은 `veo-3.1-fast-generate-preview`를 비용 기준 추천으로 제시한다. 다른 후보는 `veo-3.1-generate-preview`이며 이번에 두 모델의 실제 품질을 비교한 것은 아니다. 출력은 **4K(3840×2160)·16:9·8초**다. SDK의 `config`에 `resolution: "4k"`, `aspectRatio: "16:9"`, `durationSeconds: 8`을 설정한다. 프롬프트에 4K라고 적는 것만으로는 출력 해상도가 바뀌지 않는다.
4. 생성 후 원본 MP4를 곧바로 저장한다. 이름은 `sky-dawn-4k.mp4`, `sky-day-4k.mp4`, `sky-dusk-4k.mp4`, `sky-night-4k.mp4`를 권한다. API의 결과 보관은2일이므로 다운로드한 파일을 기준으로 작업한다.

[Google 공식 생성/프레임/해상도 안내](https://ai.google.dev/gemini-api/docs/veo). 같은 첫/끝 이미지와 루프 프롬프트도 **완벽한 반복을 보장하지 않는다**. 결과를 받은 뒤 경계의 밝기/모양/속도를 확인하고 필요하면 반복 구간을 편집한다. 카메라 확대/축소보다 구름 자체의 움직임을 우선했다. 생성 소리는 웹 연결 단계에서 제거/음소거한다.

2026-10-08 공식 단가로 Fast4K는8초당 **$2.40**, 네 시간대를 한 번씩 만들면 **$9.60**이다. Standard4K는8초당$4.80, 네 편$19.20이다. 세금/재시도는 별도이며 실제 잔액과 모델 이용 권한은 사용자 계정에서 확인한다. [Google 공식 가격표](https://ai.google.dev/gemini-api/docs/pricing). 네 입력을 준비한 것이 네 편의 실제 생성이나 API 비용 지출을 대신 승인/실행한 것은 아니다.

## 참조 이미지의 실제 해상도와 색

모든 PNG는 **1672×941**이다. 기존 낮/밤 PNG 원본을 같은 크기의 Chromium 화면에서 표시하고 현재 시안의 CSS 필터·빛 레이어를 적용해 내보냈다. 새벽/낮/노을은 같은 낮 원본, 밤은 별도의 밤 원본에서 왔다. 글자·UI·움직임·산·잔디를 제외했고 원본 전체 구도가 보이도록 첫 화면의 가장자리 확대만 제거했다. 새 그림 생성이나4K 업스케일을 하지 않았으며 원본 파일은 그대로 보존했다. 영상 모델이 만드는4K 출력과 이 입력 해상도를 구분한다.1672×941은16:9에 매우 가깝고 출력 시 가장자리가 소폭 조정될 수 있다.

특히 현재 노을 CSS의 상단 하늘은 청록 기운이 있다. 이를 임의로 보라색/주황색으로 바꾸지 않고 참조에 담았다. 프롬프트도 이 색과 살구빛 구름을 유지하도록 맞췄다. 새벽/노을의 색은 영상 도중 변화시키지 않는다. 추후 이 네 영상을 연결하면 이미 포함된 시간대 색에 기존 필터를 이중으로 적용하지 않도록 조정해야 한다.

원본/출력 크기·SHA-256·사용한 필터는 [manifest.json](manifest.json)에 기록했다. 원본의 비공개 키/실제 자료는 사용하지 않았다.
