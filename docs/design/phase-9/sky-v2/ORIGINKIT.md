# OriginKit Grass Field 비교 적용

2026-10-08, P9-06. 사용자는 새 하늘 시안에 긍정적으로 응답하고 맨 아래를 [OriginKit Grass Field · base](https://www.originkit.dev/components/grass-field?preset=base)로 시험하도록 요청했다. 마음에 들지 않을 때 기존 모습으로 돌아갈 수 있어야 한다. 실제 앱의 최종 채택/배포와 구분한다.

## 사용한 경로와 코드

실제 사이트를 Playwright로 열어 **Get this component → MCP** 탭을 확인한 뒤, 설치된 OriginKit MCP의 `get_component`를 다음 값으로 호출했다.

```json
{"name":"grass-field","preset":"base","stack":"vite","styling":"css","typescript":true}
```

응답은 React/TypeScript canvas 컴포넌트와 `dependencies: []`, `registryDependencies: []`였다. 설치·결제·새 production 패키지를 추가하지 않았다. Refero MCP와 별개다. 이번 잔디는 새 이미지 생성물이나 CSS로 닮게 만든 대체물이 아니라 **MCP 반환 코드의 잔디/지형 구현을 사용**한다.

최초 연결 커밋aafcf08에서는 원본의 `FIELD_FS`, `HILL_GLSL`, `GROUND_VS`, `BLADE_VS` 네 shader 문자열과 동일함을 대조했다. 이후 넓은 화면 보정으로 [originkit-grass.js](originkit-grass.js)에 가로 배치 배율을 추가했으므로 현재 네 문자열이 모두 원본과 같다고 주장하지 않는다. 원본의 비균일 blade 배치,9개 정점의 풀잎, 로그 간격의 지형, 바람·돌풍과 마우스 ray 계산을 이어받았다. 전체 React 컴포넌트를 수정 없이 설치한 것은 아니다. 현재 독립 HTML 검토본의 기존 하늘에 연결하려고 다음을 조정했다.

- 원본의 불투명 검정 하늘과 React lifecycle 대신 투명 canvas와 기존 `world.js`의 시계·스크롤·멈춤을 사용한다. 별도 애니메이션 루프를 만들지 않는다.
- 원본 base의 검정/형광 초록 색을 네 시간대의 지면/풀끝/원경 색으로 맞춘다. 기본 높이1.81, 바람1, 돌풍0.9, 방향15도, 시간 배수2, 마우스 강도 최대1.2를 유지한다.
- 첫 잔디 초기화 시700px 이하7,200개, 그보다 넓으면19,200개를 표시한다(이 검토본 최초9,000/24,000개·OriginKit 최대40,000개). DPR1/1.25·최대3840×2160, 잔디 draw 최대30Hz. 창 크기는 즉시 반영하며 밀도 단계는 새로고침 시 정한다.
- 공개 화면에서 지면에 가까워질 때만 모듈·GPU 자원을 만든다. 기본 사진/풀이/관리자는 잔디 모듈을 요청하지 않는다. 비교로 사진을 선택하면 잔디 그리기를 멈춘다.
- 사용자 멈춤/OS 움직임 감소/숨은 탭을 공유하고 터치 스크롤은 가로채지 않는다. 마우스가 버튼·입력 위에 있으면 반응을 줄인다. 초기화/모듈/WebGL 실패에는 원래 사진을 표시하고 context 복원 때 다시 연결한다.

원본 응답의 로컬 참고본과 실제 MCP 탭 캡처는 Git 제외 `.wrangler/design-references/p9-06-originkit/`에 있다. 줄바꿈을 정규화한 `grass-field-base.tsx`의 SHA256은 `3b549ca44727679741e6b76f78b2370605bf808966e8e1e676da6b15c1ac8d0b`다. 전송 원문 bytes의 해시라고 주장하지 않는다. 소스 주석과 이 문서에 출처를 보존한다.

## 먼 산 사진 — 2026-10-08

사용자는 움직이는 잔디와 마우스 반응을 채택하고 먼 곳에 일반 사진으로 산을 추가하도록 요청했다. 잔디 원본/바람/마우스 코드는 유지하고 뒤에 실제 촬영 사진 한 층을 추가했다. 구름은 그 앞을 지나가며 지면과 같은 스크롤 진행도로 산이 나타난다. CSS 마스크·시간대 색/밝기로 접합하며 bitmap을 AI로 생성/보정하지 않았다.

사진은 **Le Mucky (@mucky)**의 [Distant mountain ranges with atmospheric blue haze](https://unsplash.com/photos/distant-mountain-ranges-with-atmospheric-blue-haze-HHKD3m3eouo)다. [Unsplash License](https://unsplash.com/license)의 무료 사용/수정/배포 조건을2026-10-08 확인했다. 사진 자체의 재판매나 경쟁 이미지 서비스 구축 용도가 아니다. 로컬 자산은1600×900 WebP,107,914bytes이며 정확한 URL/해시는 [assets.json](assets.json)의 `photographs`에 기록했다. 생성 이미지 목록과 구분한다.

첫 화면/사진 모드/풀이·관리자에서는 새 사진을 요청하지 않고 잔디가 지면에서 표시될 때1회 로드한다. 별도 반복 애니메이션이나 GPU draw를 추가하지 않았다. 사진 로드 실패에는 산을 숨겨 기존 잔디/하늘을 유지한다. OS 움직임 감소에서는 색상 전환도 끈다.

[산 없는 이전 잔디 비교](http://localhost:4189/docs/design/phase-9/sky-v2/?ground=grass&mountains=off#ground-controls)는 `mountains=off`만 사용하며 산 파일도 요청하지 않는다. 잔디까지 되돌릴 때는 기존 사진 버튼을 쓴다. 이번 산 추가 전 기준은 **aafcf08**이며 별도 로컬 커밋으로 복귀 경계를 남긴다. 최종 산의 높이/색 검수와 실제 앱 연결·기기 검수는 구분한다.

## 넓은 화면 보정 — 2026-10-08

콘텐츠 최대 폭1440px는 그대로다.2560px에서 보이던 양쪽 급경사는 카메라에 지형 mesh의 끝이 드러난 현상이었다. 지면과 풀잎에 같은 `uFieldWidth`를 적용해 가로세로 비율에 맞게 범위를 넓힌다. 언덕 높이·광원·바람·마우스 계산과 풀잎 개수는 유지하며 resize에도 같은 배율을 적용한다. fragment shader는 그대로이고 공통 uniform/두 vertex shader의 x좌표만 조정했다. 따라서 원본 코드의 무수정 설치라고 보고하지 않는다.

산은 같은 출처의3840×2160 WebP(1,012,784bytes)를 추가했다.1600px/3840px `srcset`을 사용하고 디코딩 후 표시한다. AI 업스케일이 아니며 기존1600px 파일도 보존한다. 별도 비용·패키지·서비스 없음. 검사는 [P9-06](../../../work/P9-06.md#넓은-화면과-구름-보정--2026-10-08)을 따른다. 이번 넓은 화면/구름 보정 전 기준은**aa6d1d0**이며 해당 변경의 독립 커밋으로 복귀 경계를 남긴다.

## 가까운 큰 풀과 짧은 들판 — 2026-10-10

캔버스를 절반으로 줄였던caa18af 방식은 사용자 피드백으로 폐기했다. 변경 전0bf9acf의 전경 배치·풀 높이/폭·카메라·캔버스100%를 기준으로 복원한다. 기존 거리0.55~32.55의 후보에서 깊이18 이내의 PC16,972/모바일6,365개를 유지한다. 한쪽 경사가 드러났던 급한 절벽형 초안 대신 낮은 굴곡과 거리3~5에서 서서히 시작하는0.18 배율의 하강 지형을 쓴다. 지면 mesh의 깊이도18까지다.

사용자가 뒤쪽/왼쪽의 빈틈 보충을 추가 요청했다. 남긴 풀의x/z 위치와 개별 모양은 바꾸지 않고 PC2,228/모바일834개를 보충해19,200/7,200개로 제한한다. 보충분의 약60%는 먼 거리6~18, 나머지는 거리2~5의 전경과 왼쪽에 집중한다. GPU에는 실제 풀 수에 해당하는 속성만 올린다. 첫24,000개 모두를 압축 배치하거나 가까운 풀을 균일하게 반으로 빼지 않는다. 지형 높이가 변하므로 뿌리의y좌표는 새 지형을 따른다.

세 화면 크기에서 고정 시각의 풀 실루엣 높이는 최초의약67%였다. 물리적cm 고정값이나 전체GPU 비용67%라는 뜻은 아니다. 프레임 상한30Hz·사진 전환·산·마우스/바람·멈춤/감소를 유지한다. 최초 구도 복귀 기준은0bf9acf이며 밤 영상/유리 후속 수정과 분리해 잔디 관련 변경만 되돌려야 한다. [구현·검사·캐시 확인](../../../work/P9-06.md#잔디-원근과-밀도-보정-및-밤4k-압축--2026-10-10).
